# 元数据源

## 1. 定义

元数据源是**根据书名、作者或 ISBN 从外部服务查回书籍描述信息与封面候选的插件**。它们服务于同一个产品动作：在书籍页点「从互联网同步书籍信息」，或新书入库时自动补全。

本篇是一份**目录**：逐个列出内置的元数据源。它们没有各自的管理界面，只在插件中心作为一行存在，因此合并成一篇。

**不是什么：**

- **不是元数据本身。** 字段规则、编辑权限、别名与分类浏览属于 [元数据](../元数据.md)。
- **不是书源。** 获取书籍**正文**的能力见 [Legado](Legado.md) 与 [外部书库源](外部书库源.md)；不过 Legado 兼作元数据源。
- **不是评价。** 外部评分与书评见 [评价源](评价源.md)。

## 2. 使用场景

- **管理员希望国内书优先用豆瓣**，冷门书再退到别的来源。
- **上传的是网文**，常规书目站查不到，需要网文专用来源。
- **只知道 ISBN**，希望精确命中。
- **某个来源反复超时**，管理员想停用它而不影响其余来源。
- **站点在境外**，希望只用可访问的来源。

## 3. 功能

- 按书名、作者、ISBN 检索候选。
- 返回书名、作者、出版信息、简介与封面。
- 多个来源并行查询，部分失败不影响整体。
- 管理员按来源启停。
- 新书入库时自动补全（站点开关）。

## 4. 术语与界面用词

### 术语表

| 标准用词 | 英文 | 含义 | 示例 |
|---|---|---|---|
| 元数据源 | metadata source | 提供书籍信息检索能力的插件 | 豆瓣、百度百科、NeoDB |
| 候选 | candidate | 一次检索返回的一条待选书籍信息 | 搜「三体」返回三条候选，读者挑一条套用 |
| 并行查询 | parallel lookup | 同时向多个来源发起检索 | 七个来源同时问，先回来的先展示 |
| 启用来源 | selected sources | 参与检索的来源集合 | 管理员只勾了豆瓣和新华书店 |

### 操作按钮用词

| 界面用词 | 位置 | 行为 |
|---|---|---|
| 元数据 | 插件中心页签 | 查看元数据类插件 |
| 选择启用的元数据源 | 管理设置 | 勾选参与检索的来源 |
| 从互联网同步书籍信息 | 书籍详情、书籍管理 | 发起检索 |
| 自动补全设置 | 插件中心 | 配置新书是否自动补全、是否保留原封面 |

## 5. 行为逻辑

### 5.1 内置来源目录

| 插件 ID | 名称 | 说明 |
|---|---|---|
| `talebook.meta.douban-v2` | 豆瓣 | 解析豆瓣读书搜索页，提取书名、作者、出版信息、评分与简介 |
| `talebook.meta.baike` | 百度百科 | 从百科词条提取书籍简介、作者与出版信息 |
| `talebook.meta.calibre` | Calibre 元数据 | 复用 Calibre 自带的元数据插件体系，默认启用 Google Books、Amazon 与 Edelweiss |
| `talebook.meta.xhsd` | 新华书店 | 按 ISBN 从商品页抓取书名、作者、出版社与封面 |
| `talebook.meta.tomato` | 番茄小说 | 网文书名、作者、简介与封面 |
| `talebook.meta.qimao` | 七猫小说 | 网文书名、作者、简介与封面 |
| `talebook.meta.neodb` | NeoDB | 从联邦书目检索书名、作者、出版与评分 |

另有两个插件**兼作**元数据源，但主归属不在本篇：

| 插件 ID | 名称 | 主归属 |
|---|---|---|
| `talebook.combo.open-library` | Open Library | 按 ISBN 取元数据与评分，同时提供评价能力，见 [评价源](评价源.md) |
| `talebook.source.legado` | Legado 在线书源 | 主要是书源，兼作网文元数据来源，见 [Legado](Legado.md) |
| `talebook.combo.weread` | 微信读书 | 综合插件，见 [微信读书](微信读书.md) |

### 5.2 并行与部分失败

一次检索**并行**询问全部启用的来源，整体有总超时；超时的来源被取消，**不影响已返回的结果**。每个来源最多贡献固定条数的候选，避免单个来源刷屏。

部分来源失败时仍返回成功结果并给出失败摘要——失败摘要在展示时必须做输出转义，外部返回的错误文本不可信。

### 5.3 网文与常规书的分工

豆瓣、新华书店、Calibre、NeoDB 面向正式出版物；番茄、七猫面向网络文学。两类书的标识体系完全不同（前者有 ISBN，后者没有），因此**没有一个来源能覆盖全部**，站点需要按藏书结构选择启用组合。

### 5.4 启用与调用

哪些来源参与检索由**插件的启用状态**直接决定。管理设置里另有一组选择项与之配合，但启停的权威在插件卡片上。

自动补全是站点级开关，**默认关闭**；另有独立开关控制自动补全时是否保留原有封面，**默认保留**。

### 5.5 与书籍写入的关系

元数据源只负责**给出候选**，套用与写入的规则完全由 [元数据](../元数据.md) 定义：整体套用、仅更新信息、仅更新封面三种方式，以及封面缓存键刷新要求。

## 7. 实现对照

### 7.1 数据存储

| 概念 | 存储 | 说明 |
|---|---|---|
| 插件定义与启用 | `plugin_definitions` / `plugin_installations` | 见 [插件平台](插件平台.md) |
| 候选结果 | 不落库 | 检索结果直接返回前端，套用后写入 Calibre |

### 7.2 API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/book/<id>/refer` | 书籍页发起检索与套用 |
| POST | `/api/admin/plugins/<key>/metadata/search` | 管理端按插件检索 |
| GET / POST | `/api/admin/plugins/preferences` | 自动补全策略 |

### 7.3 关键定义

| 符号 | 值 | 含义 |
|---|---|---|
| 能力 | `metadata.lookup` | 全部元数据源共同声明 |
| `BookRefer.SOURCE_RESULT_LIMIT` | `5` | 每个来源采纳的候选条数 |
| `BookRefer.REFER_TIMEOUT` | `30` | 并行检索总超时秒数 |
| `META_SELECTED_SOURCES` | `["douban_v2","baidu","google","amazon","xinhua","booksource"]` | 默认启用来源 |
| `auto_fill_meta` / `auto_fill_keep_cover` | `False` / `True` | 自动补全策略 |
| `ai_api_url` / `ai_model` | OpenAI 兼容地址 / `gpt-3.5-turbo` | AI 元数据相关配置 |

### 7.4 代码落点

| 行为 | 文件与函数 |
|---|---|
| 插件实现 | `webserver/plugins/meta/` 下各目录 |
| 注册 | `webserver/plugins/register.py` 的 `META_PROVIDERS` |
| 能力接口 | `webserver/plugins/runtime/interfaces.py` 的 `MetadataProvider` |
| 查询输入 | `webserver/plugins/runtime/domains.py` 的 `MetadataQuery`，保留 `title`/`isbn`/`publisher`/`authors` 结构 |
| 检索与套用 | `webserver/handlers/book.py` 的 `BookRefer` |
| 自动补全 | `webserver/services/autofill.py` |
