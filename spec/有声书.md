# 有声书

## 1. 定义

有声书是**由书库里的文字书生成的衍生媒体版本**。它复用原书的书目、封面、作者、丛书与访问权限，但转换、播放、同步、统计与播客分发都使用独立的领域模型。

一句话立场：**有声书不是一种书籍格式**。音频文件不写进书籍的格式清单，不能被下载为「一个格式」，它自成一套版本与章节体系。

功能当前以 **Beta** 对读者开放。

**不是什么：**

- **不是书籍格式。** 不进 [书籍](书籍.md) 的格式列表。
- **不是导入的音频。** 只从站内文字书生成，不支持导入已有的 MP3 或 M4B。
- **不是文字阅读进度。** 收听进度独立存储，见 [阅读状态](阅读状态.md)。
- **不是公开播客。** 分发是每位读者一个私人订阅源，不做公开播客目录。

## 2. 使用场景

- **读者通勤路上想听书**，书库里只有文字版。
- **管理员想给一本长篇小说配多角色朗读**，希望先看看角色分配对不对再开始生成。
- **生成到一半失败了**，希望重试时不必从头再来。
- **读者想用 Apple Podcasts 之类的客户端听**，而不是一直开着网页。
- **读者边听边读**，希望正文跟着音频高亮。
- **管理员想知道站点的收听情况**，并且要能区分真实收听与客户端拉流。

## 3. 功能

- 从 EPUB 或 TXT 生成有声版本，快速模式或高级模式。
- 高级模式下审查角色分配、编辑单章对白。
- 持久任务队列：优先级、取消、失败重试、重启恢复。
- 一本书保留多个有声版本，试听后发布，可回滚。
- 选章生成与续补。
- 站内播放器与全站迷你播放器。
- 音文同步高亮。
- 书签与睡眠定时。
- 每位读者一个私人播客订阅源。
- 个人与全站收听统计、播客请求审计。

## 5. 行为逻辑

### 5.1 版本与发布

一本书可以有多个有声版本，但**同时只有一个已发布版本**。

- **首次**生成的完整版本**自动发布**。
- 之后成功的结果是**候选版本**，试听后手动发布，且可回滚到旧版本。
- **部分章节版本默认不可发布**，管理员可以例外发布。
- 已发布的章节资产地址是**版本化且不可变**的，防止客户端缓存到错误内容。

### 5.2 两种生成模式

| 模式 | 流程 |
|---|---|
| 快速 | 提交后自动走完全程 |
| 高级 | 先识别角色，进入待审查；人工确认角色与对白后继续 |

高级模式**不暴露完整剧本文件**，只提供角色的结构化配置界面和单章对白编辑器。这是刻意的生产边界：读者调整的是角色与台词，不是剧本格式。

### 5.3 任务队列

数据库是队列的**唯一真相**，进程重启后任务不丢。

- **去重**：同一本书 + 同一份配置指纹，同时只允许一个活跃任务。
- **并发**：默认全站 1 路，可配置到 3 路。
- **租约**：工作进程持有带过期时间的租约，崩溃后任务可被重新领取，这是重启恢复的基础。
- **取消**：请求取消后由宿主进程优雅终止，必要时强制结束。
- **重试**：失败可重跑，已完成的音频片段有缓存，续跑不必从头合成。

任务分六个阶段推进：排队、识别、审查、生成、收尾、完成。界面据此展示进度。

### 5.4 存储与安全

音频、时间轴、剧本、清单都是**文件**，不进数据库。数据库只保存路径、时长、体积与内容指纹。

**句段不入库**：一章可能有数千句，全部写库会放大迁移、查询与备份成本。句段放在逐章的时间轴文件里，客户端按需加载当前章。

所有路径以**相对根目录**的形式入库，服务端解析后**再次做目录包含校验**，越界直接拒绝。这条防的是通过构造路径读取任意文件。

### 5.5 权限

- **播放跟随原书的查看权限**——原书看不到，有声版本也听不到。
- **管理员默认可以生成**；站点开关可以允许书籍所有者生成。
- 普通读者只看得到自己的制作任务，管理员看全站。

### 5.6 收听进度

收听进度按「读者 + 版本」唯一，带**乐观版本号**，防止多设备用旧进度覆盖新进度。书签跟随有声版本，**不写入原书的文字阅读进度**。

文字与收听两套进度**完全独立**，边听边读不互相覆盖；读者要显式操作才能把收听位置转为阅读位置。

### 5.7 播客分发

每位读者**一个**活跃的私人订阅源：一本书是一季，一章是一集。不生成整书合并音频。

订阅令牌**只存哈希**，数据库里没有明文。令牌可以吊销，也可以冻结并记录原因。读者可以把某些书从自己的订阅源中隐藏。

### 5.8 两套统计绝不混算

| 口径 | 来源 | 含义 |
|---|---|---|
| 第一方统计 | 站内播放器的播放会话 | 真实收听时长，播放中增量上报，暂停或关闭时收口 |
| 传输估算 | 播客客户端的 HTTP 请求日志 | 只能估算——客户端可能预下载却没听 |

两者在日聚合表中用来源字段区分，**查询时必须按来源过滤，不能直接求和**。把拉流当收听会让统计虚高数倍。

播客访问日志保存原始 IP，默认保留 **90 天**，可配置；标记为保全的记录不清理。

### 5.9 输入与同步边界

- 只从站内的 EPUB 或 TXT 生成，**不导入已有音频**。
- TXT 为实现音文同步，会先转换为规范 EPUB 再生成。
- 同步粒度是**句子或对白逻辑片段**，不承诺逐字。

## 7. 实现对照

### 7.1 数据存储

| 概念 | 表 | 关键约束 |
|---|---|---|
| 有声版本 | `audiobook_editions` | `book_id` 一对多；`status` 默认 `draft` |
| 章节 | `audiobook_chapters` | `(edition_id, number)` 唯一 |
| 制作任务 | `audiobook_jobs` | 租约 `lease_owner` / `lease_until`；去重键 `config_hash` |
| 收听进度 | `audiobook_progress` | `(reader_id, edition_id)` 唯一；`version` 乐观锁 |
| 书签 | `audiobook_bookmarks` | 跟随版本 |
| 播放会话 | `audiobook_playback_sessions` | `uuid` 唯一，第一方统计来源 |
| 订阅 | `podcast_subscriptions` | `token_hash` 唯一；`hidden_books` |
| 播客请求日志 | `podcast_access_logs` | Range 字段用于传输估算；`protected` 标记保全 |
| 日聚合 | `audiobook_daily_stats` | `source` 字段区分两套口径 |
| 音频与时间轴 | 文件系统 | 路径相对 `AUDIOBOOK_PATH` 存储 |

| POST | `/api/audio/<id>/revisions` | 单章返工 |

| GET | `/api/audio/<id>/chapter/<n>/timeline` | 章节时间轴 |

### 7.3 关键定义

| 符号 | 值 | 含义 |
|---|---|---|
| `AUDIOBOOK_PATH` | `/data/books/audiobooks` | 产物根目录 |
| `ACTIVE_JOB_STATUSES` | `queued` `inspecting` `awaiting_review` `generating` `finalizing` | 活跃任务状态，去重依据 |
| `PLAN_PHASE_KEYS` | `queue` `inspect` `review` `generate` `finalize` `complete` | 生成计划的六个阶段 |
| 默认引擎 | `edgetts` | 另支持 Qwen3TTS |
| 并发 | 默认 1，可配 1–3 | 全站生成并发 |
| `ROLE_COLUMNS` | `9` | 角色配置表列数 |
| 日志 IP 保留 | 默认 90 天 | 播客访问日志 |
| 统计来源 | 第一方 / `podcast_estimated` | **绝不混算** |
