收紧转换与 TXT 提取的文件路径边界

在不改变正常转换、提取流程的前提下，对进入文件系统路径的书籍 ID 和目标格式执行白名单校验，并验证解析后的路径仍位于配置根目录中。

状态：SUPERSEDED创建日期：2026-08-28所属模块：webserver影响范围：转换服务、TXT 提取服务、服务测试需求来源：PR #977 CodeQL

1. 原始诉求

“修复 https://github.com/talebook/talebook/pull/977 的 codeql 报错”

PR 的 CodeQL 安全门禁报告 6 个 high 级 py/path-injection 告警：webserver/services/convert.py 2 个，webserver/services/extract.py 4 个。虽然这两个文件与 PR 基线内容一致，但 PR 变更规模过大使既有开放告警进入本次门禁。

已被替代：CI 证明 commonpath 未被 CodeQL 识别为污点屏障。本方案由 design/webserver/20260828-codeql-path-guard-follow-up.active.html 替代，后者改用查询可识别的内联 startswith 守卫。

2. 目标与边界

目标
  • 阻断书籍 ID、目标格式造成的路径穿越。
  • 阻断配置根目录内符号链接将输出导向根目录外。
  • 覆盖恶意路径组件和正常提取行为的回归测试。
非目标
  • 不调整 Readest 嵌入实现和静态资源。
  • 不改变支持的转换格式及成功响应。
  • 不处理 PR 门禁之外的其他既有 CodeQL 告警。

3. 现状、根因与证据

位置现状根因
convert.py:214,247由 book["id"]、new_fmt 拼出路径后执行打开和删除。服务层依赖调用方约束，未在文件系统边界重新校验。
extract.py:23,27,28,33由 bid 拼出目录和 JSON 路径后检查、创建及写入。URL 参数跨越到服务层后仍保留污点，且没有根目录包含性检查。

4. 方案

方案结论：在两个服务内靠近路径构造的位置执行正则 fullmatch 白名单、realpath 规范化和 commonpath 根目录包含性检查；非法输入在任何文件操作前抛出 ValueError，异步服务框架负责记录任务异常。
输入

书籍 ID、转换目标格式与配置根目录。

白名单

ID 仅允许十进制数字；格式仅允许 epub、azw3、pdf。

规范化

通过 realpath 解析根目录、候选目录及文件。

包含性检查

commonpath 不等于安全根时拒绝，正常路径继续原流程。

5. 影响范围、风险与回滚

影响范围

ConvertService.convert_and_save 与 ExtractService.parse_txt_content 的输入防御及路径生成。

保持不变

合法数字书籍 ID、既有三种输出格式、文件内容、数据库写入和消息语义不变。

主要风险：历史内部调用若传入非数字 ID 或未支持的扩展名将被拒绝；通过现有调用点检索和相关测试确认所有合法调用均符合白名单。

回滚：单提交回滚服务校验、测试和本方案即可；不涉及数据迁移或配置清理。
