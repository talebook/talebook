插件请求按 plugin + host 排队

把网络书库的并发约束从 connection 互斥改为真实 HTTP 出口上的共享 host 队列；搜索、浏览与保存在达到上限后等待，而不是立即失败。

状态：ACTIVE创建日期：2026-09-04所属模块：webserver影响范围：插件运行时、网络书库需求来源：TB-198

1. 原始诉求

“之前的 PR 已经合并了。你优化一下，按照 plugin+host 来排队，并且对于搜索、保存场景，应该是【限频后排队等待】而不是立刻失败报错。”

PR 1034 已让并发 read 绕过 connection lease，消除了点击搜索结果时的误拒绝；但它没有建立上游站点级限流，而且第一个 read 仍会持有 connection lease。

2. 目标与边界

目标

  • 以 (plugin_key, hostname, effective_port) 为唯一排队键。
  • 同键请求按 FIFO 等待空位，等待计入能力调用总 deadline。
  • 搜索、详情、目录、章节与封面请求共用同一 host 上限。
  • read 不再取得 connection lease；有副作用能力保持互斥。

非目标

  • 本次不实现 QPS/token-bucket；限制的是同时在途 HTTP 数。
  • 不新增数据库表或迁移，队列作用域为当前服务进程。
  • 不改变 HTTP API、前端交互和书源协议。
  • 不移除搜索及保存线程池的进程资源上限。

4. 方案

结论：运行时在调用 provider 时注入 plugin 身份与 host 并发配置，SafeHttpClient 按实际请求 URL 归一化 host 并进入进程级 FIFO 队列；请求完成或异常时在 finally 释放 slot。
IDENTIFY绑定 plugin

运行时以 manifest id 标识当前 provider。

GROUP归一化 host

URL 转为小写 hostname 与有效端口。

QUEUEFIFO 等待

同键达到上限后等待，保留跨键独立性。

RELEASE完成后唤醒

成功、HTTP 错误或异常均释放并唤醒队首。

配置与兼容性

  • 新增运行时连接配置 host_concurrency，默认 10，允许 1–100；Legado schema 显式展示该项。
  • search_concurrency 继续控制搜索生产者线程池，save_concurrency 继续控制单个保存任务的章节 worker；二者不再冒充 host 上限。
  • 未通过 SafeHttpClient 发出的非插件网络请求不进入此队列，避免无 plugin 身份时错误合并。
  • 队列等到总 deadline 耗尽时返回 timeout 类错误，不返回 plugin.concurrent_run。

5. 影响、风险与回滚

影响范围

safe_http.py 新增公平队列；plugin_runtime.py 注入策略并移除 read lease；Legado 暴露 host 上限；保存封面显式携带 plugin 身份。

保持不变

写、同步和 execute 的 connection lease；429 重试；搜索结果协议；保存任务去重；SSRF、重定向和响应大小校验。

风险：同步等待会占用调用线程；现有有界 worker 池提供进程容量上限。FIFO、不同 key 不互阻、异常释放、deadline 退出与多入口共享必须用并发测试锁定。

回滚：整项改动无数据迁移，可按提交回滚；旧连接没有新字段时自动使用默认值。
