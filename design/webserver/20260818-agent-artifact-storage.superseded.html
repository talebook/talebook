Agent manifest 目录化存储

让人物思维 Agent 的 manifest 以目录文件作为唯一内容来源，数据库只保存检索索引、相对路径、摘要与状态。

1. 原始诉求

TB-52 统一规范要求：“实体产物优先保存在目录中”，“统一目录为 books/ai/{user-workspace}/{feature}”，“数据库仅承担管理与检索”，并要求临时文件校验后原子替换、删除同步清理，且备份与迁移同时覆盖数据库和 books/ai。成员随后要求相关子任务按新规范修改代码。

TB-62 当前草稿 PR 仍把完整 manifest 存在 protagonist_agents.manifest，因此需要独立后续方案替换该持久化边界。本方案生效后覆盖原人物 Agent ACTIVE 方案的数据存储章节，其余产品与交互设计继续有效。

2. 目标与边界

目标非目标
  • 单一当前版 manifest.json 位于 /data/books/ai/{opaque-workspace}/agents。
  • 数据库只保留相对路径、SHA-256、状态及展示/关联索引。
  • 每次读取先做创建者、书籍 ACL 与版本检查，再校验路径和摘要。
  • 创建、重新生成使用同目录临时文件和原子替换；删除 Agent 或书籍同步清理产物。
  • 默认根目录位于既有 /data/books 数据卷，数据库迁移保持相对路径不变。
  • 不建设版本表、版本列表、回滚接口或 v{version} 目录。
  • 不改变人物思维 Agent 的产品交互和运行时协议。
  • 不为其他 AI 功能迁移数据；共享存储工具保持可复用。

3. 方案

1. 生成运行时输出经 schema 校验后序列化为稳定 JSON。
2. 原子落盘同目录临时文件 fsync 后以 os.replace 替换当前文件。
3. 索引提交数据库写入相对路径、SHA-256 和 ready 状态；不写正文。
4. 受控读取ACL 与书籍版本通过后，限制路径前缀并校验摘要再加载。

目录与数据

/data/books/ai/
  {workspace-id}/
    agents/
      {agent-id}/manifest.json
      previews/{task-id}/manifest.json

workspace-id 由安装级密钥和内部 reader id 通过 HMAC-SHA-256 确定性生成；不暴露邮箱或用户名。预览同样不把完整内容写入任务表，任务表只保存相对路径、摘要和状态引用；用户删除预览或书籍时同步清理目录。

一致性与失败

  • 新建先写文件再提交索引；数据库提交失败时删除新文件。
  • 重新生成先保存旧文件字节，原子替换后提交新摘要；提交失败时原子恢复旧文件。
  • 缺失、路径越界、SHA 不符或 JSON 结构错误统一返回产物不可用，不把部署绝对路径暴露给客户端。
  • 删除先提交数据库级联，再清理受控目录；清理失败记录服务端日志并向调用方返回明确错误，目录不能被其他用户读取。

4. 影响与风险

风险控制剩余风险
路径穿越或跨用户读取只接受受控相对路径；解析后校验根目录、workspace 与 feature 前缀。管理员直接修改文件系统仍属于部署级权限。
数据库与文件不一致原子写、SHA 校验、提交失败补偿、缺失失败关闭。进程在文件替换与数据库提交之间被强杀时可能留下可检测的不一致。
备份漏文件默认根目录固定在现有 /data/books 数据卷；方案和测试验证该约束。自定义根目录的部署者必须把该目录加入外部备份。
旧列残留ORM 删除正文列且不再读写；当前 PR 尚未合并，无生产内联 manifest 需要迁移。曾试跑草稿分支的非生产数据库可由非破坏迁移保留未使用旧列。
