区分 PDF 下载与在线阅读响应

恢复详情页 PDF 下载，并保持 PDF.js 在线阅读能力。

创建日期：2026-09-22 · 所属模块：webserver · 状态：ACTIVE · 需求来源：GitHub #1047 / Multica TB-224 · 影响：spec/书籍.md、spec/阅读器.md

1. 原始诉求

GitHub #1047 报告 v26.09.01 在 PC 与移动端的 Chrome、Firefox 中均无法通过浏览器下载 PDF。

当前处理器为所有非 OPDS PDF 返回 Content-Disposition: inline。这解决了 #595 的在线阅读媒体类型问题，却同时改变了详情页下载的语义。

2. 目标与边界

  • 普通 PDF 文件请求默认返回 application/pdf 与 attachment。
  • 统一在线阅读入口生成的 PDF URL 显式请求 inline。
  • OPDS 始终保持附件下载；非 PDF 格式、权限、计数与 Range 处理保持不变。
  • 不处理 #1026 的 PDF 封面提取，也不改变前端页面组件。

3. 方案与兼容性

文件接口默认代表下载；只有服务端统一阅读入口可通过 inline=1 声明在线阅读用途。

BookDownload.initialize() 解析严格布尔标记，BookDownload.parse_url_path() 根据格式、OPDS 与标记选择响应头。BookRead 在把文件地址编码进 PDF.js URL 前添加标记。旧的直接下载 URL 无需修改即可恢复，既有阅读入口仍能内联加载。

参数不授予额外权限，仍经过同一可见性和下载权限检查。主要风险是遗漏其他依赖内联 PDF 的调用方；仓库搜索表明在线阅读只从 BookRead 生成该 URL，测试同时锁定跳转目标与两类响应头。

4. 影响、回滚与界面审查

代码影响限于 webserver/handlers/book.py 与后端测试；同步澄清书籍下载和阅读器规格。无数据库、配置、部署或前端组件变化。

这是 HTTP 响应头与服务端跳转契约修复，无页面布局、文案、主题或交互控件变化，豁免 interface-review 和浏览器渲染审查。回滚只需撤销处理器、测试与规格改动，无数据清理。
