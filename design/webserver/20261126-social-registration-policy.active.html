社交账号遵循访客注册开关

关闭自助注册时，保留既有社交账号的登录。

ACTIVE2026-11-26webserverIssue #1091

原始诉求

关掉访客注册后仍能用社交账号创建新用户。既有账号应能继续登录。

目标与边界

复用同一个注册开关，不新增配置或迁移；保留原社交登录入口与其他原有登录路径。只认社交平台确定的绑定，不使用同名或邮件自动关联本地账号。

方案

在社交认证流水线解析既有身份后、创建账号时检查当次请求的最新注册设置。已有绑定走原流程；已登录用户的绑定不创建账号。关闭时，访客若需要新建账号则收到 403 并被提示联系管理员。设置页调整中、英、俄三种语言的开关文字。

影响范围：社交认证回调、设置页注册开关、用户与系统设置规格。部署者过去在关闭注册时仍允许社交平台自助开户的行为不再生效；已绑定账号不受影响。

  • make lint-py-fix、make lint-py、改动测试的 Ruff、make check-spec（25 篇）、make check-design 与 git diff --check：通过。
  • npm run build 通过；npm run lint 无错误，有仓库现有警告。使用 Playwright 在 Chromium 执行 Visitor registration setting：1 项通过，实际渲染中文设置页、桌面与 320 px，并核对截图。使用 Nuxt 生产构建与短生命周期模拟 API，仅做界面隔离验证。
