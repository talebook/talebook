在线书库接入 Venera 漫画源

复用书源插件底座与 Komga Reader，让读者浏览、搜索并阅读真实在线漫画。

状态：ACTIVE创建日期：2026-10-03所属模块：webserver需求来源：TB-236

原始诉求

开发者希望 Talebook 可以连接 Venera，接入 Talebook 的在线书库；至少一个实际源完成端到端验证。旧方向 PR #1073 未合并，已关闭。

目标与边界

首版支持官方配置仓库的 MangaDex 1.2.0 脚本，固定提交 d8a71168a83a6797482a5be9c000989dabf21c08 与 SHA-256。验证成功后才开放该预设。公开阅读不需要源账号；论坛 WebView 登录、收藏、评论、DRM、任意第三方源及任意脚本上传不在兼容范围。配置可选择语言、图像质量和超时。

现状与证据

官方 doc/comic_source.md 和 assets/init.js 定义 ComicSource、fetch、ComicDetails 与 Map 章节。官方无头模式没有供 Talebook 调用的漫画 HTTP 服务。MangaDex API 已返回真实 HTTP 200。Talebook SourceProvider 已提供搜索、浏览、详情、目录及正文接口；漫画 Reader 接收页面 manifest。

仓库与本机技能目录未找到 grill 技能，远端 talebook/skills 亦无该技能；按下面决策表自行逐项核实设计，现有任务已授权选用代表性源。

决策核对与方案

问题决策依据
源的真实接入机制运行固定版本官方 JS，映射 SourceProvider源是客户端扩展脚本，无统一服务端接口
隔离与网络独立 QuickJS 子进程；JS 无 Python/文件/环境访问；CPU、内存、栈、作业、请求数和墙钟限制；HTTP 仅由宿主执行复用 quickjs 依赖，禁止将脚本交给 Node 或 Python eval
供应链与凭据固定 SHA-256，首次从固定 GitHub URL 获取后缓存；不运行自动更新；固定公共 HTTPS 域名与 GET；不传入 Talebook 或源凭据被验证的 MangaDex 公开阅读不需要源账号
章节与页序按脚本 Map 的卷/语言分组和条目插入顺序展开；页面顺序严格沿用 images 数组不对字符串章节号另做排序，保留翻译版本
阅读与图片同站登录保护的图片代理、用户绑定短期签名；读取页面后交给现有 Komga Reader；不自动保存到本地不暴露上游鉴权，不扩大已有下载协议
故障反馈源不兼容、网络失败、访问被拒绝、速率限制、空章节、超时明确反馈；阅读页面可重试不以空列表掩盖源故障

QA 反馈修正方案

PR #1074 尚未合并和独立生效，同一工作继续更新唯一方案。QA 指出生产代理缺失阅读器入口，以及宿主抛出 HTTP 异常使官方脚本可选统计请求的降级失效。

为 SPA、SSR 和开发 Nginx 配置补充精确 location = /read-online-comic，保留后端 no-store；子路径仍按既有外层代理去前缀契约。宿主将允许请求的网络与上游失败通过 IPC 拒绝对应 JS Promise，携带无敏感内容的请求标识。脚本可捕获可选失败；未处理失败回传标识，由宿主保留原有明确错误类型。网络策略、大小、次数和整体时间限制仍由宿主强制终止，不允许脚本吞掉。

影响范围追加 conf/nginx 三种配置、部署与源宿主回归、生产规则验证工具及 spec/插件/Venera.md。
