把 EPUB 美化工具迁移为 Talebook 内置 tool 插件

把 mybooks 的 epub_beautify（12 套预设 × 4 种目录形式、纯无损生成新书）改造成 Talebook 的 integrations.tool 插件，沿用现有三个正文工具的 provider/handler/前端范式；同时核对内置文本工具图标并补齐新工具图标注册。

状态：ACTIVE 创建日期：2026-09-15 所属模块：webserver 影响范围：webserver/plugins/tool、handlers、app/pages/plugins、i18n、local-mdi-icons 需求来源：用户原话（2026-09-15）

1. 原始诉求

“查看 https://github.com/talebook/talebook/blob/master/document/PluginGuide.md ，我想把本地的 epubbeautify 工具改造成 talebook 的一个插件，做个计划（附加一个，之前黏菌还提交过三个工具，但是图标似乎有问题，你把图标修复也放进计划里）”

触发背景：mybooks 侧 epub_beautify 已上线并经过多轮 review（revision 0.2.2），核心逻辑无 calibre 依赖；Talebook 侧已建立 PROTOCOL_VERSION = "talebook.plugin/v1" 的插件领域模型与 TransformProvider 契约，且已有三个工具（正文查找替换 / 繁简转换 / TXT 编码修复）作为可复制的范式。图标部分为独立附加项：用户不确定三工具图标是否正常。

2. 目标与边界

目标

  • EPUB 美化以 talebook.tool.epub-beautify 内置插件交付，具备 preview / run、书籍详情页入口、运行审计。
  • 核心美化逻辑逐行复用 mybooks 实现，禁止重写导致输出不一致。
  • 坚持「只生成新书、原书零改动」的无损红线。
  • 图标修复可追溯：确认 master 已含 TB-201，并为新工具补齐图标注册与测试覆盖。

非目标

  • 不迁移 mybooks 的背景图上传（无对应 Talebook 持久层）。
  • 不迁移批量队列与后台长任务模型（v1 单本，平台已有 host queue）。
  • 不提供覆盖写回（overwrite）模式。
  • 不改动现有三个工具的行为与接口。
  • 不把所有非 tool 插件的 mdi 名纳入本次修复范围。

5. 方案

方案结论：新插件目录 webserver/plugins/tool/epub_beautify/ 拥有全部内核与 provider，Talebook 只提供平台能力（书籍定位、权限、入库、审计）；数据流为 book → preview(分析) → apply(生成 beautified.epub) → import_as_new_book，失败不落库。
Input选书 + 参数

管理员选 EPUB 与预设/目录形式/开关。

Guard权限与格式校验

can_view_book + 仅 EPUB；写操作用 @is_admin。

Coreprovider.apply

组装预设 CSS，无损重写并输出到临时目录。

Output入库 + 审计

import_as_new_book 生成新书；PluginRun 留痕。

关键决策

决策点选择理由放弃项
契约映射provider 只实现 preview/apply，不做后台任务与现有三工具一致，平台负责 run 记录与队列mybooks 的 BackgroundTask/全局锁
写回策略只生成新书保留「原书零改动」红线，降低误伤风险overwrite 模式
背景图v1 只用内置纹理无 Talebook 持久层，避免新增业务表自定义上传（后续单独立项）
批量v1 单本平台 host queue 已可横向扩展mybooks 批量队列 UI
图标基线取 master 继承 TB-201，新工具补注册避免重复修同一问题在旧分支重复修补

6. 影响范围、风险与回滚

影响范围

新增插件目录（约 1.1MB 样式与纹理）、新增 handler 路由、注册表追加一项、新前端页面与三语文案、图标注册多一项；现有三工具不变。

保持不变

TransformProvider 契约、现有工具/插件行为、Connection/启停规则、书籍详情页动作由 Capability 派生。

主要风险：① 移植文件原为 240 列格式，Talebook 的 ruff format 门禁要求 127 列并统一引号，故 vendored 文件存在一次机械重排 diff（后续同步上游需以逻辑 diff 为准）。② 原生 lib 为 GPL-3.0，与 talebook 一致；章节正则出处（txt2epub-next, MIT）已在 chapter_patterns.py 头部保留署名。③ 前端 i18n 违反 @/< 禁用会导致整个 locale 编译失败 → 已对新增文案做静态扫描（无命中），仍需本地 dev server 实测。
回滚：单分支提交；回滚即还原注册表一项与删除插件目录/页面，无数据迁移、无库表变更。
