元数据失败摘要输出转义

收紧在线书源失败信息从不可信输入到 NDJSON 响应的最后一道边界，解决 PR #950 的 CodeQL 反射型 XSS 评审问题，同时保持现有流式协议结构。

状态：ACTIVE 创建日期：2026-08-10 所属模块：webserver 影响范围：元数据失败摘要、测试 需求来源：PR #950 Review / CodeQL #152

1. 原始诉求

“解决 PR 里的评审问题。”评审线程指出 webserver/handlers/book.py 的流式失败摘要存在 reflected server-side XSS 数据流。

CodeQL 将 _dedupe_failures(failures) 的入参识别为用户可控值，并追踪至 self.write(json.dumps(...))。现有响应虽然声明为 application/x-ndjson，但失败对象仍缺少显式的输出编码边界。

2. 目标与边界

目标

  • 失败摘要进入响应前逐字段转义。
  • 仅保留 source、code、message 三个协议字段。
  • 同步与流式响应采用同一份安全化结果。
  • 恶意标签无法原样进入 HTTP 响应体。

非目标

  • 不改变书籍结果帧或搜索排序。
  • 不修改 API 路径、数据库、配置和权限。
  • 不把服务端失败文本当 HTML 渲染。
  • 不关闭在线书源或删除失败诊断。

3. 现状、根因与证据

观察证据结论
CodeQL 高危告警py/reflective-xss，source 为 _dedupe_failures 入参，sink 为流式 self.write。必须在共享失败摘要构造处建立显式 sanitizer。
失败信息来源不止固定常量MetadataSearchResult.failures 可携带在线书源名称和运行时错误摘要。不能依赖当前调用方“通常可信”。
两个输出入口共用摘要普通 JSON 返回 summary；流式接口发送 event=summary 控制帧。在去重阶段安全化，避免两个入口各自遗漏。

4. 方案

核心结论：把失败摘要视为不可信文本。在 _dedupe_failures 中先投影白名单字段，再使用标准库 html.escape(..., quote=True) 对每个值做输出转义，随后才参与去重并进入响应。
不可信失败对象在线书源名称、代码、消息，可能包含标签与引号。
→
白名单 + 转义只保留三字段；非字符串统一转为字符串；HTML 特殊字符实体化。
→
安全摘要帧普通 JSON 与 NDJSON 共用，前端继续按纯文本显示。

关键契约

safe = {
  field: html.escape(str(failure.get(field, "")), quote=True)
  for field in ("source", "code", "message")
}
dedupe_key = (safe["source"], safe["code"])

选用标准库转义而不是正则删除标签：实体化不会误删正常文本，且是 CodeQL 规则明确认可的 sanitizer。字段投影同时阻止未来调用方把额外对象属性无意暴露给客户端。

5. 影响范围、风险与回滚

影响范围

只修改 BookRefer 失败摘要的规范化逻辑和对应后端回归测试。含 HTML 特殊字符的来源名或消息会以实体文本返回。

保持不变

成功书籍数据、失败分类、去重键语义、流式帧顺序、HTTP Content-Type、前端控制帧识别均保持不变。

主要风险：调用方若曾期待失败消息中的标签被解释为 HTML，将看到实体文本；当前前端按普通文本显示失败信息，这一变化符合既有安全边界。回归测试覆盖普通 JSON 与 NDJSON 两条路径。

回滚：可按单个 follow-up 提交回滚；无数据迁移、配置清理或部署前置条件。
