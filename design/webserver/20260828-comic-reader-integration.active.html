为漫画容器提供安全的 read-comic 阅读链路

在不让浏览器接触 Calibre 路径、数据库或归档条目名的前提下，为 CBZ、ZIP、CBR、RAR 建立有预算的页面契约，并接入独立 Komga 阅读器。

状态：ACTIVE创建日期：2026-08-28所属模块：webserver影响范围：webserver、app、Docker需求来源：TB-131；Talebook PR #1012；komga-reader PR #2

1. 原始诉求

“为 Talebook 增加专用 /read-comic/:bookId 入口和安全、文档化的漫画页面 API；CBZ/ZIP/CBR/RAR 进入独立阅读器，漫画 EPUB 继续使用现有阅读器，并覆盖权限、进度、危险归档、桌面端和移动端验证。”

PR #1012 当前仍以 agent/talebook/3c9d7268 为 head 且尚未合并。本改动直接在该 PR 的 TB-129 阶段 1 提交上堆叠 TB-131 阶段 2，不把媒体分类能力误认为已进入默认分支。独立阅读器依赖 komga-reader PR #2 的固定 commit d49a2e80，以同源静态 ESM/UMD/CSS 分发；该依赖 PR 尚未合并。

2. 目标与边界

目标

  • 只向登录且有阅读、可见权限的用户返回有序页面 manifest、受控图片和漫画进度。
  • 自然排序页面，以页面序号和修订哈希构造 URL，不公开归档条目名或本地路径。
  • 对归档、单页字节、图片尺寸/像素、并发和缓存设置明确预算。
  • 书籍详情按格式稳定分流，并提供加载、错误、退出和恢复体验；漫画不展示有声书入口，也不能进入有声书候选或创建任务。
  • 电子书与漫画容器并存时，在“文件处理”提供持久的人工类型选择，避免自动识别误导阅读入口。

非目标

  • 不复制 Komga 服务端 API，不让前端解压归档。
  • 不改变漫画 EPUB、PDF、普通 EPUB/TXT/Kindle 的既有阅读路径。
  • 不发布 npm、不合并或部署 PR。
  • 不提供任意条目名查询、Range 或归档下载替代接口。

观察证据结论
PR #1012 只分类漫画且主动禁用容器在线阅读webserver/services/media_analysis.py、app/pages/book/[bid]/index.vue需新增专用归档适配层，不能复用 EPUB 读取路径。

Talebook 已有通用 ReadingState JSON 存储webserver/models.py、BookReadingProgress复用数据列，但用漫画专用、强校验接口隔离契约。
已确认：生产镜像目前没有 RAR 解压工具；仅靠 rarfile 可安全列目录但无法普遍读取压缩页面，因此运行基线需要受控安装 unar，并由应用层继续执行全部预算与权限校验。

5. 方案

方案结论：新增独立 ComicArchiveService 与 webserver.handlers.comic。服务端从书籍记录选择容器、重用导入安全分析、生成私有页面索引、限流读取并只返回序号化契约；同一后端模块处理 /read-comic/:bookId 并渲染 Jinja host 模板，不在 Nuxt 中保留同名页面目录；生产 Nginx 与 Nuxt 本地开发代理都必须把该路径直接转发到 Tornado，避免通配页面误将它经 $backend 改写成 /api/read-comic。
Input书籍 ID

客户端只能提交数字书籍 ID、数字页序和修订哈希。

Guard权限与媒体校验

登录、阅读权限、可见性、media_type、容器格式和安全预算全部通过。

Core私有索引与限流

自然排序，LRU 缓存按文件修订失效；全局并发和单归档锁防止并发放大。

Output稳定 manifest / 图片 / 进度

只公开页面 ID、序号、同源 URL、MIME、尺寸；失败返回固定错误码或 HTTP 状态。

契约与预算

GET  /api/book/:id/comic/pages
GET  /api/book/:id/comic/pages/:index?revision=:opaque
GET  /api/book/:id/comic/progress
POST /api/book/:id/comic/progress

manifest.pages[] = { id, index, url, width, height, mime_type }
progress = { kind: "comic", version: 1, pageId, pageIndex,
             percent, completed }

archive: 10,000 entries / 512 MiB expanded / ratio 200
reader page: 32 MiB / 32,768 px per side / 100 MP
concurrency: 4 reads globally; bounded wait; private revision cache
决策选择理由
页面寻址数字 index + opaque revision无法注入路径或猜测归档条目名；修订变化可拒绝陈旧请求。
进度专用 API，底层复用 ReadingState不迁移数据库，同时限定 kind/version/页面范围。
RARrarfile + 镜像中的 unar覆盖 RAR4/RAR5；不把外部工具当作安全边界。
Reader 分发固定 commit 静态 ESM/UMD；后端 host与 Candle Reader 一致，不发布 npm、不在 Nuxt/Docker 安装期构建。
媒体能力隔离漫画禁止有声书入口、候选和任务即使漫画容器同时带 EPUB/TXT 标记，也不能误入文本 TTS 流程。
混合格式分类media_type + media_type_locked人工选择可逆且可持久阻止扫描/上传重新覆盖；接口仍验证书籍确实同时包含两类格式。

6. 影响范围、风险与回滚

影响范围

新增后端服务/API/host 路由与模板、三套 Nginx 代理规则、Docker RAR 工具、固定静态 Reader，以及混合格式人工分类接口与 items.media_type_locked 自动迁移列；PR #1012 的漫画详情状态从“暂不可读”切换为专用入口。

保持不变

Calibre 文件位置与数据库不向前端暴露；导入/下载契约、EPUB/PDF/TXT/Kindle 分流、通用进度列和漫画 EPUB 阅读器不变。

主要风险：归档读取造成 CPU、内存或外部进程放大；通过导入预检、读时复检、32 MiB/100 MP 单页上限、4 并发、超时锁和修订 LRU 限制。RAR 工具缺失或损坏时返回稳定不可用状态，不回退为直接下载或路径读取。
回滚：移除新增后端路由、模板、静态 Reader 和 unar 即可；自动增加的 media_type_locked 布尔列可安全保留，由旧版本忽略。已保存的 kind=comic JSON 可由旧版本当作普通未知进度保留，不影响其他阅读器。
