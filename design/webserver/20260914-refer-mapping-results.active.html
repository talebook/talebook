QA 阻塞修订（2026-09-14）

真实结构化搜索返回数字词条 ID，但 provider 详情把 ID 当作 bk_key 书名，结果为空；此前回归替换了详情或 get_book，未覆盖该路径。详情沿用了 copy_image=False，封面选用也未得到真实验证。

新 provider_value 格式：baike:v1: 后接 JSON 对象（title、author、id）。仅在 BaiduBaikeProvider 搜索/详情输出此不透明值，基础 API 继续输出数字 ID 供旧入口使用。详情校验引用类型与长度，用书名/作者查询固定百科接口并验证词条 ID，不将引用作为 URL 下载；详情单独创建 copy_image=True 的 API，避免修改共享 provider 的状态。佚名/Unknown/未知等占位作者不参与作者匹配。

兼容：talebook.meta.baike 的旧数字 ID、旧 URL、非法或不支持版本值不再误作搜索词；返回 metadata.not_found 并提示重新搜索，客户端重开弹窗即可获得新引用，无持久库表迁移。旧 provider_key=BaiduBaike 加数字 ID 的既有路径仍按当前书名与期望 ID 查询。通用插件连接缺失与详情为空分别返回 plugin.connection_missing 和 metadata.not_found。

验证计划：HTTP fixture 按 bk_key 区分书名成功/数字失败；真实 runtime/provider/详情/POST 写库在临时隔离 Calibre 库覆盖三模式、旧引用、ID 漂移与缺失封面；检查持久字段与封面。修订磁盘说明：设置 Python CONF 而非环境变量。完成后全仓重跑 DeepSec，更新本方案与原 PR。
