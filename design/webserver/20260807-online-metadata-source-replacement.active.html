Talebook / metadata routing / issue 937

把失效入口
接回真实书源

用在线书源替换优书网和旧笔趣阁，同时以零 Key 的结构化 JSON 路径保留百度百科；并修复七猫、番茄，让 DeepSeek 等 Chat Completions 模型基于可追溯在线证据整理元数据。

状态：ACTIVE 创建日期：2026-08-07 所属模块：webserver 影响范围：webserver / app / tests 需求来源：GitHub Issue #937

01原始诉求

Issue #937：“网文刮削接口全部失效”，优书网报错、百度触发安全验证、笔趣阁等不可用，AI 模型没有联网搜索。

用户进一步确认：“都修复，不要下线数据源，你到在线书源 JSON 里找找”“直接替换”，并要求百度百科方案“不使用 Key”。需求来源：GitHub Issue #937 。

本方案把“修复”定义为：停止调用已被登录墙、验证码或域名漂移永久阻断的旧路径；优书网和旧笔趣阁改由真实在线书源替代，百度百科则保留独立来源名并改走零 Key 结构化 JSON 兼容接口。任何暂时失败都不会删除或自动下线来源。

02目标与边界

必须交付

  • 设置页保留“百度百科”，新增“在线书源”替换优书网与旧笔趣阁；所有结果展示真实来源名。
  • 百度百科不新增 Key：停止公开 HTML 抓取，改用在线规则中仍可访问的结构化 JSON 接口，严格校验题名、义项与图书字段。
  • 搜索管理员已导入且启用的书源；仓库同时内置版本化、可审计的 JSON 快照作为空库兜底。
  • 修复七猫新响应字段与番茄“正文含验证二字即误判”的独立缺陷。
  • AI 先取得在线书源证据再整理，保持 DeepSeek 等 OpenAI Chat Completions 兼容接口可用。
  • 单源失败不阻断其他来源，用户能看到部分失败摘要与下一步指引。

明确不做

  • 不恢复优书网或已漂移笔趣阁的品牌伪装；百度结果只在真实命中百度结构化接口时标注“百度百科”。
  • 不要求百度 AppBuilder / 千帆 API Key，不引入付费百科 API，也不复用 DeepSeek 等模型的 Key。
  • 不在每次元数据搜索时从 GitHub 拉订阅，不把远程仓库变成运行时单点依赖。
  • 不执行书源里的 java.ajax、java.post、WebView、登录和设备环境脚本。
  • 不删除、禁用或清洗管理员已导入的来源；兼容性失败只记为本次查询失败。
  • 不承诺所有 Legado 方言都兼容，也不扩展正文下载或付费内容能力。

03现状、根因与证据

来源2026-08-05 实测代码根因处理结论
优书网登录 / 验证墙YoushuApi 把登录页当搜索命中继续解析；且当前无视管理员勾选，始终创建任务。停止旧调用，迁移到“在线书源”。
百度百科HTML 403；旧 JSON 部分可用现实现只抓公开 HTML，未使用在线规则指向的 BaikeLemmaCardApi；旧 JSON 会以 HTTP 200 返回 errno，且同名义项可能选错。保留独立来源；改用零 Key JSON，严格验错与消歧，失败后由在线书源兜底。
旧笔趣阁404 / 域名已漂移xbiqugu.la 固定端点已不提供原搜索协议。停止固定域名插件，改用真实来源池。
番茄小说搜索与详情可达详情 HTML 任意位置出现“验证”就抛 VerifyError；真实章节名可触发误判。改为结构化挑战特征判定。
七猫小说接口 200，解析为空搜索已使用 data.books、id/title/author/image_link；代码仍读旧字段。兼容新旧字段并锁定契约测试。
AI仅模型记忆请求只有 model/messages/temperature，提示词要求“look up”却没有任何在线证据。书源检索前置，Chat Completions 负责证据整理。
在线 JSON 调查：XIU2/Yuedu 的 26 个来源中，大量条目依赖网络型 JavaScript、验证码或已经失效；“酷我小说”搜索接口返回空集合，“熊猫看书”证书异常，简单站点也存在超时。七猫签名 API 来源提供了可复用的新字段与纯计算签名思路，但必须裁剪掉网络型脚本。候选证据固定到 XIU2/Yuedu 470e6d7 与 yuedu520/250904.json；内置快照不照单全收，只保留通过 Talebook 实测的元数据规则。
百度零 Key 调查：在线 Legado 字典规则 baidubaike.json 指向历史 BaikeLemmaCardApi。2026-08-07 实测《东周列国志》《法神重生》等可返回 card/image/abstract，但《百年孤独》等会返回 {"errno":2}，不同出口或时刻也可能产生差异。因此该接口是无 SLA 的尽力能力，不得把单次 HTTP 200 当作成功；公开词条 HTML 则稳定触发 403，不再调用。

04架构方案：一个入口，多条真实线路

核心结论：BookSourceModel + BookSourceEngine 继续拥有书源解析和安全边界；新增元数据适配层只负责选择来源、并发检索、转换 Calibre Metadata、签发结果令牌以及向 AI 提供证据，不复制一套抓取器。
优书网登录墙 / 无条件执行
百度公开 HTML403 安全验证
旧笔趣阁域名与协议漂移
→
百度零 Key 适配器验错、图书义项校验、有限重试
在线书源元数据适配层并发、去重、来源标注、失败隔离
签名结果令牌来源 ID + 书籍 URL + HMAC
→
百度结构化兼容接口无 Key、无 HTML、尽力返回
管理员启用的 JSON 书源权重优先，保留真实站名
内置已验证快照空库兜底，版本随发布
DeepSeek 等 AI只整理已取得的在线证据

百度来源名与旧配置保持不变，只移除 HTML 网络路径；优书网与旧笔趣阁名称仅参与配置迁移。任何来源都不会因一次元数据失败而被自动停用。

一次查询的处理顺序

Select选择来源

按启用、健康状态和权重取前 N 个；与内置快照按 URL 去重。

Search隔离并发

复用受限书源引擎；每个来源独立超时与错误。

Convert转换结果

映射标题、作者、标签、简介、封面和真实来源。

Ground共享给 AI

同一次检索只执行一次；证据裁剪后进入 Chat Completions。

Apply校验后应用

验证服务器签名与来源状态，再抓详情和封面。

来源选择与时限

  • 复用现有权重排序；元数据入口新增较小的 BOOKSOURCE_METADATA_TOP_K（默认 10），避免网络书库的 50 源规模耗尽 30 秒引用超时。
  • 复用 BOOKSOURCE_MAX_WORKERS 与 BOOKSOURCE_HTTP_TIMEOUT，但总查询受 BookRefer.REFER_TIMEOUT 限制；未完成任务只记为部分失败。
  • 管理员已导入来源优先；内置来源仅补足缺失 URL，不覆盖管理员版本，也不运行时拉远程订阅。
  • 标题与作者相同的重复结果按信息完整度合并；来源名保留首个命中站点，AI 证据仍保留多个来源供交叉校验。
  • 百度每次查询先使用规范化题名；响应必须包含匹配题名、摘要或基本信息卡，并呈现图书/小说义项。错误义项或 errno 只允许再用“题名 + 已知作者”或“题名 + 小说”重试一次，随后结束百度任务，不循环探测。

05接口契约、配置与兼容

契约新行为兼容策略
META_SELECTED_SOURCES保留 baidu 并新增 booksource；设置页不再列出 biquge 或历史 youshu。读取与保存时仅把优书网、笔趣阁旧值映射为一个 booksource 并去重；百度旧值原样保留，旧 auto.py 无需手改。
GET /api/admin/settingsMETA_ALL_SOURCES 同时返回“百度百科”和“在线书源”。其余来源和值不变；默认选择保留百度并加入在线书源兜底。
GET /api/book/:id/refer?stream=1书籍帧增加真实来源；结束前可发送带失败摘要的控制帧。控制帧含明确 event=summary，新版前端不当作书籍；首行握手保持。
POST /api/book/:id/refer在线书源使用 provider_key=BookSource 和服务器签发的有时限令牌；百度继续使用 BaiduBaike，应用前复查题名与义项。百度 provider 保持兼容；旧优书/笔趣阁令牌不再新发，历史请求返回明确的来源已替换错误。
AI Chat Completions只发送通用 model/messages/temperature；证据在消息正文中，解析 content 与可选 reasoning_content。DeepSeek 不需要专有 tool 或 thinking 参数；模型是否推理由管理员所选模型决定。

签名令牌

{
  "v": 1,
  "source": "db:42" | "builtin:qimao-api",
  "book_url": "https://example.invalid/book/123",
  "issued_at": 1786000000
}

provider_value = tornado.web.create_signed_value(cookie_secret, "booksource-meta", payload)

应用时使用同一密钥验签并限制令牌寿命；数据库来源必须仍存在且启用，内置来源必须仍在当前快照中。客户端不能替换 book_url 发起任意请求。

流式失败摘要

适配层记录 timeout、fetch_failed、rule_unsupported、no_result、legacy_errno 和 entity_mismatch。页面在存在结果时显示“部分来源未返回”，零结果时引导管理员检查书源管理；不展示异常堆栈或远程响应正文。

06逐源修复与内置快照

工作项实现关键验收
旧站替换删除 BookRefer 对优书的无条件任务，移除固定笔趣阁任务分支及设置项；两者旧配置统一映射到在线书源。旧配置只创建一次在线书源任务；日志中不再访问优书网和固定笔趣阁域名。
百度零 Key 修复重写百度适配器，固定请求 BaikeLemmaCardApi 的 HTTPS host；解析 card/image/abstract，检查 errno、题名和图书义项。接口存在间歇性 errno，每个查询至多尝试三次；首个义项不匹配时再带作者消歧。彻底停止 /search/word 与词条 HTML 解析。完整响应可生成作者、简介、封面和来源；errno、错误义项、非 JSON、超时均安全返回未命中，且在线书源任务继续。
在线书源适配器新增查询/转换服务，复用 BookSourceEngine.search()、book_info() 和封面下载；返回真实来源。搜索卡片可单独应用信息、封面或两者，篡改令牌被拒绝。
内置 JSON 快照把现有假示例替换为元数据用途的已验证来源集合；首个来源从 yuedu520 七猫签名源裁剪，补齐受限运行时所需的纯 MD5 帮助函数，移除正文解密、网络 JS 与伪分类 URL；将七猫封面 CDN 纳入图片代理精确白名单。快照记录上游 URL、commit、裁剪说明和抓取日期；至少两个不同书名可搜索并抓详情，封面代理仍拒绝未知域、伪后缀和非标准端口。
七猫独立插件搜索兼容 books/book_list/ret_data，ID 兼容 id/book_id；详情兼容 intro/image_link/category1_name/category2_name 与旧字段。新旧 fixture 均返回标题、作者、简介、标签、封面与稳定 provider ID。
番茄独立插件验证码判断改用 HTTP 状态、最终 URL、页面标题和专用 DOM/脚本标志，不扫描全文普通词语。章节或简介含“验证”不误报；真实挑战页仍抛 VerifyError。
AI 联网证据在线书源查询使用请求级共享缓存；证据以限制字段、条数和字符数的 JSON 写入 prompt，要求模型只据证据输出，AI 结果标明证据来源。DeepSeek 兼容请求不含专有工具参数；没有证据时返回 unknown，不伪造联网结果。
内置来源门禁已通过：2026-08-07 已直接使用 Talebook 的 BookSourceEngine 对《三体》《斗破苍穹》《西游记》完成真实搜索与详情闭环；搜索及详情均返回 HTTPS 封面，七猫 CDN 实测为 200 image/jpeg。快照固定到 yuedu520 提交 b5524f41，只保留元数据规则。

07影响范围、风险与回滚

代码与体验

  • webserver/handlers/book.py：来源编排、旧值别名、流式摘要与应用分支。
  • webserver/services/booksource/：元数据搜索复用、纯计算 JS 帮助函数、内置 JSON。
  • webserver/plugins/meta/baike、qimao、tomato、ai：零 Key 结构化适配、契约修复与证据整理。
  • app/pages/admin/settings.vue、书籍详情弹窗和中英文文案：新来源名与失败摘要。

保持不变

  • 数据库结构、Calibre 元数据写入方式、用户书籍权限不变。
  • 网络书库的导入、启停、权重、体检、阅读和保存接口不变。
  • 豆瓣、Google、Amazon、新华、NeoDB 等其他来源不变。
  • 在线来源失败不会自动修改 BookSourceModel.enabled。
主要风险：百度历史 JSON 接口无官方 SLA，可能限流、漏词或选择错误义项；本方案用 schema 校验、图书义项校验、有限重试和多源并发把它限定为尽力能力，不承诺单源全命中。其他第三方站点也会变化；通过版本化快照、真实联调、逐源失败隔离和真实来源展示降低影响。导入规则可能构造 SSRF；继续禁止网络型 JS，并用签名令牌阻止客户端篡改详情 URL。大量来源使用独立 TOP K、并发上限和总时限约束。
回滚：代码和内置 JSON 可随提交整体回滚，不涉及库表迁移。百度配置值始终保留；优书网与笔趣阁旧值保留读取别名，因此前滚或回滚都不要求管理员修改 auto.py。管理员已导入来源不被写改，无数据恢复步骤。
