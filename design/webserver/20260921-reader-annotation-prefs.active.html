阅读器新增阅读辅助开关：关闭章评、划线笔记、阅读笔记悬浮窗与选中文本

Talebook 的 EPUB 阅读器把章评标记、划线高亮和「阅读笔记」悬浮窗都叠在正文上，读者没有任何办法把它们收起来；只想安静读几页时，鼠标一拖还会把正文选中、弹出划词工具栏。本方案在阅读器自己的「设置」面板末尾补一个阅读辅助分组，四个开关按浏览器本地保存，关掉之后对应的标记、入口与交互立即消失。

状态：ACTIVE 创建日期：2026-09-21 所属模块：webserver 影响范围：webserver/resources/book/creader.html、spec/划线笔记.md、spec/阅读器.md 需求来源：读者原话「让其中的 EPUB 阅读器 Candle Reader 支持关闭章评、划线笔记和阅读笔记悬浮窗功能」「能不能调整成可关闭文本选中功能，有时候只想看书，会不小心选中文本」

1. 原始诉求

“给这个项目提交一个 PR，让其中的 EPUB 阅读器 Candle Reader 支持关闭章评、划线笔记和阅读笔记悬浮窗功能。”
“能不能调整成可关闭文本选中功能，有时候只想看书，会不小心选中文本。”

澄清后确认两点：开关放在阅读器「设置」面板里（读书时随手开关、只影响当前浏览器）；「章评」既指正文里的章评标记，也指底部导航的「评论」入口。第二条诉求来自实际使用反馈——正文只要被拖到就会选中并弹出划词工具栏，读者只想要一个「别理我，让我读」的开关。

2. 目标与边界

目标

  • 阅读器「设置」面板出现「章评 / 划线笔记 / 阅读笔记悬浮窗 / 选中文本」四个开关，默认全部开启，行为与改动前一致。
  • 关掉某个开关后立即生效，不需要刷新：正文里对应的高亮被移除、划词工具栏不再弹出、「评论」入口与「阅读笔记」悬浮按钮隐藏、正文不再被选中。
  • 开关状态存在浏览器本地，刷新页面、换一本书、重新打开阅读器后依然生效。
  • 读者没有任何操作时，正文渲染、笔记创建、笔记面板等既有行为不变。

非目标

  • 不改变服务端注解接口与可见性规则，/api/book/<book_id>/annotations 契约不动。
  • 不做站点级或账号级开关，也不新增用户偏好接口；开关只是阅读器里的一份本地显示偏好。
  • 不重建 candle-reader 阅读器本体与其内置设置面板，四个开关由宿主页 webserver/resources/book/creader.html 追加到面板末尾。
  • 不改变「关闭」的含义——关掉只是不显示，数据仍在服务端，重新打开即恢复。
  • 不做 i18n；阅读器宿主页现存文案同样是中文硬编码。

4. 现状、根因与证据

观察权威证据结论
正文上的章评与划线高亮没有任何关闭入口 webserver/resources/book/creader.html:718 renderAnnotation()、:736 loadChapterAnnotations() 无条件渲染注解 Talebook 自己叠加的注解层（划线与章评）在渲染前没有可见性判断
右上角「阅读笔记」按钮与侧边面板常驻 creader.html:515 #annotation-toggle、:538 #annotation-shell 悬浮层由模板里的 request.user 判断控制是否输出，读者无法再关掉
划词工具栏会在选中文字时弹出 creader.html:684 handleSelection()、:849 rendition.on('selected', handleSelection) 选段即弹，没有「不需要划线」的退路
candle-reader 自带的章评开关在 Talebook 里已经失效 creader.html:850 proxy.load_comments_summary = function () {};；:153 #comments-toolbar { display: none !important; } 阅读器内建的段评气泡与段评工具栏被宿主页停用，注解层接管了章评；那行「章评*」开关因此名不副实
阅读器的设置面板由阅读器本体渲染，宿主页无法直接改 app/public/static/candle-reader/candle-reader.es.js 为构建产物；candle-reader-version.txt 记录 v1.1.0 talebook 仓库里没有阅读器源码，设置项只能由宿主页追加
事实与推断：未验证的假设只有一个——「设置面板的 DOM 结构在阅读器升级后仍然稳定」。因此定位面板时不用组件 scope id，而是找「包含亮度滑杆的那张 bottom-sheet」，并用 MutationObserver 在面板重渲染后补回注入节点；结构真的变了，最坏结果是四个开关不出现，阅读器其余功能不受影响。

5. 方案

方案结论：偏好归宿主页 creader.html 所有，存在 localStorage.talebookReaderPrefs；宿主页负责渲染开关、执行显隐，并在开关变化时通知注解层。注解层只增加一个「这条注解该不该显示」的判断和一次重算，不引入新的接口与数据。
Input读者点开关

四个开关位于阅读器设置面板末尾的「阅读辅助」分组，点击即写本地偏好

Guard面板与阅读器可能还没就绪

设置面板是懒挂载的 Vue 子树，面板关闭时整块被卸载；用观察器在出现后补挂注入节点，同时在这一轮里尝试给正文加锁

Core宿主页执行显隐与锁

隐藏「评论」入口与「阅读笔记」悬浮层；把偏好广播给注解层；把 user-select: none 交给 rendition.themes 写进正文文档

Output正文与入口同步收敛

不可见的注解被撤销渲染，可见的重新渲染；两项全关时不再请求注解接口；正文拖不出选区

关键决策

决策点选择理由放弃项
开关归谁所有 宿主页 creader.html，写 localStorage 四个开关里有三个（划线高亮、阅读笔记悬浮窗、选中文本锁）本来就是宿主页的 DOM；本地偏好与阅读器自己的 readerSettings 同一层，无需接口与迁移 改 candle-reader 的 Settings.vue 并发版——那需要先发阅读器版本再升 candle-reader-version.txt，跨两个仓库、两个发布周期
开关放在哪 追加到阅读器设置面板末尾，加「阅读辅助」小标题 读者开关阅读相关设置的地方就在那里；面板由阅读器渲染，宿主页只在末尾追加、不参与其 vdom 更新 新开一个悬浮设置入口——阅读器已经有一个悬浮按钮，再加一个会让小屏更挤
与内置「章评*」开关的关系 收起那一行，并把章评开关同步给阅读器 settings.show_comments 内置开关管的是已被宿主页停用的段评气泡，留着会与本方案的「章评」重名且互相矛盾 两个同名开关并存；或直接删掉阅读器里的设置项——那是阅读器本体的代码，宿主页不该改
关掉后如何处理已渲染的高亮 调用 rendition.annotations.remove(cfi, 'highlight') 逐条撤销 不撤销就要等重新渲染才消失，读者会以为开关没生效 整页重排或刷新——会丢失阅读位置附近的状态
面板结构改动的兜底 用「含亮度滑杆的 bottom-sheet」定位，MutationObserver 补挂 宿主页读不到阅读器源码，不能依赖组件 scope id；结构变化时降级为「开关不出现」而不是报错 硬编码 data-v-* scope id 选择器
怎么让正文不能被选中 用 epub.js 的 rendition.themes.override('user-select', 'none', true) 正文在阅读器的 iframe 里，宿主页的样式够不着；themes.override 把规则写进每个 content 文档，并且挂在 rendition.hooks.content 上，换章新建的文档会自动补上，不需要宿主页追着每次渲染补样式。removeOverride 能干净撤销，开关可来回切 宿主页自己遍历 iframe 注入 <style>——要额外监听章节切换与文档重建，容易漏掉新章节；也不能用 rendition.annotations（那是往正文加东西，不是拦选择）
「选中文本」放在哪段脚本 放在未登录也输出的那段偏好模块里 未登录读者同样能打开阅读器，而「选中文本」与账号、与注解层都无关；若放进登录态那段脚本（request.user 判断之内），游客会看到一个点了没反应的开关 跟着其余三个开关一起放进登录态脚本——省事但会留下一个对游客失效的死开关
「选中文本」与「划线笔记」的关系 两个独立开关，不互相联动 想安静读书和想临时复制一段文字是两件事；关划线笔记但仍想选中正文复制，是合理组合 关掉划线笔记时顺带把选中一起锁上——看着省一个开关，实际把「能不能复制」也绑进了注解偏好 
// 阅读辅助偏好（宿主页）
const STORAGE_KEY = 'talebookReaderPrefs';
const DEFAULTS = { chapterComments: true, highlights: true, notePanel: true, textSelection: true };

// 正文在阅读器的 iframe 里：把「不能选中」交给 epub.js 的主题覆盖，
// 它挂在 rendition 的 content hook 上，换章新建的文档会自动补上
const SELECTION_LOCK = [
  ['user-select', 'none'],
  ['-webkit-user-select', 'none'],
  ['-webkit-touch-callout', 'none'],
];

function applyTextSelectionLock() {
  const locked = !prefs.textSelection;
  const rendition = readerProxy()?.rendition;
  if (!rendition || !rendition.themes) return;      // 阅读器还没挂载好，等下一轮观察器再试
  SELECTION_LOCK.forEach(function (pair) {
    if (locked) rendition.themes.override(pair[0], pair[1], true);
    else rendition.themes.removeOverride(pair[0]);
  });
}

// 注解层：按类型决定这条注解该不该出现在正文里
function shouldRenderAnnotation(annotation) {
  if (annotation.annotation_type === 'chapter_comment') return readerPrefs.chapterComments;
  return readerPrefs.highlights;
}

// 开关变化后：撤销不再可见的，再重算当前章节
function refreshRenderedAnnotations() {
  const proxy = readerProxy();
  if (proxy) {
    Array.from(renderedAnnotationMap.keys()).forEach(function (id) {
      if (!shouldRenderAnnotation(renderedAnnotationMap.get(id))) dropRenderedAnnotation(proxy.rendition, id);
    });
  }
  annotationRefreshTimer = window.setTimeout(function () {
    const current = readerProxy();
    if (current) loadChapterAnnotations(current);
  }, 0);
}

6. 影响范围、风险与回滚

影响范围

webserver/resources/book/creader.html 新增一个偏好模块、注解层的一处可见性判断与一次 rendition.themes 覆盖；产品行为变化涉及 spec/划线笔记.md（阅读器里的显示开关）与 spec/阅读器.md（阅读器功能与界面用词），两份都已在本 PR 内更新。不涉及接口、数据表、配置、权限与部署。

保持不变

注解接口与可见性规则、笔记数据、阅读进度、主题与皮肤、有声书同步、/read/<id> 入口与权限判定全部不动。默认四个开关全开，读者不做任何操作时阅读器与改动前一致。

主要风险：阅读器升级后设置面板 DOM 变化，注入节点找不到位置（触发条件：candle-reader-version.txt 升版且面板结构改动）。表现为四个开关不出现，正文渲染与笔记功能不受影响。缓解：定位不依赖 scope id，解析不到就直接放弃注入；tests/test_candle_reader_host.py 守住宿主页模板里的关键片段，不随阅读器升级静默丢失。
已知交互：「选中文本」关掉后，横向拖拽不再被选中动作消费，会落到阅读器自己的翻页手势上（滑动翻页模式下表现为翻页）。这是阅读器既有行为，不是本方案引入的；不想翻页就用点击区域翻页或滚轮。
回滚：回滚单位是 creader.html 这一个文件，无数据迁移。rendition.themes 的覆盖只活在当前页面里，刷新即失效。读者浏览器里可能残留 localStorage.talebookReaderPrefs；因为旧代码不读这个键，残留值不会影响行为。

8. 决策记录

  1. 2026-09-21：确认开关放在阅读器自带的设置面板，而不是站点后台或账号偏好——读者要的是「读这本书时随手关掉」，不是全局设置。
  2. 2026-09-21：确认「章评」同时覆盖正文章评标记与底部「评论」入口；「划线笔记」覆盖高亮与笔记两类，并连带停用划词工具栏，避免出现「关掉了还能新建」的矛盾。
  3. 2026-09-21：实现期发现阅读器内置的「章评*」开关在 Talebook 下已被宿主页停用（load_comments_summary 被替换为空函数），于是把它收起并把开关同步给 settings.show_comments，避免两个同名开关并存。
