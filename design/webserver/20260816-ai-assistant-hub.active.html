用注册协议汇聚 AI 辅助整理能力与任务

为登录用户提供一个稳定的“辅助整理”入口：发现当前可用能力、查看自己有权限的任务，并把写操作安全地送回具体功能。

状态：ACTIVE创建日期：2026-08-16所属模块：webserver / app需求来源：TB-58影响：AI API、导航、响应式页面

1. 原始诉求

“新增‘辅助整理’导航入口与响应式页面；能力和任务通过注册结构汇总，支持状态与书库筛选、分页、局部错误、详情跳转，以及服务端声明并复验权限后的取消 / 重试。入口不得直接持有业务写权限，也不得感知 AI provider。”

当前 feat/ai_1.0 已有运行时中立的 AgentRuntime、创作者私有的 AITask 与总结鸭适配器，但只有阅读器内的单功能入口，用户无法集中发现能力和任务。

2. 目标与边界

目标

  • 注册对象是能力元数据与任务投影的唯一来源，核心入口不按 feature 写分支。
  • 列表只返回当前用户、逐书 ACL 通过的最小摘要，并支持 category、library、page、page_size。
  • 页面分别承受能力注册失败和任务列表失败；一个能力探测异常只禁用该卡片。
  • 取消 / 重试只在摘要声明 allowed_actions 后出现，执行时仍重新查任务、所有权和资源 ACL。

非目标

  • 不复制总结鸭编辑、导出或预览页面，不新增工作流编排、定时或串联。
  • 不保存章节正文、AI 成果或原始内部错误到总入口响应或埋点。
  • 不让总入口调用 OpenAI、Codex 或未来 Claude Code / Trae 协议。
  • 不承诺现有功能无法安全重试时强行提供重试；动作由适配器逐任务声明。

4. 现状与证据

观察证据结论
AI HTTP 表面已按 feature 路由webserver/handlers/ai.py 的 AI_FEATURES 与通用 task route扩展注册对象，无需另建 provider API
任务表已隔离创建者AITask.creator_id 和 _own_task中心查询必须延续 creator filter，并逐记录做书籍 ACL
总结鸭不持久化章节正文chapter_text_hash、长度与定位器，不保存正文中心不能在缺少源正文时伪装可重试；动作声明为 false
存在两套主导航渲染器AppHeader.vue 与 BuiltinThemeHeader.vue两处均加入登录用户入口并覆盖测试

5. 方案

方案结论：在 AI handler 内把 feature registry 升级成稳定适配协议；新增只读 hub API 和窄动作 API。前端只消费能力、状态类别、最小对象摘要、详情 URL 和 allowed_actions，不识别 Codex 事件或具体 feature。
REGISTER能力自描述

ID、名称、说明、图标、范围、入口、权限、flag 和探测结果由适配器提供。

PROJECT最小任务投影

中心按 creator 查询候选，再逐项 ACL 和 feature 投影，单项异常形成局部错误。

DISPLAY统一页面

按 category / library 过滤、分页，呈现能力、汇总计数、空态与失败重试。

DELEGATE动作回送适配器

中心重验可见性与状态；取消先确认，业务写入仍留在业务详情页。

稳定响应契约

对象字段隐私 / 兼容约束
capabilityid、name、description、icon、scope、entry、permissions、feature_flag、available、reasonreason 是枚举 / 安全文案；单能力异常不让 endpoint 失败
task summaryid、feature、object、category、status、progress、timestamps、detail_url、allowed_actions、safe_errorobject 只含 library / book id / title / chapter title；safe_error 仅脱敏码与安全文案
paginationpage、page_size、total、pages；另含 category_counts 与 libraries计数和筛选只基于已通过 ACL 的集合

状态映射

统一类别当前原始状态动作
runningqueued、running仅适配器与运行时均可取消时 cancel
pending_confirmation未来功能注册的 review / preview 状态仅跳业务详情确认
failedfailed、cancelled只有能从持久化安全输入重建请求的功能才 retry
completedsucceeded只进入业务详情

6. 影响、风险与回滚

影响范围

AI handler 与注册协议、响应式 Nuxt 页面、两套导航、中文 / 英文 i18n、Python API 测试、Vue 组件 / E2E 测试和访问埋点。本次不加库表，不做迁移。

保持不变

AgentRuntime 协议、总结鸭原 API、正文最小化策略、结果编辑与导出、业务确认责任边界保持不变。

主要风险：跨能力状态语义漂移 → 映射由适配器测试锁定；列表查询当前用户的全部候选任务，数据增长后需关注查询和逐书 ACL 成本，逐能力异常已隔离；详情泄露 → creator + ACL 后才构造摘要；误取消 → 前端确认与服务端二次状态校验。
回滚：页面和 hub routes 可整体回滚；数据表无变化。功能总 flag 关闭时卡片保留禁用说明，入口仍可展示历史任务；若需完全隐藏可回滚导航提交。

8. 决策记录

  1. 2026-08-16：需求已给出权限、注册、provider 中立和非目标边界，无需等待额外产品选择；采用“适配器自描述 + 中心只投影”的最小完整设计。
  2. 2026-08-16：本地实例当前只有一个 AI 任务书库，仍保留 library 字段与筛选协议，值为稳定的 local，为未来注册能力扩展留出兼容面。
  3. 2026-08-16：总结鸭因不持久化章节正文，失败任务不在中心声明 retry，避免绕过阅读器重新采集与用户确认。
