需求来源
用户请求：为 Talebook 增加 MCP 与 Skill，并体现网络书库等原生能力。

原始诉求与目标

为 Talebook 提供可由 MCP 客户端直接连接的书库工具，并交付可安装的智能体 Skill。实现需基于 Talebook 当前代码独立设计；外部项目副本与示例仅用于理解用户期望，不作为代码、文案或测试来源。

  • 提供内置 Streamable HTTP 端点 /mcp，覆盖初始化、工具发现与工具调用。
  • 使用 Authorization: Bearer <token> 鉴权，不向模型暴露 Talebook 用户名或密码。
  • 首期覆盖本地书库管理、阅读状态和网络书库；排除文件上传/下载、邮件和局域网设备推送。
  • 协议响应、业务响应与错误结构保持稳定，可由 Skill CLI 和通用 MCP 客户端共同使用。

关键设计决策

主题决策边界与原因
协议实现无状态 Streamable HTTP JSON-RPC；支持 initialize、notifications/initialized、ping、tools/list、tools/call。单次调用返回 JSON，不建立服务器会话；GET 返回 405，不提供 SSE 流。协议版本以当前稳定版 2025-11-25 为首选，并兼容常见旧版初始化。
依赖协议核心使用项目现有 Python/Tornado 能力实现，不引入第二套 ASGI 服务。避免为一个端点同时维护 Tornado 与 Starlette 生命周期；以协议契约测试保证兼容。
鉴权Token 默认空值即关闭 MCP；运行时优先读取 TALEBOOK_MCP_TOKEN，可回退到本地配置 MCP_TOKEN。使用常量时间比较。Token 只授权 /mcp 的固定工具集合，不可用于其他 HTTP API。请求映射到第一个有效管理员，以复用私有书可见性与现有写权限。
秘密处理管理设置接口不回传 Token，日志不记录 Authorization、Token 或完整工具参数。Skill 通过环境变量读取地址和 Token，命令行参数不携带秘密。
部署入口SPA、SSR 与开发三套 Nginx 配置均精确代理 /mcp 到 Tornado；Compose 显式透传宿主机 Token。不使用覆盖范围更大的路径正则；Token 未设置时容器内保持空值并禁用 MCP。
业务复用MCP 工具服务复用 BookFormatter、Calibre cache、ReadingState、AutoFillService、网络书源引擎与后台任务。不从其他项目移植 handler；必要的共享逻辑从 Talebook 现有 handler 中提取为本项目服务。
写操作编辑、阅读状态、自动补全、元数据写回和网络书保存均保留现有权限与参数约束。Skill 对元数据覆盖、自动补全和网络书保存要求先确认目标；上传、下载、邮件、设备推送不进入工具表。

协议与错误契约

  • JSON-RPC 协议错误使用标准 error.code：解析错误、无效请求、未知方法、无效参数和内部错误。
  • tools/call 的业务错误仍返回 MCP result，并设置 isError: true；文本内容为结构化 JSON，便于通用客户端展示。
  • 工具成功结果统一为 {"ok": true, "data": ...}，失败为 {"ok": false, "error": {"code": ..., "message": ...}}，不向客户端返回 traceback。
  • 无 Token、Token 错误或功能未启用返回 HTTP 401/503，并附带不含秘密的说明；未知 Origin 不授予浏览器跨域凭据。
  • 通知请求不生成 JSON-RPC body，HTTP 返回 202；批量 JSON-RPC 请求不在首期支持。

Skill 交付

在 skills/talebook/ 创建独立 Skill。SKILL.md 只保留触发条件、工作流、安全确认和资源导航；完整工具参数放入 references/tools.md；scripts/talebook_mcp.py 使用 Python 标准库调用 MCP，支持 list、call 和连接自检。凭据仅从 TALEBOOK_MCP_URL 与 TALEBOOK_MCP_TOKEN 读取。

写操作前，Skill 必须先通过搜索或详情确认唯一 book ID；覆盖元数据、启动自动补全、写回文件、保存网络书时明确向用户复述目标。纯查询操作无需额外确认。
