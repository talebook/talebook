插件包上传与开发工具

让管理员从插件包完成安装，让开发者通过独立工具交付插件，同时延续 Talebook 的能力契约、连接所有权与运行审计。

状态：WIP创建日期：2026-10-03所属模块：webserver影响范围：后端 / app / SDK / 文档需求来源：房间开发者消息交付：调研与设计提案

1. 原始诉求与交付范围

“talebook有插件功能，但是这个插件不支持直接上传插件的方式进行导入……还实现了开发插件的工具，你看看它们是怎么实现的。”

需求来源为当前房间的开发者消息。引文省略外部项目名称和链接。本轮完成源码调研与可评审的实现方案，后续实现继续更新这一份 WIP。

目标场景：管理员拿到一个插件 ZIP 包，在插件中心上传、查看能力和权限、安装并启用；插件作者用工具生成项目、验证、打包、升级版本，独立于 Talebook 主仓库发版。

当前状态：上传、外部运行时、SDK 与 CLI 尚未实现。本文件是设计提案；现有产品行为仍由 spec/插件/插件平台.md 描述。

2. 目标与首期边界

首期形成完整闭环

  • 支持管理员上传 ZIP，静态检查成功后再安装；首期只接受可信来源的 Python 插件。
  • 支持元数据检索和正文处理两类模板，对应 metadata.lookup 与 integrations.tool。
  • 提供安装、升级、停用、卸载和恢复上一可用版本；来源、安装版本、运行版本分别可见。
  • 复用 Definition、Installation、Connection、Secret、Run 与既有权限模型。
  • 提供项目生成、目录与归档校验、契约测试、构建、版本升级命令及示例。

明确后续范围

  • 批注、评价、书源、推送及综合插件的完整进程适配器分后续批次补齐；未支持的能力必须拒绝安装。
  • 首期使用宿主的配置表单、能力测试和通用工具页面；自带 HTML/JS 页面单独进入第二阶段。
  • 插件市场、在线依赖安装、7z、任意 Shell 入口和代码热加载不进入首期。
  • 独立进程提供故障终止边界；面对不可信代码的操作系统沙箱需另行落地，首期不承诺。

选择元数据与正文工具作为首期，是为了同时验证只读结果和文件处理两条真实能力链路。它们不是新增的通用 execute() 契约，仍分别使用既有类型接口。

4. 插件包契约

example.meta.catalog/
├── manifest.json                 # 现有 talebook.plugin/v1 声明
├── plugin-package.json           # 新增 talebook.package/v1 包描述
├── backend/
│   ├── __init__.py
│   └── provider.py               # SDK Provider；由 runner 加载
├── tests/                        # 开发者契约与业务测试，不进入发布包
├── README.md
└── LICENSE

manifest.json 保留既有必填字段和闭集规则，设置 runtime_kind=managed_process。不添加 entrypoint、api_routes 等未知键。插件 ID 使用作者命名空间，例如 example.meta.catalog；talebook.* 留给内置插件，上传不得占用已有身份或系统前缀。

{
  "format": "talebook.package/v1",
  "entrypoint": "backend.provider:PROVIDER",
  "primary_type": "meta",
  "sdk_version": "1.0.0"
}

包描述只表达入口、主类型与 SDK 要求，不重复 ID、版本、能力、权限和配置。入口必须是包内 Python 模块及合法符号名，不接受命令、路径跳转或绝对路径。主类型与所声明能力必须匹配。

兼容性同时检查包格式、插件协议、SDK 主版本及 manifest.compatibility.talebook 范围。应使用统一的实际发行版本标识；现有 webserver/version.py 值不是完整的标准 SemVer，不能未经定义直接做字符串比较。编码时应接入现有发行版本解析或明确不支持的版本表达式。

默认校验上限（提案）：压缩包 20 MiB、解压总量 100 MiB、单文件 20 MiB、文件数 2,000、JSON 清单 256 KiB；均在传输层上限之内单独强制执行。允许后续按真实样本调整，不借用电子书上传的业务上限。
  • 按归档实际内容识别 ZIP；拒绝加密包、符号链接、特殊文件、绝对路径、盘符、反斜线绕过、路径穿越和规范化后重名。
  • 先枚举所有成员，再逐个受限写出；解压过程中计数，不能只相信 ZIP 声明的大小。
  • 生成 SHA256 用于内容身份、重复包判定和重试，不把摘要等同于作者签名或来源认证。
  • 同 ID 同版本同摘要为幂等请求；同版本不同摘要拒绝。升级包 ID 必须与目标安装一致。
  • 首期不安装 requirements，不执行安装钩子、前端构建命令或打包脚本；新增第三方依赖需由服务版本提供。

5. 上传、安装与版本生命周期

Upload上传与静态验证

验证管理员身份和上传开关，限制大小、目录、字段与兼容性；此时不执行外部代码。

Review预览并确认安装

展示名称、版本、来源、能力、权限、数据策略与兼容性；管理员选择授权。

Commit保存待加载版本

保留旧有效版本和所有连接；新包持久化成功后标为待重启，新安装默认停用。

Activate重启校验与切换

独立 runner 校验握手和契约；成功后切换有效版本，失败则保留旧版本并展示原因。

首期采用重启加载新代码的模型，不在线修改 Web 路由或 Python 模块。界面同时展示安装版本和当前运行版本；更新已有插件时，不能把仍可用的旧安装整体标为 inactive。停用安装不启动插件进程，重启仅按清单登记宿主代理；首次启用后执行受限握手，加载失败时不允许业务调用。

方法与路径（均为提案）输入语义
POST /api/admin/plugins/packagemultipart file创建暂存包，返回 upload_id、SHA256、规范清单、兼容性与权限预览。
GET / DELETE /api/admin/plugins/package/<upload_id>上传标识查看验证结果或删除未安装暂存包；仅上传管理员可读取，建议 TTL 24 小时。
POST /api/admin/plugins/installationupload_id、expected_checksum、approved_permissions安装全新外部插件；不改变旧 builtin 安装接口。
POST /api/admin/plugins/installations/<id>/versionupload_id、expected_current_version、approved_permissions以乐观并发检查提交新版本，默认只允许版本前进。
POST /api/admin/plugins/installations/<id>/restore上一可用 artifact_id、expected_current_version显式恢复旧代码版本；与业务 Run 的 rollback 区分。
DELETE /api/admin/plugins/installations/<id>外部安装 ID立即阻止新运行，标记卸载；保留历史运行、已导入数据和连接，等待运行结束后清理代码。

JSON 接口复用 @js 与 @is_admin；成功使用 err=ok，失败用稳定业务错误码。上传是特权操作，必须补齐同源或 CSRF 校验；当前全局 xsrf_cookies=False 不能直接视为安装端点的安全保障。

持久化与崩溃恢复

建议代码目录为 /data/books/plugins/artifacts/<sha256>/，另有 staging 与按插件隔离的工作目录；不存到应用镜像或可被下载的电子书目录。最终目录不可原地覆盖，暂存目录与目标位于同一文件系统，校验完以 rename 完成发布。

新增 PluginArtifact，保存插件 ID、版本、完整清单、包描述、摘要、来源、安装者及加载诊断；新增 PluginLifecycleOperation 记录安装、升级、恢复、卸载。Installation 增加 desired_artifact_id 与 active_artifact_id；内置安装两者为空。

执行顺序：锁定插件身份 → 创建经验证的不可变产物 → 单事务记录 artifact、目标版本、授权和操作事件 → 提交。提交失败只清理未引用的新产物；启动时回收无引用残留并校验当前引用是否缺失。数据库和文件系统不是一个事务，必须显式恢复；不得先删除旧目录再尝试安装。

启停、升级、卸载与恢复

  • 停用立即拒绝新调用；正在运行的任务按既有生命周期处理，保留连接、凭据和业务数据。
  • 升级仍复用 installation_id，个人与实例连接身份不变。权限新增项不自动授权；只有新版本校验成功后才切换 active artifact。
  • 新配置 schema 不兼容现有连接时显示“需要更新配置”，暂停受影响连接；不能自动删除凭据或擅自迁移。
  • 每次 Run 绑定实际使用的 artifact_id，保证重试和诊断可区分代码版本；代码清理必须避开仍被运行引用的版本。
  • 卸载后以墓碑状态保留旧连接和运行；重新安装同 ID 可恢复配置。页面提供单独的数据清理流程，不把卸载当作删除书籍或读者笔记。
  • 恢复旧版本只切换代码和匹配的授权快照，不自动撤销插件已经写入的领域数据。

6. 独立进程接入既有能力

调用链：现有业务入口 → PluginRuntime（连接、授权、租约、审计）→ 宿主自有 typed adapter → runner 进程 → SDK Provider → 类型化结果 → 宿主校验和领域 writer。

Web 进程只加载由 Talebook 交付的适配器代码。runner 使用固定 Python 可执行文件和固定 SDK 入口启动，以包摘要作为代码身份，在子进程内加载插件。命令参数不用 shell，不接受插件提供的任意执行命令。

用有请求 ID 的 JSON Lines 做本地双向通信，stdout 只写协议帧、stderr 写受限日志。握手返回协议、SDK 版本及实现的能力；宿主只接受清单声明和该阶段适配器支持范围的交集。请求超时关闭结果、终止并回收确切进程；晚到结果不能写入或推进游标。

能力桥接方法重要校验
metadata.lookupsearch_books、get_metadata、get_cover、self_check输入与 BookMetadata 对齐；封面二进制编码有上限，URL 经宿主网络策略校验。
integrations.toolpreview、apply、self_check只传本次授权书籍的输入副本和输出工作目录；ToolReport、ToolOutput 由宿主重建与验证。
其他既有能力逐个实现 typed adapter 后再开放不注册一个假装实现全部协议的万能代理，也不把任意 extra feature 开放为 Shell 执行。

进程按 artifact_id 与 connection_id 隔离复用，不让不同读者共享保留凭据的进程状态；按插件限制总并发、任务按连接取得租约，空闲超时后回收。请求环境只包含必要配置，不继承服务密钥环境变量；只传本次连接解密后的最小凭据，禁止把 SQLAlchemy session、Calibre DB、所有读者配置或全局设置传进插件。

宿主能力与工具文件

首期 SDK 以接收参数、返回结构化结果为主。需要 HTTP 时走宿主的受控网络 RPC，复用 SafeHttpClient、逐跳目标验证、响应上限和按插件与主机排队；不能让插件配置给自己创建私网白名单。

元数据由宿主现有写入路径消费。正文工具由通用编排入口复制输入、执行 preview/apply、确认预览、备份、导入或写回书库。返回的相对路径必须位于本次输出目录，拒绝链接和目录逃逸，输出格式与内容再次校验。插件无权自行决定 book_id 的所有权。

新增通用工具接口 /api/plugins/connections/<id>/tool/preview 与 /tool/run（提案），显式执行资源级权限检查，并绑定输入摘要、选项与 artifact 的预览标识。既有内置工具页面继续走自身编排。

可信代码边界：相同系统账号下的子进程仍可直接读磁盘或联网。独立进程、清单权限和 RPC 约束不会自动形成强沙箱。因此首期仅限管理员安装可信包；不可信分发要先落地独立账号、文件挂载、出网与资源限制，才可对外承诺隔离。

7. SDK、模板与开发工具

建议新增独立 Python 包 talebook-plugin-sdk，提供公共类型、Provider 协议、清单校验、进程握手与消息编解码，并暴露 talebook-plugin 命令。名称和命令均为提案，尚未发布。选择 Python 可与服务端共享验证器，避免为清单再维护一份不同语言的规则。

将 webserver/plugins/runtime/ 中公共契约提取到不依赖 Calibre、ORM 和 Tornado 的公共 SDK，宿主保留兼容导出；迁移必须保持现有导入和全部内置契约测试通过。SDK 不导出 webserver 内部模型，也不直接提供数据库 session。

命令（提案）作用验证重点
talebook-plugin init example.meta.catalog --type meta生成清单、包描述、Provider、测试、README 与 LICENSE 模板。模板能形成真实可运行包；ID、协议与能力一致。
talebook-plugin validate . / validate file.zip静态校验结构、路径、清单、版本和支持矩阵。不导入代码，不执行钩子；服务端仍重新完整验证。
talebook-plugin test .显式在子进程执行契约测试和开发者测试。缺方法、错误返回类型、超时与无效输出都要失败。
talebook-plugin build .白名单打包到 dist，生成 SHA256。稳定排序、固定 ZIP 时间；排除凭据、.env、.git、虚拟环境、缓存和嵌套 dist。
talebook-plugin bump patch修改 manifest 的 version；支持 major、minor、patch。不在后台偷偷修改版本或上传发布。

打包采用显式允许清单：manifest、包描述、backend 中的许可文件、README、LICENSE 与可选安全图标。前端进入第二阶段后才把构建产物加入清单；前端命令只在作者本机显式执行，服务器不会执行。

首期调试路径：本地生成 → 编辑 Provider → validate/test → build → 上传真实 Talebook 开发实例 → 查看诊断与运行记录。CLI test 可以使用隔离样本，但不能将其描述成完整书库联调；真实安装测试仍需要项目既有 Docker 后端。

CLI 发布验收必须启动真实命令入口，不只测 runInit/runBuild 等内部函数；同时检查支持的 Python 版本、安装后可执行性及模板依赖。

8. 管理界面与自带前端

在 /admin/plugins 工具栏增加“上传插件”，开关关闭时显示明确原因。步骤为选包 → 验证进度 → 包信息与权限预览 → 安装结果。已有插件卡片增加来源、安装版本、运行版本、待重启与加载失败信息，并提供更新、恢复和卸载。

内置插件保留启停行为。目录接口必须同时返回已安装的失败外部包，不能沿用“只展示已注册 Provider”的过滤而使问题插件从界面消失。类型由服务端明示；作者命名空间不能导致列表漏项。

首期复用现有配置 schema 表单与能力测试组件，正文工具进入宿主通用页面，不接受任意 manage_route 指向脚本页面。上传成功不等于可运行，停用状态、未配置状态和加载失败分别展示。

第二阶段：独立静态前端

若插件需要自带页面，包中增加受控 frontend/index.html 及静态资源，由固定动态宿主页承载，不让插件添加 Nuxt 编译期路由。主题、语言、提示与高度通过版本化桥接消息同步，不因换主题重载页面。

使用只允许必要脚本的 iframe sandbox，避免同时给同源页面 allow-scripts 与 allow-same-origin。推荐以独立源或不透明源隔离，配置限制性 CSP；父页校验 event.source、会话 nonce、插件身份及消息 schema，使用 MessageChannel 传输。插件不能直接读取主站 Cookie 或把任意 URL 交给宿主请求。

桥接请求由父页调用项目统一 backend()，服务端仍逐请求校验连接所有权、插件启用状态、能力与资源权限。前端桥是交互协议，不替代服务器鉴权；样式隔离也不等于安全隔离。

10. 影响范围、风险与回滚

当前仓库改动仅为本 WIP，产品运行行为未改变，因此此时不更新 spec。实现后在同一交付中更新 spec/插件/插件平台.md；新增通用正文工具行为时同步更新对应正文工具规格与索引，明确内置和外部安装的区别。

计划影响后端：插件模型、迁移、包管理、启动加载、运行时注册与发现、进程代理、工具编排、鉴权和下载边界。前端：插件中心、配置、通用工具、国际化与 E2E。部署：持久插件目录、可用 SDK 与进程运行环境。

  • 升级失败或产物缺失：保留 active artifact 与旧目录，目录页面显示错误；启动与升级故障注入验证。
  • 恶意或错误插件：可信来源限制、进程总时限、输出校验、权限限制；强沙箱进入后续范围。
  • 用户连接被覆盖：升级保持 installation_id，测试两个读者的独立凭据与 role；管理员接口不返回个人凭据。
  • 内置物化污染外部安装：物化只枚举内置集合；来源和版本保真回归测试。
  • 全局开关关闭：拒绝新上传和新的外部运行；不删除已安装产物或历史数据。

回滚实现版本前先停用外部运行时；保留插件数据库、产物和领域数据，按显式迁移恢复读兼容。恢复包版本与回滚业务数据是两个操作，不让恢复旧代码自动删除书籍。
