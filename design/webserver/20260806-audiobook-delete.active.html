Destructive operation contract · book scoped

按书籍彻底删除有声书

为管理员提供一个明确、可确认、可重试的整本删除入口：正文书籍继续保留，有声书的所有版本、任务、收听痕迹与独占文件全部清空。

状态：ACTIVE 创建日期：2026-08-06 所属模块：webserver 影响范围：webserver / app / tests 需求来源：用户 quick fix

1. 原始诉求

首次诉求：“quick fix: new git wt， 给有声书增加删除功能”
grill 后最终确认：“还是不区分了，就一个删除按钮，删了就全删。”

当前页面已经允许管理员逐个删除候选或历史版本，但后端明确禁止删除正在发布的版本，因此无法把某本书的有声内容完整移除。此次需求不是删除 Calibre 正文书，也不是只下架当前版本，而是按 book_id 清空整个有声书域。

2. 目标与边界

必须达成

  • 管理员能在书籍的有声书详情页发起整本删除，并在不可逆操作前看到清晰确认。
  • 删除该书所有发布、候选、历史、草稿和部分章节版本，以及对应任务、用户数据、统计、审计与独占文件。
  • 删除成功后立即从有声书馆藏、阅读器注入和 Podcast Feed 消失；当前浏览器若正在播放该书则关闭播放器并清理本地恢复状态。
  • 保留正文书籍、封面、收藏、阅读进度和其他书籍的有声书数据。

明确不做

  • 不删除 Calibre 书籍及 EPUB、TXT 等正文格式。
  • 不自动回滚或重新发布任何历史有声版本，因为全部版本都属于清理范围。
  • 不清空全局 TTS 分段缓存或公共音色预览；这些资源无法安全归属单本书，且可能被其他书复用。
  • 不改变现有单版本发布、回滚和候选/历史版本删除能力。

3. 现状、根因与证据

观察代码证据结论
发布版本无法删除webserver/handlers/audiobook.py 的 AudiobookEditionAction.patch()action=delete 遇到 published 会返回 state.invalid。
删除入口只覆盖非发布版本app/pages/book/[bid]/audios.vue 的 managedEditions页面仅在“候选与历史版本”列表展示逐版本删除，没有整本有声书删除入口。
数据跨越多个表与目录webserver/models.py 与 AudiobookStorage完整清理必须按书籍先解析版本、章节和任务 ID，再按外键依赖顺序删除。
运行中任务会继续写目录AudiobookScheduler._process() 与 VoicebookProcess.run()单按钮语义要求接口在同一次操作中写入取消标记、删除任务使租约失效，并保证后续事件不会重建数据。
已证实边界：公开馆藏、阅读器和 Podcast 都只读取 status=published 的版本；全部版本记录移除后，这些消费面无需额外下架状态即可一致消失。

4. 删除边界：书芯保留，声音外层清空

视觉上的删除边界以正文书籍为中心：红色环内是本次不可逆清理对象，绿色书芯是不变量；灰色共享缓存位于边界外。

删除：有声书专属域

所有版本、章节、任务、工作目录、收听数据、统计和 Podcast 审计。

保留：正文书籍

Calibre 元数据、电子书格式、收藏与文字阅读状态不受影响。

保留：共享缓存

内容寻址的 TTS 分段缓存和音色预览可能被其他书复用，不能按书安全识别。

资源定位条件处理说明
AudiobookEdition / AudiobookChapter版本 book_id 与派生 ID全部删除覆盖 published、ready、partial、historical、draft 等所有状态。
AudiobookJobbook_id全部删除活跃任务先写取消标记并失效租约；所有状态的制作历史都在同一次操作中删除。
Progress / Bookmark / PlaybackSessionedition_id全部删除清除所有用户的进度、书签和播放会话。
DailyStat / PodcastAccessLogbook_id，并兼容派生 ID全部删除即使审计记录已标记 protected，也服从用户确认的“所有数据”。
PodcastSubscription.hidden_books隐藏书籍 ID 列表移除引用订阅本身和 Token 保留，仅清掉目标书 ID。
editions/{id} / jobs/{id}数据库解析出的可信 ID递归删除只通过 AudiobookStorage 解析受控路径。
正文书籍及共享缓存不适用保留不是单本有声书独占资源。

5. 实现方案

方案结论：在现有书籍有声资源上新增管理员专用 DELETE /api/book/{book_id}/audios。接口以 book_id 为唯一删除边界，返回各类资源的删除计数；前端用独立危险操作对话框解释“删声音、留正文”。
Guard管理员确认

页面展示不可恢复范围；后端用 @is_admin 重新鉴权。

Quiesce终止活跃任务

对活跃任务写取消文件和取消状态；删除任务行使 worker 租约失效，后续事件因任务不存在而忽略。

Purge清数据再清文件

按外键依赖从叶子表向版本表删除并提交，再移除已解析的版本/任务目录。

Refresh收敛客户端状态

关闭当前书播放器、清本地恢复记录、刷新详情为空态并提示完成。

前端交互

状态呈现行为

删除成功全局成功提示，详情页进入“还没有可收听版本”空态若正在播放目标书，调用播放器 close() 清理音频对象和 localStorage。
存在活跃任务仍由同一个确认按钮完成后端先发出取消信号，再删除任务、版本与文件；用户无需先去任务页操作。

6. 影响范围、风险与回滚

实际改动

webserver/handlers/audiobook.py 增加整本删除方法与数据清理；app/pages/book/[bid]/audios.vue 增加危险操作入口；中英文 i18n、mock API、后端集成测试和前端 E2E 同步更新。

兼容与部署

复用现有路由和数据库表，不新增迁移、配置或依赖。GET 契约、媒体路径、Podcast Token 和单版本 PATCH 操作保持兼容。

主要风险：误删不可恢复。缓解方式是管理员权限、整本专用文案、确认对话框、严格的 book_id 查询边界、受控路径解析，以及覆盖“目标书清空、其他书与正文保留”的测试。
并发风险：活跃 Voicebook 子进程可能仍持有文件句柄。接口先写取消文件，再删除任务行令租约失效；worker 下一次控制检查会终止子进程，删除后的事件因任务不存在而被忽略。定向测试必须覆盖删除后不重建任务、版本或章节。
失败与回滚：数据库清理先在单一事务中完成；提交后再删除已解析的独占目录。目录删除失败时响应明确给出清理失败，不恢复已删除的数据库数据，并允许管理员依据错误日志人工清理残留目录。发布后若回滚代码，已删除的数据与媒体不可恢复，这是交互中必须明确告知的产品事实。

8. 决策记录

  1. 2026-08-06：使用新 worktree feat/20260806-audiobook-delete，基于 origin/master 隔离开发。
  2. 2026-08-06：用户确认“删除整个有声书”是按书籍删除所有版本、历史和全部关联数据；正文书籍保留。
  3. 2026-08-06：共享 TTS 缓存不具备可靠的单书归属，删除它会伤及其他书，因此不纳入“关联数据”；所有可以用书籍、版本、章节或任务 ID 确定归属的数据均删除。
  4. 2026-08-07：曾讨论把有声书删除与处理任务删除拆成两个入口，用户最终撤回该方向，明确只保留一个按钮并清理全部数据。
  5. 2026-08-07：活跃任务不再阻塞删除；同一次请求先发取消信号，再通过删除任务行失效租约并清理全部数据。
  6. 2026-08-07：定向与全量回归、前端 E2E 和生产构建均通过；真实 Docker 数据下完成桌面、深色与移动端渲染验收，方案转为 ACTIVE。
