AI 金句卡片与双格式导出

把 EPUB 选文转成可核验、可编辑、可回跳、可复习的私人成果，并在章节内主动推荐最多五条候选。

状态：ACTIVE创建日期：2026-08-16所属模块：webserver / reader需求来源：TB-54基线：feat/ai_1.0

1. 原始诉求

首版仅支持 locator 稳定的 EPUB。用户可将当前选文制成金句卡，也可请求章节推荐；确认后保存逐字原句、AI 解释、主题、笔记、书名/章节、locator 与时间。必须支持编辑、删除、去重、精确回跳及 Markdown/PNG 导出，并在 AI 不可用时保留手动摘录。

2. 目标与边界

首版目标明确不做
选文制卡、最多五条章节候选、逐字校验、创建者隔离、来源版本失效、卡片管理、双格式导出、AgentRuntime 复用。PDF/OCR、全书后台扫描、跨书聚类、知识图谱、公开社区、整章批量摘录、Claude Code/Trae 真适配器。

3. 核心流程

采集
阅读器提取当前章节或选区及 href/start/end。
校验
后端限制长度、核验 locator 与原句，按书版本和创建者去重。
生成
推荐只经现有 AgentRuntime，输出 schema 白名单并逐候选复核。
成果
确认后保存；可编辑说明/主题/笔记、回跳、删除及 Markdown/PNG 导出。

4. 数据与 API

新增 quote_cards，保存 UUID、创建者、书籍/版本、章节、逐字原句或改写笔记类型、locator、校验摘要、AI 原稿、用户说明、主题、笔记、schema/prompt 版本、来源有效标记和时间。推荐任务继续使用 AITask 与 /api/ai/quote_card/tasks；成果使用 /api/quote-cards 列表/创建/编辑/删除，另提供 Markdown 导出。

5. 权限、安全与失败

  • 所有卡片和推荐任务限定创建者，并在每次访问时重验原书 ACL；删书同步清理。
  • 书籍版本变化时卡片仍可读但标记来源失效、禁用回跳；重新验证成功前不恢复逐字引用状态。
  • 逐字引用的原句和 locator 不允许在编辑时变化；用户要改原句须显式转为“摘录改写/笔记”。
  • 正文仅作结构化数据；解释、主题和笔记限制长度并转义 HTML。运行时不获得书库、MCP 或写工具。
  • AI 缺失、未登录、限额、协议错误、崩溃、超时、取消及 schema 错误沿用 AgentRuntime 分类；手动保存不依赖 AI。

6. 界面与导出

阅读器提供“金句”入口，优先识别当前选区，并提供“推荐本章金句”和“已保存”管理视图。候选按原句、为什么重要、主题、来源展示，用户编辑后确认。PNG 在浏览器 Canvas 中生成，不上传正文；单卡和批量 Markdown 均限制引用长度并保留来源。亮暗主题、320px 窄屏、键盘焦点和安全 DOM 构造纳入验收。

7. 去重与兼容策略

逐字引用以创建者、书版本、章节 href、范围和规范化原句摘要形成唯一键。重复创建返回现有卡片，界面允许打开或显式合并说明/主题/笔记，不静默新增。旧数据库通过现有 create_all/迁移脚本创建新表；现有 summary_duck API 与数据不变。
