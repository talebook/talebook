插件公共后端底座

以受控 manifest 和持久运行状态机统一四类插件能力，使后续管理页与第三方适配器共享安装、连接、凭据、执行日志、幂等和回滚语义。

状态：ACTIVE创建日期：2026-08-14所属模块：webserver需求来源：TB-40 / TB-14无界面影响
原始诉求目标与边界协议数据模型运行时安全迁移与风险测试结果决策

1. 原始诉求

“实现 Talebook 插件系统的公共后端底座：冻结 manifest/category/capability/runtime action 与协议版本；建立 definitions、installations、connections、secrets、runs、run items、entity matches、source records、permissions；支持 test、preview、run、游标、连接防并发、失败项重试、来源追踪和安全回滚，并以 mock provider 验证跨 Tab 复用。”

批准来源为 TB-14 的完整插件方案；AI、具体第三方业务和管理页视觉不属于本次。书源明确排除 Calibre Content Server 与 Calibre-Web。

2. 目标与边界

目标

  • 一套版本化协议覆盖元数据、笔记、评价、书源。
  • 实例级和用户级连接共享安装，Secret 始终密文落库且普通序列化只给掩码。
  • 执行可诊断、可重试、同源幂等；失败不推进游标。
  • 每连接持久租约防并发；429、401、超时和退避形成结构化结果。
  • 按 run 回滚时保护本地修改并持久化冲突。

非目标

  • 不实现任意代码热加载、插件市场或签名分发。
  • 不实现具体第三方 API、AI 或四 Tab 管理界面。
  • 不把 Calibre 主库对象复制进 SQLAlchemy；真实域写入由后续 adapter 负责。
  • 不承诺跨进程强制终止已超时的第三方线程；平台只关闭结果并拒绝写入。

3. 冻结协议

协议版本固定为 talebook.plugin/v1。manifest 必填 id、version、categories、capabilities、runtime_kind、actions、auth_schema、config_schema、permissions、data_policy、compatibility、homepage、license。

枚举值约束
categorymetadata / annotations / reviews / book_sourcescapability 使用 category.verb，且前缀必须在 categories 中。
runtime_kindbuiltin / file / http / managed_processV1 不允许 Web 进程动态 import 用户代码。
actiontest / preview / run / retry / rollback全部产生持久 run；preview 不写 source record。
run statusqueued → running → succeeded / failed / partial / rolled_back仅终态可重试或回滚；状态转换由 runtime 校验。
healthunknown / healthy / degraded / unauthorized401 不重试；429/超时退避后标 degraded。

4. 持久对象

表职责关键约束
plugin_definitions规范化 manifest(plugin_key, version) 唯一，保存协议版本与 schemas。
plugin_installations实例安装、启停和配置一个 plugin_key 只保留一个当前安装；四 Tab 共用。
plugin_connections实例/用户连接、游标、健康、调度和租约(installation, owner_type, owner_id, name) 唯一；租约原子获取。
plugin_secrets加密凭据与轮换版本密文、key id、掩码 hint；API 模型不暴露 ciphertext。
plugin_runs / plugin_run_items状态机、计数、结构化错误、逐项结果日志先脱敏；失败/partial 不写 connection.cursor。
plugin_entity_matches外部实体与书籍匹配来源外部 ID 唯一；置信度和人工确认可审计。
plugin_source_records幂等、来源追踪与回滚(connection, entity_type, external_id) 唯一；本地修改阻止静默回滚。
plugin_permissions管理员批准的数据范围批准、撤销时间和操作者持久化。

5. 公共执行流程

1. 排队创建 queued run，记录 action/trigger/requester。
2. 取租约原子更新 connection lease；已有有效租约返回 concurrent_run。
3. 调 Provider注入只读配置、临时解密 secret、游标、deadline 和目标失败项。
4. 写结果preview 仅记录 items；run 以来源键 upsert，逐项失败形成 partial。
5. 收尾全成功才推进游标；更新 health，释放租约，错误与日志脱敏。

重试与回滚

retry 只把目标 run 的失败 external_id 交给 provider；成功后产生独立审计 run。rollback 仅处理目标 run 写入且仍为 active 的 source record；local_modified=true 的记录变为 conflict item，不删除、不改来源状态。

最小 mock provider

内置 talebook.mock.multi-tab 同时声明 metadata.lookup 和 reviews.import，支持 test、preview、run、指定项失败、401、429、重复输入、游标及 rollback，证明跨两个 Tab 复用同一 installation、connection、secret 和 run log。

6. Secret 与日志安全

  • 使用 Fernet 认证加密；密钥优先取 PLUGIN_SECRET_KEY，兼容使用已修改的非默认 cookie secret；默认占位 key 会拒绝保存凭据。密文带 key id 和版本，支持重新加密轮换。
  • Secret 只在 provider 调用边界内解密为短生命周期 dict；模型/handler/run item/异常不序列化明文。
  • 脱敏器递归处理结构化数据，替换实际 secret 值和常见 bearer/token/key/password 字段；错误只持久化稳定 error code 与截断后的安全消息。
  • 实例连接仅管理员创建；用户连接必须绑定当前 user id。安装权限单独持久化，不因 manifest 升级自动扩大。

7. 迁移、影响与风险

SQLAlchemy create_all 会创建新表，现有 migrate_db.py 仍负责增量列；本次不修改任何既有表和 Calibre 主库。内置 definition 采用幂等 bootstrap，不自动安装，避免升级后获得新权限。

兼容性

  • 无现有 API 路径变化。
  • 只新增 /api/admin/plugins/* 管理接口。
  • 旧元数据/书源路径暂不迁移。

剩余风险

  • Python 线程超时后底层阻塞调用可能短暂存活，但其结果不再提交。
  • 多进程租约依赖数据库时钟与 lease TTL；长任务需续租扩展。
  • 真实域回滚需 adapter 事务钩子，本底座只管理 source record。

界面审查豁免：本次只新增后端模型、服务与 JSON API，不修改页面、文案、布局或现有前端消费者，因此无需 interface-review。

9. 决策记录

决策结论原因
动态代码V1 不在 Web 进程加载避免插件拿到无限权限；builtin registry 是本次可执行边界。
definition 与 installation分离定义可版本化，安装保存实例配置和批准权限；跨 Tab 不重复安装。
失败游标仅全成功推进partial/failed 保留旧 cursor，避免跳过失败数据。
连接并发数据库租约，不只进程锁兼容多 worker；崩溃后 TTL 可恢复。
Secret 密钥显式 key 优先，兼容派生新部署可独立轮换，旧部署不因缺配置写入明文。
