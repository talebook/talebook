PR #977 CodeQL 安全告警修复

消除门禁中的弱密码生成、邮箱正则回溯与跳转路径注入。

2026-09-06webserver / testsACTIVE来源：PR #977

原始诉求

开发者要求修复 PR #977 的 CodeQL 报错，并核实 PR 中的评审问题。基线提交 1fa40d1347edf2e818219fb8d7f63b4348127882，CodeQL 汇总 101417444594 有七处标注：两个旧密码测试、两个邮箱正则调用、重置密码 MD5、两个元数据更新跳转。路径遍历评审三条均已 resolved，保留现有根目录与符号链接防护并回归。

目标与边界决策

只修复本次门禁涉及的代码，不关闭规则、不排除测试或第三方扫描目录、不修改告警状态。保留旧 SHA256 密码校验和登录迁移到 bcrypt；测试改用固定历史哈希向量，避免在测试中重新实现不安全的密码写入。新密码仍以 bcrypt 存储，无数据库迁移。

邮箱仍支持 Unicode、本地部分加号和多级域名；禁止空白、多个 @、空域名段和尾部垃圾。域名正则按点分段，各重复部分不重叠，整体匹配。重置密码使用 secrets.token_urlsafe(12)，保持 16 字符长度，提供 96 位安全随机熵。

作者与出版社名称必须作为单个 URL 路径段编码，保留中文、斜杠、问号和井号作为名称本身的含义。显式传 status=302，纠正原调用将 302 当作 permanent 参数的问题。未改变权限或接口路径。

方案

  1. Reader.RE_EMAIL 使用互斥的域名段字符集与严格结尾。
  2. Reader.reset_password 使用安全随机数并调用现有 bcrypt 写入。
  3. 两个更新 handler 使用 quote(name, safe="") 生成固定站内路径。
  4. 历史密码测试使用固定盐和预计算哈希，增加重置密码、邮箱长输入、恶意跳转的回归测试。

元数据旧更新 handler 的测试采用独立路由、空更新集合，隔离现存通用路由遮挡和旧更新 hook；本次不恢复旧接口的完整更新流程。无界面影响：不改前端页面、组件、布局或文案；仅后端输入验证、凭证生成和路径编码，不适用大型界面功能审查。兼容性变化：畸形邮箱将拒绝，更新后跳转明确使用临时重定向。
