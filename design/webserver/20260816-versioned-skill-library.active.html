目录权威的 SKILL 沉淀

把一次有效的 AI 工作方法保存为符合 Agent Skills 规范的当前目录；目录是内容唯一来源，数据库只承担私有索引、状态与运行审计。

状态：ACTIVE创建日期：2026-08-16所属模块：webserver / app 需求来源：TB-56基线：feat/ai_1.0

1. 原始诉求

“支持从已完成的 AI 成果/任务生成 SKILL 草稿，也支持空白模板创建；提供结构化字段与 Markdown 编辑、预览、样例试运行、草稿/启用/停用、版本记录和回滚；AI 中心提供创建者私有的列表、搜索、版本和手动运行，并展示版本、输入摘要、授权上下文、进度与唯一终态。”

评审反馈：初版把数据库 manifest 当作产品本体，不符合 Agent Skills 的自包含目录规则。核心流程必须是生成 SKILL ZIP、查看包内文件、下载与删除；每个 ZIP 必须有单一同名根目录、必需的 SKILL.md，以及真正需要时才加载的 scripts/、references/、assets/。

统一存储规范：TB-52 要求所有 AI 产物采用 books/ai/{user-workspace}/{feature}/...，目录为权威内容来源；应用层不做默认版本化，不保存完整正文副本，不提供版本列表、回滚或 v{version} 目录。

2. 目标与边界

首版交付明确不做
以当前 Agent Skills 文件夹为交付本体；生成、编辑、查看、下载 ZIP、删除；严格 hyphen-case 包名；SKILL.md 仅含 name/description frontmatter；按需引用 references/contract.json。数据库只承担 owner/workspace、名称、相对路径、SHA-256、状态和运行审计。应用层版本列表、不可变版本表、回滚、v{version} 目录；公开市场、团队共享、远程导入、上传任意 ZIP、后台静默触发、自我修改、任意脚本/依赖安装、MCP、任意系统写入。

3. 产品流程

生成
从空白模板或本人已成功 AI 任务提取最小来源摘要，原子写入当前 Agent Skills 文件夹，不复制整段正文或会话。
查看与保存
服务端在 ACL 通过后从当前目录读取 SKILL.md 和 references/contract.json；保存校验后原子替换当前目录并更新索引 SHA。
下载或删除
按当前目录即时生成确定性 ZIP；删除前明确确认，同步删除索引、目录和终态运行记录，活跃运行必须先取消。
试运行
运行开始时从当前目录读取、校验并记录相对路径与 SHA；同时重验 owner、schema 与授权上下文。
启用复用
当前 SHA 试运行成功后才能启用；内容修改后回到草稿并要求新 SHA 重新试运行，可停用但不提供应用层历史回滚。

4. 数据与状态

skills 保存 owner、稳定工作空间 key、名称、描述、状态、相对目录、当前 SHA、来源摘要和敏感信息确认；不保存 manifest 或 Markdown。删除 skill_versions。skill_runs 绑定 owner、skill、运行时读取的相对路径和 SHA、运行模式、输入摘要、授权上下文、进度、唯一终态、输出或脱敏错误。

状态为 draft、enabled、disabled；运行终态为 succeeded、failed 或 cancelled。内容 SHA 改变即撤销旧试运行门禁，不把运行审计误当作产物版本。

5. manifest 与 API

manifest 必含显示名、符合 ^[a-z0-9]+(?:-[a-z0-9]+)*$ 且不超过 64 位的包名、描述、适用范围、前提、触发说明、输入 schema、步骤、术语/例子、失败条件、输出 schema、来源与自测；只接受 JSON Schema 的安全子集。物化后的 ZIP 以包名作为唯一根目录；SKILL.md frontmatter 只写同名 name 与同时说明用途和触发时机的 description，正文限制 500 行，并明确何时读取 references/contract.json。

所有 AI 产物统一落在可配置根目录 AI_ARTIFACT_ROOT，默认 /data/books/ai。当前 SKILL 目录为 {workspace_key}/skills/{skill_id}/{package_name}/，业务只保存相对目录；ZIP 不持久化，下载时从目录生成。写入使用同一文件系统的 staging 与原子 replace，目录/文件权限分别为 0700/0600；读取拒绝符号链接、路径越界、缺文件、额外文件或 SHA 不匹配，不从数据库重建正文。删除对象同步清理当前目录和空父目录。

API 保留创建、详情、状态、运行、文件包、下载和删除；移除 /versions 与 /rollback。所有入口均需登录并按当前 owner 过滤；文件内容必须在 ACL 通过后再读取。备份只需覆盖既有 /data/books 卷即可同时包含 DB 与 books/ai，数据库迁移不会伪装成文件迁移，缺失目录显式失败并可诊断。

6. 运行时与权限

继续使用统一 AgentRuntime 与 Codex app-server；每次读取当前目录并把校验后的内容作为提示数据块，不写入用户全局技能目录。运行目录为空、只读、无 readable roots、审批关闭、无 MCP；限制输入体积、schema 深度、总时长与并发。成功必须同时满足 app-server 完成终态、输出 JSON 解析、输出 schema、任务仍归当前 owner，且运行记录绑定启动时的目录 SHA。

创建来源、目录读取、启停、运行、轮询和取消都重验 owner。运行保存授权上下文摘要而非长期权限；涉及书籍的上下文只记录当次重新验证后的资源标识。

7. 安全策略

  • 保存前扫描常见 API key、token、私钥、邮箱、Unix/Windows 用户路径；默认拒绝，并返回类别与字段位置，不回显完整命中值。
  • 来源和 Markdown 明确作为不可信数据，不可覆盖系统指令；不接受脚本、依赖、工具声明或远程 URL 导入。
  • 限制 manifest/Markdown/input/output 大小、SKILL 正文行数、schema 深度与步骤数量；ZIP 路径由服务端静态生成，禁止用户路径穿越；日志和错误不持久化提示词、输入正文、凭据或进程原始输出。

8. 界面

登录用户可从导航进入“SKILL 生成器”：搜索和状态筛选在左侧列表，右侧把“下载 ZIP”“删除 SKILL”设为直接动作，并提供“文件包”标签查看当前 SKILL.md 与 references/contract.json。编辑器分离显示名和包名，保存动作明确为“保存并替换当前 SKILL”；移除版本标签、版本号、历史载入和回滚。预览、试运行与启停保留。亮暗主题、390px 重排、键盘路径、删除确认、错误与空态纳入验证。

9. 风险与兼容性

  • 未合并旧实现：直接移除版本模型与版本 API；新表由现有 create_all 创建。若评审环境已有旧目录，显式迁移脚本只接受 owner ACL 与 SHA 都可验证的数据，否则报告并停止，不静默复制。
  • schema 复杂度：首版拒绝引用、组合关键字和远程 schema，只实现 object/array/string/number/integer/boolean/null 及基础约束。
  • 运行时不可用或中断：任务失败关闭并保留可重试的运行记录，不把草稿误标为启用。

12. 决策记录

首版采用通用但受限的 JSON Schema 子集；启用前要求当前 SHA 至少一次试运行成功；“从成果生成”只提取本人成功任务的类型、协议版本和结果结构摘要，避免复制正文。TB-52 的统一规范取代旧版本化决定：Agent Skills 当前目录是唯一内容来源，数据库不保存正文副本；所有文件型产物置于 books/ai/{user-workspace}/skills，运行记录只钉住相对路径与 SHA，不提供应用层回滚。
