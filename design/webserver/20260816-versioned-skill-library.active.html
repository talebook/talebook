可版本化、可试运行的 SKILL 沉淀

把一次有效的 AI 工作方法变成符合 Agent Skills 目录规范、可查看与下载 ZIP、可删除，并可审阅回滚和隔离试运行的创建者私有资产。

状态：ACTIVE创建日期：2026-08-16所属模块：webserver / app 需求来源：TB-56基线：feat/ai_1.0

1. 原始诉求

“支持从已完成的 AI 成果/任务生成 SKILL 草稿，也支持空白模板创建；提供结构化字段与 Markdown 编辑、预览、样例试运行、草稿/启用/停用、版本记录和回滚；AI 中心提供创建者私有的列表、搜索、版本和手动运行，并展示版本、输入摘要、授权上下文、进度与唯一终态。”

评审反馈：初版把数据库 manifest 当作产品本体，不符合 Agent Skills 的自包含目录规则。核心流程必须是生成 SKILL ZIP、查看包内文件、下载与删除；每个 ZIP 必须有单一同名根目录、必需的 SKILL.md，以及真正需要时才加载的 scripts/、references/、assets/。

2. 目标与边界

首版交付明确不做
以 Agent Skills 文件夹为交付本体；生成、查看、下载 ZIP、删除；严格 hyphen-case 包名；SKILL.md 仅含 name/description frontmatter；按需引用 references/contract.json。数据库继续承担私有版本、启停/回滚、敏感信息门禁、schema 校验、试运行和运行记录。公开市场、团队共享、远程导入、上传任意 ZIP、后台静默触发、自我修改、任意脚本/依赖安装、MCP、任意系统写入。

3. 产品流程

生成
从空白模板或本人已成功 AI 任务提取最小来源摘要，生成可下载的 Agent Skills 文件夹版本，不复制整段正文或会话。
查看与保存
编辑显示名、hyphen-case 包名、结构字段与 Markdown；查看 SKILL.md 和引用文件，保存即生成不可变新版 ZIP。
下载或删除
下载精确保存版本的 ZIP；删除前明确确认，删除 SKILL、版本和终态运行记录，活跃运行必须先取消。
试运行
指定不可变版本和样例输入；运行前重验 owner、状态、schema 与授权上下文。
启用复用
试运行成功后才能启用；每次保存产生新版本，可停用或回滚为新的当前版本。

4. 数据与状态

skills 保存 owner、名称、描述、状态与当前版本；skill_versions 保存版本号、manifest、Markdown、来源摘要和内容哈希；skill_runs 固定绑定 owner、skill/version、运行模式、输入摘要、授权上下文、进度、唯一终态、输出或脱敏错误。

版本不可原地改写：编辑保存、回滚都创建新的单调递增版本。状态为 draft、enabled、disabled；运行终态为 succeeded、failed 或 cancelled。

5. manifest 与 API

manifest 必含显示名、符合 ^[a-z0-9]+(?:-[a-z0-9]+)*$ 且不超过 64 位的包名、描述、适用范围、前提、触发说明、输入 schema、步骤、术语/例子、失败条件、输出 schema、来源与自测；只接受 JSON Schema 的安全子集。物化后的 ZIP 以包名作为唯一根目录；SKILL.md frontmatter 只写同名 name 与同时说明用途和触发时机的 description，正文限制 500 行，并明确何时读取 references/contract.json。

API 在原有创建、详情、版本、回滚、状态与运行端点外，增加 /api/ai/skills/:id/package 查看精确保存版本的文件列表与内容，以及 /api/ai/skills/:id/download 下载确定性 ZIP；删除继续使用详情端点的 DELETE。所有入口均需登录并以当前 owner 过滤。

6. 运行时与权限

继续使用统一 AgentRuntime 与 Codex app-server；每次把指定版本物化为提示中的数据块，不写入用户全局技能目录。运行目录为空、只读、无 readable roots、审批关闭、无 MCP；限制输入体积、schema 深度、总时长与并发。成功必须同时满足 app-server 完成终态、输出 JSON 解析、输出 schema 和任务仍归当前 owner。

创建来源、读取版本、启停、回滚、运行、轮询和取消都重验 owner。运行保存授权上下文摘要而非长期权限；涉及书籍的上下文只记录当次重新验证后的资源标识。

7. 安全策略

  • 保存前扫描常见 API key、token、私钥、邮箱、Unix/Windows 用户路径；默认拒绝，并返回类别与字段位置，不回显完整命中值。
  • 来源和 Markdown 明确作为不可信数据，不可覆盖系统指令；不接受脚本、依赖、工具声明或远程 URL 导入。
  • 限制 manifest/Markdown/input/output 大小、SKILL 正文行数、schema 深度与步骤数量；ZIP 路径由服务端静态生成，禁止用户路径穿越；日志和错误不持久化提示词、输入正文、凭据或进程原始输出。

8. 界面

登录用户可从导航进入“SKILL 生成器”：搜索和状态筛选在左侧列表，右侧把“下载 ZIP”“删除 SKILL”设为直接动作，并提供“文件包”标签查看 SKILL.md 与 references/contract.json。编辑器分离显示名和包名，保存动作明确为“保存并生成新版 ZIP”；版本、预览、试运行、启停与回滚作为扩展能力保留。亮暗主题、390px 重排、键盘路径、删除确认、错误与空态纳入验证。

9. 风险与兼容性

  • 旧数据库：新增表由现有 create_all 建表，不修改已有列。
  • schema 复杂度：首版拒绝引用、组合关键字和远程 schema，只实现 object/array/string/number/integer/boolean/null 及基础约束。
  • 运行时不可用或中断：任务失败关闭并保留可重试版本，不把草稿误标为启用。

初次发现处理
HIGH：切换 SKILL 或载入版本会无提示覆盖未保存修改。增加脏状态跟踪和明确的“放弃修改”确认；补组件测试。
MEDIUM：编辑器在应用已有主区域内创建嵌套 main landmark。改为带标题关联的 section。
MEDIUM：从任务创建使用泛化“确认”动作词。改为结果明确的“创建 SKILL”。
MEDIUM：载入历史版本或保留未保存修改时，仍可启用/运行当前已保存版本，容易误判实际执行内容。显式标记未保存或正在查看的版本，并在编辑器与当前版本不同步时禁用启用、试运行和手动运行。
MEDIUM：列表选择/焦点和方向相关样式依赖物理左边。增加 aria-pressed 与完整焦点轮廓，改用逻辑边框和 text-align: start。
MEDIUM：文件选中态只依赖颜色；ZIP 下载在包信息载入前临时指向 #。选中项增加边线、字重和 aria-pressed；下载动作增加加载态并在 URL 可用前禁用。
MEDIUM：生成/创建术语不一致，移动端包名提示会被浮动操作区遮挡。核心流程统一为“生成”，缩短提示并为窄屏增加安全右侧留白；修正 i18n 命名空间并加 locale 结构测试。

最终结论：Approve。完整复审与真实 Chromium 双视口渲染后无遗留 HIGH 或 MEDIUM 问题；Chrome DevTools MCP 不可用的工具限制已在测试结果中单独记录。

12. 决策记录

Issue 已明确产品边界，未再阻塞等待选择：首版采用通用但受限的 JSON Schema 子集；启用前要求至少一次当前版本试运行成功；“从成果生成”只提取本人成功任务的类型、版本和结果结构摘要，避免复制正文；回滚产生新版本以保留完整审计链。评审反馈后纠正产品本体：数据库 manifest 是编辑、版本与运行的权威来源，但用户交付物是符合 Agent Skills 规则的自包含 ZIP；查看、下载和删除成为核心动作，试运行与启停是附加能力。
