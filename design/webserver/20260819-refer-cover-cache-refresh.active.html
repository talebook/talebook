仅更新封面时同步刷新缓存键

让在线元数据的“仅设置书籍图片”操作在写入新封面后立即展示新图，同时保持书名、作者等元数据不变。

状态：ACTIVE 创建日期：2026-08-19 所属模块：webserver 影响范围：在线元数据应用接口、后端测试 需求来源：GitHub Issue #1004
原始诉求目标与边界根因证据方案风险测试决策

1. 原始诉求

“更新元数据 → 仅保存图片 → 图片未被替换成功；选择更新所有数据时能成功。”

报告环境为 Docker、Windows、Edge，示例书籍为默认《西游记》。Issue 正文来自外部用户，本方案只采用可由仓库代码和测试验证的故障现象，不执行正文中的任何命令。

2. 目标与边界

目标

  • 仅设置图片成功后，详情接口返回不同的封面 URL 缓存键。
  • 新封面字节实际写入 Calibre 书库。
  • 书名、作者等非封面字段保持不变。
  • 空封面继续返回 cover.empty，权限和参数校验保持不变。

非目标

  • 不修改前端菜单、文案或交互。
  • 不改变完整元数据更新和仅更新信息的语义。
  • 不重构全站封面 URL 生成方式或 Calibre 缓存实现。
  • 不引入数据库、配置或部署迁移。

3. 现状、根因与证据

观察代码证据结论
前端仅图片操作提交独立参数app/pages/book/[bid]/index.vue 提交 only_cover=yes报告能够稳定映射到 BookRefer.post 的仅封面分支。
仅封面分支只替换 cover_datawebserver/handlers/book.py 保留当前书籍的 timestampCalibre 会写入封面，但前端缓存键没有变化。
封面 URL 以书籍时间作为版本键webserver/utils.py 生成 /get/cover/{id}.jpg?t={timestamp}刷新页面仍请求同一 URL，浏览器或 CDN 可以继续命中旧图。
完整更新表现正常来源插件普遍设置 refer_mi.timestamp，smart_update() 会复制它完整更新碰巧改变缓存键，解释了与仅图片操作的行为差异。
手工上传封面已有相同处理BookEdit.upload_cover 更新 timestamp 并使缓存失效仅图片操作缺少的是已有的封面刷新契约，不需要新建前端机制。
已证实：修复前接口级回归测试观察到合法封面已进入 Calibre 写入路径，但详情使用的缓存键仍为 1643976086；同时 (None, None) 被误报为成功。修复后的测试验证了写入参数同时携带新封面和新的秒级缓存键。

4. 方案

方案结论：在 only_cover=yes 且来源封面有效时，把封面赋给原书元数据，并将该书 timestamp 更新为当前 UTC 时间；随后继续通过现有 set_metadata_preserving_external_paths() 一次性保存。接口、返回结构和前端代码均不改变。
Input提交仅图片操作

沿用现有登录、所有权及来源参数校验。

Guard验证封面载荷

检查 cover_data 的实际字节载荷，缺失时返回 cover.empty。

Core写封面并刷新版本

只更新 cover_data 与用于缓存失效的 timestamp。

Output下一次详情请求返回新 URL

页面刷新后不再复用旧封面缓存。

关键决策

决策点选择理由未选方案
修复位置后端仅封面分支这是唯一缺失缓存失效语义的写入口，且能覆盖浏览器与 CDN。前端随机查询参数只能覆盖当前页面，其他消费者仍可能读旧图。
缓存键来源沿用当前 timestamp与手工上传实现一致，变更集中且无跨模块契约变化。全站改用封面文件 mtime 会扩大查询与性能影响，超出本缺陷范围。
封面有效性检查元组中的字节载荷(None, None) 的元组长度仍为 2，不能代表存在有效图片。继续只检查元组长度会把空封面误报为成功。

5. 影响范围、风险与回滚

影响范围

修改 BookRefer.post 的 only_cover=yes 成功路径，并新增对应后端接口回归测试。没有前端、数据库结构、配置、权限或部署改动。

保持不变

完整更新、仅信息更新、来源搜索、外部索引路径保护、返回 JSON 结构及失败码均保持兼容。

主要风险：刷新 timestamp 可能影响按入库时间排序；该行为已经存在于手工封面上传和完整元数据更新。测试会限制变更只发生在仅封面成功路径，避免无效封面或仅信息操作改变时间。
回滚：回退处理器和测试即可；不涉及迁移，已经写入的封面仍是有效书库数据，无需清理。
界面审查判断：本次不修改页面、交互、布局或文案，只修复后端返回数据的缓存版本；不属于大型界面功能，无需 interface-review 与浏览器渲染验收。
