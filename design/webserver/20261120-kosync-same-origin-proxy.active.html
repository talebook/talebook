为 Readest KOSync 使用 Talebook 同源代理

浏览器内嵌的 Readest 通过本站转送 KOSync 请求，使读者可以使用自选的外部同步服务，同时由后端限制代理目标和资源消耗。

状态：ACTIVE创建日期：2026-11-20所属模块：webserver影响：webserver、app/public/readest、scripts/readest；spec/阅读器.md来源：PR #1095 评审意见

1. 原始诉求

“嵌入式 Readest 原本透过 Readest 官方代理存取 KOSync，在浏览器端会受到跨域限制导致无法正常使用。这个 PR 改为由 Talebook 转送，让使用者使用自己的 KOSync 帳號同步 KOReader 阅读进度。”

评审还要求为新增的 JSON API、出站代理和 Readest 传输切换补充领域规格及设计记录。

2. 目标与边界

目标网页 Readest 使用同源接口代理 KOSync 认证、注册、进度读取和更新；要求 Talebook 登录；限制目标 URL、转发字段、大小、超时和并发。
非目标Talebook 不托管 KOSync 账号或数据，不改变本站阅读进度存储；不代理通用 HTTP 请求；原生 Readest 桌面端沿用原生网络行为。

3. 现状与证据

浏览器跨域规则阻止嵌入式 Readest 直接访问用户选择的 KOSync 服务。当前实现增加 POST /api/kosync，静态传输适配器使用相对路径构造同源地址，支持站点子路径。

目标服务由用户配置，因此必须防止协议滥用、重定向逃逸、DNS 解析切换以及过大或过慢的请求消耗。

4. 方案

Readest 网页端将有限格式的操作、目标服务地址及 KOSync 数据提交至本站。后端依次验证请求来源、登录态、JSON 结构、目标 URL 和允许的操作，再解析 DNS 并固定本次连接地址，向上游发送请求并返回状态与 JSON 数据。

边界规则
浏览器入口同源 JSON 请求并带 Talebook 标记；跨站 Fetch Metadata 或不匹配 Origin 拒绝。
操作范围仅允许认证、创建用户、更新进度及按 32 位十六进制 ID 读取进度。
目标地址仅 HTTP/HTTPS；拒绝凭据、查询、片段、路径穿越和非法字符；不跟随重定向。
资源约束请求体 16 KiB、响应体 64 KiB；DNS 5 秒、连接 5 秒、总请求 15 秒；并发槽位 8，等待槽位 2 秒。
失败语义上游 400/401 即使响应为空或 HTML，也以安全 JSON 保留状态供 Readest 认证回退；其他无效响应作为上游失败。

5. 影响范围、风险与回滚

涉及后端处理器与传输校验、Readest 静态产物及上游补丁，领域行为写入 spec/阅读器.md。不涉及数据库迁移或 Talebook 进度数据。

主要风险是用户指定的外部服务可能不可达或返回非标准响应；操作白名单、固定 DNS、禁止重定向、时限与体积限制控制代理边界。回滚可整体移除代理处理器和 Readest 适配器及对应静态产物，不需数据清理。

6. 测试结果

  • 在 app/ 执行 npx vitest run test/utils/readestKOSync.spec.ts，14 项通过。
  • 在 app/ 执行 node --test test/readest-kosync-browser.test.cjs，2 项通过。Chromium 在根路径和 /team/books 子路径加载实际传输模块，使用模拟 Talebook 接口验证同源路径、会话 Cookie 和上游认证失败状态的传递。
  • make check-spec、make check-design 通过。
  • 用 docker build --build-arg BUILD_COUNTRY=CN -t talebook/test --target test -f Dockerfile . 构建测试映像，在容器内执行 pytest -q tests/test_kosync_proxy.py tests/test_kosync_transport.py，51 项通过。后端传输测试使用本机模拟 KOSync 上游。
  • 本地 Chromium 从 Nginx 入口打开《爱丽丝梦游仙境》，经真实 Docker 后端连接测试 KOSync 服务。登录 Talebook 后，Readest 的 KOReader 同步设置显示连接成功。游客提交后显示 Failed to connect: 请先登录。
  • 提交者使用同一份 EPUB 和同一个 KOSync 账号，完成 KOReader 到 Readest、Readest 到 KOReader 的实际进度同步验证。

直接从本地 Nuxt 开发端口进入时，Nuxt 的 API 代理改写 Host，登录后的 KOSync 请求会被后端以 kosync.origin 拒绝。Nginx 保留浏览器请求的 Host，通过该入口验证连接成功。完整的 interface-review full 仍待完成。
