原始诉求与解释边界

GitHub Issue #886 的标题为“添加演示模式（单个 demo 账号）”，维护者评论要求执行。当前任务上下文未包含更详细的 Issue 正文，公开页面又因运行环境网络限制无法读取，因此采用能够由标题确定的最小安全解释：演示模式只允许一个配置账号登录；账号可以浏览其原有角色可见的页面和数据，但不得执行会改变服务端业务数据或产生外部副作用的操作。

默认兼容：功能默认关闭；未配置时所有认证、API 和 WebDAV 行为保持现状。演示模式不创建账号、不保存明文密码，也不改变既有用户权限模型。

目标与非目标

目标

  • 部署者可通过配置开启演示模式并指定唯一演示账号。
  • 仅该账号可通过网页密码、HTTP Basic 与 WebDAV 认证；社交账号入口关闭。
  • 网页 API 的业务写请求由后端统一拒绝，不能靠绕过前端限制写入。
  • WebDAV 在演示模式下只允许浏览和读取。
  • 不记录共享账号的登录 IP、访问时间、阅读历史和下载/访问计数。
  • 拒绝结果提供稳定错误码与中文提示。

非目标

  • 不自动创建、重置或定期清理演示账号。
  • 不在管理后台提供开关，避免演示账号通过界面锁定或解除自身模式。
  • 不实现多个演示账号、账号组或细粒度写操作白名单。
  • 不修改现有角色和权限位，也不把演示账号强制改为管理员。
  • 不隐藏写操作按钮；后端拒绝仍是最终安全边界。

方案

1. 配置与账号判定

新增默认配置 DEMO_MODE = False 与 DEMO_USERNAME = "demo"。用户名比较统一去除首尾空白并转小写。模式开启但用户名为空时采取安全失败：没有账号可通过认证。部署者在持久化 settings 覆盖文件中设置值；功能不暴露到后台保存字段。

2. 网页 API 服务端写保护

在 BaseHandler.prepare() 的公共请求入口实施演示策略。除登录、验证码验证和访问码提交外，POST、PUT、PATCH、DELETE 等非读取方法直接返回 demo.read_only。同时拦截历史上采用 GET 但会激活账号、发送激活邮件或切换后台模拟用户的入口。这样现有及未来继承 BaseHandler 的业务接口默认受保护。

3. 单账号认证

网页密码登录、HTTP Basic 和 WebDAV 认证均复用同一“是否演示账号”判断。社交账号流程可能在回调阶段创建账号或关联记录，因此模式开启时隐藏社交入口，并在独立的 social-auth 路由上拒绝登录、回调和解绑。已存在的非演示账号 cookie 在模式开启后不再解析为当前用户，避免旧会话越过单账号限制。登录演示账号仅刷新会话 cookie，不写入账号的访问时间和 IP；旧密码哈希也不在演示登录时迁移。

4. 读取副作用与 WebDAV

演示模式下跳过共享账号的阅读/下载历史、消息弹出删除与访问统计写入。WebDAV handler 具有独立的 prepare()，因此显式拒绝除 GET、HEAD、OPTIONS、PROPFIND 外的方法；WebDAV 认证同时限制为唯一演示账号。

安全、兼容性与风险

  • 策略放在后端公共入口，前端、脚本或直接 HTTP 调用均不能绕过。
  • 登录白名单只包含会话建立所需接口，不允许注册、重置密码或 social-auth 创建其他账号。
  • GET 历史接口并非全部严格无副作用，因此显式覆盖已知写入入口，并抑制公共读取链路中的统计/历史写入。
  • WebDAV 不经过 BaseHandler.prepare() 的现有实现，必须单独应用同一模式判断。
  • 默认关闭保证存量部署兼容；配置错误会安全地拒绝全部账号，而不是退回 unrestricted 模式。
  • 演示账号仍应由部署者设置独立密码，并按希望展示的范围赋予既有角色与权限。
