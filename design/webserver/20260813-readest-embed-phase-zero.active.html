Readest 嵌入 Talebook：阶段 0 边界验证

创建日期：2026-08-13 · 模块：webserver / Readest embed · 状态：ACTIVE · 需求来源：TB-36

原始诉求

在不删除、不移动、不替换完整 Readest/Moke 路径的前提下，建立并行的 Web Reader 构建目标，验证 Talebook 同源授权 EPUB 能否被该目标打开，并让禁入模块、产物边界和实际体积可自动审计。

目标与边界

  • 阶段 0 仅支持 EPUB 打开、基本翻页、返回书籍页和 Candle 回退。
  • 不实现服务端进度、批注、PDF、AI、同步、集成、账号或 Tauri 能力。
  • 完整 Readest app 与 Moke 原构建命令保持不变；embed 是新的独立 workspace app。

方案

1. /read
沿用现有阅读权限和格式判断。
2. bootstrap
返回版本化书籍、资源、导航与 capability 契约。
3. resource
专用同源 EPUB stream，支持 Range、ETag、正确 MIME。
4. embed
只加载 React 与 foliate-js 的单路由静态应用。

资源接口使用在线阅读权限，而非下载权限；私有书继续对无权用户返回 404。资源响应为 private, no-store，权限撤销后不能依赖长期缓存继续访问。

产品功能矩阵

能力阶段 0控制方式
EPUB 渲染、翻页、本地外观启用统一 capabilities manifest
返回书籍页、Candle 回退启用bootstrap navigation
library/account/cloud/sync/payment/send/RSS/OPDS禁入源码 import graph + 构建插件 + 产物扫描
Integrations/Telemetry/AI/Reedy/Gateway/Tauri禁入默认 deny 且无条件 import
进度、批注、PDF延后阶段 1 后独立设计和权限测试

API / 协议

GET /api/book/<id>/reader-bootstrap?engine=readest 返回 talebook.reader.bootstrap.v1；GET /read/resource/<id>.epub 返回 application/epub+zip 并支持字节范围；/read/<id>?reader=candle 是显式回退。

测试计划与结果

实现完成后验证：Talebook 权限矩阵与 Range/ETag/MIME；embed 类型、单测、import graph、生产构建、产物扫描；Moke 与完整 Readest 原构建路径。实测命令、体积和环境限制记录在 TB-36 PR 与 issue 评论中。

风险与 Go/No-Go

完整 EPUB URL 技术上可被浏览器保存，这是产品安全取舍而非 DRM。阶段 0 只有在无权用户无法取得资源、禁入依赖不进 bundle、完整路径不回归时才可 Go；进度和批注仍为 No-Go。
