UTF-8 导入文件名保真

创建：2026-09-14 · 模块：webserver · 状态：ACTIVE

来源：TB-217 / GitHub #1033

原始诉求与证据

imports 导入后部分书名约十字符处截断。附件实际为文件管理器列表，标题后仍有作者及扩展名。main.py 将 Calibre PATH_LIMIT=100 导出的文件标题预算 42 再除以 4，恰好留下 10 字符。扫描、入库及 API 标题不使用该命名结果；页面卡片的 CSS 单行省略另属展示逻辑。

目标与边界决策

保留 Calibre 原始字符预算，避免把所有字符当作四字节。每个目录项另外限制为 255 UTF-8 字节，文件名为扩展名、分隔符预留空间，截断保持完整码点。保留字符清理、空值回退、保留名及书籍 ID。超长标题仍允许安全缩短落盘名称，完整元数据保持不变。

不自动迁移或重命名既有书库；仅新建或由 Calibre 正常更新的路径使用新规则。index 模式仍使用原路径；不从已截短文件名反推覆盖元数据。边界核对已依据当前代码自行决策；仓库未提供 grill 技能，无需额外开发者决策。

实现方案

仅修改 main.py 的 UTF-8 命名函数：去掉 /4，加入码点安全的字节截断。路径目录分别预留书籍 ID 字节及 Windows 保留名后缀；文件标题和作者各分配 (255 - 扩展名长度 - 点号 - 分隔符长度)/2 字节。

新增命名单元测试及真实扫描→导入→Calibre 数据库→API 集成验证。测试输入包含中文、ASCII、四字节字符、非法字符、空白、保留名、长扩展名、同前缀不同书籍。

界面审查

无界面影响：仅修改后端存储命名，不改变页面组件、布局、交互或 API 契约，豁免 interface-review。附件是原问题证据；无需构造页面截图。风险：极长名称仍截断；已有文件不主动迁移；测试运行于 Linux，Windows 仅静态规则和边界测试。
