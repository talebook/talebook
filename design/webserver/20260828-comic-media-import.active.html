漫画媒体安全导入与分类

在不引入漫画阅读器的前提下，让 CBZ、ZIP、CBR、RAR 可安全入库，并用持久分类和明确阅读状态区分漫画与普通电子书。

状态：ACTIVE创建日期：2026-08-28所属模块：webserver影响：webserver / app / tests需求来源：TB-129

1. 原始诉求

“支持导入并保存 cbz、zip、cbr、rar；媒体分析阶段持久区分漫画型内容和普通电子书。漫画容器暂不在线阅读，漫画型 EPUB 仍使用现有 EPUB 阅读器。不能只信扩展名，并限制不可信压缩包的资源消耗。”

本期只打通上传、目录扫描、Calibre 入库、API/详情展示、下载及阅读路由保护，不解压渲染漫画页面。

2. 目标与边界

目标

  • 验证 ZIP、RAR、EPUB、PDF 的签名与必要容器结构，损坏或伪装文件明确失败。
  • 持久化 unknown / ebook / comic 内容分类并由 API 返回。
  • 漫画 ZIP/RAR 可管理与下载，但不会进入现有阅读器；漫画 EPUB 正常阅读。
  • 检测只读取目录、受限 XML/XHTML 和极少图片头，不提取整本漫画。

非目标

  • 漫画图片阅读器、翻页、预加载、缩放与在线预览。
  • PDF OCR 或漫画语义判断；PDF 保持 unknown。
  • 仅凭 fixed-layout 元数据判断漫画。
  • 全量回填既有书籍；旧记录迁移后保持 unknown。

3. 现状与证据

现状证据结论
上传和目录扫描仅允许六种电子书扩展名。webserver/handlers/scan.py、webserver/services/scan.py两条导入链路必须共享同一分析规则。
结构校验仅检查 EPUB 的 ZIP 头和 PDF 头。webserver/handlers/book.py需要验证 EPUB mimetype/OPF/spine 和图片压缩包内容。
扩展属性位于 Talebook 的 Item 表，Calibre 负责格式文件。webserver/models.py、webserver/handlers/base.py分类应落在 Item，不修改 Calibre 表结构。
详情页顶部始终提供阅读按钮。app/pages/book/[bid]/index.vue容器漫画需显示禁用状态和原因。
Komga EPUB 检测要求每个 spine 页面正文不超过阈值且只对应一张 manifest 图片。Komga EpubExtractor.getDivinaPages采用同类保守启发式，不把 pre-paginated 当分类依据。

4. 方案

核心结论：新增独立媒体分析服务；上传在写入临时目录后分析，扫描在标记 READY 前分析，入库时再次确认。分析结果写入 Item.media_type，详情 API 同时给出 online_readable。
INPUT扩展名白名单

允许现有格式及 CBZ/ZIP/CBR/RAR。

GUARD签名与预算

限制条目数、展开大小、压缩比、路径和单条目大小。

ANALYZE容器结构

图片归档判漫画；EPUB 按 manifest/spine 分析。

OUTPUT持久化与路由

分类入 Item；API/界面展示并保护阅读入口。

关键决策

  • 字段：不用现有 book_type，它表达本地/在线/实体来源；新增 media_type 表达内容形态。
  • RAR：引入小型纯 Python rarfile 仅解析目录，不增加 unrar 系统组件、不解压页面；测试覆盖 RAR4/5 目录行为。
  • 合并：同一本书追加格式时采用 comic > ebook > unknown，避免 PDF 或后续未知分析降级已识别漫画。
  • 既有数据：自动迁移新增列且默认 unknown；只对新上传、新扫描或重新添加格式的书更新分类，不在启动时全库解包。

5. 影响、风险与回滚

影响范围

Item 自动迁移、上传与扫描、书籍 API formatter、阅读路由、详情页和中英文文案；新增 Python 小依赖。

保持不变

EPUB/PDF/TXT/Kindle 阅读优先级、Calibre 文件所有权、下载权限、漫画 EPUB 阅读器选择以及 PDF 分类语义。

风险：恶意压缩包可能制造 CPU/内存消耗；通过条目/大小/压缩比/读取上限、禁止加密和路径穿越缓解。保守 EPUB 规则可能留下 unknown/ebook，但优先避免把小说误判为漫画。

回滚：业务代码和前端可整体回滚；新增列为向后兼容附加列，无需删列。已导入容器仍是 Calibre 普通格式，可继续下载或由管理员删除。
