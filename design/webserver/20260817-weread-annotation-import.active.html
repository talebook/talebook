微信读书笔记导入

把用户自己的划线、想法、章节点评和整本书评安全导入 Talebook，并把真实插件做成笔记类 provider 的端到端样板。

原始诉求目标流程数据与安全匹配与定位接口测试

1. 原始诉求

支持用户 API Key 和官方导出 JSON 两种来源，解析微信读书划线、想法、章节与个人整本书评；按 provider ID、ISBN、规范化书名作者匹配；多候选必须确认；preview、批量、幂等、重试、回滚和无 CFI 降级都必须可验证。官方目前只提供书签数量，不承诺导出书签正文。

2. 目标与边界

本次目标

  • 内置 talebook.annotations.weread provider，使用官方 Agent Gateway。
  • 导出 JSON 作为私有 run input，不进入公开连接配置或 API 回包。
  • 成功项写入 Annotation 与 AnnotationSource；source + external_id 保持幂等。
  • 用户可以预览候选、确认匹配、执行导入、重试失败项和按 run/source 回滚。
  • Web 显示来源及无 CFI 的章节级降级；同一 annotations API 可供 Moke/Readest 消费。

明确边界

  • 不伪造微信读书书签正文；只报告统计口径限制。
  • 不把 API Key 写入日志、run item、公开 JSON 或页面状态。
  • 不对低置信文本生成 CFI；无法确认唯一文本节点时保留章节、原文与 source_position。
  • 不在本仓库修改外部 Moke/Readest 客户端；服务端兼容由 API 和测试保证。

3. 端到端流程

1. 取数API Key 调 Gateway，或读取用户上传 JSON。
2. 解析合并划线、想法、章节点评与书评，稳定派生 external_id。
3. 匹配复用已确认选择；再按 provider ID、ISBN、规范化标题作者评分。
4. 预览/确认唯一高置信候选可写；多候选或低置信只展示并等待确认。
5. 写入幂等 materialize，成功才推进游标；失败项可重试和回滚。

4. 数据与安全

对象用途安全/幂等约束
PluginSecret用户 API KeyFernet 密文，公开模型只返回 configured/mask；401 不重试。
PluginRun.input_data一次导入的官方 JSON不被 to_public_dict 序列化；仅 retry 读取父 run 输入。
PluginEntityMatch微信书籍到 Calibre book_id每连接、source book ID 唯一；人工确认覆盖候选并审计 confirmed_by。
PluginSourceRecordpayload hash、run、真实 annotation id(connection, annotation, external_id) 唯一；第二次相同导入跳过。
AnnotationSource来源、连接、run、位置、更新时间source identity 唯一；对外只暴露非敏感来源数据。

5. 书籍匹配与 CFI

候选顺序为：已确认映射 → Calibre identifier 中的 WeRead bookId → ISBN → NFKC/casefold/去空白标点后的标题与作者。只有唯一的强匹配自动采用；两个及以上候选或只有标题弱匹配时，run item 标为 conflict，run 保持 partial/failed，且游标不推进。

定位器只在 EPUB 中找到唯一章节文件、唯一规范化原文、并能落到单个文本节点时生成 EPUB CFI。任何歧义、格式缺失或解析失败都令 cfi = null，同时保存 chapter、quote_text 与 chapterUid/range 形式的 source_position。

6. 用户接口与页面

  • POST /api/plugins/weread/import：test/preview/run；支持 api_key、export、matches，返回 run 与包含候选的数据项。
  • GET /api/plugins/weread/import：当前连接掩码与最近运行；不返回凭据或导入正文。
  • 现有 retry/rollback 与 annotation source DELETE 继续可用，补充用户 run detail 权限隔离。
  • AnnotationPanel 提供“导入微信读书”对话框：选择 JSON 或填写 API Key、预览、多候选选择、确认写入和结果摘要。
