微信读书通用集成

基于 weread-skills v1.0.4 的真实接口能力，把搜索、书架、阅读统计、个人笔记、社区与发现收进一个只读工作台；只有个人笔记支持单向导入 Talebook。

1. 原始诉求与能力复核

首版只覆盖个人划线与想法导入。反馈要求实际安装并分析 Tencent/WeChatReading：本机试装的 weread-skills v1.0.4 及 Gateway /_list 实测确认有 17 个只读操作，覆盖搜索、书籍信息/目录/进度、书架、统计、个人笔记、社区点评和推荐发现；没有任何写回微信读书的 API。因此插件应从“笔记导入器”重构为通用微信读书集成，同时保留成熟的单向笔记导入链路。

2. 目标与边界

本次目标

  • 内置 talebook.weread provider，新增 integrations 插件分类。
  • 提供搜索、书架、统计、笔记、社区、发现六个工作台 tab；管理插件页提供“综合服务”tab。
  • 所有查询通过服务端 17 项固定 allowlist 转发，并校验字段、类型、分页数量和嵌套 range。
  • API Key 只加密保存到当前用户连接；上游若意外回显敏感字段，API 回包再次脱敏。
  • 个人划线、想法、章评和书评继续支持预览、匹配、幂等导入、重试与回滚。

明确边界

  • 微信读书侧完全只读；Talebook 的修改不能回写。
  • 书签只展示数量，不能导出正文；文章收藏接口只返回入口，不返回文章列表。
  • 书架总数必须包含电子书、有声专辑和文章收藏入口，并按真实数组统计公开/私密条目。
  • 本机 npx skills add 仅用于能力分析，不代表将 skill 导入 Multica 工作区。
  • 不把用户 API Key 写入源码、日志、run item、公开 JSON 或测试产物。

3. 端到端流程

1. 连接用户输入 Key；服务端保存为用户级 PluginSecret 密文。
2. 查询工作台只提交 operation + params，不接收任意 api_name。
3. 校验allowlist 映射到 Gateway；拒绝未知操作、字段、类型和越界值。
4. 展示六个 tab 按官方字段口径呈现，只使用回包存在的 deepLink。
5. 可选导入仅个人笔记走原有预览/确认/幂等 materialize 链路。

6. 用户接口与页面

  • GET /api/plugins/weread：返回个人连接掩码、最近导入运行、17 项 operation、只读标识与 skill 版本。
  • POST /api/plugins/weread/query：接受 api_key（可选，仅更新连接）、operation 与 params；成功后清空页面 Key 输入。
  • GET/POST /api/plugins/weread/import：继续负责 test/preview/run、导出 JSON、多候选确认和写入 Talebook。
  • /plugins/weread：六 tab 响应式工作台；AnnotationPanel 的入口跳到 Notes tab；管理插件页的综合服务卡片跳到工作台。
