TaleAgent Markdown Agent 产物

把 TaleAgent 的目录权威产物从实现专用 JSON 改为标准、可读、可复用的 Agent 文档目录，同时保留数据库索引、完整性校验和原子替换。

1. 原始诉求

成员要求：“实际存储的文件应该是 AGENTS.md 这种非常标准的 ai agent 文件，并且控制 agents.md 文件长度尽量不要超过 80 行，复杂的内容可以使用 references/ 目录来额外存储 doc.md。”后续补充：“references/ 里可以放多个文档。”

opaque workspace 仅表示目录名不暴露邮箱、用户名或连续 reader id；本方案保留隐私目录名，但不再让它暗示产物内容不可读。

2. 目标与边界

目标边界
  • 每个预览或正式 Agent 目录都有 AGENTS.md 。
  • AGENTS.md 是短入口，硬限制不超过 80 行。
  • 完整资料按职责拆分为 references/ 下的多个 Markdown 文档。
  • 运行时从 Markdown 文档恢复经验证的 manifest，不依赖数据库正文。
  • 数据库仍只保存相对入口路径、目录摘要和状态。
  • 不改变 TaleAgent 页面、API 或会话 JSON 模型。
  • 不保存 EPUB 正文、运行时 prompt 或对话内容到 Agent 文件。
  • 不保留 manifest.json 兼容副本；草稿 PR 尚未生产落地。
  • 不引入版本目录、回滚接口或额外库表。

3. 目录与文档契约

books/ai/{workspace}/agents/
  {agent-id}/
    AGENTS.md                 # 标准入口，≤ 80 行
    references/
      profile.md              # 名称与介绍
      thinking.md             # 思维、决策、步骤与盲点
      sources.md              # 证据来源
  previews/{task-id}/
    AGENTS.md
    references/
      profile.md
      thinking.md
      sources.md

AGENTS.md

包含 TaleAgent 身份、必须先读取三个 references 文档的指令、使用思维模式帮助用户解决问题的核心行为，以及不得虚构来源/不得声称是原人物等简短边界。

references/

profile.md 保存 display name 和 introduction，thinking.md 保存 thinking patterns、decision principles、problem-solving steps 与 blind spots，sources.md 保存来源。写入时把列表项规范为单行；读取时严格检查每份文档的章节、数量和结构。后续可在不增长 AGENTS.md 主体的前提下继续扩展受约束的 references 文档。

4. 一致性、安全与兼容

  • 摘要覆盖 AGENTS.md 与 references/ 下的全部受控文档，任一文件缺失、多出或被篡改即失败关闭。
  • 替换前保存旧目录字节；新文件在受控临时目录内写入、fsync 后切换，数据库提交失败时恢复旧目录。
  • 只接受当前创建者 workspace、固定 feature、固定文件名和受控目录深度，拒绝绝对路径与 ..。
  • 删除入口路径时删除整个 Agent 目录及 references；预览、Agent、书籍删除流程保持一致。
  • 旧 manifest.json 不兼容。本实现只存在于未合并草稿 PR，无生产迁移对象。
