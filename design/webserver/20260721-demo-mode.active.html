演示模式：单账号只读体验、自动开户与真实管理员维护

为公开演示站提供一个可浏览完整功能、但不能改变业务数据的共享账号：演示模式开启后仅配置的 demo 账号（及数据库中真实的管理员账号）可登录，demo 账号首次登录自动开户并进入“伪管理员设置面板”体验交互流程，未登录访客与 demo 账号的阅读/下载权限统一对齐后台“访客权限”设置，真实管理员账号则不受任何限制、可持续维护演示站。

原始诉求

GitHub Issue #886 标题为“添加演示模式（单个 demo 账号）”，要求为公开演示站提供只读体验。实现进入 PR #887 后，维护者在评论区分批补充了具体诉求，最终共同构成本方案：

“我希望打开演示模式时自动创建一个名为 demo 的用户……demo 用户可以查看管理员面板，但是内部内容为虚假体验版……点击保存按钮是不会真的去保存的。”（2026-08-01）
“那我要怎么维护 demo？给我管理员账号允许登录”（2026-08-01）
“我希望演示模式时，在用户管理中，演示用户的操作按钮直接被隐藏……然后演示模式的未登录与演示用户的权限要遵循访客权限设置的”（2026-08-01）
“这个 PR 更新：默认密码设置为 talebook，方案文档合并为 1 份，不要保留中间临时方案”（2026-08-03）

拆解为六个可验证的行为点：① 演示模式只允许配置的 demo 账号与数据库中真实管理员登录，其余账号一律拒绝；② demo 账号不产生登录 IP、访问时间、阅读历史、访问计数等副作用；③ demo 账号首次登录按需自动开户，默认密码为 talebook，已存在同名账号不覆盖；④ demo 账号可进入“管理员设置”页面看到 settings.py 出厂默认值，点击保存返回成功但不真实写入；⑤ 真实管理员账号在演示模式下不受只读限制，可正常维护站点；⑥ 未登录访客与 demo 账号的阅读/下载权限统一遵循后台“访客权限”设置，用户管理页对 demo 账号隐藏操作入口。

目标与非目标

目标

  • 新增配置 DEMO_MODE（默认 False）与 DEMO_USERNAME（默认 demo）；关闭时不改变任何现有行为。
  • 演示模式开启后，仅配置的 demo 账号与数据库中 admin=True 的真实管理员账号可登录（网页密码、HTTP Basic、WebDAV 认证均适用）；其余账号与已登录的旧会话一律视为未登录。
  • demo 账号的业务写请求、会产生副作用的 GET（如 /api/admin/users/owner、/api/active/*）、WebDAV 写方法与社交登录/绑定统一拒绝；真实管理员账号不受此限制。
  • demo 账号不记录登录 IP、访问时间、阅读历史、书籍访问计数、站内消息与书源搜索权重等副作用数据；真实管理员账号正常记录。
  • demo 账号不存在时首次登录按需自动创建（非管理员、可登录、密码固定为 talebook），已存在同名账号不覆盖资料或重置密码。
  • demo 账号数据库 admin 字段仍为 False，但 /api/user/info 向前端展示管理员入口；GET /api/admin/settings 只返回 settings.py 出厂默认值，POST 校验通过后返回成功但不写入 CONF/auto.py；其余管理接口仍按真实权限拒绝 demo 账号。
  • 未登录访客与 demo 账号的在线阅读、EPUB 分页读取、下载统一遵循 ALLOW_GUEST_READ/ALLOW_GUEST_DOWNLOAD，忽略 demo 账号自身默认拥有的权限位；真实管理员不受影响。
  • GET /api/admin/users 为每个用户新增 is_demo 字段；用户管理页在演示模式开启且该行是 demo 账号时，以锁定提示替换操作菜单。

非目标

  • 不在管理后台提供“开启/关闭演示模式”的开关，仍只能通过配置文件修改并重启生效，避免 demo 账号通过伪设置页改变安全边界。
  • 不为管理员设置页面之外的其它管理子页面构造虚假数据，其余 @is_admin 接口对 demo 账号继续拒绝。
  • 不放开 WebDAV 写操作：WebDAVHandler.prepare() 的只读检查发生在完整解析请求者身份之前，真实管理员如需上传/整理文件需改走网页后台，不通过 WebDAV 同步。
  • 不放开社交账号登录：演示模式下 /auth/login、/auth/complete、/auth/disconnect 对所有账号统一拒绝，管理员需用户名密码登录。
  • 不扩大推送、上传的只读白名单：两者是 POST 请求，已被统一只读策略拒绝，不重复处理。
  • 不新增独立的“演示模式访客权限”配置项，复用既有 ALLOW_GUEST_* 四项配置。
  • 不新增“管理员专用密码”，真实管理员账号本就由部署者预先创建并维护，与 demo 账号的密码策略无关。

方案

1. 配置与账号判定（webserver/demo_mode.py）

新增 DEMO_MODE = False、DEMO_USERNAME = "demo" 两项默认配置。用户名比较统一去除首尾空白并转小写。核心判定函数：

  • is_demo_user(conf, user) — 是否为配置的演示账号。
  • is_real_admin(user) — 是否为数据库 admin=True 的真实管理员，与 is_demo_user 相互独立。
  • can_login(conf, user) — not is_demo_mode(conf) or is_demo_user(conf, user) or is_real_admin(user)，统一驱动网页登录、HTTP Basic Auth、WebDAV 认证与社交回调四处调用点。
  • is_demo_restricted(conf, user) — 演示模式开启且用户不是真实管理员时为真；取代分散各处的 is_demo_mode(CONF) 布尔检查，是“该请求是否套用只读/伪造限制”的唯一入口。

2. 会话与只读写保护（webserver/handlers/base.py）

get_current_user() 复用 can_login()：不允许登录的账号也不允许维持已登录状态，因此旧管理员会话不会被强制清空，普通账号会话则被清空。request_is_allowed(conf, method, path, user) 在 is_demo_restricted() 为假（真实管理员）时直接放行任意方法与路径；为真时仅放行 GET/HEAD/OPTIONS/PROPFIND、登录/验证码/首页等会话建立路径（DEMO_SESSION_PATHS），以及 /api/admin/settings 这一条“假保存”路径（DEMO_FAKE_SAVE_PATHS），并显式拒绝 DEMO_BLOCKED_GET_PATHS 与 /api/active/*。BaseHandler.prepare() 在公共入口调用该判定，其它继承 BaseHandler 的业务接口默认受保护，不依赖各 handler 单独实现。

登录 IP/时间记录（login_user）、站内消息写入/弹出（add_msg/pop_messages）、阅读历史（user_history）、图书访问计数（count_increase）与密码格式迁移，判定条件统一改为 is_demo_restricted(CONF, user)：真实管理员正常记录/迁移，demo 账号与匿名访客继续跳过。webserver/handlers/network_library.py 中的书源搜索权重更新同样按此判定。

3. 自动开户（demo_mode.ensure_demo_account()）

演示模式开启且配置了 DEMO_USERNAME 时，登录请求（SignIn.post()）里若按用户名查不到 demo 账号则自动创建：admin=False、active=True、无自定义权限位，密码为常量 DEMO_DEFAULT_PASSWORD = "talebook"（走既有 bcrypt 哈希，不明文存储）。先查后建保证幂等，已存在的同名账号（含部署者手工创建、设置了更强密码的账号）不会被覆盖或重置密码。选择“登录时按需创建”而非“服务启动时创建”，避免依赖启动时序，也不需要改动 main.py 的会话生命周期。

4. 伪管理员设置面板（webserver/handlers/admin.py 的 AdminSettings）

新增 is_demo_fake_admin()：演示模式开启且当前账号是配置的 demo 账号时为真。GET 在该条件下返回 webserver/settings.py 里的原始 settings 字典（出厂默认值），不合并 auto.py/manual.py 覆盖的运行时 CONF，避免向公开演示访客泄露真实站点标题、密钥、数据库连接串等。POST 只做 JSON 解码校验后直接返回 {"err": "ok", ...}，不经过字段白名单过滤、SettingsSaverLogic.save_extra_settings()、写 auto.py 等真实保存路径。该特判只加在 AdminSettings 一个 handler 里，不修改 BaseHandler.is_admin() 或全局 @is_admin 装饰器，其它管理接口继续依据数据库真实 admin 字段拒绝 demo 账号。UserInfo.get_user_info() 对 demo 账号返回 is_admin: true（叠加 user.is_admin() or is_demo_fake_admin），复用前端既有管理员导航入口与设置页组件，无需新增或修改 .vue 文件。

5. 真实管理员登录维护

放行条件严格锚定数据库既有的 Reader.admin 字段，不新增角色或“演示管理员”白名单。第 1、2 节中 can_login()/get_current_user()/request_is_allowed() 的改造统一覆盖该场景后，webserver/handlers/admin.py 中的 @is_admin 装饰器与 self.admin_user 判断无需任何改动，即可对真实管理员“开箱即用”：用户管理、批量删除、书源管理等所有既有管理接口在演示模式下对真实管理员正常工作。AdminSettings.is_demo_fake_admin() 只判断“是否为配置的 demo 账号”，真实管理员始终为假，因此继续走真实保存路径，与伪管理员面板逻辑互不干扰。WebDAV 写操作是唯一未放开的例外（见“非目标”），管理员改用网页后台维护书库。

6. 访客权限对齐（webserver/handlers/book.py、webserver/handlers/files.py）

在线阅读（BookRead.get，含 PDF 分支）、EPUB 分页读取（EpubReader.get）、书籍下载（BookDownload.prepare）三处权限判断前统一计算：

guest_like = not self.current_user or demo_mode.is_demo_restricted(CONF, self.current_user)

为真时只检查对应的 ALLOW_GUEST_READ/ALLOW_GUEST_DOWNLOAD，不再检查账号自身的 is_active()/can_read()/can_save()——demo 账号自动创建时未设置权限位，按 has_permission() 默认语义等同拥有全部权限，若不做此对齐会绕开后台的访客权限收紧。真实管理员场景下 guest_like 恒为假，继续按自身权限位判断，不受影响。推送、上传接口维持现状：两者是 POST 请求，已被第 2 节的只读策略统一拦截为 demo.read_only，重复判断是死代码。

7. 用户管理页锁定（webserver/handlers/admin.py 的 AdminUsers、app/pages/admin/users.vue）

AdminUsers.get() 为每个用户新增 "is_demo": demo_mode.is_demo_user(CONF, user)，只回答“这是不是配置的演示账号”，是否需要锁定展示由前端结合已有的 sys.demo_mode 一并判断。admin/users.vue 的“操作”单元格在 sys.demo_mode && item.is_demo 为真时，将下拉菜单替换为锁定提示文字（i18n key admin.users.label.demoAccountLocked），信息层级遵循“状态优先于操作”，用浅紫底色与次要文本色弱化区分，不使用红色/警告色——这不是错误状态，而是演示站点的正常边界。演示模式关闭或该行不是演示账号时，操作按钮保持原有下拉菜单。

安全边界与风险

  • 后端是最终边界：策略统一放在 BaseHandler.prepare() 公共入口与 WebDAV 独立 prepare()，前端隐藏按钮、直接 HTTP 调用或脚本均不能绕过；用户管理页的锁定提示只是体验优化。
  • 不产生真实管理员权限：demo 账号数据库 admin 字段始终为 False，除 AdminSettings 一处伪造视图外，其余所有 @is_admin 接口继续拒绝 demo 账号，避免“伪管理员”被误用为真实提权入口。
  • 不泄露真实配置：设置页对 demo 账号只读出 settings.py 出厂默认值，不合并 auto.py/manual.py 覆盖，真实密钥、数据库连接串、站点标题不经此接口泄露。
  • 固定密码是已知且刻意接受的风险：talebook 是公开可预期的密码，任何人都能登录 demo 账号——这符合“公开演示账号”定位，且登录后仍受全局只读写保护约束，不能执行真实业务写操作；若同名账号已由部署者手工创建，自动开户逻辑不会重置其密码。
  • 真实管理员密码是整站写权限的唯一门槛：演示模式开启后与关闭时一致，本方案不降低也不提高这一固有风险，需部署者自行妥善保管。
  • 放行面收窄到必要路径：只读策略对 demo 账号的例外只加了 /api/admin/settings 一条 POST 路径，不是放开整个 /api/admin/* 前缀，降低误放行到破坏性接口（批量删除、迁移数据库等）的风险。
  • 访客权限判定不影响真实管理员：guest_like 表达式在真实管理员场景下恒为假，不会出现“管理员因访客权限关闭而读不了书”的回归。
  • 演示模式只能通过配置文件关闭：不在管理后台提供开关，避免 demo 账号通过伪设置页或其它途径意外关闭只读保护。
