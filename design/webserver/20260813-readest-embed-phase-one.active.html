Readest embed 阶段 1 最小 EPUB 正式集成

在阶段 0 的独立构建与权限边界上，补齐可人工验收的 EPUB 阅读主流程，同时保持完整 Readest、Moke 与 Candle 路径不变。

状态：ACTIVE创建日期：2026-08-13所属模块：webserver影响范围：Readest embed、阅读接口、静态部署需求来源：TB-38

1. 原始诉求

“在阶段 0 已推送的三个远端分支上继续实施阶段 1：授权用户能打开真实 EPUB，完成目录、章节、翻页或滚动、搜索、字体、排版、主题和语言设置；刷新或深链可重新打开；错误可理解且始终能重试、返回书籍页或切回 Candle。”

阶段 0 已确认 opt-in 路由、逐书权限、同源 EPUB 资源、独立构建与禁入依赖门禁可行，但 UI 仅有加载和翻页。

2. 目标与边界

目标
  • 复用 foliate-js 高层 View 完成目录、搜索、章节导航和位置恢复。
  • 提供严格能力门禁控制的本地基础设置。
  • 建立可操作错误模型、静态缓存/CSP 和可复现产物契约。
  • 保留逐书授权、Range、ETag、MIME 与撤权行为。
非目标
  • 不保存服务端进度，不做多设备冲突。
  • 不做书签、高亮、笔记、PDF、AI、云服务、Telemetry、Integrations。
  • 不开放自定义字体、背景图、网络翻译或 TTS。
  • 不设为默认阅读器，不改变完整 Readest/Moke 构建。

3. 功能与权限矩阵

能力授权用户游客失败表现
EPUB 阅读、目录、搜索支持仅在允许游客阅读时支持登录、激活、无权限、缺书、格式或资源错误分别提示
本地排版、主题与 UI 语言支持，浏览器本地保存支持，浏览器本地保存损坏值回落到默认值
服务端进度与批注不支持不支持入口和动态依赖均不存在

4. 方案

宿主 bootstrap
校验权限、格式、revision 与同源 URL。
隔离加载
CSP 默认拒绝外部连接，EPUB iframe 不允许顶层导航或弹窗。
ReaderView
foliate-js View 负责目录解析、CFI、搜索、分页与滚动。
本地状态
设置按 profile 保存，位置按书和 revision 保存并同步 URL hash。

唯一的 ReaderCapabilities 默认全拒绝，显式开启目录、搜索、导航、位置恢复、排版、外观和语言。所有 UI 入口、快捷键及搜索动态 import 都先检查该对象。

静态入口与 manifest 禁止缓存，带 hash 的 JS/CSS 使用 immutable；Docker 构建检查已验证 manifest 存在。Talebook 更新脚本继续在复制前验证每个文件 SHA-256。

5. 风险与兼容

  • embed 复用 View/search 会增加包体；继续报告 raw/gzip/brotli 增量并保留门禁。
  • 本阶段仍在浏览器内完整缓冲 EPUB，超大书内存峰值留待后续优化。
  • 位置仅存在当前浏览器；revision 改变后不复用旧 CFI，避免资源变化导致错误跳转。
  • 完整 Readest 与 Moke 只增加 submodule 指针，不删除或替换任何现有入口。

6. 测试计划与结果

验证完成。

  • Readest embed：import graph、Biome、TypeScript、7 项 Vitest、生产构建及产物扫描通过。
  • 真实 EPUB 浏览器回归：Chromium、Firefox、WebKit 均通过目录、搜索、翻页、滚动、移动端设置、刷新、CFI 深链与本地恢复；三种内核均无页面错误。
  • 完整路径：完整 Readest 生产构建通过；Moke typecheck 与 131 项测试通过。
  • Talebook：聚焦 16 项测试通过；全量 829 项通过、20 项跳过；Python lint/格式通过；SPA production Docker 构建通过并验证 manifest/baseline 入镜像。
  • 体积：阶段 0 的 414,916 / 153,689 / 134,444 字节（raw/gzip/brotli）增长为 496,240 / 180,806 / 158,418，增量为 81,324 / 27,117 / 23,974。增量来自高层 View、目录/CFI/搜索动态 chunk、设置与恢复 UI。

未发现阻断问题。阶段 2 可复用现有 book id、revision 与 CFI，但服务端进度 API、冲突策略和隐私边界尚未实现，必须作为独立后续工作评审。
