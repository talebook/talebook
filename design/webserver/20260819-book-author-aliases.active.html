用独立别名索引聚合书籍与作者

在保留 Calibre 主书名与作者字段兼容性的前提下，让中英文名、译名和标点变体可以被维护、检索与聚合，并提供显式的作者合并操作。

状态：ACTIVE创建日期：2026-08-19所属模块：webserver影响范围：webserver、app、tests需求来源：TB-67 / GitHub #1002

1. 原始诉求

“每本书可维护多个别名并在详情页展示；每位作者可维护多个中英文、译名或标点别名，将别名下的书聚合到同一主页，并支持合并作者。”

现有全文搜索和作者分类只读取 Calibre 主字段。同一实体使用不同写法时，搜索结果与作者主页都会分裂。

2. 目标与边界

目标

  • 编辑书籍时批量维护标题别名，详情页可见。
  • 书名别名和作者任一别名都能命中完整书目。
  • 作者列表与主页按规范作者聚合。
  • 管理员可预览并显式执行作者合并。

非目标

  • 不改变 EPUB/OPF 内嵌元数据格式。
  • 不自动猜测翻译名或联网补齐别名。
  • 不自动合并同书不同版本或文件格式。
  • 不把别名写入 Calibre 自定义列。

3. 产品与权限矩阵

任务游客登录用户管理员验收
按别名搜索和浏览聚合作者页支持公开书支持有权书籍支持全部可见书籍别名与规范名返回同一集合，继续遵守私有书过滤。
维护书籍别名不支持仅有编辑权限且为书主支持沿用现有书籍编辑权限，空值删除。
维护作者别名、合并作者不支持不支持支持全局操作仅管理员可执行；合并前显示将修改的书籍数量。

4. 现状与根因

观察证据结论
搜索只使用 Calibre 缓存webserver/handlers/book.py 的 SearchBook.getTalebook 扩展字段必须在搜索结果上做并集。
作者页按单个 category name 查书webserver/handlers/meta.py 的 MetaBooks.get需要把输入名解析为规范名并扩展完整别名组。
Calibre 8.5.0 的作者模型只有 id/name/sort/link，没有别名字段或别名关系metadata_sqlite.sql；公开 author_data() 也只返回 name/sort/linkauthor_sort 是排序名，不是可检索的多值别名；别名仍归 Talebook 业务库。
Calibre 提供原生作者重命名/合并new_api.rename_items("authors", ...)重命名到已存在作者时复用目标作者 ID，并更新关联书籍的 author_sort、路径、dirty 状态与事件；Talebook 不重复逐书实现。
Calibre 数据不由 SQLAlchemy 管理webserver/CLAUDE.md别名归 Talebook 业务库，显式合并才调用 Calibre 公开 API。

5. 方案

结论：新增 book_aliases 和 author_aliases 两张 Talebook 表；统一服务负责规范化、分组和查找。读取路径只做扩展，写入路径沿用现有权限。作者合并先保存别名组，再用 Calibre 公开的 author_data() 解析作者 ID，并以一次 rename_items("authors", ...) 完成原生重命名/合并。

数据与接口

对象契约兼容策略
书籍别名book_id + normalized_name 唯一，保留展示名。旧书默认空数组；删除书籍时清理记录。
作者别名normalized_name 全局唯一并指向规范展示名。规范名自身也入组；冲突返回参数错误，不静默搬组。
书籍详情/编辑book.aliases: string[]，现有编辑接口接受同名字段。旧客户端忽略新增响应字段；未传 aliases 时保持不变。
作者定位GET /api/authors?name=<name> 返回 Calibre 数字作者 ID。保留现有按名称访问的 /author/<name> 页面；只读解析层将可变名称转换为资源 ID。
作者别名集合GET /api/authors/<id>/aliases；PUT /api/authors/<id>/aliases 完整替换别名表示。读取公开；PUT 需登录、编辑权限和管理员身份。
作者合并集合POST /api/authors/<id>/merges 创建一次显式合并并返回结果。仅管理员；与别名更新分离，不再用请求体 merge 开关改变同一路由语义。

处理顺序

  1. 输入统一去首尾空白、过滤空值并按 Unicode casefold 去重。
  2. 搜索先取 Calibre 结果，再并入书籍别名命中的 ID 与作者别名组对应的 ID。
  3. 作者分类把组成员折叠到规范名；作者详情查询组内所有名称并去重书籍。
  4. 合并时以 author_data() 将精确组成员解析为作者 ID，再交给 rename_items("authors", ...)；普通 Calibre 书沿用原生路径更新，外部索引书在调用期间临时清空 Calibre path，完成后恢复源文件映射，避免移动外部文件。

6. 影响、风险与回滚

影响范围

新增业务库表、两个 JSON 接口字段、搜索/作者分类读路径，以及书籍编辑、详情、作者页三处界面。

保持不变

Calibre 主字段、下载/阅读协议、现有 URL、私有书权限和未传新字段的客户端行为保持不变。

主要风险：全局作者合并会由 Calibre 原生 API 更新作者关系、author_sort 与普通书路径；因此限制管理员显式确认。外部索引书在调用前保存路径并在 finally 中恢复。别名表提交与 Calibre 不具备跨库事务；原生调用失败时保留无损的别名聚合，并返回本次受影响书籍 ID。
回滚：代码回滚后新增表不会影响旧版本；只删除别名记录即可撤销索引。作者合并属于显式元数据变更，回滚需用保存的别名组反向编辑，界面在确认前提示不可自动撤销。

8. 决策记录

  1. 2026-08-19：别名属于 Talebook 增强索引，不塞入 Calibre 主字段或自定义列，以保证现有书库可直接升级。
  2. 2026-08-19：别名聚合与作者合并拆为两个动作；聚合无损且即时生效，合并为管理员显式确认的写操作。
  3. 2026-08-19：作者别名全局唯一；普通保存遇到跨组冲突时拒绝写入，管理员显式合并时才吸收完整冲突组，避免同一输入不确定地路由到多个作者。
  4. 2026-08-29：复核 Calibre 8.5.0 数据模型与公开 DB API：原生没有作者别名字段，但已有作者 ID 重命名/合并能力；移除 Talebook 的逐书合并实现，改用 author_data() + rename_items("authors", ...)。
  5. 2026-08-29：作者别名 API 改为复数资源与数字 ID 层级：查询名称只负责解析 ID，别名以 GET/PUT 表示，合并以独立 POST 子资源表示；删除未发布的 /api/author-aliases/(.*)，不保留动作开关兼容层。
