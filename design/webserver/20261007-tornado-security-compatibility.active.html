Tornado 安全升级兼容修复

修复 PR #1072 的运行时兼容问题，保留静态文件的安全边界。

ACTIVE2026-10-07webserver需求来源：PR #1072 与开发者直接修复请求

1. 原始诉求与目标

开发者要求直接在 PR #1072 上修复已确认的破坏性兼容问题。Tornado 6.5.9 的 StaticFileHandler 新增属性由 initialize 设置，Talebook 的 BookDownload 与 BookReaderResource 跳过了该初始化，正常资源请求变为 500。静态根内的 logo 软链接还会因跨目录访问被拒绝。

目标是继续获得上游安全修复，使电子书下载、PDF 内联、OPDS 下载与 Readest EPUB 资源保持成功响应及既有权限、Range 和缓存语义，支持部署中已有的自定义 logo 目录，并保留中文错误说明。

2. 实现方案与确认边界

决策实现依据
依赖版本三个依赖文件统一使用 Tornado 6.5.10，更新锁文件中的 Tornado 包元数据；已有其他依赖保持原锁定版本。6.5.10 修复自定义 initialize 与新增属性的兼容问题，并保留 6.5.9 的安全修复。
处理器初始化两个处理器显式调用 StaticFileHandler.initialize(self, path="/")，随后执行既有 BaseHandler 初始化。保留已有由书目解析绝对路径的设计，避免依赖上游的类属性回退。
logo 软链接在静态 catch-all 前增加 /logo/(.*) 路由，以 html_path/logo 为静态根。静态根自身可以是部署维护的软链接；根下指向外部文件的链接、路径穿越仍由 Tornado 拒绝。无需扩大整个站点的允许目录。
中文错误说明BaseHandler.write_error 从 HTTPError.reason 读取说明，经 HTML 转义后写入正文；状态行仍由上游安全校验，调试栈输出委托父类。6.5.3 起状态行禁止不符合协议的字符，中文 reason 变为 Unknown；只恢复正文中的说明，不恢复危险状态行。
回归验证真实后端下载、EPUB 资源、权限与 Range 测试；独立静态路由测试覆盖正常 logo、普通静态文件、外部链接、穿越、缺失文件。使用已有 Calibre 测试镜像与当前源码，并挂载所需 Tornado 版本，避免重建大镜像。

设计边界已由开发者请求与上一轮兼容性复现确定：直接更新现有 PR 分支，不合并 PR；保持数据、配置及身份权限契约；补充安全边界与核心接口回归测试。

3. 影响范围、风险与回滚

涉及 pyproject.toml、requirements.txt、uv.lock、webserver/handlers/base.py、webserver/handlers/book.py、webserver/handlers/files.py 与 tests/ 的相关用例。spec/系统设置.md 补充自定义站点标识的资源边界；阅读与下载的既有产品规则不变，中文错误说明延续原有页面契约。

跨目录软链接仍可能影响其他自定义静态资源；只适配部署已支持的 logo 根目录。调用已有文件初始化不改变 BaseHandler 的认证与授权顺序。

本次不修改前端页面、交互、文案或布局。使用 interface-review full 审查完整分支改动及下载/阅读/标识的消费者；实际浏览器渲染不属于这次后端兼容修复的验证范围，最终记录审查覆盖与剩余限制。

回滚单位为本次修复提交，无数据库迁移。回退到 6.5.9 会重新引入初始化兼容风险；回退到 6.5 会失去安全修复。
