书籍工具改为按插件 ID 分发的统一接口

四个书籍工具各自在 handler 里注册专属路由，每加一个工具就要新增 handler 类和接口。本方案把它们收敛为 /api/plugins/<plugin_key>/tool、/tool/preview、/tool/run 三条通用路由，工具差异全部由插件自述。

状态：WIP 创建日期：2026-10-08 所属模块：webserver 影响范围：webserver/handlers/plugin_booktools.py、webserver/plugins/tool/、app/pages/plugins/、spec/插件/ 需求来源：Rex 在项目对话中的原话

1. 原始诉求

“优化一下 talebook 项目的插件系统：当前每个插件都要修改handler暴露独立的api接口，这不合理，应该是有统一的restfull的api，不要每新增插件都新增api”

插件平台的连接、五种动作、运行记录和额外功能已经是按插件 ID 或连接 ID 分发的通用接口；真正“每个插件一套接口”的是书籍工具（integrations.tool）：正文查找替换、TXT 编码修复、繁简转换、EPUB 美化各自有 2 到 3 条专属路由和对应 handler 类，handler 里硬编码了每个工具的参数、格式优先级、写回方式和新书后缀。

2. 目标与边界

目标

  • 所有书籍工具共用三条按 plugin_key 分发的路由，路由表中不出现任何工具名。
  • handler 不认识具体工具：格式优先级、参数白名单、写回方式、新书后缀、元数据同步、超时、审计摘要都由 provider 自述。
  • 新增书籍工具只需实现 TransformProvider 并在 register.py 注册，不改 handler、不加路由。
  • 保持权限不变：预览要求登录且逐书校验可见性，执行仅管理员并留下 PluginRun 审计，覆盖写回可回滚。

非目标

  • 不改动平台既有通用接口（连接、五动作、运行记录、/features/ 逃生舱、管理端按能力的测试接口）。
  • 不改动网络书库与 Venera 漫画接口：它们按书源能力分发，属于书源领域，不是“每插件一套”。
  • 不保留旧路由别名：前后端同仓同版本发布，保留别名等于保留“每插件一套接口”。
  • 不改变工具页的界面与交互。

4. 现状、根因与证据

观察权威证据结论
每个工具都有专属路由plugin_booktools.py routes()：text-replace/preview、run；txt-fixer/analyze、run；zh-converter/run；epub-beautify/presets、preview、run新增工具必须新增 handler 与路由
handler 硬编码工具差异UserZhConverterRun 内的方向、语言后缀与元数据同步；_epub_beautify_input 的 17 个字段工具语义泄漏到 HTTP 层
写回方式命名不一致繁简转换用 replace，其余工具用 overwrite统一为 new / overwrite，由 provider 声明可用集合
工具选择靠前端路由_tool_runtime(handler, manage_route) 用 ui.manage_route 反查 provider改为直接用 plugin_key 定位已启用连接

5. 方案

方案结论：HTTP 层只保留平台职责（定位插件、校验书籍可见性、挑选输入文件、临时目录、备份与回滚、入库、审计），工具语义下沉到 TransformProvider 契约。所有工具经同一组路由按 plugin_key 分发；未知插件、非工具插件、未启用、无可用格式、写回方式不被允许都返回统一的 booktools.failed。
Input/api/plugins/<key>/tool/run

请求体 {book_id, output_mode, suffix, params}

Guard定位与校验

已启用的 integrations.tool 连接；管理员；书籍可见；output_mode 属于 provider.output_modes

Coreprovider 自述

input_formats 挑文件，tool_input 白名单收敛 params，apply 生成结果

Output写回与审计

覆盖时备份并按 book_updates 同步元数据；另存时用 new_book_title_suffix 入库；PluginRun 记录 audit_fields

接口

方法路径权限说明
GET/api/plugins/<key>/tool登录返回 formats、output_modes、options（provider.describe()）
POST/api/plugins/<key>/tool/preview登录 + 书籍可见只读预览，替代原 preview / analyze
POST/api/plugins/<key>/tool/run管理员执行并写回，替代原各工具 run
GET/api/plugins/tools/books、/book-actions不变本来就是工具无关的通用接口，保留

关键决策

决策点选择理由放弃项
路由形态/api/plugins/<key>/tool[/preview|/run]与既有 /api/plugins/<key>/features/<action> 同构；单数名词，符合仓库 RESTful 约定/api/book/<id>/tool/<key>：描述接口与书无关，拆两处反而不统一
参数位置工具参数放 params，平台字段在顶层与 /features/ 一致；平台字段与插件字段不会撞名扁平请求体：无法区分平台字段与插件字段
工具差异归属扩展 TransformProvider 协议，内置工具由 TextTransformPlugin 提供默认实现契约校验在加载期就能发现缺失方法在 handler 里按 plugin_key 分支
兼容策略删除旧路由，前端同步迁移前后端同版本发布；保留别名与诉求相悖旧路由转发：仍需为每个工具维护一条路由
写回方式命名统一 new / overwrite繁简转换的 replace 与其余工具语义相同同时接受 replace：同一语义两个名字
 
POST /api/plugins/talebook.tool.zh-converter/tool/run
{"book_id": 12, "output_mode": "overwrite",
 "params": {"direction": "t2s", "use_a5": true, "convert_title": true}}

6. 影响范围、风险与回滚

影响范围

后端：webserver/handlers/plugin_booktools.py、webserver/plugins/runtime/interfaces.py、webserver/plugins/tool/ 四个 provider 与基类。前端：app/pages/plugins/ 四个工具页、app/utils/book-tools.ts、mock server。文档：spec/插件/插件平台.md（新增「统一接口」规则与 7.2 接口）、正文查找替换.md、TXT编码修复.md、繁简转换.md、EPUB美化.md（7.2 接口），document/PluginGuide.md。

保持不变

工具页界面与交互、权限模型、PluginRun 审计、覆盖写回的备份与回滚、数据库结构、插件 manifest 字段集合。

主要风险：外部脚本直接调用旧的 /api/plugins/tools/<tool>/* 会失效 → 发布说明列出新旧路由对照。繁简转换另存新书时现在也接受客户端 suffix，与其余工具一致；为空时仍按语言使用「（简体版）/（繁體版）」。
回滚：整体回退本次提交即可，无数据迁移与配置变更。
