阅读器评论改为宿主回调，并接入回复、赞踩与 BRS 同步

新版 candle-reader 不再直接请求任何后端，划线、评论、回复、赞踩、登录态与有声书都通过宿主回调交给 Talebook。Talebook 作为评论的权威存储，补齐回复、投票、分页与段落计数，并把公开评论、回复、赞踩和删除同步到 BRS。

状态：WIP 创建日期：2026-10-07 所属模块：webserver 影响范围：webserver/handlers/annotations.py、models.py、services/annotation_sync.py、plugins/annotation/brs.py、resources/book/creader.html、app/public/static/candle-reader；spec/划线笔记.md、spec/阅读器.md、spec/插件/BRS.md 需求来源：用户原话（见 1）；candle-reader PR #18

1. 原始诉求

“candle-reader 不要直接调用 brs，它只走 hook 调用 talebook 的。因此三个仓库都要一起改。”
“先提交。然后把有声书的也改成 hook。然后你去修改 talebook 里的相关代码。”

candle-reader（PR #18）已经把划线、文字评论、整书评论统一为一种记录，并新增评论抽屉、完整评论页、评论详情页、回复与赞踩；全部数据通过宿主注入的 annotation_callbacks 与 audiobook_callbacks 获取，契约写在 candle-reader 的 DESIGN.md。Talebook 的阅读页仍内嵌 v1.1.0 阅读器，并由宿主自己画了一套选字工具栏与笔记侧栏，需要换成新阅读器和回调。

2. 目标与边界

目标

  • 阅读页注入完整的评论回调与有声书回调，去掉宿主自绘的选字工具栏和笔记侧栏。
  • 笔记接口支持阅读器的查看范围（本段 / 本章 / 全书 / 我的）、全量排序后分页、段落评论计数、单条读取。
  • 新增回复（挂在主评论下，跟随主评论公开范围）与赞踩（每人每条一票）。
  • 新增整书评论类型 book_comment 与真实选区字段 range_cfi。
  • 删除主评论连同全部回复和投票真删除；删除第一层回复连同其下回复。
  • 公开评论、回复、赞踩和删除同步到 BRS（BRS 仓库同步改造）。
  • 保持不变量：Talebook 是唯一权威存储；私有记录永不外发；管理员没有读取他人私有内容的旁路。

非目标

  • 不对游客开放评论：游客在阅读器里只看到登录提示（见决策 1）。
  • 不改 Talebook 笔记页（/book/<id>/annotations）的界面与筛选；它继续只列顶层记录。
  • 不改有声书后端接口，只把阅读页改为通过回调调用。
  • 不迁移 BRS 旧数据（用户确认清空）。

5. 方案

方案结论：权威数据仍在 annotations 表：回复是带 root_id 的笔记行，投票放新表 annotation_votes。阅读页把阅读器回调一一翻译成现有 REST 风格的笔记接口；所有可见性、作者身份、级联删除都在服务端判定。同步沿用异步扇出，扩展为「更新 / 删除 / 投票」三种动作。

5.1 数据

表 / 字段说明
annotations.range_cfi真实选区；cfi 继续表示归属位置（文字评论为段落，跨段归属最后一段）
annotations.root_id回复所属主评论；顶层记录为空
annotations.reply_to_id回复对象；空表示直接回复主评论
annotations.thread_id所属第一层回复，由服务端根据 reply_to_id 推出
annotation_votesannotation_id、reader_id、value（1 / -1）；唯一约束 (annotation_id, reader_id)
ANNOTATION_TYPES增加 book_comment；旧 chapter_comment 作为该章公开评论展示，不挂段落

5.2 接口

方法与路径说明

5.3 可见性规则（服务端强制）

  1. 所有评论接口要求登录，且书籍须可访问（沿用 @auth 与书籍可见性校验）。
  2. 私有记录及其全部回复，只有主评论作者可见；对他人按不存在处理（含读取、回复、投票）。
  3. 回复没有独立公开范围，跟随主评论；公开改私有后已有回复只有主评论作者可见。
  4. 只能修改、删除自己的记录；删除主评论连同全部回复与投票，删除第一层回复连同其下回复（决策 2）。
  5. 划线固定私有；私有记录不接受投票和回复。

5.4 阅读页

  • creader.html 换用新版 candle-reader 打包产物，去掉宿主自绘的选字工具栏、笔记侧栏和旧社区接口的伪造响应。
  • 注入 annotation_callbacks：user 取模板里的当前读者；login 跳转登录页并带回跳地址；游客调用列表类回调时以 need_login 拒绝，阅读器显示登录提示（candle-reader 同步支持该约定）；其余回调映射到 5.2 的接口。
  • 注入 audiobook_callbacks，映射到现有有声书接口，行为不变。

5.5 BRS 同步

  • 公开顶层评论与回复：沿用异步扇出；已有副本时调用 BRS 更新接口，不再重复新增。回复携带主评论与回复对象在 BRS 的 id；主评论尚未同步时记为同步失败，可重试。
  • 删除：删除前记下各副本身份，提交后异步调用 BRS 删除接口（BRS 侧级联删除回复）。
  • 投票：投票人自己的 BRS 连接异步推送；目标尚未同步到 BRS 时跳过并记日志。
  • 插件能力接口新增可选的 delete_annotation 与 push_vote；不实现的来源直接跳过。
  • 外部身份按实例匹配：回复与投票只引用同一实例上的副本（优先同一连接，其次 endpoint 相同的其他读者连接），别的实例上的 id 不用于当前连接。
  • 写入途中撤回：外部写入返回后复查本站记录，若已删除、改为私有或映射已解除，立即删除刚写出的副本，并停止向其余来源扇出。
  • 重新公开：主评论由私有改回公开时，按创建顺序把其下回复在主评论之后重新入队。
  • BRS 仓库配套新增更新、删除、投票接口，记录整书评论类型，清空旧数据（单独改造，见 BRS 仓库）。

6. 影响范围、风险与回滚

影响范围

webserver 笔记接口、模型、同步服务、BRS 插件；阅读页模板与 candle-reader 静态产物。产品行为变化涉及 spec/划线笔记.md（回复、投票、整书评论、级联删除、新接口）、spec/阅读器.md（新阅读器与回调）、spec/插件/BRS.md（同步回复、投票与删除）。

保持不变

笔记页与跨书管理接口的行为、导入与回滚、私有默认值、管理员无私有旁路、有声书后端接口。

主要风险：级联删除会删掉他人的回复 → 仅主评论作者可触发，删除前阅读器有确认提示，测试覆盖。分页排序依赖「自己的在前」的 SQL 排序 → 用全量排序后的偏移游标，测试覆盖跨页不重不漏。BRS 不可用 → 同步失败只记录状态，不影响本站写入。
回滚：代码回滚即可；新增列与新表保留不影响旧代码（旧代码不读取它们）。阅读页可回退到旧模板与旧静态产物。

8. 决策记录

  1. 2026-10-07：游客只看到登录提示，不开放匿名浏览公开评论（保持 Talebook 现行「公开 = 登录且有阅读权限」规则）。
  2. 2026-10-07：删除主评论时，其下他人的回复与投票一并真删除（回复从属于主评论，spec 中写明为例外）。
  3. 2026-10-07：旧 chapter_comment 作为该章公开评论展示在本章与全书范围，不挂段落、不计入段尾气泡。
  4. 2026-10-07：回复与赞踩本次一起同步到 BRS；BRS 仓库配套改造，旧数据清空。
  5. 2026-10-07：阅读器只通过回调访问数据（candle-reader 仓库已实施，契约见其 DESIGN.md）；有声书同样改为回调。
