首页书籍推荐优化

根据读者兴趣发现下一本书，没有个人兴趣记录时先推荐热门书籍。

2026-10-01webserverACTIVE需求来源：开发者反馈

原始诉求

开发者反馈首页推荐缺乏相关性，希望按阅读兴趣和书库质量进行推荐。现有首页从可见书籍中随机抽样，再按 ID 排序，未使用个人偏好。

目标与边界

  • 使用现有本地元数据和当前读者的收藏、想读、阅读状态；不接入外部模型、不新增跟踪或库表。
  • 推荐排除正在读、已读和已有阅读进度的书，优先发现未读内容；想读和收藏仍可推荐。
  • 游客或无兴趣数据时优先按访问量加两倍下载量排序；热度相同时按评分、入库时间和 ID 决定，不因评分或新鲜度让冷门书挤掉热门书。没有全站热度时回退评分和入库时间；排序可复现。
  • 有兴趣记录时适度分散作者和系列；书少时允许推荐不足，不用已读书填满。仅打开过书但没有阅读进度，不视为已开始阅读。
  • 保留 random_books、random_books_count、random 参数与 MAIN_PAGE_RANDOM_COUNT 的兼容性，零值隐藏，并保留管理界面已有的 768 本推荐数量选择，不增加 200 本推荐上限。最近上架继续独立返回，允许与推荐重叠。

设计决策与澄清

2026-10-03 开发者补充：没有浏览记录时先推荐热门书籍。PR 尚未合并或上线，作为同一工作的反馈迭代，先将唯一方案恢复 WIP；冷启动改为热度优先的独立排序，收藏、想读和有效阅读状态出现后仍使用个人兴趣排序。本地没有单独的个人浏览历史，故以现有可见书籍的收藏、想读、已读和在读记录判断可用兴趣信号；仅打开标记或无效/不可见记录不构成有效兴趣。

已向开发者提供“个人兴趣优先 / 全站优质热门 / 兴趣与探索各半”的选择；按已授权的优化范围，默认个人兴趣优先。仓库要求的 grill skill 未随仓库或本会话安装；此次用直接澄清与本节逐项记录完成设计边界判断。

问题决定依据
兴趣信号收藏 5、想读 3、已读 2、在读 1；最近 100 条有效记录，并随 180 天尺度衰减主动收藏比打开或浏览更能表达偏好
匹配维度系列、作者、标签本地 Calibre 已有结构化元数据
热度作用冷启动按原始热度优先；个性化模式才对数缩放并封顶无记录时先看热门，有兴趣时热度不压过个人匹配
权限候选及兴趣种子均先过滤不可见书，查询仅限当前读者私藏不影响无权访问的读者结果
稳定性无随机抽样，同分按入库时间和 ID 决定刷新不再无依据变动

实现方案

  1. 在独立推荐服务中批量读取 Calibre 缓存字段和业务库的聚合计数；不逐书查询数据库或读取书籍文件。
  2. 从当前读者最近的有效兴趣记录构建加权作者、标签、系列画像，过滤未知作者及空值。
  3. 没有可见书籍的有效兴趣记录时，先过滤已开始或已完成阅读的书，再按访问量 + 2 × 下载量降序选择；热度同分按评分、入库时间、ID，冷启动不使用作者/系列惩罚打乱热门顺序。存在兴趣记录时，为未读候选计算兴趣匹配（系列 12、作者 10、标签 8）、质量（评分最多 6）、热度（对数缩放且最多 2）和新鲜度（最多 1）得分；未读收藏另加 6，想读另加 4。重复作者扣 4、系列扣 6，避免堆叠同一作者或系列，在高分候选中补充作者和系列代表书，防止高分候选全被同一作者占据；再用重复作者/系列惩罚逐次选择；使用惩罚只增不减的堆进行惰性重排，避免大推荐数量逐次扫描所有候选。
  4. 首页按推荐顺序加载和格式化选中的书；最近上架按入库时间降序，不再随机抽样。

影响范围：webserver/services/recommendations.py、webserver/handlers/book.py、tests/test_recommendations.py、spec/书库.md。前端 app/pages/index.vue 的推荐和最近上架区域保留原有布局；新增 visible_books_count 与 recommendations_enabled 响应字段，用于区分“无未读推荐”与“空书库”并隐藏禁用的推荐区域。两种语言的数量设置改称“推荐图书数量”，不修改配置键。相关前端回归位于 app/test/e2e/home.spec.ts 。

风险与权衡

偏好依赖标签、作者和系列元数据质量；没有评价人数，因此不能将单个评分解释为可靠的大众口碑。热门计数是全站聚合数据，无法消除历史曝光偏差。候选扫描为线性复杂度，采用 Calibre 批量缓存读取与有界重排，不新增持久缓存，避免跨读者串用。首页每次返回都重新请求，避免更新收藏或阅读状态后仍展示旧结果；SQL 查询不按全部书籍构造 IN 参数，避免大书库超过 SQLite 参数限制。首页推荐可能为空，即使书库里仍有已读书；界面区分无未读推荐与空书库，并隐藏配置为零的推荐区。权重是初始启发式，实际偏好仍需通过使用反馈校准。
