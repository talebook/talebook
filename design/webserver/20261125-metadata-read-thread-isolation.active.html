修复元数据流式搜索的连接会话串用

流式查询的后台线程不再读取请求线程的 SQLAlchemy 连接对象。

状态：ACTIVE 创建日期：2026-11-25 所属模块：webserver 需求来源：#1101

原始诉求

修复「从互联网同步书籍信息」并行流式搜索偶发的 PluginConnection deleted，让处于有效状态的来源正常返回结果。

目标与边界

失效或离开请求会话的 ORM 属性不得在搜索线程求值。保留现有连接级重试次数、退避、有界线程池、超时和请求线程上的审计；不改变插件接口、前端交互、配置字段和数据库结构。

方案

在准备阶段读取独立的连接配置快照，提供给后台重试器。重试器不读取提供器上下文中合并的安装级或请求级配置，避免悄悄改变配置优先级。搜索任务只捕获可调用对象；原连接和审计记录保留在请求线程侧。相比为 worker 新建数据库会话，此方案不新增查询，不引入 ORM 生命周期和跨线程写入成本。

影响与风险

影响元数据搜索和复用该重试桥的插件读取。已派发操作沿用准备时的策略，后续请求仍会重新读取配置。无界面变化，不影响 元数据源 的产品规则或公开接口。

测试结果

  • 修复前，新添的 external_pool_read_survives_expired_connection_config 两个分支均失败：过期属性在工作线程触发 SQLite 跨线程查询。
  • 修复后，python -m pytest -q tests/test_plugin_capability_lookup.py tests/test_plugin_runtime.py：58 项通过。使用真实 SQLAlchemy/SQLite 与线程池、受控外部来源，断言查询返回结果、退避、重试次数及审计。
  • make lint-py、make check-design、make check-spec 和 git diff --check 均在提交前检查。
  • 未连接真实豆瓣、百度百科，未进行浏览器或完整本地 Calibre 集成测试；本次仅恢复原有后端行为，无 UI 实现变更。
