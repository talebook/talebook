Annotation 数据域与服务端 API

ACTIVE 创建日期：2026-08-14 所属模块：webserver 需求来源：Multica TB-42

1. 原始诉求

为微信读书、Readwise、Web、Moke 与 Readest 等笔记插件提供统一服务端契约：个人高亮、笔记与书签可幂等导入、查询、导出和按来源删除；无法精确定位的记录仍可按章节展示；章评使用独立数据域；管理员不能借普通接口读取其他用户的私密正文。

2. 目标与边界

  • 个人 annotation 以当前登录用户为强制租户边界，书籍访问同时服从现有 can_view_book 权限。
  • 支持 highlight、note、bookmark，允许 cfi=NULL 并保留章节、引用文本与来源位置。
  • 支持客户端 client_id 幂等，以及 owner + book + source + external_id 来源幂等。
  • 章评写入独立表；其正文按书籍可见性读取，写入、修改和来源删除仅限导入者，不复用个人 annotation 的私密查询。
  • 本次只提供后端数据与 JSON API，不改页面和阅读器；外部插件连接管理由后续插件底座承接。

3. 数据模型

book_annotations用户私密数据。保存内容、定位、来源标识、远端时间与人工修改时间。
chapter_comments章评独立数据。读取服从书籍可见性，写操作归导入者。
readers / Calibre books用户外键由认证库维护；书籍存在性和可见性继续由 Calibre 与 Item.scope 判定。
分组关键字段约束与说明
身份reader_id、book_idannotation 的所有读写固定到当前用户；chapter comment 的 reader 是导入者。
内容kind、text、refer_text、colorkind 仅允许 highlight / note / bookmark；正文不进入管理接口。
定位cfi、chapter、source_positionCFI 可空；章节与来源位置提供降级展示。
来源source、external_id、connection_id、run_id、raw_hash、remote_updated_at与插件 source record / connection / run 对齐，均可随 API 返回。
冲突user_modified_at、update_time人工 PUT 后，后续来源 upsert 默认只刷新来源元数据，不覆盖正文。

4. API 契约

方法路径行为
GET / POST/api/book/:book_id/annotations列出当前用户该书记录；按 client_id 或 source + external_id 幂等 upsert。
PUT / DELETE/api/book/:book_id/annotations/:id仅 owner 修改或删除；PUT 标记人工修改保护。
GET / DELETE/api/annotations按 book/source/run/connection 查询；DELETE 至少提供一个来源筛选，默认保留人工修改记录。
GET/api/annotations/export返回带 schema version 和导出时间的 JSON 数据集，接受相同筛选。
GET / POST/api/book/:book_id/chapter-comments按书读取章评；登录用户可幂等导入。
PUT / DELETE/api/book/:book_id/chapter-comments/:id仅导入者修改或删除。
GET / DELETE/api/chapter-comments按 source/run/connection 查询或来源清理；不会触及 annotations。
GET/api/chapter-comments/export按相同来源条件导出导入者的章评，并提供独立 schema version。

所有端点返回 HTTP 200 的 Talebook JSON 错误契约；写接口使用 @js + @auth。章评集合读取也要求登录，避免在缺少产品公开策略前扩大公开面。

5. 幂等与冲突规则

  1. 有 external_id 时优先按 owner + book + source + external_id 查找；否则按 owner + book + client_id 查找。
  2. raw_hash 相同视为重复投递；早于现存 remote_updated_at 的来源事件视为 stale，不回滚内容。同一远端时间允许来源修正后重新解析。
  3. 通过单条 PUT 修改内容后写入 user_modified_at；来源 upsert 返回 conflict_protected=true，保留内容但允许更新 connection/run/hash/remote time，便于审计本次同步。
  4. 来源批量删除默认跳过人工修改记录，显式 include_modified=true 才删除；返回删除数与保护数。
普通管理接口不增加 annotation 查询能力。管理员调用 annotation API 时仍只以自己的 reader_id 查询，不能越权读取其他用户正文。

6. Migration

补强 compare_and_migrate：先按 SQLAlchemy metadata 创建缺失表，再沿用现有逻辑为既有表补列。新表由 metadata 一次性创建，因此唯一约束、索引和外键随 migration 落地；已有表不做破坏性重建。

8. 风险与兼容性

  • 旧 SQLite / MySQL 通过缺失表创建获得新域，不修改 Calibre metadata 数据库。
  • 当前连接和 run 只是稳定字符串引用；插件底座未来可在不改变记录结构的前提下增加实体表和外键映射。
  • 章评的跨用户可见性被限制在登录且可查看该书的用户；若产品未来要求完全公开或完全私密，需要独立策略变更。
  • 本次仅新增服务端数据、迁移和 JSON API，没有页面、交互、文案或其他界面消费者变更，因此豁免 interface-review；剩余风险是外部插件仍需按本契约完成接入。
