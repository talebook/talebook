Annotation 数据域与服务端 API

ACTIVE 创建日期：2026-08-14 所属模块：webserver 需求来源：Multica TB-42

1. 原始诉求

为微信读书、BRS、Calibre、Web、Moke 与 Readest 等笔记来源提供统一服务端契约。2026-08-15 评审确认：Talebook 的 annotations 是唯一权威内容表；章评也是 annotation 类型，不另建内容表；Calibre 等系统只是可导入、可回写的 source。用户新建或修改非私有 annotation 后，由后台任务异步写入所有已注册 source。

2. 目标与边界

  • annotations 保存权威正文、位置、隐私和 owner；外部系统不得成为内容主表。
  • 支持 highlight、note、bookmark、chapter_comment，允许 cfi=NULL 并保留章节级定位。
  • 私有记录只对 owner 可见；非私有记录对所有有该书阅读权限的登录用户可见，但只有 owner 可修改或删除。
  • annotation_sources 只保存一条权威记录在各外部系统中的映射和同步状态，所有外部引用字段统一使用 source_ 前缀。
  • 本次提供 source writer 注册和异步分发契约；BRS、微信读书、Calibre 的具体认证与网络适配由对应插件注册 writer，不在本任务内硬编码。

3. 数据模型

annotationsTalebook 权威内容。私人笔记和公共章评使用同一生命周期。
annotation_sources一对多外部副本映射。Calibre、微信读书、BRS 都只是 source。
source writers非私有记录提交后异步扇出；失败状态留在映射表，权威内容不回滚。
分组关键字段约束与说明
权威身份annotations.id、reader_id、book_id、client_id(reader_id, book_id, client_id) 保证 Talebook 客户端幂等；书籍仍是跨数据库逻辑引用。
权威内容annotation_type、content、quote_text、color、author_name章评用 chapter_comment 类型表达，不再创建 chapter_comments 表。
位置与隐私cfi、chapter、is_privateCFI 可空；is_private=true 为安全默认值，且不会向外部 source 扇出。
外部身份source_name、source_connection_id、source_annotation_id位于 annotation_sources；外部唯一键为三者组合，每条 annotation 在同一 source connection 只有一个副本。
外部状态source_run_id、source_position、source_raw_hash、source_updated_at用于来源幂等、旧事件保护和定位追踪，避免无前缀字段被误认为 Talebook 权威属性。
同步状态source_sync_status、source_synced_at、source_sync_error状态为 pending / synced / failed；外部失败只更新副本状态，不回滚 annotations。

4. API 契约

方法路径行为
GET / POST/api/book/:book_id/annotationsGET 返回 owner 私有记录及该书公共记录；POST 按 client_id 或 source 三元身份幂等 upsert。
PUT / DELETE/api/book/:book_id/annotations/:id仅 owner 修改或删除；非私有内容更新后再次异步扇出。
GET / DELETE/api/annotations仅管理当前用户权威记录；来源筛选字段均为 source_*。DELETE 来源筛选只解除匹配 source 映射，不删除权威正文。
GET/api/annotations/export导出 Talebook 权威记录以及每条记录的 sources 映射列表。

不再提供 /api/*/chapter-comments 路由。创建 payload 使用 annotation_type、content、quote_text、is_private；来源导入额外携带 source_name、source_connection_id、source_annotation_id 等统一前缀字段。

5. 幂等与冲突规则

  1. 有 source_name + source_connection_id + source_annotation_id 时优先按 source 映射查找；本地创建则按 owner + book + client_id 查找。
  2. 早于现存 source_updated_at 且 hash 不同的来源事件视为 stale，不回滚权威内容。
  3. 通过 Talebook PUT 修改内容后写入 user_modified_at；后续来源导入只刷新该 source 映射并返回 conflict_protected=true。
  4. 来源清理删除的是 annotation_sources 映射。权威 annotation 只能通过单条 owner DELETE 删除。
管理员不会获得读取他人私有正文的旁路；公共 annotation 也必须先通过该书现有可见性校验。

6. 异步 source 扇出

  1. handler 先提交 Talebook 权威事务，再把 annotation id 放入 AnnotationSyncService 队列。
  2. 服务枚举插件注册的 source writer；为每个 writer upsert 一条 pending 映射，然后调用 writer。
  3. 成功后记录外部 id、hash、远端时间并标记 synced；异常写入 failed 与错误摘要，其他 source 继续执行。
  4. 私有 annotation 不入队；来源导入可排除原 source，避免回环，同时仍可扇出到其他已注册 source。

7. Migration

PR 尚未合入且旧新表均未发布，因此直接以最终模型创建 annotations 与 annotation_sources，不为草稿中的 book_annotations / chapter_comments 增加兼容迁移。compare_and_migrate 仍先创建缺失整表，确保唯一约束、索引和 FK 一并落地。

9. 风险与兼容性

  • 外部写入不是数据库事务的一部分，允许短暂最终一致；pending / failed 状态用于观察和后续重试。
  • 删除向外部 source 的传播和持久化重试调度暂不在本任务内，后续插件实现必须补齐。
  • book_id 仍是跨用户库与 Calibre 库的逻辑引用，数据库无法建立 FK。
  • 本次仅调整后端数据、迁移与 JSON API，没有页面、交互或文案变化，因此豁免 interface-review；外部消费者必须切换到新字段名。
