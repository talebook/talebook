Request

原始诉求与目标

原始诉求

在当前分支中合并 PR #916 与 PR #923 的优点，形成优势互补的实现；提供两版 Skill，一版兼容地直接使用原有 API，另一版使用新加入的 /mcp。

成功标准

  • 两个 Skill 有独立名称、配置、脚本和参考文档。
  • API 版不要求升级服务端；MCP 版默认关闭且可显式启用。
  • 危险操作、凭据、重定向和外部内容均有明确边界。
  • 协议、部署、CLI 与关键业务能力均有自动化测试。
Decision record

两个 Skill，不做隐式自动降级

talebook-api

原有 API 兼容版

  • 使用 Guest 或 HTTP Basic Auth。
  • 覆盖查询、上传下载、阅读状态、网络书源及管理员命令。
  • 管理写入、删除、外发操作必须显式确认。
  • 限制跨域重定向，预览和错误输出中脱敏凭据。
talebook-mcp

内置 MCP 版

  • 使用独立 Bearer Token，仅授权固定工具白名单。
  • 覆盖检索、阅读状态、元数据和网络书库核心流程。
  • 不暴露删除、用户、系统设置、邮件或任意原始请求。
  • 提供协议发现和结构化结果，适配标准 MCP 客户端。

边界决策

不让一个 Skill 在运行时悄悄切换传输方式。调用者应显式选择兼容版或 MCP 版，从名称、配置和权限上都能判断当前使用哪条通道。MCP Token 仍映射到一个启用的管理员身份，因此 MCP 工具集保持最小化，并在文档中明确 Token 的部署级权限性质。

Security gates

凭据不混用，危险能力不扩散

API 版门禁

  1. 解析站点并拒绝内嵌凭据、非 HTTP(S) scheme。
  2. Basic Auth 只发送给同源地址，跨源重定向拒绝。
  3. 管理员命令调用前验证当前用户身份。
  4. 写入、删除、外发先输出脱敏预览；只有显式确认后执行。

MCP 版门禁

  1. 未配置 Token 时端点返回禁用状态。
  2. 固定时间比较 Bearer Token，不在管理设置接口回传。
  3. 拒绝跨源浏览器请求，只允许固定工具集合。
  4. 控制分页、批量数、阅读正文长度与进度载荷大小。
