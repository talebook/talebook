01 / 原始诉求与共同决策

manifest 与音频一起创建新版本

“manifest 肯定也要创建新版本啊。”

用户确认的版本语义如下：用户可见版本以 edition revision 为单位；任务重试只是内部 attempt，不增加版本号。生成成功后得到候选版本，仍由管理员显式发布；失败或取消的 attempt 不替换候选版，也不计入历史备份数量。

  • 失败 attempt 继续使用现有 AUDIOBOOK_FAILED_TEMP_DAYS，默认保留 7 天供排障。
  • 重试发现完整、可校验的暂存结果时直接继续提交；部分结果交给 Voicebook --resume 续跑；无效结果才重新生成。
  • 不新增数据库字段、迁移、管理命令或 Voicebook 子命令。

02 / 缺陷证据

内存基线无法跨越取消、异常与进程死亡

当前单章修订在调用 Voicebook 前，从候选目录的 manifest.v2.json 读取完整基线到 Python 内存；Voicebook 随即把同一文件改写成所选章节清单。只有命令正常返回且合并成功时，Talebook 才把完整清单写回。

中断点磁盘状态重试后风险
生成完成后收到取消只剩所选章节 manifest残缺文件被当成新基线
Voicebook 退出后工作进程死亡内存基线消失租约回收后无法恢复全章集合
合并或落盘异常Voicebook 输出已覆盖原文件失败重试可以“成功”完成残缺版本

现有纯函数测试只证明“完整基线 + 单章结果”能够合并，没有覆盖基线在磁盘上已经丢失的真实恢复路径。

03 / 存储模型

两条轨道，只在校验门后交汇

Edition revision

  • 当前 manifest 始终完整且可读
  • 旧章节资产保持不可变
  • 管理员发布前不影响线上版
  • 通过 manifest_path 指向已提交清单
VALIDATE + COMMIT

Job attempt

  • Voicebook 只写 job 暂存目录
  • 保存生成中的 manifest 与缓存
  • 取消、失败和租约恢复可续跑
  • 不成为用户可见版本

目录约定

edition/current复制自来源版本的完整 manifest
＋
jobs/{id}/revision-outputVoicebook 暂存 manifest、章节与 timeline
→
validate格式、章节集合、文件存在性与路径安全
→
edition/versions/job-{id}原子提交的不可变新资产
＋
edition/manifests/job-{id}.v2.json新的完整候选 manifest

04 / 状态与恢复

切换指针是最后一步，所有路径都可幂等重放

  1. 修订任务从 edition.manifest_path 读取当前完整基线，但绝不修改该文件。
  2. Voicebook 在 job 暂存目录生成；重试时带 --resume，复用完整章节与缓存。
  3. Talebook 校验生成 manifest 的格式、章节选择、相对路径和实际文件；单章结果与完整基线合并，整本结果必须保持相同章节集合。
  4. 新资产先复制到临时版本目录，再通过目录重命名原子提交；新完整 manifest 使用临时文件原子替换。
  5. _finalize() 再次比较新旧章节集合，写入章节记录并更新 edition.manifest_path；数据库事务完成前，旧指针保持有效。
  6. 管理员显式发布候选 edition 后，旧 published edition 才进入 historical；原有备份保留与清理策略不变。
恢复场景处理不变量
取消任务进入 cancelled；暂存结果保留供显式重试edition 指针不变
Voicebook 中途失败任务进入 failed；重试使用 --resume残缺 manifest 不进入 edition
提交前进程死亡租约回收后重放校验与提交旧版本持续完整
资产目录已提交、数据库未提交识别确定性的 job-{id} 目录并幂等继续不会产生用户可见重复版本
章节集合或资产校验失败硬失败并保留诊断产物；显式重试先归档无效 manifest，再强制重建禁止残缺版本变为 ready/published

05 / 边界与兼容性

修复生命周期，不把内容逻辑拉回 Talebook

  • Voicebook：继续负责从现有剧本生成所选音频、timeline 和 v2 manifest；无需新增命令或感知 Talebook 版本。
  • Talebook：负责输出隔离、路径验证、完整清单合并、版本提交、候选发布和恢复。
  • 历史数据：不迁移、不重写；已有 edition 的旧 manifest.v2.json 仍可读取，新修订成功后才使用版本化路径。
  • API / UI：接口和交互保持不变；任务完成后仍显示候选版，管理员决定发布。
  • 清理：历史 edition 按现有备份数显式清理；失败 attempt 按现有 7 天临时策略清理。
