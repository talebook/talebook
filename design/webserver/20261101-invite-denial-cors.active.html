TB-445 · INT-01

邀请拒绝响应的跨源一致性

创建日期：2026-11-01 · 所属模块：webserver · 状态：ACTIVE

需求来源：TB-443 / TB-445 当前 INT-01 修复阶段；固定起点 32f8109f2daab34be84495ed2aac998a1c48b7aa。

原始诉求与目标

Moke Web 首次读取真实邀请模式书库时，公共拒绝响应缺 CORS，浏览器不能读取 not_invited，也无法进入访问码表单。本轮恢复该既有流程，不授予邀请、账号或管理权限。

已核定的决策与边界

现有 @js 响应反射 Origin（缺省为 *），允许 credentials，未发现全局可信来源白名单。这是既有宽松 API 策略，不能作为可信来源证明。只将相同响应头用于固定公开的邀请拒绝 envelope，不推广到 prepare、默认头、异常、其他早退或敏感响应；不改 Cookie、TLS、OPTIONS 或客户端。

本轮不修 SELF-01、不改 Moke/Reader/依赖；原生/独立物理 LAN 等已有证据不代替此路径。

实现方案与影响范围

  1. 仅在 BaseHandler.send_error_of_not_invited 写入 Access-Control-Allow-Origin、Access-Control-Allow-Credentials 和 Cache-Control，保留 HTTP200、精确 not_invited JSON 与 Finish。
  2. OPDS、下载和封面的独立401覆盖不改；升级跨源写保护不改。
  3. 补邀请挑战、welcome、无Origin、权限、其他早退/原始协议与预检边界回归。

影响 spec/用户.md 的邀请模式规则；产品仅变更 webserver/handlers/base.py，另有针对性 tests/test_invite_cors.py。

风险与兼容

反射来源策略原已存在，本补丁只公开无敏感字段的拒绝状态。可读拒绝不等于授权；跨站Cookie、后续预检及认证能力仍依赖原有浏览器/服务器策略。不会声称其严格隔离或兼容所有跨站部署。
