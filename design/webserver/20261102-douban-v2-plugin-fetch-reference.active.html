豆瓣V2 插件详情取用 provider_value 修复

2026-11-02 · ACTIVE · 来源 talebook#1060（外部 issue）

原始诉求

talebook#1060：书籍页「从互联网同步书籍信息」选到豆瓣候选后点「设置」，提示「未获取到所选记录，请重新搜索」；百度百科、新华书店等其他来源正常。多名用户复现，且指出该问题从某个版本起出现，回退到更早版本（调用旧 douban-api）则正常，当前各版本均复现。grill 技能在本仓库未找到，设计边界按 issue 描述、现有代码契约与 2026-11-01 的 PR 自动化授权确定。

目标与影响范围

根因：豆瓣(V2) 现以 webserver/plugins/meta/douban_v2/plugin.py 的 DoubanV2Provider（MetaSourceMixin）注册为通用插件来源。书籍页选中候选后走 book.py 的通用插件分支 _plugin_metadata_detail → PluginRuntime.read_many(..., "get_metadata", provider_value) → MetaSourceMixin.get_metadata(external_id, context) → DoubanV2Provider._fetch(external_id, context)，这条路径只收到 provider_value 和 context，没有原书 mi。旧版 _fetch 直接 self.get_metadata_by_provider(external_id)，mi=None 时 get_metadata_by_provider 的 query = (mi.isbn or mi.title) if mi else None 必为空，函数立即 return mi（即 None），_plugin_metadata_detail 把空结果当「插件返回空」，抛 metadata.not_found，book.py 映射成「未获取到所选记录」——与用户看到的提示一致，且与 tests/test_meta_provider.py 现有用例（全部手工传入 mi，从未覆盖 _fetch 路径）吻合，是测试空白。book.py 中 elif provider_key == douban_v2.KEY 的旧硬编码分支仍存在但已不会被当前搜索结果触发（搜索结果的 provider_key 是 manifest id talebook.meta.douban-v2，不是 douban_v2.KEY 字符串），故此修复只改通用插件路径，不动该分支（避免影响旧值兼容）。影响 webserver/plugins/meta/douban_v2/plugin.py（DoubanV2Provider._search/_fetch）与 tests/test_meta_provider.py，不改 API 路径、数据库结构、页面与产品规格；spec/元数据.md/spec/插件/元数据源.md 已经写明「用户从候选中选择后套用」是预期行为，本次是让实现符合既有规格，不需要改 spec。webserver/plugins/meta/neodb/plugin.py 的 _fetch 有完全相同的缺口（同样丢弃 mi），但 issue 只涉及豆瓣、NeoDB 默认未启用且无用户报告，本次不处理，留作后续独立修复。纯后端改动，不涉及任何页面、交互或可视结果，故依据 AGENTS.md 的豁免条款不执行 interface-review，仅在此记录判断依据：改动只影响 _search/_fetch 内部返回值的编码方式，前端照旧把 provider_value 当不透明字符串传回，无界面可感知差异。

方案

参照同一文件家族里百度百科 BaiduBaikeProvider 已验证过的做法（design/webserver/20260914-refer-mapping-results.active.html）：让 _search 阶段把重搜所需的查询词和豆瓣条目 id 一起编码进不透明的 provider_value，_fetch 阶段解码后还原出等价的查询上下文，不再依赖外部传入的 mi。

具体改动：DoubanV2Provider 新增 REFERENCE_PREFIX = "douban_v2:v1:"；_search 在拿到 self.search(...) 结果后，把每条结果的 provider_value 改写成 REFERENCE_PREFIX + json.dumps({"id", "isbn", "title"})；_fetch 校验前缀、JSON 结构、字段类型与长度（id 必须是 1~20 位数字字符串，title 非空且不超 512 字符，isbn 可空但不超 64 字符；任一校验失败直接返回 None，不发请求），通过后用 types.SimpleNamespace(title=title, isbn=isbn, cover_url=None) 构造一个只需具备 get_metadata_by_provider 实际读取的三个属性（isbn/title/cover_url）的轻量替身，调用现有 get_metadata_by_provider(item_id, mi) 复用未改动的重搜/匹配/构建逻辑。不引入 calibre 依赖（get_metadata_by_provider 本身不要求真正的 calibre Metadata 对象），也不改该方法签名，book.py 里仍直接传真实 mi 的硬编码分支不受影响。

验证结果

环境限制：本仓库 make pytest/make test 走 Docker 镜像（内置 calibre），当前沙箱没有 Docker daemon；pip install -r requirements.txt 中 quickjs 需要编译 CPython 扩展，沙箱没有可用的 python3-dev（apt 源里没有候选包），因此任何会触发 import webserver.plugins.register（test_meta_providers.py、test_plugin_runtime.py、test_plugin_contract.py 等）的测试在本地都在 collection 阶段因 ModuleNotFoundError: No module named 'quickjs' 失败，与本次改动无关，未能在本地验证；风险：register.py 侧的契约测试（test_plugin_contract.py 对 manifest/协议的检查）未覆盖本次改动，需要 CI 的 Docker 环境补充确认。已执行并全部通过的部分：在裸 venv（pip install 除 quickjs 外的全部 requirements.txt + requirements-test.txt）下 pytest tests/test_meta_provider.py -v → 7 passed（含新增 TestDoubanV2ProviderReferences 两个用例：test_search_reference_round_trips_through_fetch 还原 isbn/title 后重搜、匹配、成功返回候选；test_legacy_and_malformed_references_require_a_new_search_without_http 覆盖旧裸 id、前缀版本不符、非 JSON、非对象、id 非数字字符串、title 为空、路径穿越式 id、超长字符串八种畸形输入，断言均返回 None 且不发出任何网络请求）；额外手写了一段不经 mock 框架的最小复现脚本，证实旧实现在同样输入下返回 None（对应用户看到的「未获取到所选记录」），新实现返回候选标题。ruff check/ruff format --diff 对 webserver/plugins/meta/douban_v2/plugin.py 与 tests/test_meta_provider.py 均通过。未改动前端代码，未执行 npm run lint。

风险

新 provider_value 格式仅对走 _search→_fetch 这条通用插件路径的候选生效；用户当前页面上已经打开、仍是旧裸数字 id 的候选在这次改动后依然会命中「未获取到所选记录」（校验不通过直接返回 None），但这和用户现在看到的失败现象一致，重新搜索即可拿到新格式候选，不构成回归。book.py 中的硬编码 douban_v2.KEY 分支与 get_metadata_by_provider 公开签名均未改动，兼容依赖它们的既有调用方。本次只验证了纯 Python 单测，未在 Docker/Calibre 环境跑端到端集成测试与契约测试，需要仓库 CI 补充确认；NeoDB 的同构缺口留待后续。
