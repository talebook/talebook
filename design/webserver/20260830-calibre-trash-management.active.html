提供可恢复的 Calibre 回收站管理

管理员可查看、批量恢复或永久删除 Calibre 回收站中的整本书；私藏书删除则绕过回收站，直接永久删除。

状态：ACTIVE创建日期：2026-08-30所属模块：webserver影响范围：webserver / app / tests需求来源：TB-135（houheya）

1. 原始诉求

“侧边栏管理区域加入回收站管理，可查看 Calibre library/.caltrash 内容并恢复或彻底删除；私藏书籍删除时直接永久删除；仅管理员可访问。”

现有设置页只能显示回收站总大小并一键清空，不能按书查看或恢复。普通删除调用 Calibre 默认删除语义，文件进入库级回收站。

2. 目标与边界

目标

  • 管理员在独立页面查看书名、作者、删除时间、格式和占用空间。
  • 单本或批量恢复，重建 Calibre 数据库记录并沿用 Talebook 的 Item 扩展数据。
  • 单本或批量永久删除，必须经过明确二次确认。
  • 所有私藏书删除入口使用 Calibre permanent=True。

非目标

  • 不恢复被现有删除流程清理的 ScanFile 导入历史。
  • 不展示本地绝对路径，不允许客户端提交文件路径。
  • 不管理 Calibre 的“单格式回收站”；本页只管理已删除整本书。
  • 不改变上传临时目录的现有清理功能。

4. 现状与证据

观察证据结论
普通删除进入回收站webserver/handlers/book.py 调用 LibraryDatabase.delete_book(bid)Calibre 默认 permanent=False。
Calibre 已提供安全的恢复能力Cache.list_trash_entries()、move_book_from_trash()、delete_trash_entry()无需自行解析 OPF 或移动目录，应复用上游锁和路径边界。
Talebook 扩展数据可跨普通删除保留普通 BookDelete 不删除 Item；仅清理 ScanFile恢复原 ID 后收藏者、私密范围和计数可重新关联。

5. 方案

方案结论：以 Calibre 新 API 作为回收站状态的唯一真相。后端只接受整数 ID，在管理员权限和 Calibre 写锁内完成列表、恢复、删除；前端提供独立管理页、批量选择和危险确认。
Input管理员选择 ID

客户端只发送整数 idlist。

Guard权限与存在性

@is_admin；对照实时回收站条目。

Core调用 Calibre API

恢复用 move_book_from_trash；删除用 delete_trash_entry。

Output逐项结果

返回成功 ID 与失败原因，前端刷新列表。

关键决策

决策点选择理由放弃项
回收站读写Calibre new_api上游已处理 OPF、封面、格式、注解、数据库重建、写锁和受控路径。直接遍历并移动 .caltrash，容易破坏一致性。
批量失败逐项执行并返回部分结果单个 ID 冲突不应阻断其他条目；结果可观察。首错即停会留下难判断状态。
关联数据普通删除保留 Item恢复使用原书 ID，可保留访问、下载与归属数据。恢复时凭 OPF 无法重建 Talebook 扩展字段。
私藏删除调用 delete_book(..., permanent=True)沿用 Calibre 的安全永久删除开关，不自行删目录。删除后再从回收站清理会产生短暂可见窗口。

6. 影响范围、风险与回滚

影响范围

新增管理员 API 和页面；两套侧边栏增加入口；单本及后台批量删除按 Item.scope 决定 Calibre 永久删除参数；补充中英文文案、后端和 E2E 测试。

保持不变

普通书仍进入 Calibre 回收站；既有回收站大小和清空上传目录功能保留；外部索引书不删除外部源文件；不新增表或迁移。

主要风险：恢复时原 ID 已被占用会失败；批量接口必须原样报告失败且不覆盖现有书。永久删除不可撤销，因此 UI 使用持久危险对话框并显示选中数量。
回滚：代码可整体回滚，无 schema 或配置迁移；已经执行的永久删除无法通过代码回滚恢复。
