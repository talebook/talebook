认证页面主题运行时
系统化修复

把主题从“页头附带的 CSS”提升为应用级能力，使登录、退出、注册、欢迎、安装与激活成功页在没有 Header 时仍获得完整且一致的主题语义。

ROOT
CAUSE

主题的全局样式、Body 标记与清理动作当前由 BuiltinThemeHeader 挂载；页面一旦隐藏或卸载 Header，主题运行时也随之消失。修复的核心不是补颜色，而是重新划分所有权。

01 / Intent

原始诉求与已确认边界

需求来源

用户截图与连续反馈

暖红主题下，登录页工具栏仍为默认蓝色；退出页完全回退到默认蓝色和蓝灰色。用户要求新开 worktree 分支进行系统性修改优化，避免继续逐页遗漏。

目标体验

一套主题，一致生效

内置皮肤接管全站 primary 语义；认证页保留现有结构与主题身份；Header 是否存在不再影响主题；主题加载失败时整套回退默认。

已完成 grill：运行时覆盖默认布局与认证用途的 blank 布局；阅读器明确退出内置皮肤运行时。重点验收登录、退出、注册、欢迎、安装、激活成功；不重做五套认证页面结构。

02 / Evidence

现状证据与失效链路

① 激活皮肤

themeStore.activeTheme 得到内置主题，布局选择对应 Header / Footer。

② Header 挂载

Header 的 onMounted 注入页面 CSS，并在 Body 写入主题名和明暗模式类。

③ 页面隐藏导航

logout 等页面执行 setNavbar(false)，布局不再渲染 Header。

④ 主题被清空

Header 卸载时移除 Body 类与 Style；页面重新暴露 Vuetify 默认蓝色。

03 / Ownership

目标架构：应用级 Provider 原子提交

职责上移

Provider 始终存在

在 app.vue 层包裹布局。主题解析与 DOM 副作用不再属于 Header，因此 store.nav 只控制导航可见性。

两阶段提交

先暂存，后切换

先解析 Header、Footer、页面 CSS 和语义调色板；全部成功后一次提交。任一必需资源失败则清除皮肤并整套回退默认。

显式依赖

布局只消费公开状态

通过 Symbol key 的 provide/inject 暴露 ready、有效主题和动态组件，避免布局复制主题加载逻辑。

副作用边界

DOM 操作集中且可清理

Body 类和 Style 的创建/更新/清理集中在 Provider；纯调色板与 CSS 构建函数可独立测试，SSR 阶段不访问 DOM。

04 / Semantic contract

05 / State flow

缓存优先、服务端校准、失败原子回退

① Hydrate

客户端显式读取 talebook.activeTheme，避免 SSR Pinia 状态覆盖本地缓存。

② Apply cached

有缓存时立即解析并应用；布局 ready 后展示页面，不等待网络。

③ Reconcile

后台请求 /themes/active；结果不同则执行新一轮原子切换。

④ First visit

无缓存时维持 Loading，直到接口确认主题或默认状态，再展示页面。

接口失败

保留已缓存主题

延续现有静默失败策略，站点继续可用；不因临时网络错误清空用户已见主题。

组件或样式失败

整套回退默认

默认 Header、Footer、默认蓝色和无主题 Body 类一次性生效；记录 console warning，不阻断页面。

09 / Safety

兼容性、风险与回滚

第三方主题

保持现有 API 契约

继续支持 API 返回的 Header/Footer 模块；本次语义 palette 只覆盖五个内置主题，不引入上传格式或后端变化。外部组件加载失败按原子策略回退。

CSS 优先级

Body 作用域高于 Vuetify 默认值

生成 token CSS 时限定主题名与模式，避免污染默认主题；移除 Header 内旧注入后检查不存在重复 Style 与残留 Body 类。

路由切换

阅读器进出必须清洁

进入 opt-out 页面时清除内置主题 DOM 状态，离开后从有效主题重新应用；防止阅读器和站点主题互相泄漏。

回滚

前端提交可整体撤回

不改数据库、接口或持久化 key。若上线异常，可整体回退本次前端提交，恢复 Header 承载的旧运行时；用户缓存仍兼容。

10 / Done

验收标准

  1. 暖红主题登录页工具栏、主按钮、链接和背景不再出现默认蓝色；退出页在 nav=false 时仍保持暖红主题。
  2. 五个内置主题的 light/dark primary 都与本方案色谱一致，默认主题仍为 #1976D2。
  3. 主题 Body 类与注入 Style 的存在只取决于有效主题和路由策略，不取决于 Header 是否渲染。
  4. 登录、退出、注册、欢迎、安装、激活成功在直接访问和导航后均无主题混搭；阅读器保持独立配色。
  5. 有缓存时快速应用；无缓存时 Loading 等待服务端确认；组件/样式失败整套回退默认。
  6. 自动化、真实浏览器计算样式验收、lint、typecheck、build 与设计门禁均已记录；与本次改动相关的检查无失败。
