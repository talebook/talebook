Readest 宿主协议根因修复

让 dev 与生产都把浏览器带入同源、可诊断的 Readest launch，并完整转发 EPUB 的 HEAD/Range 契约；撤销会吞掉真实缺包的通用 chunk 200。

状态：ACTIVE创建日期：2026-08-30所属模块：app影响范围：Nuxt server、Readest launcher、Nginx、BookRead需求来源：TB-139 / PR #977 根因复核

1. 原始诉求

“实现 dev/prod 等价的浏览器可见同源 launch 与保头资源代理，并删除或严格收窄无条件 chunk 200 恢复层。补齐真实 EPUB 新旧 profile 首屏/翻页证据、错误回退、构建与相关测试。”

真实 EPUB 逐跳审计确认：Nuxt route-rule proxy 跟随后端 302，浏览器丢失 file/moke/mokeBookId；即使手工补参数，通用 proxy 又删除 HEAD Content-Length，Readest 无法开始 Range 读取。

2. 目标与边界

  • 浏览器必须看到后端 302，并在同源 launcher 中消费版本化 bootstrap。
  • dev 的 /read/resource/*.epub 保留 Content-Length、Content-Range、Accept-Ranges、ETag、MIME、Cookie 与状态码；生产 Nginx 保持同一 URL 契约。
  • bootstrap、参数或权限失败展示返回书籍页、Candle 回退和重试，不进入永久 spinner。
  • 未知 Nuxt chunk 恢复为真实 404；只保留精确识别旧 /readest/sw.js 的一次性清理。
  • 不扩展 PDF、批注、同步等 Readest 能力；不使用 404→200 或 MIME 改写。

3. 根因与证据

逐跳失败证据方案约束
/read/1Nitro 对后端 302 自动 follow，浏览器地址无 launch query。显式 Node server route 使用 redirect: manual。
Readest initInitialize books []，无 EPUB/bootstrap 请求。Talebook launcher 读取 bootstrap 并构造绝对同源 file URL。
EPUB HEAD通用 H3 proxy 明确过滤 content-length。自有透明响应路径复制非 hop-by-hop 头，并以真实浏览器测试。
旧 chunk全新 profile 同样失败；通用 JS 200 与主因无关。删除 Vite/Nitro/Nginx fallback，缺包保持 404。

4. 方案

入口BookRead 完成权限、格式和 revision 判断后 302 到 Talebook launcher。
Bootstraplauncher 同源请求 v1 schema，严格校验 book/resource/navigation。
Reader用当前浏览器 origin 构造绝对 EPUB URL，再 replace 到原始 Readest reader。
资源Nuxt 显式 read proxy 手工转发，不 follow 302、不删除 HEAD/Range 必需头。
失败launcher 文本化显示错误，保留重试、书籍页、Candle、登录入口。

关键决策

决策选择理由
谁消费 bootstrapTalebook 静态 launcher不修改或伪造 Readest 内核；把宿主协议和错误 UI 留在宿主。
dev proxy专用 server route 返回原始 ResponserouteRules/H3 proxy 会 follow 302 或过滤 Content-Length，无法满足契约。
旧 profile保留精确 worker/cache cleanup历史污染真实存在，但不得借未知 chunk 200 掩盖部署错误。
资源缓存生产和 dev 均保留后端 private, no-store权限撤销与私有资源不能经过共享/持久缓存。

5. 影响、风险与回滚

主要风险：手工代理若错误复制 hop-by-hop 或压缩头会破坏流；因此只代理 /read/**，过滤连接级头，对被自动解压的响应删除编码与长度，并对 EPUB HEAD/206 做真实头断言。
  • 生产 Nginx 继续直连 Tornado；仅调整 EPUB location 的缓存头覆盖。
  • Readest 静态内核与 source commit 不变；新增文件只是 Talebook 协议适配和错误页。
  • 回滚单位为 launcher、专用 proxy 和 BookRead 重定向；无数据迁移。
  • Windows 原生环境不可用时，明确保留 Windows npm run dev 未闭合项，不以 Linux 构建替代。
