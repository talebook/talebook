安装态保留安全状态并合并重复跳转

后端尚未安装或私有图书馆尚未通过访问码时，前端应只发起一次有效导航，并在导航期间保持 Pinia 的安全默认配置，避免布局组件读取未定义字段。

状态：ACTIVE 创建日期：2026-08-11 所属模块：app 影响范围：启动状态、控制信封、安装与私有图书馆流程 需求来源：TB-17

1. 原始诉求

安装页面出现多项 Cannot read properties of undefined，并反复输出 [Talebook] Redirecting to /install；补充条件为已启用“私有图书馆”模式。

2. 目标与边界

  • not_installed 与 not_invited 响应不得把 store.sys 或 store.user 替换为 undefined。
  • 同一目标的并发控制信封只触发一次导航；已经位于目标页时不再导航或打印日志。
  • 保持后端响应结构、302 跳转语义和安装表单行为不变。
  • 本次不重构全部启动请求，也不改变主题或消息的加载时机。

3. 现状与证据

loadUserInfo() 无条件调用 login(rsp)；而 login() 只判断响应对象存在，随后直接读取不存在的 rsp.sys 与 rsp.user。未安装时响应为 not_installed，私有图书馆未获访问许可时响应为 not_invited；布局、主题和页面请求会并发收到同类控制信封并各自调用导航。

4. 方案

验证数据只有同时存在 sys 与 user 时才更新全局状态。
合并导航按目标路径记录进行中的跳转，并跳过当前已到达的目标。
真实回归让 mock 覆盖未安装态与私有图书馆访问门禁，断言各自只导航一次且无页面 TypeError。

5. 影响与风险

成功响应仍按原结构覆盖状态；错误响应改为保留默认值。去重只覆盖同一目标路径：到达目标后继续保留记录，离开该目标页时释放，因此后续真实状态变化仍可再次触发跳转。

  • npx vitest run test/stores/main.nuxt.spec.ts test/plugins/talebook.nuxt.spec.ts：10 项通过；测试环境仍输出既有 Vuetify i18n 初始化警告。
