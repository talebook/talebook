Talebook / App / PR #934

保留标签列表，用渐进展开承载大书库

出版社、作者与标签继续以熟悉的可点选列表呈现；去掉横向箭头与搜索框，用自动换行和“显示更多”分批披露上万项元数据。

状态：SUPERSEDED 创建日期：2026-08-04 所属模块：app 需求来源：PR #934 用户复审

1. 原始诉求

替代说明：用户进一步要求“显示更多”打开浮窗，并缩小标签文字、提高密度。本方案已由 design/app/20260805-library-filter-picker-dialog.active.html 替代；原实现与验证记录保留用于追溯。
“我不要这种搜索框的模式。你要保持原来的那种 tag 列表 + 显示更多。”

用户否决上一版将高基数元数据改成搜索框的方案。目标不是发明新的筛选方式，而是修好原标签列表的扩展能力：列表仍可扫视和直接点击，“显示更多”必须始终可发现，也不能把一万多项一次性渲染出来。

2. 目标与边界

目标保留“全部 + 标签项 + 显示更多”的原有心智模型；所有标签自动换行，不出现左右翻页箭头；在 375px 到 1440px 都无页面级横向溢出。
性能边界首屏只渲染前 10 项；每次点击“显示更多”新增 50 项；展开后提供“收起”，避免 big-metadata.db 的 10,945 个标签同时进入 DOM。
保持不变单选语义、元数据排序、接口、查询参数、书籍分页、连载状态开关以及格式筛选不变。
非目标不增加搜索、多选、标签层级、服务端分页或新的元数据接口；不重做书卡与全局搜索。

3. 证据与设计判断

证据问题设计回应
PR 截图在平板宽度已出现左右箭头“更多”跟随横向轨道移动，发现成本高。弃用 slide-group 横向轨道，使用普通 flex 换行。
big-metadata.db 含 1,663 个出版社、14,951 位作者、10,945 个标签一次性展开会产生大量 DOM，卡顿且难以收回。固定批量渐进披露，任一时刻只渲染用户主动展开的部分。
用户明确要求原 tag 列表搜索框改变既有浏览型交互，无法通过视觉扫视发现分类。标签是主交互；“更多”是同行末端的次级操作。
URL 可带入不在首批内的筛选值深链选中项可能不可见。若当前选中项不在已展开范围，额外附加显示并保持选中态。
UI/UX 结论：“自动换行 + 渐进披露”与用户的浏览任务匹配。44px 点击目标、可见焦点、aria-pressed、剩余数量和收起入口保证可用性；不使用横向滚动隐藏内容。

默认呈现

“全部”和前 10 项可直接点击；更多按钮紧跟其后并参与换行。

分批展开

每次点击追加 50 项，更多按钮同步显示尚未呈现的剩余数。

选择刷新

点选标签后立即刷新书单第一页；标签列表保持当前展开范围。

一键收起

展开后在末尾保留收起按钮；回到前 10 项，当前选中项仍可见。

组件职责

  • 新增复用筛选行组件，接收标签、选项、当前值、首批数量与批量大小，只抛出单选值。
  • 组件内部维护已显示数量；数据源变化时不超过新数组长度。
  • 页面继续拥有筛选状态和 API 请求；出版社、作者、标签使用渐进组件，格式和连载状态保持少量换行标签。
  • “全部”用 null 表达，不把本地化文案写进请求参数。

5. 风险、兼容性与回滚

长列表风险用户连续展开很多次时 DOM 仍会增长，但增长由明确操作触发且每批固定；收起可立即恢复轻量状态。
长文案风险单个超长标签允许截断并保留 title；标签容器可收缩，避免撑宽页面。
兼容性无后端、数据库、权限、配置与 URL 契约变化；仅改变书库筛选区的渲染与交互。
回滚撤销新增组件和页面接入即可恢复旧筛选；不需要数据迁移。
