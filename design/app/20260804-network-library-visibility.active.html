01 / Intent

原始诉求

“如果没有设置网络书库，‘已完本’和‘连载中’就不应该出现；在设置中增加一个是否显示网络书库，控制侧栏入口和这两个筛选选项。”

Issue 后续还补充：出版社较多时，筛选行左侧的“出版社”会被横向 chip 挤成两行。维护者要求解决这些问题并提交 PR。

02 / Scope

目标与边界

目标 / Goals
  • 新增可持久化站点设置 SHOW_NETWORK_LIBRARY。
  • 同一设置控制经典侧栏、内置主题侧栏与书库连载状态筛选。
  • 筛选标题在 chip 较多和窄视口下保持单行可读。
  • 为配置传播、开关两态与布局回归补充自动化测试。
非目标 / Non-goals
  • 不把显示设置升级为权限开关，不拦截 /network 直接访问。
  • 不自动探测书源数量，也不改变书源启停逻辑。
  • 不删除网络书元数据，不改变搜索、保存或连载状态接口。
  • 不隐藏已保存网络书卡片上的状态角标。
03 / Evidence

现状、根因与证据

观察代码证据结论
两套侧栏总是显示网络书库app/components/AppHeader.vue、app/components/themes/BuiltinThemeHeader.vue两处都要读取同一系统配置，避免主题切换后行为分叉。
本地书库总是显示连载状态筛选app/pages/library.vue筛选行应按站点开关条件渲染，关闭时不触发专属接口。
“出版社”被挤成多行筛选标题是 flex 子项，当前允许收缩和换行为所有筛选标题统一设置 flex: 0 0 auto 与 white-space: nowrap。
截图中的 render_book_list 异常NetworkBaseHandler 已继承 ListHandler，且 tests/test_network_library.py 已覆盖目标分支已修复，本次只做回归验证，不重复改动。
兼容事实

旧配置文件不存在新键。后端默认值、接口回退值和 Pinia 首屏初始值必须一致为 true，才能保持升级前行为并避免 SSR 首屏闪烁。

04 / Design

关键决策

决策点选择理由不采用
默认值true旧部署无新键时保持现有入口，避免升级即隐藏已在使用的能力。默认关闭会让既有网络书库用户升级后失去导航入口。
显示与权限仅控制展示符合设置命名；已由用户确认，且不产生未经设计的权限变化。路由拦截需要新的授权模型和错误契约，超出 issue 范围。
无书源判断由管理员显式设置书源可能暂时停用或检测失败，数量不是稳定的产品意图信号。按书源数量自动隐藏会造成入口随运行状态抖动。
标题布局所有筛选标题统一不收缩、不换行解决出版社问题，也避免作者、标签和格式出现同类缺陷。只给“出版社”特判会留下重复缺陷。
05 / Safety

影响范围、风险与回滚

影响范围

后端默认配置与保存白名单、公开系统信息字段、Pinia 初始值、经典和内置主题侧栏、书库筛选布局、中英文文案、后端测试与前端组件/E2E 测试。

保持不变

数据库结构、书源和网络书数据、API 路由与鉴权、直接访问语义、保存和搜索流程、现有 render_book_list 修复。

主要风险

两套导航只改一处会导致主题间行为不一致；后端、Pinia 默认值不一致会造成 hydration 闪烁；测试 mock 未同步会产生假通过。通过两套组件断言、开关两态 E2E 和后端系统信息测试共同约束。

回滚

管理员可重新勾选立即恢复入口。代码回滚只需撤销配置投影和条件渲染；无数据迁移、无清理任务，旧配置中遗留的布尔键可安全忽略。
