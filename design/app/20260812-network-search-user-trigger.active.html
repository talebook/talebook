网络书库仅由用户动作触发搜索

保留上次搜索缓存的即时展示，但停止页面挂载时的后台重搜，避免用户未操作便创建耗时的书源搜索任务。

状态：ACTIVE 创建日期：2026-08-12 所属模块：app 影响范围：网络书库搜索页与 E2E 测试 需求来源：GitHub Issue #965

1. 原始诉求

“每次一打开在线书库，它就自动开始上一次的搜索，我都没搜，它就自己开始搜了。”

Issue 附图显示网络书库打开后沿用旧关键词，同时搜索按钮进入加载态并出现“已完成 5/50 个书源”的进度。该行为会消耗书源搜索资源，也违背“搜索由本次用户动作发起”的预期。

2. 目标与边界

目标

  • 重新进入或刷新网络书库时，不自动调用网络搜索接口。
  • 仍从本地缓存恢复上次关键词、范围、页码和结果，避免返回页面后历史结果丢失。
  • 点击搜索、回车和翻页继续正常发起搜索。

非目标

  • 不清除或迁移现有 localStorage 缓存。
  • 不改变后端搜索任务、轮询协议与书源排序。
  • 不调整网络书库布局、文案或视觉样式。

4. 现状、根因与证据

观察权威证据结论
打开页面后出现旧关键词、加载按钮及 5/50 搜索进度。Issue #965 附图；app/pages/network/index.vue 的 onMounted不是浏览器自动提交表单，而是页面代码恢复缓存后调用 fetchSearch。
缓存恢复本身已有 E2E 约束。app/test/e2e/network.spec.ts 的缓存恢复用例；提交 4edbf002无需删除缓存能力，只需切断挂载与新搜索任务之间的隐式触发。
事实与推断：根因可由静态调用链和附图直接证实。实现后需用请求计数断言证明二次进入页面不会调用搜索接口，同时缓存结果仍可见。

5. 方案

方案结论：页面挂载只负责恢复本地缓存和加载书源，不再执行 fetchSearch。搜索任务仍由 doSearch 与 changeSearchPage 两个显式用户路径负责，缓存读写格式保持不变。
Enter进入网络书库

读取上次搜索元数据与缓存条目。

Restore恢复静态状态

回填关键词、范围、页码、结果与失败源列表。

Idle保持空闲

不调用搜索接口，不显示搜索进度或加载态。

Action等待用户动作

点击搜索、回车或翻页后才创建新任务。

关键决策

决策点选择理由放弃项
缓存与刷新恢复缓存但不后台刷新解决无操作搜索，同时保留返回页面的上下文。完全删除缓存会让返回页面丢失结果；保留自动刷新无法解决 Issue。
测试信号监听搜索接口请求数量既验证可见缓存，也验证没有隐藏的网络副作用。只断言按钮未加载可能漏掉快速完成的自动请求。
 
onMounted:

  loadSources()

onUserSubmit / onPageChange:
  fetchSearch(page)

6. 影响范围、风险与回滚

影响范围

app/pages/network/index.vue 的挂载行为，以及 app/test/e2e/network.spec.ts 对缓存恢复的验收。用户再次打开页面时不再看到自动搜索进度。

保持不变

后端 API、缓存键及数据结构、主动搜索与分页、搜索轮询、登录权限、界面布局和 i18n 文案均不变。

主要风险：恢复的结果可能不是最新数据；但它被明确视为历史缓存，用户主动搜索即可刷新。E2E 同时覆盖缓存展示与主动搜索，防止误伤原能力。
回滚：仅需恢复挂载阶段的 fetchSearch 调用；不涉及数据、配置、迁移或缓存清理。
