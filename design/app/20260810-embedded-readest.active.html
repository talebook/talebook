Talebook 同源嵌入 Readest

在保留 `/read/{id}` 权限入口、转换流程和旧阅读器回退的前提下，构建专用 Readest 静态产物并由 Talebook 镜像同源托管。

状态：ACTIVE 创建日期：2026-08-10 所属模块：app（跨 webserver / Docker） 需求来源：TAL-11

1. 原始诉求

“让 Talebook Web 端可直接使用 Moke 维护的 Readest 阅读器，同时保留现有权限、历史、转换和旧阅读器回退能力；不要求用户另行部署或登录 Readest 云服务。” PR 评审进一步要求解决启用构建后静态产物增加约 155.1 MiB、明显大于 Candle Reader 的问题。

首期聚焦 EPUB 与现有 MOBI/AZW/AZW3 转 EPUB 路径。PDF、TXT 保持原阅读器，直至 Range、内存、编码和定位能力达到同等可靠性。

2. 目标与边界

目标

  • 后台新增 Readest 选项，默认仍为 Candle Reader。
  • 书籍内容只从同源、受阅读权限保护的接口进入浏览器 Blob。
  • 登录用户保存并恢复 moke.readest.progress.v1。
  • 裁剪后静态产物不超过 50 MiB，并由构建门禁阻止体积回涨。
  • 转换、资源缺失、内容错误均有明确状态与旧阅读器入口。

非目标

  • 不引入 Readest 账号、云同步、支付或外部存储。
  • 不改变 PDF.js 与 TXT 阅读路径。
  • 不承诺 Readest 笔记跨端同步。
  • 不把 Readest AGPL 源码并入 Talebook 的 BSD 许可声明。

4. 技术证据与门禁

观察证据决策
Talebook 的 EPUB 入口已集中完成权限、历史与格式分流。webserver/handlers/book.py:1605继续以 /read/{id} 为唯一入口。
下载接口要求 can_save，不能用于仅有阅读权限的用户。webserver/handlers/book.py:1019新增只服务 EPUB 的阅读内容流，复用 can_view_book 与阅读权限。
Readest Web 默认拒绝 file=，但 Web AppService 可导入浏览器 File。apps/readest-app/src/helpers/openWith.ts仅在 talebook=1 时接收同源 Blob URL，拒绝任意 HTTP URL。
Readest 可静态导出，但 Web 动态分享路由需嵌入构建分支。next.config.mjs 与实际 build-embedded-web专用环境保持 Web 存储能力，关闭 runtime config/PWA，并输出到 out/readest。
原始静态产物为 156 MiB，其中 186 个 sourcemap 共 105,934,986 字节。固定 commit 本地执行 build-embedded-web 后逐文件统计生产镜像不分发调试映射；保留编译后的 JS、CSS、WASM 与语言资源。
vendor/pdfjs 占 5,247,446 字节。Talebook 格式矩阵只把 EPUB 与转码后的 EPUB 交给 Readest裁剪 PDF.js 公共运行资源；PDF 仍由 Talebook 既有阅读器处理。
仅删除 sourcemap 与 PDF.js 公共资源后预计约 47 MiB。原始固定构建的文件字节数差额设置 50 MiB 硬上限并验证入口、阅读页、中英文资源、分词与简繁转换资源仍存在。

5. 架构与数据流

1. 权限入口/read/{id} 完成游客、账号、可见性、历史和格式判断。
2. 内容预取Readest 启动页轮询受保护 EPUB 流，校验 HTTP、大小与 ZIP 魔数。
3. 同源嵌入父页创建 Blob URL，Readest 仅将同源 Blob 转为临时 File。
4. 进度闭环恢复经 schema/book-id 校验；翻页由同源 fetch 节流保存。

阅读器选择与回退

EPUB_VIEWER=readest.html 启用新路径；?reader=creader 和 ?reader=epubjs 是受控覆盖。管理员切回配置不需要迁移数据。

构建拓扑

Talebook 固定 Readest fork 及其 foliate-js、simplecc-wasm、js-mdict 依赖 commit。Docker 的独立 Node 22 build stage 生成静态产物，复制许可说明后运行仓库内裁剪脚本，最后才复制到 SPA 和 SSR 托管目录。裁剪脚本删除生产环境不需要的 sourcemap 与 EPUB-only 接入不会访问的 vendor/pdfjs，校验核心文件并以 50 MiB 为失败阈值；运行时不增加 Node sidecar。

评审反馈 grill 结论

  • 体积口径：以构建目录内所有常规文件的原始字节和为门禁口径，不用镜像层压缩率掩盖静态产物膨胀。
  • 功能边界：继续保留 Readest 的 EPUB 阅读、主题、全部语言包、结巴分词、简繁转换和浏览器数据库；不为追求 8 MiB 猜测性删除共享 chunk。
  • PDF 边界：Talebook 不向 Readest 传入 PDF，因此只移除静态导出中的 PDF.js 公共运行目录；Readest 编译所需依赖和 Talebook 原 PDF 阅读路径均不变。
  • 回归约束：脚本必须在缺失核心文件或超过 50 MiB 时失败，并通过独立测试覆盖裁剪、幂等与超限场景。

6. 安全、许可与运维

  • 内容端点不接受文件路径参数，只从书籍 ID 解析 Calibre 已登记的 EPUB 路径；返回 application/epub+zip。
  • 启动页拒绝重定向、HTML/JSON、非 ZIP 内容、空文件和超过 512 MiB 的响应。
  • Readest 嵌入参数只接受父页创建的同源 Blob URL；浏览器进度写入固定到当前 origin。
  • Readest 继续以 AGPLv3 独立作品和源码 commit 分发；镜像包含其许可证、源码地址、精确 commit 与第三方依赖声明。Talebook 自有代码继续 BSD-2-Clause。
  • Readest 构建资源缺失时不静默白屏；用户可立即返回 Candle Reader。默认配置保持 Candle Reader。
  • 裁剪只作用于临时构建输出，不修改固定上游源码；AGPL 许可和精确源码说明继续随产物分发。

8. 决策记录

  1. 选择静态产物同源托管，不采用 Next.js sidecar。
  2. 不复用下载接口，避免把“可阅读”错误收紧为“可下载”。
  3. 不直接把书籍 HTTP URL交给 Readest；由 Talebook 父页校验并转为 Blob。
  4. 本期不改变默认阅读器；体积门禁解决镜像无界增长，但外部 fork 的功能稳定性仍需继续评审。
  5. 评审反馈后不另建方案，恢复同一文件为 WIP 并在这里记录体积分析、裁剪边界和验证结果。
  6. 相关自动化、完整固定源码构建与 50 MiB 门禁均通过，本文件转为 .active.html。
