内置主题搜索参数修复

ACTIVE 创建日期：2026-07-18 所属模块：app 需求来源：GitHub Issue #875 维护者评论

原始诉求

“找个当前项目里的前端 BUG，然后提交 PR”。

检查发现：使用任一内置主题时，页头搜索提交的是 keyword 查询参数，但现有 /api/search 接口读取 name，导致搜索词丢失。

边界与决策

决策点结论
缺陷范围五个共用 BuiltinThemeHeader 的内置主题；默认主题已经使用正确参数。
接口契约沿用后端和默认主题既有的 name 参数，不新增兼容参数，不改后端。
搜索语法保留浅灰主题的分类前缀拼接及首尾空白清理，仅修正参数名。
空输入维持当前“不跳转”行为。
测试层级组件测试精确覆盖普通搜索的路由对象与空输入；E2E 在激活内置主题后覆盖真实提交与结果页。

仓库要求使用 grill 澄清；当前执行环境未提供该工具，上述结论依据现有 API、默认页头实现和搜索 E2E 契约形成。

目标

  • 内置主题搜索提交 /search?name=...，搜索词能被后端识别。
  • 浅灰主题选择标题、作者、ISBN 或标签时，分类前缀仍完整传入 name。
  • 特殊字符交由 Vue Router 的对象式查询序列化处理。
  • 不改变搜索接口、结果页、主题外观或其他导航行为。

方案

内置主题页头输入 → router.push({ path: '/search', query: { name } }) → BookList 转发 route.fullPath → /api/search 读取 name
  1. 将 BuiltinThemeHeader.vue 的路由查询字段从 keyword 改为 name。
  2. 新增组件测试，覆盖普通主题搜索、特殊字符原样交给路由序列化与空输入。
  3. 扩展搜索 E2E：激活内置主题，输入 mock 中存在的书名片段，断言 URL 参数和结果。

影响范围

  • app/components/themes/BuiltinThemeHeader.vue：修正查询参数。
  • app/test/components/BuiltinThemeHeader.spec.ts：新增组件回归测试。
  • app/test/e2e/search.spec.ts：新增浏览器回归测试。
  • 后端、配置、数据结构、i18n：无变化。
