界面图标本地 SVG 化

移除首屏对整包 MDI 图标字体的请求，把实际使用的图标路径在构建期打进应用，使菜单和按钮不再经历方框占位。

状态：ACTIVE 创建日期：2026-08-10 所属模块：app 影响范围：全站 Vuetify 图标 需求来源：TAL-13

1. 原始诉求

“截图里的 icon 加载很久，排查是否因为引用了外部资源，并把资源全部本地化。”

截图中菜单、顶栏和悬浮按钮的所有图标同时显示为空方框，符合图标字体尚未可用时的表现。

2. 现状与结论

没有运行时外部 CDN

@mdi/font 由 npm 在构建阶段提供，Nuxt 会把字体输出到本站 _nuxt 资源目录。

仍存在首屏字体依赖

当前会发布约 403 KB WOFF2 和约 418 KB 完整图标 CSS；字体完成前，私有区码只能显示为方框。

3. 目标与边界

目标
  • 界面图标不再发起字体或图标 CDN 请求。
  • 只把仓库实际使用的 MDI SVG 路径打包进应用。
  • 保持既有 mdi-* 图标名称和所有页面行为不变。
非目标
  • 不改变书籍封面、头像、验证码和用户主动配置的远端链接。
  • 不改造独立阅读器内自带且已本地化的图标资源。
  • 不改变 Vuetify 主题、布局或交互。

4. 实现方案

1. 收集名称扫描应用源码中的 mdi-* 字面量并维护显式注册表。
2. 构建期解析从 @mdi/js 静态导入相应 SVG path，允许打包器摇树优化。
3. 本地渲染通过 Vuetify 自定义图标集直接输出内联 <svg>，不再请求字体。

Vuetify 内置控件使用的 $alias 继续复用官方 mdi-svg aliases；业务代码传入的 mdi-name 由本地图标组件查表。未知名称在开发环境报警，并渲染问号兜底图标。

5. 风险与控制

  • 新增图标忘记注册：测试扫描生产源码，发现未注册的 mdi-* 名称即失败。
  • SSR 与客户端不一致：图标组件只依赖静态映射，服务端和浏览器执行相同渲染函数。
  • 包体回退：构建后检查不再生成 MDI 字体，并记录产物体积变化。

6. 测试结果

验证通过

  • npx vitest run test/components/：14 个测试文件、63 个用例全部通过。
  • npm run lint：0 error；保留 193 条与本次无关的既有 warning。
  • npm run build 与 npm run generate：SSR 和静态构建均通过。
  • 构建产物检查：主应用 _nuxt 中无 MDI 字体文件、Material Design Icons CSS 或外部图标 CDN 引用；独立阅读器目录原有的本地图标字体保持不变。
  • Chromium 实际渲染：390×844 移动首页与浅灰主题侧栏共 2 个 Playwright 用例通过；所有 Vuetify 图标均包含 svg.v-icon__svg，资源时间线中无 font 请求。

7. 决策记录

  1. 选择 SVG 而不是把完整字体复制进仓库，因为复制只能改变所有权，不能消除字体下载与方框占位。
  2. 保留现有图标名称，不批量改写页面模板，降低全站迁移风险。
  3. 图标依赖保留为构建期 npm 包；运行时产物全部由 Talebook 同源提供。
