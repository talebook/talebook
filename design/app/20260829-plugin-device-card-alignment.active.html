插件设备类型联动与卡片布局优化

让阅读设备配置严格跟随已启用推送插件，并重排插件卡片的信息与操作层级。

状态：ACTIVE创建日期：2026-08-29所属模块：app影响：app + webserver

1. 原始诉求

“插件-设备里面的激活列表，跟用户-阅读设备里的类型列表不匹配。用户能配置的类型列表应当跟插件里启动状态保持一致。”
“插件列表的卡片样式应当有卡片阴影。状态标签放在插件名称右侧；名称下方的‘内置’换成 taglist；操作按钮放置在右上角；停用按钮放置在配置页里面右上角。”
体验反馈：“状态 tag 的样式缩小，要比卡片主标题的字体小一点。”状态 tag 使用 12px 紧凑规格，仍明显小于 15px 标题，同时守住小字可读性下限。
体验反馈：“【详情】还是要放在卡片的右下角。”因此右上角只放主操作，详情作为次级入口固定在卡片右下角。
体验反馈：“卡片左下角是执行记录，右下角是详情按钮。现在这两个错位了，没有同一行。”执行摘要与详情改为同一个不换行 footer，按垂直中心对齐；长摘要省略显示并保留 title。
体验缺陷：“元数据的插件，点击【配置】按钮怎么没反应？”根因是插件目录 API 序列化时遗漏 connection_owners，前端将实例级插件误判为不支持配置并静默返回。目录响应补回该 manifest 字段。
产品重规划：Talebook 是多用户实例，插件安装与全局策略属于管理员；微信读书、BRS 账号和阅读设备等连接属于当前用户。用户确认采用“双控制面”方案，并选择 A「设置清单」视觉：管理员页面使用紧凑分组列表，不再使用插件卡片。
最终交互确认：插件页面提供“插件管理”和“个人配置”两个 Tab。前者只供管理员启停内置插件和维护实例配置；后者始终配置当前登录账号。普通用户复用同一套个人配置内容，但不显示管理 Tab。
BRS 个人配置参考 candle-reader 的“快速登录/注册”：提供登录、快速注册和忘记密码。用户进一步明确，三项账号操作均由浏览器直接调用所填 BRS 服务器 API，不经过 Talebook 内部 handler；仅在登录成功后用现有通用插件连接接口保存已验证的 endpoint 与个人凭证。
设置归并：原“互联网书籍信息源”和“全局设备管理”从系统设置移入插件中心。元数据插件的启停直接决定是否参与查询，不再维护第二份“选择启用的元数据源”列表。
文案与信息降噪：“尚未建立个人连接”改为“需要绑定账号”；删除列表行中“实例配置 / 尚未测试”等无操作价值的技术信息，只保留名称、状态、简介和操作。
列表密度反馈：插件行上下留白过多。桌面端单行基准高度从 96px 收紧至 72px，缩短标题与简介间距，同时保留状态标签、图标和操作按钮的可读性。
配置模型反馈：免配置的豆瓣、Calibre 和 Open Library 不得显示“连接名称 / 公开配置（JSON）”通用框。只有 manifest 明确声明 configuration_mode=form 的插件才展示字段化设置；定制管理器和免配置插件分别进入专用入口或详情。
公开书源反馈：书源 Tab 提供无需账号的公开站点用于体验。首批提供 Project Gutenberg 与 Standard Ebooks·最新上架的一键预览；Standard Ebooks 完整 OPDS 已需授权，因此改用官方匿名 Atom feed。Internet Archive 权利状态混合，只标示风险而不冒充公开免费来源。
Legado 交互反馈：“Legado 书源插件，应该跟微信读书一样有自己的工作台页面。”插件中心不再内嵌整个书源管理页，改为声明式跳转 /plugins/legado 。
协议测试反馈：插件状态“已停用”统一改为“未启用”；详情页删除连接模型遗留的“测试连接 / 预览 / 立即执行”。管理员测试插件时必须调用具体能力协议，例如元数据走 MetadataProvider.search_books()，书源走 SourceProvider.search()，评价走 ReviewProvider.get_reviews()。
详情信息层级反馈：“权限与数据范围”属于低频审计信息，默认折叠；能力测试和插件设置保持直接可见。
插件边界反馈：“嵌入文件元数据”是 EPUB 导入的默认解析能力，不是管理员可启停的外部插件。移除其 Provider 与注册项；解析器迁入平台 service，历史定义仅从目录隐藏，不破坏性删除旧记录。
折叠区视觉反馈：“权限与数据范围”改为透明、无阴影的细分隔线样式，标题字号与强调度低于主要设置和能力测试。
导航反馈：插件管理页右侧增加与系统设置页一致的粘性分类导航；点击分类平滑定位，页面滚动同步高亮，窄屏隐藏以保留列表宽度。
粘性定位复验反馈：导航虽然声明了 position: sticky，但祖先 v-window 的 overflow:hidden 建立了错误的滚动容器，导致页面向下滚动时不吸顶。插件页仅在该管理窗口覆写为可见溢出，并增加滚动后实际坐标断言。
分类跳转反馈：点击“书源”等分类时不能把分组标题对齐到视口零点并藏在固定头部后；分组使用与系统设置页一致的滚动留白，验收以标题实际可见位置为准。
元数据同步弹窗反馈：隐藏弹窗内部滚动条但保留鼠标滚轮与触摸滚动；顶部大块失败警告替换为紧凑的书源完成进度条，持续展示完成数、总数和失败来源。
品牌识别反馈：面向第三方外部服务的插件应展示对应服务的官方图标，例如微信读书。固定品牌资源从官网、官方仓库或官方应用目录核验后本地托管，由 Provider manifest 的 ui.brand_icon 声明；插件列表前端只做通用渲染与 MDI 降级，不得按插件 ID 硬编码品牌映射。
元数据运行时反馈：未启用的七猫不得出现在书籍元数据候选中；每个启用来源最多返回 5 条候选。排查确认在线书源聚合器会无条件追加内置七猫快照，绕过独立七猫插件状态；现改为仅查询用户显式启用的数据库书源。Calibre 标题搜索原先只查询 Amazon，且首条结果后的 30 秒等待与外层超时相撞；现同时查询 Google 与 Amazon，并以进程内可恢复方式把等待上限缩短至 2 秒。
异常状态排查：豆瓣的“异常”来自旧通用“立即执行”误调用类型化 Provider 后留下的失败健康记录，并非豆瓣查询失败；新详情页已删除该入口。七猫则是底层站点搜索与 MetadataProvider.search_books() 同名，在多继承 MRO 下调用错方法；底层搜索改名为 search_catalog() 并保留兼容包装。
Provider 边界调整：独立“在线书源元数据”并不是新的外部服务，而是 Legado 已启用书源的派生能力。删除 talebook.meta.book-source 的注册项，将 metadata.lookup 并入 talebook.source.legado；Legado 总开关同时控制书源与元数据能力，工作台内单个书源的启停决定它是否参与两类查询。
Calibre 插件边界反馈：talebook.meta.calibre-provider-bridge 只枚举 Calibre 运行时中的 identify Provider，不提供书籍查询，不应成为管理员可启停插件。删除该桥接 Provider；保留真正按 ISBN、书名和作者查询 Google Books / Amazon 的 talebook.meta.calibre。
配置入口与书籍工具反馈：插件中心原有“打开工作台 / 设置 / 管理账号 / 管理设备”等按钮按配置归属统一为“全局配置 / 个人设置”。三个正文 Tool 属于实例级全局能力；插件中心负责启停与全局策略，针对某一本书的处理入口由已启用 Tool 动态出现在书籍详情页“处理”菜单中。
目录清理反馈：Talebook Mock Multi-tab Provider 只用于验证跨类别、重试与回滚，不是用户插件；从生产注册表与插件目录彻底移除，测试改用独立 Registry。历史数据库里的未注册或隐藏定义也不得从个人插件接口重新暴露。
命名与默认值反馈：插件名称由“talebook-brs 章评”调整为“talebook-brs 章评服务器”，默认服务器地址为 https://brs.talebook.org；插件 ID 与能力协议保持不变，已有连接保存的地址优先。
生命周期与导航反馈：AI 元数据保留现有能力与启停状态，但 manifest 明确标记为“已废弃”，等待后续重构；左侧管理菜单“插件”改为“插件中心”，页面内部标题暂不扩大调整。
Calibre 来源与分类说明反馈：明确列出 Calibre 内置来源并尽量默认启用；插件管理每个分类标题下补充面向用户的用途和入口说明。实际运行时中 Google Books（插件名 Google）、Amazon.com 与 Edelweiss 支持书籍信息检索，Big Book Search、Google Images 与 Open Library 仅支持封面下载，两组必须分别表述。
AI 元数据后续反馈：不再只标记“已废弃”，先从插件列表和运行时注册表移除，待后续重构后再重新接入；实现源码与历史安装记录暂时保留。
元数据默认状态反馈：元数据主分类中的插件除 NeoDB 外首次全部启用；NeoDB 默认关闭。该规则只用于首次物化，已有管理员启停选择不得被升级或旧配置重算覆盖。

2. 目标与边界

目标

  • /api/user/devices 返回已启用且状态为 active 的推送插件类型。
  • 新增设备默认使用第一个可用类型；无可用插件时禁止新增并给出方向。
  • 全部系统内置插件由平台幂等物化，管理员只启停，不再执行“安装”。
  • 管理员采用 A 风格分组列表；停用操作只出现在详情/配置抽屉右上角。
  • 插件页分为实例级“插件管理”和当前账号“个人配置”；普通用户只进入个人配置。
  • 元数据查询只读取插件安装启停状态；免配置插件不暴露平台连接或 JSON 实现细节。
  • 生产注册表不包含测试 Provider；用户目录只返回当前注册且非隐藏的插件。
  • 插件 manifest 可声明废弃状态，目录在不改变启停事实的前提下单独展示。
  • 书源 Tab 提供可直接预览的公开免费目录，并区分“公开免费”与“权利状态混合”。
  • 系统设置不再重复呈现互联网来源和全局设备管理入口。
  • BRS 提供独立个人账号页，直接连接 BRS 完成登录、注册与密码重置。

非目标

  • 不引入组织/租户、插件商店、第三方包下载或用户代配能力。
  • 不改推送协议和设备数据库结构，不删除历史设备记录。
  • 不让管理员读取用户 Secret、私人配置或执行内容；管理员只看匿名健康汇总。
  • 不跑完整后端和全量 E2E；按用户要求只做聚焦验证。

3. 方案

设备类型单一事实源

PluginRuntime.enabled_providers(capability) 聚合安装状态；用户设备 handler 将推送 Provider 的 ui.device_type、名称与默认端口返回为 device_types。Vue 页面只消费该字段，不维护插件名或类型表。

管理员管理面采用紧凑分组列表，不再展示“实例配置”“尚未测试”等内部模型与低价值摘要。状态只描述管理员可行动的结果；账号型个人插件未绑定时统一提示“需要绑定账号”。

2026-08-29 体验迭代：双 Tab 与 A 风格列表

插件
├─ 插件管理（仅管理员）
│  ├─ 按插件类别分组的设置清单
│  ├─ 已停用行直接“启用”
│  └─ 已启用行进入详情后“停用”/维护实例配置
└─ 个人配置（当前登录账号）
   ├─ 仅列出 connection_owners 含 user 的插件
   ├─ 专用入口：微信读书工作台、阅读设备
   └─ 通用表单：按 manifest schema 保存当前用户连接

普通用户通过 /plugins 进入个人配置；管理员在 /admin/plugins 内切换两个 Tab。两处复用同一个个人配置组件和普通用户 API。管理员 Tab 不再出现“管理个人配置”跳转，避免把管理员身份与管理员自己的用户身份混为一谈。

新增普通用户目录 GET /api/plugins，只返回支持用户连接的内置插件、实例启停状态、当前用户自己的连接和运行摘要。停用插件保留连接并显示“管理员已停用”；用户 A 永远不能读取用户 B 的连接、Secret 或执行记录。

现有五个自动物化插件扩展为全部内置 provider：已有安装状态保持不变；首次物化时，原有具备初始状态策略的插件沿用该策略，其余插件默认停用，避免升级后意外打开网络访问或写权限。只为声明实例连接的插件创建内置连接，用户插件不创建伪造的实例连接。

系统设置归并与迁移

系统设置页删除“互联网书籍信息源”和“全局设备管理”两节。元数据主分类首次物化时，除 NeoDB 外默认全部启用；NeoDB 默认关闭，但旧 META_SELECTED_SOURCES 曾显式选择 NeoDB 时仍承接该选择。安装记录一旦存在，搜索与自动补全只查询启用且 active 的 metadata.lookup 插件，后续启动不得重算或覆盖管理员选择。Calibre 插件启用后固定查询 Google、Amazon.com 与 Edelweiss，不再维护第二份上游选择；只有真正需要 API 参数的插件保留字段化实例设置。

每个分类标题下显示一段简短的用户说明，解释插件能力会在什么业务入口生效。元数据分类同时指向书籍管理中的“从互联网同步书籍信息”和“自动补全设置”；不使用“右侧”等会在窄屏失真的空间方位词。其余分类分别说明综合服务、划线笔记、评价、书源、书籍工具与推送设备的用途。说明属于分类级帮助，不在每个插件行重复。

配置能力与公开书源

configuration_mode
├─ none     免配置：启停 + 详情（公开书源可直接“体验”）
├─ form     字段化设置：例如 AI API、Watch Folder、WebDAV
└─ manager  专用管理器：例如 OPDS 与 Legado

前端不根据 connection_owners 猜测是否显示配置，而是严格消费插件的 UI 声明。平台可继续为免配置插件维护隐藏内置连接，但不向普通管理员暴露连接名、role 或原始 JSON。公开来源调研证据记录于 research/public-free-book-sources-20260829/findings.md 。

按能力协议测试

插件详情
├─ metadata.lookup   ── POST /metadata/search ── MetadataProvider.search_books
├─ book_sources.*   ── POST /source/search   ── SourceProvider.search
├─ reviews.lookup   ── POST /reviews/lookup  ── ReviewProvider.get_reviews
└─ 工作台 / 推送 / 同步类插件 ── 进入各自业务页面，不显示伪通用动作

能力测试使用结构化业务输入并直接返回有限数量的领域对象摘要；它不再创建“preview/run”式通用任务。运行时仍负责安装状态、连接配置、权限、凭据解密、超时、审计与脱敏。元数据输入保留标题、ISBN、作者与出版社的结构，不压缩成一段 JSON 或“连接测试”。详情中的“权限与数据范围”默认折叠，避免低频协议字段抢占主要操作空间。

EPUB 嵌入元数据解析属于导入基础设施，保留为 webserver/services/epub_metadata.py 的内部函数，不再声明 talebook.meta.embedded-file。插件目录只返回当前注册表中的定义，因此升级前已经物化的旧内置定义不会继续显示，也不会删除其历史记录。

Legado 多能力收敛

talebook.source.legado（唯一生命周期）
├─ book_sources.browse / search / acquire
└─ metadata.lookup
   └─ 只查询 Legado 工作台中 enabled=true 的文本书源

删除独立 talebook.meta.book-source Provider，历史定义、安装和运行记录不做破坏性删除，但因不再注册而从插件目录与调度器隐藏。升级时不读取旧元数据插件状态反向开启 Legado；Legado 当前安装状态是唯一总开关。旧内置七猫快照只保留为历史候选 token 的解析材料，不进入新查询。

Calibre Provider 收敛

talebook.meta.calibre（保留）
├─ metadata.lookup ── Google / Amazon.com / Edelweiss（默认全部查询）
└─ Calibre 封面源 ── Big Book Search / Google Images / Open Library

talebook.meta.calibre-provider-bridge（删除）
└─ metadata.discover ── 仅枚举运行时 Provider，无用户业务结果

Calibre identify 注册、可用性检测和调用细节属于 talebook.meta.calibre 的内部实现，不再以独立插件暴露。插件启用后，三个 identify Provider 都参与 ISBN、书名和作者查询，并共享单次查询总超时预算，避免来源增加后线性放大等待时间；三个 cover-only Provider 一并注册到 Calibre 运行时，但不冒充可返回作者、出版社和简介的书籍信息源。Calibre 上游默认停用的 Edelweiss、Big Book Search 与 Google Images 由 Talebook 显式启用，因为管理员只使用 Talebook 插件总开关，不再维护第二套子来源状态。历史 Bridge 定义与运行记录不做破坏性删除，但注册表、插件目录和新调度均不再包含该 ID。

├─ connection_owners 含 instance ── 全局配置
└─ connection_owners 仅含 user   ── 个人设置

书籍详情 · 处理菜单
└─ GET /api/plugins/tools/book-actions?book_id={id}
   └─ enabled + active + integrations.tool + 支持当前格式
      └─ Provider name / icon / manage_route

“全局配置 / 个人设置”只表达配置与数据归属，不再由各插件自由提供按钮文案。书籍页不读取完整插件目录、不识别插件 ID，也不复制格式兼容表；后端在 Tool Provider seam 上根据安装状态、supported_formats 与当前书籍格式返回可执行动作。三个现有工作台接受 book_id 查询参数并自动选中当前书，同一路由参数变化时重新加载，仍保留书籍搜索作为兼容入口。

测试 Provider 与待重构插件隔离

talebook.mock.multi-tab 迁至 tests/ 的 fixture，只注册到测试专用 PluginRegistry；生产 ALL_BUILTIN_PROVIDERS、自动物化和两类目录接口均不再包含它。个人目录额外按当前 Registry 与 ui.hidden 过滤，使升级前遗留定义自然隐藏而无需破坏性删库。talebook.meta.ai 同样先从生产装配表移除，源码与历史数据保留，当前不显示、不自动物化，也不参与元数据调度。

全局共享设备的管理入口迁至插件中心，并按推送插件能力展示；个人设备仍由当前账号在“个人配置”维护。设备类型可选项继续完全由已启用推送插件声明，旧记录不因插件停用被删除。

BRS 快速账号页

浏览器
  ├─ 登录 ───── POST {endpoint}/api/user/sign_in ── 成功 ── 保存 Talebook 个人连接
  ├─ 快速注册 ─ POST {endpoint}/api/user/sign_up  ── 邮件接收随机密码
  └─ 忘记密码 ─ POST {endpoint}/api/user/reset    ── 邮件接收重置密码

/plugins/brs 复用 candle-reader 的三态交互，但使用 Composition API 和 Talebook 视觉体系。BRS endpoint 始终由用户明确填写；页面解析 BRS 的 JSON 错误信封并原样显示安全文案。登录失败不得保存或覆盖 Talebook 连接；登录成功后才调用现有 POST /api/plugins/connections，将 endpoint 写入公开配置，并把邮箱、密码作为加密 Secret 保存。注册与重置不在 Talebook 留存密码。

4. 风险与兼容性

  • 已保存但插件已停用的设备仍展示，类型以不可选状态标记；用户可删除或改为当前启用类型。
  • Kindle 邮件推送目前不是推送插件，因此不再出现在新增设备类型中；既有 Kindle 记录不被迁移或删除。
  • 普通用户无法启用插件；空列表文案引导联系管理员，而不是跳转到无权限页面。
