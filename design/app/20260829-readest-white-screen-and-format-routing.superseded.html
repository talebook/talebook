修复 Readest 白屏并恢复格式分流

停止 Talebook 嵌入版 Readest 对宿主站点注册根作用域 Service Worker，清理已安装的旧 Worker；同时确保 Readest 仅参与 EPUB 分流，TXT 继续进入 Talebook 专用阅读器。

状态：SUPERSEDED创建日期：2026-08-29所属模块：app影响范围：Readest 静态产物、Nginx、BookRead需求来源：PR #977 体验反馈

1. 原始诉求

“使用 Readest 点击阅读时白屏，控制台提示 Nuxt CSS 以 application/json 返回并有资源 404；另外阅读 TXT 时没有使用 TXT 阅读器。”

核查确认：旧嵌入产物会从 /readest/sw.js 注册作用域为 / 的 Worker，因而能拦截 Talebook 的 /_nuxt/ 资源；后端又在 EPUB/PDF/TXT 格式判断之前应用 Readest 默认项，导致 TXT 被错误送入 Readest 的 EPUB 限制页。

已被替代：仅保留 tombstone 无法立即触发已安装 Worker 更新，用户仍可能长期白屏。本方案由 design/app/20260830-readest-legacy-worker-cleanup-bootstrap.active.html 替代，后者由宿主页主动注销旧 Worker 并清理完整运行时缓存集合。

2. 目标与边界

  • Talebook 嵌入构建不再注册 Service Worker，不影响完整 Readest Web/PWA 和原生应用。
  • 保留稳定的 /readest/sw.js 注销脚本，使旧浏览器能删除 Readest 的 Serwist 缓存并注销根作用域 Worker。
  • EPUB 仍按 Readest/Candle 设置选择；PDF、TXT 仍使用各自专用阅读器；MOBI/AZW/AZW3 继续先转 EPUB。
  • 不扩大 Readest 嵌入模式支持格式，不改动阅读权限和下载权限。

3. 实现流程

停止新增污染Talebook profile 禁用 Serwist，生成的主 bundle 不包含 serviceWorker.register。
清理历史状态构建产物保留无缓存 tombstone；Nginx/Nuxt 允许旧根作用域注册更新到该脚本，随后注销并刷新受控页面。
恢复格式路由BookRead 先判定实际格式，仅在存在 EPUB 时应用 Readest 选择，TXT 直接跳转 /book/:id/readtxt。

4. 风险与兼容

风险处理
旧 Worker 继续控制已经打开的页面Tombstone 使用 skipWaiting，删除仅以 serwist- 开头的缓存，注销后导航刷新窗口。
注销脚本被长期缓存Nuxt route rule 与两套生产 Nginx 配置均对该 URL 设置 no-store。
影响独立 Readest PWA禁用条件仅为 talebookExport；普通 Web 和其他平台配置不变。
Kindle 格式转换等待页找不到 Readest 模板转换期间显式复用 Candle 等待页；转换后重新进入时按 EPUB 默认项打开 Readest。

5. 测试结果

  • Readest build:talebook-static：通过，2 个 worker，产物 406 个文件；无残留 Next/PostCSS 子进程。
  • 静态契约检查：31 个 Reader HTML 引用均存在；主 bundle 不含注册调用；无 swe-worker；tombstone 含注销逻辑。
  • make lint-py：通过；ruff 与 Python 语法检查通过。
  • 本机缺少 Calibre Python 模块，tests/test_readest_embed.py 无法启动；已补 TXT 分流和静态产物回归用例，交由 PR CI 的 Calibre 环境执行。
