阅读笔记与来源治理

让读者在书籍详情和阅读过程中辨认、筛选并管理来自 Talebook 与外部阅读服务的笔记，同时保留无法精确定位的章节级记录。

状态：ACTIVE创建日期：2026-08-16所属模块：app需求来源：TB-44

1. 原始诉求

“展示原生及外部导入的高亮、笔记、书签，支持按来源筛选；CFI 可用时精确定位，CFI 为空时按章节展示并明确降级；支持删除自己的笔记，以及按 run/source 撤销导入数据。”

2026-08-17 视觉反馈：“视觉太松散了！笔记的数量是非常多的，你要紧凑一些。”

2. 目标与边界

目标

  • 同一组件覆盖书籍详情和阅读器入口。
  • 来源、类型、章节、原文、时间和定位能力一眼可辨。
  • 加载、空、权限、删除竞态、定位失败和部分回滚均有可行动反馈。
  • 键盘、焦点、窄屏与明暗主题可用。

非目标

  • 不在本任务内实现外部平台认证和导入器。
  • 不改变“来源清理只解除映射、不删除权威正文”的服务端语义。
  • 不在 Candle Reader 内创建或编辑笔记；本期展示和导航。

3. 产品功能矩阵

4. 现状与证据

  • /api/book/:id/annotations 已返回 annotation 与 sources；CFI 允许为空。
  • DELETE /api/annotations 按 source 筛选只删除来源映射。
  • 当前返回未暴露列表项的 owner 能力，前端无法可靠隐藏他人的删除操作；本次增加只读 can_edit 能力字段。
  • 主 EPUB 入口是 Candle Reader 的服务端模板，需以宿主覆盖层接入，避免修改 vendored reader bundle。

5. 方案

读取

统一组件调用书籍笔记 API。

辨认

按来源和类型分组，显示来源徽标。

行动

精确定位、删除或按批次撤销。

反馈

刷新权威列表并保留成功或降级提示。

界面方向

采用“高密度批注账本”：保留克制的蓝灰主体和卡片左侧来源线，但删除装饰性眉题，把类型、来源、章节和降级状态合并到同一元数据行；引用、正文、时间和定位紧随其后。信息不折叠、不截断，只压缩无语义留白。桌面端典型含引用与正文的卡片目标不超过 150px，移动端不再强制把时间与定位拆成上下两行。

关键决策

决策选择理由
组件所有权Nuxt 共享组件；Candle Reader 使用轻量原生宿主避免直接改动打包后的第三方阅读器，同时让详情页保留完整管理体验。
定位协议详情页 query + 阅读器事件/URL 桥接CFI 存在时尝试精确定位；无 CFI 时只展示章节说明。
列表密度单行元数据 + 紧凑正文节奏高笔记量场景优先提高纵向吞吐，不通过截断隐藏内容，也不缩小交互命中区。
删除权限服务端提供 can_edit不泄露 reader id，也不让客户端猜测所有权。
来源撤销source/run/connection 三元筛选与 API 契约一致，避免误删相邻导入批次。

6. 影响、风险与回滚

影响

新增共享笔记组件、详情页入口、阅读器覆盖层、i18n、mock/E2E/组件测试，以及 API 权限能力字段。

风险与回滚

Candle Reader 的定位 API 可能因版本差异不可用，必须显式反馈定位失败且保留章节信息。可独立移除宿主脚本和组件，不影响 annotation 数据或 API 写入。
