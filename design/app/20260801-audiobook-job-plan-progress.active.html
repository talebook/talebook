真实过程与可展示信息

步骤真实来源展示内容无数据时
任务入队Talebook 创建任务创建时间、优先级、模式、引擎、语速、章节选择始终存在
识别书籍phase_started: INSPECTING 与 inspect 完成事件章节数、角色数、开始/完成时间执行中显示不定进度，不虚构细分百分比
脚本审核Talebook AWAITING_REVIEW / confirm高级模式等待审核；快捷模式明确标记“自动跳过”不隐藏该步骤

生成片段segment_completed已完成片段数、缓存命中数、章节百分比只展示计数，不展示内部 fingerprint
完成章节chapter_completed时长、文件大小、片段数、是否整章续跑复用等待生成
整理产物Talebook 导入 manifest 与章节记录明确的 FINALIZING 阶段执行前显示待处理
终态completed / cancelled / failed完成、取消或失败位置；错误码、错误消息、是否可重试始终可判定

整体进度算法

整体百分比是“真实里程碑 + 已完成片段”的确定性计算，不是剩余时间预测：

入队 0%→ 识别中 5%→ 识别完成 15%→ 审核完成/跳过 20%→ 片段生成 20%–95%→ 整理产物 98%→ 完成 100%
  • 生成区间按 已完成片段 / 总片段 线性计算；整章续跑复用按该章全部片段完成计入。
  • 失败或取消保留停止时的百分比，配合失败阶段展示，不倒退。
  • 旧任务缺少章节计划时仍展示阶段和已有 job.progress，明细标记“历史任务无逐章数据”。

接口与持久化

GET /api/audio-jobs 增量返回

  • book：id、title、author、img、thumb。
  • plan.overall_percent：0–100 整数。
  • plan.phases：步骤、状态、时间、摘要。
  • plan.summary：章节/片段/缓存/重试计数。
  • plan.chapters：每章标题、状态、片段进度、时长、大小、续跑标记。

数据策略

  • 不建表：精简章节计划写入现有 AudiobookJob.data JSON。
  • 每次事件采用复制后整体赋值，保证 SQLAlchemy JSON 变更可追踪。
  • 任务列表批量读取书籍，避免前端逐任务请求形成 N+1。
  • API 只返回 UI 需要的稳定字段，不暴露脚本正文、路径或指纹。
兼容性处理
旧任务没有 plan服务端从现有 phase/progress/data 生成兼容摘要，前端不报错。
书籍已删除book 为 null，保留“已删除书籍 #ID”回退文案与任务操作。
Voicebook 新事件保留 last_event，但未知事件不进入公开 plan 契约。
重试/断点续跑保留已完成章节；重置当前失败状态，累计 attempts、cache_hits、resumed。

风险与控制

风险控制状态
长篇小说产生大量 DOM只有当前任务展开；章节区域使用定高滚动，避免同时渲染多张展开卡。已控制
轮询导致展开状态丢失仅保存稳定的 job id，不把响应对象作为展开状态。E2E 通过
事件重复导致计数膨胀继续使用 seq 幂等门禁，并按章节/片段索引更新而非盲目追加。幂等测试通过
进度看似精确但不可解释界面注明“整体进度”，方案固定权重；不展示 ETA。已定义
真实书籍隐私扩散仅登录且有权查看任务的用户获得书籍摘要；不增加新的匿名接口。权限不扩大

回滚：移除导航项和展开 UI，并停止写入新的 plan 字段即可；新增 JSON 字段可被旧代码忽略，无数据库降级操作。
