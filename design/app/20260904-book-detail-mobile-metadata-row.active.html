修复移动端书籍元数据同排显示

在窄屏保留稳定的字段名列，让元数据名称和值优先同排展示，长值只在自身区域内换行。

状态：ACTIVE创建日期：2026-09-04所属模块：app影响范围：书籍详情页与 E2E需求来源：TB-202

1. 原始诉求

“书籍详情页在手机模式下，元数据的 name 和 value 换行了。应当尽量保持在同一行。”

2. 目标与边界

目标

  • 390px 与 320px 手机视口中，元数据字段名和值保持左右同排。
  • 字段值可在右侧剩余空间内自然换行。
  • 不产生页面水平滚动，不影响已有标签和阅读状态操作。

非目标

  • 不调整字段顺序、数据来源、文案或业务交互。
  • 不修改桌面布局、后端接口、权限或数据模型。
  • 不重构详情页其他区域。

3. 现状与根因

app/pages/book/[bid]/index.vue 的元数据默认使用 76px minmax(0, 1fr) 两列 Grid，但在 480px 以下被媒体查询改成单列，导致每个 dt 与 dd 必然上下排列。该断点覆盖与“优先同排”的目标直接冲突。

4. 方案

结论：删除 480px 以下强制单列的覆盖，移动端沿用已有的固定字段名列与弹性值列。字段值列保留 minmax(0, 1fr) 和现有换行能力，因此短值同排、长值在值列内折行。
  • 保持字段名称起始位置和字段值起始位置稳定，延续桌面端信息扫描方式。
  • 用 E2E 在 390×844 和 320×800 下逐行断言值列位于名称列右侧，并检查文档宽度不超过视口。
  • 保留现有 chip 换行、评分、阅读状态和格式操作样式，不新增响应式特例。

5. 影响、风险与回滚

影响范围

书籍详情页局部响应式 CSS、书籍详情 E2E 和本方案文件。

主要风险

超长值或多枚标签会增加值列高度；通过允许值列内部换行和 320px 水平溢出断言控制风险。

回滚：恢复 480px 以下单列覆盖并删除对应 E2E 断言即可；无数据迁移或兼容性清理。
