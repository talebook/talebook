BookCards 固定高度修复

把由简介长度撑开的书籍列表卡片收回统一的 150px 规格，让首页与所有复用 BookCards 的列表重新形成稳定、可扫读的书架节奏。

ACTIVE · 已完成验证 创建日期 2026-07-30 所属模块 app 分支 fix/20260730-book-card-fixed-height 需求来源 用户截图反馈

01. 原始诉求与问题取证

原始诉求：“开个 git wt 处理这个样式问题：book card 高度异常，应该是固定高度的卡片形式，解决，并让我本地体验。”用户进一步确认：修复应用到所有使用 BookCards 的列表，但不包含 BookCards_Small；验收须导入 Docker 默认书籍并用真实封面截图。实现验收中用户追加反馈“封面下面有一个空白”，因此同一修复补充了封面贴齐卡片底边的约束。

截图中的短简介卡片约为 150px 高；长简介卡片会增长到约 220px，导致同一三列网格出现明显的高低错位。当前 app/components/BookCards.vue 只对标题和简介设置行数截断，外层 v-card 没有高度与溢出边界，富文本简介仍能参与行高计算并撑大卡片。

观察现有行为结论
短简介或“暂无简介”卡片高度接近封面自然高度，约 150px以 150px 作为既有视觉基线，不重新设计卡片比例
长简介外层卡片随内容增长，三列网格失去基线必须约束卡片本身，而不是只依赖文本截断
组件复用首页、书库、分类、最近、热门、私有书籍和网络书籍搜索结果共用 BookCards修复应落在共享组件，页面不分别覆写
相似组件BookCards_Small 仅用于详情弹窗，并带独立操作区按用户决定明确排除，避免改变操作区布局

02. 目标与边界

必须达成

固定规格，内容不再撑高

  • 每个 BookCards 卡片外框固定为 150px 高。
  • 标题继续单行截断，简介最多展示三行；超出内容隐藏。
  • 短简介、长简介、无简介、有“已读”标签和连载状态标签时高度一致。
  • 存在封面时，封面区域贴齐卡片底边，不在图片下方留下空白条。
  • 桌面和移动视口均无溢出、重叠或横向滚动。

明确不做

不扩大视觉改版范围

  • 不修改 BookCards_Small、首页纯封面推荐卡或空状态卡片。
  • 不修改 API、书籍数据、简介内容或国际化文案。
  • 不改变三列响应式栅格、封面宽高比、主题颜色和阴影。
  • 不新增高度配置项；当前规格作为共享组件内部契约。

04. 实现方案

在 BookCards.vue 的书籍 v-card 上增加组件专用类，并由 scoped CSS 设置 height: 150px 与 overflow: hidden。内部行吸收 Vuetify 栅格的 12px 负 gutter，封面列与图片占满可用高度，因此图片从卡片顶边连续覆盖到底边；标题、简介和可选状态标签维持现有内容层级。这样每个调用页面自动获得同一规格，不需要页面级样式。
文件计划变更回归保护
app/components/BookCards.vue给书籍卡片和封面增加明确类名；固定 150px 高并隐藏超出区域；让内部布局与封面受该高度约束不使用全局 .v-card 选择器，避免影响空状态、导航卡和其他组件；封面底边纳入浏览器几何断言
app/test/components/BookCards.nuxt.spec.ts补充短简介、长简介、无简介样本，断言每张书籍卡都挂载固定高度专用类保护共享组件契约及现有链接、已读标签行为
app/test/e2e/home.spec.ts读取首页“新书推荐”中的多张卡片边界，断言高度均为 150px，并断言封面底边等于卡片底边用真实浏览器布局弥补 happy-dom 不计算 CSS 尺寸的限制

06. 风险、兼容性与回滚

风险控制

  • 固定高度可能在窄屏裁掉状态标签：移动视口必须实际验收标题、简介和标签组合。
  • 富文本简介可能包含异常块级元素：外层卡片溢出边界作为最终保护。
  • 主题可能覆写 Vuetify 卡片样式：浅色与深色分别检查计算高度。

兼容与回滚

不涉及 API、数据、权限、迁移或配置，发布沿用现有前端构建流程。若出现不可接受的裁切，可整体回退组件样式与对应测试；无需后端操作。
