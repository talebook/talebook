并行预加载 Readest 启动资源

状态：ACTIVE · 创建日期：2026-09-06 · 所属模块：app / scripts/readest · 需求来源：TB-204

原始诉求

开发者要求进一步提速，允许向 readest-reader 提交 PR，并建议在“正在启动 Readest 阅读器”阶段加载部分资源。

目标与边界

把启动页权限校验与阅读器公开 JS/CSS 下载重叠，缩短整个点击阅读到页码出现的时间，而不是把等待转移到另一个画面。保持鉴权、失败恢复、Candle 回退、EPUB 字节校验、书籍标识与目录/进度语义不变。当前预览维持已部署 99217c09，候选用隔离 Docker 验证；新部署需要确认。

grill 技能不可用，按需求确认以下保守边界：只预取公开同源哈希静态资源，不提前读书籍、不运行阅读器脚本、不加等待倒计时、不增加跨会话私有内容缓存。本轮如改动仅在宿主，则更新 Talebook PR，无需为宿主逻辑修改上游。

现状与证据

启动页 talebook-launch.js 等待 reader-bootstrap 后才 location.replace；reader.html 才发现 Next JS/CSS。现有优化版已经减少 Range、预hash和缩略图开销，但两个页面的静态下载仍串行。预加载跨导航能否复用、是否挤占权限请求必须用真实浏览器验证。

方案

  1. 同步产物时从 reader.html 提取本构建真实引用的静态资源，选取少量关键 JS/CSS，在宿主启动页 head 中生成低优先级 preload；不手写漂移的 chunk 名称。
  2. 仅接受 /readest/_next/static/ 内的现存 JS/CSS，去重、限制数量，排除 nomodule。同步脚本幂等刷新，避免升级后预载过期路径。
  3. 权限请求保持独立；预加载不作为启动门槛，失败由 reader 正常请求回退。浏览器不支持 hint 时保持原流程。
  4. 测量全新浏览器 context 的自然冷开及慢 bootstrap 场景；记录资源开始时间、重复下载和全流程计时，必要时调整资源选择，不宣称秒开。

影响、风险与回滚

影响宿主启动 HTML、同步脚本与测试。低带宽下预加载可能争用连接；无权限/无效入口也可能下载少量公开程序资源，但不得请求 EPUB。静态资源与哈希变更要同步。回滚宿主 HTML 与脚本即可，无数据迁移。原生阅读器不受影响。

测量驱动的迭代

首版7资源 preload：100 ms/10 Mbps 单轮 baseline 15.528秒，candidate 15.771秒。权限响应427→764ms，部分较大请求跨导航未完成，只有3项缓存命中。拒绝这版；调整为仅预加载2个小型框架/主入口脚本，不占满HTTP/1连接，避免大CSS/阅读页bundle跨导航浪费。
