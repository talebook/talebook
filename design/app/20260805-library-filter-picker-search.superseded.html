1. 原始诉求

“浮窗里面要支持搜索。”

上一版已经把上万项元数据放入可分页浮窗，并保留主页面紧凑标签列表。新要求是在浮窗内补充快速定位能力，解决冷门作者、出版社和标签需要连续翻页的问题。

替代说明：搜索交互继续有效，但本方案的 13px / 32px 密度已被 design/app/20260805-library-filter-density-refinement.active.html 的 12px / 28px 高密度规格替代。

2. 结论与边界

搜索是浮窗目录的辅助工具。搜索框固定在标题与滚动标签区之间，对当前已加载的名称做客户端包含匹配；结果沿用每页 100 项的分页和原有单选行为。
保留主页面前 10 项、显示更多、紧凑 13px 标签、单选和后端排序。
新增名称搜索、结果数、清除入口、无结果状态以及分页自动归一。
不做不新增后端接口，不搜索书籍正文，不增加多选、模糊拼音或高级语法。
性能最多过滤约 15,000 个短字符串；计算结果缓存，DOM 仍最多显示 100 个标签。

3. 视觉与信息层级

主题：延续“图书馆目录卡”浮窗，新增一条固定的“查找带”。它像实体目录柜上的检索卡：边界清楚、位置稳定，但不抢走标签目录的主体地位。

  • 搜索区使用中性浅表面和蓝灰边线，输入高度约 40px；标签继续使用 13px、32px 高和 6px 间距。
  • 搜索时标题摘要切换为“找到 n / 总数项”，让筛选范围可见；无关键词时仍显示总项数。
  • 桌面搜索区与页脚固定，只有标签区域滚动；移动端保持全屏浮窗，搜索区不随结果滚走。

4. 交互与可访问性

  1. 打开浮窗时清空上次搜索；没有搜索词时，若已有选中项，仍打开其所在页。
  2. 输入去除首尾空格后按名称做大小写不敏感的包含匹配，每次变化回到结果第一页。
  3. 搜索结果继续每页 100 项；选择标签后立即关闭浮窗并刷新书单，主页面显示该选中项。
  4. 无结果时显示“没有匹配项”和“清除搜索”；清除后恢复完整目录第一页。
  5. 搜索框有可见标签、清除按钮和键盘焦点；标签继续提供 aria-pressed，浮窗继续支持 Escape。

5. 风险与回滚

匹配预期首版只做名称包含匹配，不承诺拼音、同义词或分词；文案使用“输入关键词筛选”说明范围。
移动端键盘浮窗打开时不强制聚焦，避免软键盘遮挡浏览；用户点击搜索框后再唤起键盘。
性能过滤使用 Vue computed 缓存，分页切片基于过滤结果；不会把全部结果渲染到 DOM。
回滚移除查找带和过滤计算即可恢复上一版浮窗；API、URL 与数据库均无变化。

7. 决策记录

  1. 2026-08-05：用户要求浮窗支持搜索；搜索作为标签浏览的补充，不改变主页面交互。
  2. 2026-08-05：选择客户端名称包含匹配，避免增加接口和网络往返。
  3. 2026-08-05：搜索区固定、结果继续分页；移动端不自动聚焦，优先保留浏览空间。
  4. 2026-08-05：用户反馈标签仍过大，本方案由高密度视觉方案替代；浮窗搜索、分页和选择逻辑保留。
