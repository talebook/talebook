重构书籍详情页信息与操作布局

以书名、封面与元数据、唯一操作区、内容与笔记四个稳定区块重建详情页层级，消除重复入口；四区只表达信息层级，不使用黑色描边或割裂式卡片边界。

状态：ACTIVE创建日期：2026-08-31所属模块：app影响范围：书籍详情页与 E2E需求来源：TB-194

1. 原始诉求

“当前页面中按钮出现重复，布局混乱，手机模式下按钮展示不完整，需要重构。参考图片分为 4 个区：1. 书名标题；2. 封面 + 元数据（以及上传时间、上传者等等）；3. 操作按钮区（浏览者的阅读、下载等，管理员的写操作按钮）；4. 内容简介、划线笔记等等。”

后续反馈明确：参考图仅用于表达分区，不应复刻黑色边框；详情页应主要通过留白和排版层级形成连续整体，操作、上传信息及批注区域不使用外层容器底色。后续反馈进一步要求书名下移靠近封面、阅读/书架状态迁入元数据且删除操作区旧入口、简介占满可用宽度；UX 复验又要求两条状态行统一为“字段名｜当前状态｜操作”，修复 chip 与 44px 按钮混排、未加入时方形 tonal 按钮及两行无稳定列基准的问题。最新反馈要求两条状态行的视觉行高回归其他元数据行，同时保留 44px 可点击热区且不让热区参与布局。

现页同时在顶部工具栏和下方卡片提供阅读、下载、发送到设备，在顶部与阅读状态卡片重复提供书架操作；窄屏依赖工具栏折行，操作顺序和分组不稳定。

2. 目标与边界

目标

  • 每个用户操作只有一个可见入口。
  • 页面按四区顺序呈现，标题只出现一次。
  • 四区不使用黑色描边或独立卡片边界，以留白和排版层级保持整体感。
  • 管理员写操作与读者主操作在同一操作区分组；阅读与书架状态只在元数据区出现。
  • 简介不设置最大行宽或额外横向 padding。
  • 320px 起不产生水平溢出，全部操作保持可触达。
  • 保留当前权限、菜单行为、对话框与后端请求。

非目标

  • 不修改 API、权限或数据模型。
  • 不重做发送、格式转换、元数据同步等对话框。
  • 不改变在线阅读、漫画、有声书与插件工具的业务条件。
  • 不新增封面或元数据字段。

3. 现状与根因

现象证据结论
阅读、下载、发送入口各出现两次app/pages/book/[bid]/index.vue 顶部工具栏与下方 Action Buttons同一任务被两个表现层分别实现，没有单一操作区。
书架操作出现两次顶部工具栏与独立阅读状态卡片阅读状态与页面主操作没有统一分组。
内容简介混在元数据卡中封面右侧第二段 v-card-text信息浏览与长内容阅读层级不清。
移动端仅让工具栏自动折行.book-action-toolbar 窄屏样式按钮宽度、顺序和管理分组无法保证，文字较长时仍拥挤。

4. 方案

结论：页面本身拥有唯一的主操作区；阅读与书架状态则归入元数据，不在操作区保留旧入口。对话框和业务方法保持原位；四区外框和容器底色全部移除，以连续留白与标题层级建立分区。
书名

独立 H1，下移并将封面前间距收敛到 26px 内。

封面与元数据

阅读与书架共用“字段名｜当前状态｜操作”三列语义，两者切换互不清除。

操作

只保留阅读、下载、发送、有声书及拥有者菜单，不重复状态操作。

内容

简介取消 75ch 上限和横向 padding，桌面与移动端占满第四区。

交互与响应式决策

  • 阅读始终显示“想读/在读/已读”chip；书架始终显示“未加入书架/已加入书架”chip，右侧分别提供下一状态和加入/移除操作。
  • 两行内部统一为 112px 状态列 + 8px 间距 + 操作列；chip 均为 112×30px、同圆角与 18px 图标，操作统一使用无背景、无边框的 text 层级。
  • 状态操作恢复 Vuetify small 按钮的 28px 可见盒；通过绝对定位伪元素把命中区垂直扩展到 44px，伪元素不参与 Grid 尺寸计算，因此桌面控制行保持 30px，移动端含字段名的整行保持 56px。
  • 桌面字段行垂直居中；480px 以下字段名独占上一行，两条内部列起点和宽度保持一致。44px 命中区必须可由实际命中测试验证，不能仅记录 CSS 声明。
  • 管理员组继续使用“文件处理”“管理”两个菜单；操作区按“阅读 → 下载 → 发送到设备 → 有声书”排序。
  • 关键入口加入稳定测试标识，E2E 校验状态循环、统一结构、双视口几何与窄屏边界。

5. 影响、风险与回滚

影响范围

书籍详情模板与局部样式、书籍详情 E2E、双语区块文案。

保持不变

已有对话框、方法、API 请求、角色判断、阅读器路由和批注组件。

风险：合并入口时可能遗漏条件操作或让菜单在窄屏不可达。通过拥有者普通书、漫画书、不兼容格式书和 390px 视口 E2E 覆盖；人工渲染同时检查深浅主题与水平溢出。

回滚：仅回滚页面、文案、测试和本方案文件，不涉及迁移或数据清理。

7. 决策记录

  1. 2026-08-31：需求已明确给出四区结构；实现按该结构收敛，不再保留“工具栏 + 快捷卡片”双入口。
  2. 2026-08-31：读者操作和管理员操作同区分组，不用移动端抽屉隐藏能力，确保窄屏任务可见。
  3. 2026-08-31：保持所有业务条件与方法不变，本轮只重构信息架构和响应式表现。
  4. 2026-08-31：interface-review 初审后将操作区和简介标题明确为 H2、拥有者分组保留 H3，为封面补充 alt，并把简介行宽收敛到 75ch；复审通过。
  5. 2026-08-31：Chrome DevTools MCP 记录到仓库既有的 SSR hydration mismatch；实际浅色、窄屏和深色渲染均无可见错位，相关 E2E 全通过，本次不扩大到 SSR 数据装载重构。
  6. 2026-08-31：根据反馈明确把参考截图仅视为信息架构示意；移除标题饰线、三个区块外描边、操作区分隔线和批注外框，改为弹性留白、排版层级与封面承托色。
  7. 2026-09-01：UX 复验要求进一步去卡片化：移除操作区整块渐变与圆角、上传信息灰底圆角、批注外层浅灰背景与圆角，保留现有四区间距、按钮主次和移动端单列行为。
  8. 2026-09-01：按最新反馈将标题下移并收窄封面前间距；把阅读三态与书架状态迁入元数据、删除操作区原入口；用户明确要求简介全宽，因此取消初审采用的 75ch 上限及横向 padding，并用双视口几何断言保证左右额外间距为 0。
  9. 2026-09-01：按 UX 复验统一两条状态行为“字段名｜当前状态｜操作”：未加入书架也始终显示 chip，两个操作均使用 text 层级；固定共同的状态/操作列与视觉规格，同时保留 44px 点击热区和现有独立状态逻辑。
  10. 2026-09-01：按最新视觉反馈把 44px 命中区从 Grid 布局尺寸中剥离：按钮恢复 28px 可见盒，透明伪元素扩展到 44px；视觉行高回归其他元数据范围，并用双视口几何与实际命中测试防止回归。
