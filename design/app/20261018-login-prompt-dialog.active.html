需要登录时就地弹出登录浮窗

游客访问需要登录的页面或操作时，不再跳转到登录页，而是在当前页面上叠加全页蒙版和登录浮窗；登录成功后当前页面原地重新加载内容。

状态：ACTIVE 创建日期：2026-10-18 所属模块：app 影响范围：app/ 登录入口、路由中间件、backend() 错误信封；spec/用户.md 需求来源：Rex 在项目中的原话

1. 原始诉求

“优化登录窗口的体验：任何页面需要登录时，应该是整个页面蒙版+弹出登录浮窗，登录完毕后当前页面直接加载内容或者刷新。”

现状是任何需要登录的场景都跳转到独立的 /login 页面，读者离开了正在看的页面，登录后再靠 next 参数跳回（部分入口甚至没有带 next，登录后回到首页）。

2. 目标与边界

目标

  • 需要登录的路由（如「我的」下各页面）在原地址显示全页蒙版和登录浮窗，登录前不渲染页面内容。
  • 任意接口返回 user.need_login 时，在当前页面弹出登录浮窗，页面保持在原地址。
  • 头部「请登录」、书籍详情阅读状态、TXT 阅读页、应用接入页的登录入口都改为打开浮窗。
  • 登录成功后不跳转、不整页刷新：当前页面重新挂载并以登录身份重新加载数据。
  • 取消登录：非必须登录的页面仅关闭浮窗；必须登录的页面返回上一页（没有上一页时回到首页）。

非目标

  • 保留 /login 独立登录页及其 next 参数，供直接访问、书签与外部链接使用。
  • 不改变后端接口与登录协议。
  • 社交账号登录仍是整页跳转到第三方授权，回调行为不变。
  • 由后端直接提供的阅读器页面（candle-reader 内的「登录后查看评论」）不在本次范围，仍走登录页。

4. 方案

方案结论：登录状态由 useMainStore 的 loginPrompt（show / requiredPath / hint）统一承载；所有登录入口只调用 openLoginPrompt()，布局中唯一的 LoginPrompt 浮窗负责展示。登录表单抽成 LoginForm 组件，由独立登录页与浮窗共用。
Trigger需要登录

auth 中间件（required）、接口 need_login、登录按钮

Prompt全页蒙版 + 浮窗

required 时页面不渲染；地址栏不变

LoginLoginForm 登录

沿用验证码、找回密码、注册入口

Reload页面原地重载

clearNuxtData + authEpoch 递增使页面重新挂载

关键决策

决策点选择理由放弃项
登录后如何加载内容给 NuxtPage 加 authEpoch key，登录后递增并清空 asyncData 缓存页面所有数据请求（onMounted、useAsyncData）自动以登录身份重跑，头部布局不闪烁location.reload()：最稳但整页白屏重载；逐页监听登录事件：改动面太大
必须登录的页面登录前显示什么页面不渲染，只显示布局、蒙版与浮窗避免页面以游客身份发出必然失败的请求与错误提示渲染页面再盖蒙版：会触发一串 need_login 请求与报错
浮窗与全局错误提示浮窗打开时收起并抑制全局 alert页面因未登录产生的错误提示没有意义，登录错误由表单内联展示两个模态叠加
浮窗生命周期路由 path 变化时由全局中间件关闭浮窗，导航完成后再解除旧页面的 requiredPath浮窗只属于触发它的页面；新页面需要登录时再由 auth 中间件打开跨页面保留浮窗
SSR服务端中间件与 backend() 只写 store 状态，随 Pinia 注水到客户端直接打开需要登录的地址时首屏即为蒙版状态，无跳转服务端 302 到登录页

5. 影响范围、风险与回滚

影响范围

前端：stores/main.ts、app.vue、两个布局、middleware/auth.ts、新增 middleware/login-prompt.global.ts、plugins/talebook.js、新增 components/LoginForm.vue 与 components/LoginPrompt.vue、pages/login.vue、两个头部、书籍详情、TXT 阅读页、应用接入页。产品行为：spec/用户.md 的「登录 / 退出」入口描述。

保持不变

后端接口、/login 与 /signup 页面地址、登录页的 next 回跳、社交登录、验证码流程。

主要风险：登录后页面重新挂载，页面内未保存的本地状态（例如表单输入）会丢失 → 只在登录成功时触发，且未登录时这类写操作本就失败。浮窗期间全局 alert 被抑制 → 登录接口自身的网络错误由表单内联提示兜底。
回滚：纯前端改动，回滚提交即可，无数据迁移。

7. 决策记录

  1. 2026-10-18：保留 /login 独立页供直接访问；站内所有登录入口改为浮窗。
  2. 2026-10-18：登录成功采用页面原地重新挂载而非整页刷新。
  3. 2026-10-18：实现偏离：最初用布尔 required 标记页面需要登录，取消时导航途中页面会先渲染并再次触发未登录。改为记录 requiredPath，导航完成后（router.afterEach）才解除，页面在离开前始终不渲染。
  4. 2026-10-18：登录成功后用 authEpoch 重新挂载浮窗里的表单，避免下次打开时残留已填写的密码。
  5. 2026-10-19：按 Rex 反馈把蒙版改为页面背景色（亮色主题为白色）、不透明度 0.94 加模糊，基本看不到背景内容；暗色主题跟随深色背景，避免整屏刺眼的白。
  6. 2026-10-20：处理 Codex 评审：独立登录页不叠加浮窗；关闭浮窗后焦点还给打开它的控件；页面首次加载期间（导航开始到 page:finish）发出的请求返回未登录时，按「必须登录」处理，覆盖未挂 auth 中间件的管理页等。新增 2 条 E2E，login-prompt 共 7 条通过。
