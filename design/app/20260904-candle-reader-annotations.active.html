1. 原始诉求

“candle-reader 自身闭环实现所有的 UI，提供划线笔记的 UI、功能、框架，并且设置选项里允许关闭；对外提供 callback，让 Talebook 注入读取、写入笔记，未注入时默认写浏览器 localStorage。”

现状是 Talebook 的 creader.html 在阅读器外再次实现选择工具栏、笔记编辑器、浮动入口、列表侧栏和 EPUB 高亮，随后替换 candle-reader 的 selected 监听，形成两套 UI 和事件所有权冲突。

2. 目标与边界

目标

  • 选择文本、划线、写笔记、查看与定位均由 candle-reader UI 完成。
  • 提供异步 load / save 回调契约，Talebook 只负责接 API。
  • 无回调时按书隔离写入 localStorage。
  • 设置主开关可关闭评论加载、选区动作和标记，保留统一入口与数据。

非目标

  • 不改变 Talebook 注释后端的数据模型和 HTTP API。
  • 本次不新增删除、编辑、冲突合并与离线服务端同步。
  • 不改章评后端、有声书播放逻辑及旧阅读器；整合社区与笔记入口。

3. 方案

结论：candle-reader 暴露 annotation_callbacks，内部统一标准化回调结果、渲染标记与反馈。Talebook 登录态注入 API 适配器；游客不注入并自然使用本地存储。

回调契约

annotation_callbacks: {
  load: async ({ book_id, book_url, chapter }) => Annotation[] | { annotations: Annotation[] },
  save: async (annotation) => Annotation | { annotation: Annotation }
}

数据流

  1. 章节变化或用户打开笔记面板时，阅读器调用 load；未注入则读取按书隔离的 localStorage。
  2. 用户选择文字后由阅读器展示工具栏，划线直接保存，笔记经阅读器对话框编辑后保存。
  3. 保存成功后阅读器渲染 EPUB CFI 高亮并刷新列表；宿主错误只通过阅读器统一反馈，不静默降级到本地。
  4. Talebook 模板删除外挂 DOM/CSS/事件替换，仅保留 API 回调和现有社区兼容代理。

4. 兼容性、风险与回滚

场景行为兼容策略
独立 candle-reader本地读取、保存、显示笔记新参数可选，旧初始化代码无需修改
Talebook 登录用户回调访问现有 annotations API沿用现有字段、权限、cookie 与错误语义
Talebook 游客无服务端回调，使用本地存储不再渲染可能泄露私密内容的外挂 iframe
关闭笔记功能保留统一入口并提示去设置开启；隐藏选区动作，不加载标记/评论不删除已有数据，重新开启即可恢复
主要风险：两个仓库必须按“先发布 candle-reader，再更新 Talebook 静态包”交付；以 Talebook 内同步构建产物和模板测试避免回调先于运行时代码上线。回滚以两个仓库各自提交为单位，不涉及数据迁移。
