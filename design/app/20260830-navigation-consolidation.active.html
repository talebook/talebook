整合书库、阅读与系统设置导航

把书库浏览、我的阅读和系统设置三组路由页签统一为已确认的标题型样式，并删除子页面中重复表达当前页的“书库”“插件”“主题管理”“私有书籍”等标题。

状态：ACTIVE 创建日期：2026-08-30 所属模块：app 影响范围：主导航、路由页签、插件中心、个人阅读与推送设备 需求来源：会话内界面反馈

“个人插件里的推送设备设置应跳到 /me/devices；设备表单文字不能被顶部挡住；恢复 Kindle 邮箱推送功能。”

已确认版本以路由级 Tab 取代聚合页独立标题：选中项 24px / 700 / 主题色，未选中项 16px / 600 / 中性灰并下移 2px；文字到亮条可见净距为 8px。正式实现覆盖本次导航整合产生的三组路由 Tab。

2. 目标与边界

目标

  • /library/*、/me/*、/admin/settings/* 统一使用已确认的大页签，并让左侧主导航按路径前缀持续选中对应聚合入口。
  • 每个 Tab 内页在大页签下方渲染同一规格的说明栏：左侧灰色小字，存在页级操作时放在右侧；路由壳层不重复渲染说明。
  • 把管理员插件页的个人设置迁移到 /me/plugins，并命名为“个人插件设置”；把用户中心内嵌的“基本信息 / 阅读设备”提升为 /me/account 与 /me/devices 两个路由级 Tab。
  • 所有推送插件把个人管理入口直接声明为 /me/devices；设备表单保留浮动标签所需顶部空间并在 320px 下改为分行布局；把既有 Kindle 邮箱推送能力补成可启停、默认启用且使用官方品牌图标的 talebook.push.kindle Provider。
  • 底部帮助按钮默认透明，只在真实交互态高亮；长导航在管理菜单展开后由菜单内容区独立滚动，帮助入口固定留在侧栏底部。
  • 帮助菜单采用紧凑列表：Logo 置顶，链接项使用小字号和窄图标间距，版本与用户数使用标准列表项表达。
  • 删除子页面重复页级标题和多余嵌套边距；系统设置说明栏与内容区共享水平 margin / padding 基线；把旧 OPDS / WebDAV 页的客户端、配置步骤和注意事项完整迁入“使用 App 访问”。

非目标

  • 不改变搜索/浏览、阅读中/已读等仍有独立任务语义的页面内部功能 Tab。
  • 不删除 Moke、OPDS、插件分类、设置分区等真实内容标题。
  • 不改变既有权限模型、数据库结构或外部 API 兼容约定。

4. 现状、根因与证据

观察权威证据结论
独立大标题压过页签app/components/RouteTabShell.vue：标题最大 1.75rem，页签仅 .875rem 且 compact。层级问题来自字号、留白与组件密度共同作用，不是只把 Tab 字号调大。
路由与内容已经稳定app/pages/library.vue 与三个子路由。原型只替换壳层渲染，复用真实内容，避免把内容差异误判成导航差异。
验证结论：复用既有路由与页面语言、把标题职责收进路由页签，能够得到用户确认的大 Tab；无需再引入独立页标题或第二层聚合容器。

5. 方案

正式方案：把已确认的标题型页签收敛进公共 RouteTabShell，把说明与页级操作收敛进公共 RoutePageToolbar。壳层只负责页签和内容插槽；每个内页负责自己的说明和操作，避免重复说明与插件页二次容器。
Route进入真实书库页面

保留当前路径、登录态和内容数据。

Shell公共壳层统一

三组路由共享同一字号、颜色、对齐、亮条和分割线规则。

Content删除重复页标题

只删除与当前路由 Tab 同义的标题，保留内容分区标题和操作。

Verify跨页面验证

检查三组路由、移动端横向滚动和无重复标题。

6. 影响范围、风险与回滚

影响范围

公共路由 Tab 壳层、三个聚合页、个人资料与设备路由、两套侧栏滚动布局、帮助菜单、本地书库、私有书籍、插件中心、主题管理，以及“使用 App 访问”的 OPDS / WebDAV 指引内容。

保持不变

权限、用户资料与设备保存协议、内容分区标题保持不变；旧设备查询参数通过重定向兼容。Kindle 发送仍复用既有 SMTP 与格式转换能力，只补齐插件注册和统一入口。

主要风险：公共壳层同时影响三组页面，完整指引也会增加 App 页高度。已通过公共组件、41 条相关 E2E、320px 设备表单、键盘导航、暗色主题和真实 Docker 页面截图覆盖；剩余风险主要是不同自定义主题可能对共享 Vuetify 变量产生额外覆盖。
回滚：恢复公共壳层的独立标题和 compact 样式，并恢复四处子页面页级标题即可；无数据与接口清理。

8. 决策记录

  1. 2026-08-30：用户明确否定“大标题 + compact Tab”，要求先看多个大 Tab 版本。
  2. 2026-08-30：原型使用现有路由和真实内容，通过开发态 query 切换；选定前不改正式交互、不更新 PR。
  3. 2026-08-30：移动端不依赖横向自动滚动，三个大页签固定同屏；保留图标与名称，隐藏说明，确保活动项始终可见。
  4. 2026-08-30：用户否决 A/B/C 全部重设计，要求只在当前版本上把 Tab 提升到标题位置并使用 H1 字号；旧原型和切换器必须删除。
  5. 2026-08-30：实际渲染发现 Vuetify 的按钮字号变量覆盖外层 Tab 规则；H1 字号需同时落到 --v-btn-size 与文字内容层。Tab 组下增加贯穿内容区的 1px 分割线，活动项短线叠加其上。
  6. 2026-08-30：用户确认 28px 过大，桌面上限降为 24px，保持标题型 Tab 层级但降低视觉压迫感。
  7. 2026-08-30：用户明确最终采用 H2 视觉规格；Tab 保持导航语义，避免为视觉效果创建三个文档标题。
  8. 2026-08-30：用户进一步指定精确字号为 20px，替代此前 24px 方案。
  9. 2026-08-30：未选中 Tab 降为 18px、600 字重和中性灰；选中项保持 20px、700 字重和主题色。
  10. 2026-08-30：未选中 Tab 进一步降为 16px，并将内容整体下移 2px，使其与 20px 选中项形成底部对齐。
  11. 2026-08-30：用户反馈文字与活动亮条间距过大；Tab 从居中布局改为贴底布局。4px 试稿过紧；直接使用 8px 内边距时会包含 4px 亮条，视觉净距仍只有 4px，因此最终使用 12px 内边距，并以 DOM 几何位置验证文字到亮条净距为 8px。
  12. 2026-08-30：用户指定选中 Tab 使用 24px，替代此前 20px；未选中项仍为 16px。
  13. 2026-08-30：用户确认当前视觉版本，要求推广到本次导航整合的其他路由型 Tab，并删除内页重复页级标题；页面内部二级功能 Tab 不提升层级。
  14. 2026-08-30：补齐先前导航合并的内容漏项：旧 OPDS / WebDAV 介绍页中的地址说明、常用客户端、配置步骤和注意事项全部迁入 /library/apps；旧路径继续重定向。
