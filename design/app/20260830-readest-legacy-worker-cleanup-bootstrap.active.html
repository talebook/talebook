主动清理 Readest 遗留根作用域 Worker

让 Nuxt 宿主页与 Readest 静态入口都主动注销旧 /readest/sw.js Worker、删除其运行时缓存并刷新受控页面，不再依赖浏览器未来某次周期性更新。

状态：ACTIVE创建日期：2026-08-30所属模块：app影响范围：Nuxt head、Readest 静态入口、Nginx需求来源：PR #977 再次白屏反馈

1. 原始诉求

“修复readest仍然白屏，然后控制台日志显示 Refused to apply style from http://127.0.0.1:9000/_nuxt/entry.Qt6l3l2G.css because its MIME type (application/json) is not a supported stylesheet MIME type；CKHYTMRW.js 404。”

现象说明浏览器实际执行了旧 Nuxt HTML 中的资源引用，而当前 Nuxt 服务已不再提供对应 hash，404 JSON 又因严格 MIME 检查不能作为 CSS 使用。

2. 根因与证据

证据结论
旧 Readest bundle 以 {scope: "/"} 注册 /readest/sw.js，并用 offline-cache 缓存几乎所有同源 HTTP 请求。Worker 能控制 Talebook 的 /_nuxt/ 与 /read/:id，把旧 HTML/资源缓存带入 Nuxt。
上一轮产物移除了注册调用，只保留 /readest/sw.js tombstone。新页面不再主动请求 Worker 更新；已安装 Worker 只能等待浏览器周期更新，用户可持续处于污染状态。
tombstone 只删除 serwist-*。旧 Worker 的 client-pages、offline-cache、fonts-cache 未被清除。

3. 目标与边界

目标
  • 当前页面发现旧 Worker 后立即注销并刷新。
  • 只删除可确认属于旧 Readest 的缓存。
  • Nuxt 和 Readest 两个入口均能触发恢复。
非目标
  • 不恢复 Readest PWA 注册。
  • 不清除 Talebook cookie、IndexedDB 或其他站点缓存。
  • 不改变阅读权限、资源 URL 与格式路由。

4. 方案

稳定脚本新增固定 URL 的兼容清理脚本，保证旧 Worker 可从网络取得。
精确识别仅匹配 scriptURL 路径为 /readest/sw.js 的 registration/controller。
注销清理注销 registration，删除 serwist 前缀和三类旧 runtime cache。
脱离控制仅当当前页面由旧 Worker 控制时刷新一次；注销后不会形成循环。

脚本同时由 Nuxt 全局 head 和 readest/reader.html 最前部加载；两套 Nginx 与 Nuxt route rule 对稳定 URL 设置 no-store 和 nosniff。

5. 风险与回滚

  • 额外请求：所有 Nuxt 页面会请求一个很小的同源脚本；无旧 Worker 时立即退出。
  • 误删风险：不按根 scope 粗略匹配，只按旧 Readest scriptURL；缓存名使用旧产物中的确定集合。
  • 回滚：删除 head/reader 引用、兼容脚本和专用缓存规则即可，无数据迁移。
