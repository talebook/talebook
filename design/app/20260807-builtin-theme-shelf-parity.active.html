内置主题“我的书架”导航一致性修复

让所有非默认内置主题与默认主题保持一致：已登录用户可在左侧栏进入“我的书架”，游客不显示该入口；同时确认系统设置保存不会再清除当前激活主题。

状态：ACTIVE 创建日期：2026-08-07 所属模块：app 影响范围：内置主题共享导航、前端回归测试 需求来源：TAL-6 / GitHub Issue #941

原始诉求与根因

Issue #941 报告两个问题：非默认主题左侧栏缺少“我的书架”；激活非默认主题后，再次保存系统设置会恢复默认主题。

默认主题

AppHeader.vue 会在 store.user.is_login 为真时加入 /user/shelf。

→

非默认内置主题

五个主题共用 BuiltinThemeHeader.vue，其 navItems 未加入书架项，属于导航定义遗漏。

设置保存问题已由当前基线的 design/webserver/20260806-admin-settings-preserve-config.active.html 修复：保存候选以完整 CONF 为基线，页面仅覆盖白名单字段，因此 ACTIVE_THEME 会保留。此次不重复修改后端，只执行针对性回归验证。

目标、边界与决策

  • 浅灰、极简、石墨、黄铜、暖红五个非默认内置主题均显示相同的书架入口。
  • 入口只对已登录用户显示，使用既有文案 navigation.myShelf、图标 mdi-bookshelf 和路径 /user/shelf。
  • 位置与默认主题一致：在书库/有声书入口之后、管理员入口之前。
  • 不改变默认主题、不调整书架页面或权限接口、不重构整个导航模型。
  • 不把 ACTIVE_THEME 暴露为管理员设置页面可写字段；保留应继续由服务端完整候选机制保证。

实现与验证路径

01 · NAV

补齐入口

在共享 navItems 中按登录态插入书架项，一次覆盖五个主题。

02 · COMPONENT

组件回归

分别断言游客隐藏、登录用户显示，并核对链接目标。

03 · SETTINGS

持久化回归

运行现有后端测试，确认保存配置前后的 ACTIVE_THEME 均为原值。

04 · RENDER

实际渲染

连接真实 Docker 后端，在桌面 Chrome 验证非默认主题侧栏与设置保存后的主题状态。
