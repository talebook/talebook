有声书剧本生产边界与修订工作台方案

把剧本内容质量收回 Voicebook 的“新剧本生产”职责；Talebook 只编排任务、保存版本、展示生产报告，并继续提供可编辑、可局部返工、可回滚的管理工作台。

ACTIVE · 已验证 创建日期：2026-08-03 所属模块：app（主） 影响范围：webserver / tests / Voicebook 集成契约 需求来源：PR 929 架构边界纠正

01 / 原始诉求与最终澄清

只保证以后生产正确，不治理历史存量

“这个优化应该由 voicebook 来做，你要遵守好二者的能力界限。”
“为什么增加这些新命令？已有的剧本就不用管它了，大家只负责产生新的剧本时能正确就行了。”

本方案纠正原方案把剧本规范化放进 Talebook 的设计。新边界不增加管理员命令、迁移脚本或补跑入口，也不在创建修订版本时偷偷重写已有剧本。

  • 新剧本：Voicebook 的既有 inspect / convert 流程从原书构建正确章节、正文、语言感知切片与 locator。
  • 已有剧本：保持原样；仍可查看、编辑、创建版本并调用 generate 返工音频，但不会自动清洗 CSS、重命名章节、重新切片或重编号。
  • Talebook：不理解 EPUB 正文规则，不引入 YAML 解析依赖，不复制 Voicebook 的清洗算法。

02 / 能力边界

生产者对内容负责，宿主对生命周期负责

Voicebook · 剧本生产者

  • 利用 HTML / spine / nav / NCX 解析章节
  • 在提取层排除样式、脚本、封面等非正文
  • 恢复可读章节标题，无法恢复时诚实兜底
  • 按确定性、语言感知规则生成语义切片
  • 同步生成可追踪 locator
  • 在既有完成事件中报告生产统计
BOOK.SCRIPT + EVENT

Talebook · 任务宿主

  • 新书发起 inspect；已有剧本发起 generate
  • 保存剧本文件与版本关系
  • 提供审核、编辑、章节返工入口
  • 候选音频成功后原子发布
  • 保留和显式清理历史备份
  • 原样展示 Voicebook 的生产报告
行为VoicebookTalebook
判断 CSS / 非正文拥有规则并测试不得实现
章节标题恢复与文本切片从原书生成新剧本时完成不得二次加工
剧本人工编辑与版本链无状态 CLI，不持有拥有工作流与持久化
章节 / 整本重新生成generate 只读剧本并生成音频决定范围并编排
已有剧本自动修复不补跑不迁移、不改写

03 / 唯一跨界契约

Talebook 只接收产物与报告

Talebook新书调用既有 inspect
→
Voicebook解析并生成干净的新剧本
→
book.script章节、片段、角色与 locator
+
completed event可选、有界 normalization 计数
→
工作台保存并原样展示

Voicebook 在既有 JSONL inspect completed 事件中增加可选的 normalization 对象，只含前后章节数、前后片段数、移除/改名计数和 locator 降级计数，不携带正文或无界数组。Talebook 仅把它保存到 Job.data 并用于 UI 摘要；字段缺失或未来出现未知字段时继续展示已知计数，不自行扫描剧本来“补”报告。

  • 不增加 normalize 子命令。
  • 不让 Talebook 读取 YAML frontmatter 来推导内容质量。
  • Voicebook 固定到推送后的不可变 commit，保证生产契约可复现。

04 / 保留的 Talebook 产品能力

版本、编辑和安全替换继续由工作台承担

能力行为边界约束
查看与编辑剧本完成任务也能查看；创建候选版本后编辑片段。复制内容时保持原样，不做隐式清洗。
单章返工只改对白且章节结构不变时，允许高级模式重生成当前章。Talebook 选择范围；Voicebook generate 不修改输入剧本。
整本返工结构变化或管理员主动选择时生成完整候选版。仍使用已有剧本调用 generate；候选完成前线上版本不变。
发布替换候选音频完整成功后由管理员确认，原子切换当前版本。失败产物永不覆盖线上版。
备份清理默认保留 3 个历史版，可配置 0–20；仅显式点击清理。不删除当前版、候选版和运行中任务。

05 / 明确不做

不存在“顺手修复旧数据”

  • 不为已有 book.script 增加迁移、批处理、管理命令或定时任务。
  • 从旧版本创建修订版时只复制原剧本；若管理员要修正，只通过显式人工编辑完成。
  • 不在 Talebook 中保留 CSS 检测、自然章节名识别、句子切分、locator 重写代码。
  • 不改变旧版本的播放结果，也不承诺旧剧本出现生产报告。
  • 不依据 normalization 报告决定是否允许返工；报告只用于解释新书 inspect 的生产结果。
