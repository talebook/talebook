书籍详情页离场请求修复

当用户从详情页进入“最近”列表时，让详情数据加载随详情路由一起结束，不再把已经消失的书籍参数拼成后端请求。

ACTIVE · 已验证 创建日期 2026-07-30 模块 app 需求来源 用户缺陷反馈

01. 原始诉求与可观察症状

用户从书籍详情页点击 navbar 的“最近”后，列表页会弹出 404；网络请求显示前端访问了 http://127.0.0.1:8080/api/book/undefined。
操作预期当前异常
打开 /book/{bid}请求当前书籍详情详情正常加载
点击 navbar 的 /recent仅加载最近书籍列表详情组件离场时又请求 /book/undefined
进入列表页无错误弹窗无效详情请求触发 404 弹窗

02. 目标、边界与已确认决策

必须达成

详情请求只属于有效详情路由

  • 详情页首次打开仍请求正确的书籍 ID。
  • 详情页离场时不请求 /book/undefined。
  • 从详情页进入 Recent 后，列表正常展示且没有相关错误弹窗。

明确不做

不扩大到全局容错

  • 不在全局 backend() 静默过滤包含 undefined 的 URL。
  • 不修改 Recent API、后端路由或错误提示策略。
  • 不借机重构详情页其他数据与交互。

用户已确认采用局部生命周期修复。该选择保留全局 API 层对调用错误的可见性，避免掩盖其他无效参数来源。

03. 根因假设与验证顺序

优先级可证伪假设预测
H1详情页的响应式 useAsyncData key 依赖全局路由参数；离场时参数先清空、组件后卸载，触发一次重取捕获客户端导航网络请求时，会在 /recent 期间观察到一次 /api/book/undefined
H2navbar 自身拼出了错误详情 URL检查链接属性会出现书籍详情地址，而不是 /recent
H3Recent 列表数据包含缺失 ID 的书籍卡片并在加载时自动打开直接打开 /recent 也会发出相同无效请求

验证结论：H1 成立。本地 Nuxt 实现会监听响应式 key 并在 key 变化时初始化新数据项；修复前回归用例连续两次均捕获到一次无效请求。navbar 的实际链接为 /recent，且直接 Recent 加载不会触发详情请求，H2 与 H3 被排除。

04. 请求航迹与修复点

  1. 详情数据 key 使用进入该详情组件时确定的有效书籍 ID，不把离场后的空路由参数作为新数据源。
  2. 保留详情路由之间切换书籍时的正确刷新能力；若实现需要响应路由变化，则只接受有效 ID。
  3. 回归测试在真实导航链路捕获所有请求，直接断言无 /api/book/undefined。

05. 实现影响与风险

位置计划变更兼容性与风险控制
app/pages/book/[bid]/index.vue限制详情数据源只对有效书籍 ID 发起请求，避免离场重取不改变模板、接口形状或服务端契约；验证客户端切换书籍仍刷新
app/test/e2e/book-detail.spec.ts新增“详情页点击 Recent”网络回归用例直接覆盖用户操作与精确异常 URL

回滚：改动仅在详情页数据加载逻辑和测试，可整体回退；无数据库、配置或迁移步骤。
