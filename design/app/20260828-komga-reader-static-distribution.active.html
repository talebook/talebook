将漫画阅读器改为版本化静态 JavaScript 分发

沿用 Candle Reader 的浏览器 bundle 集成边界，移除 Talebook 在安装期从 Git 构建 Vue 包的耦合，同时保持漫画 API 和用户体验不变。

状态：ACTIVE创建日期：2026-08-28所属模块：app影响范围：komga-reader、app、依赖分发需求来源：TB-131 用户反馈；Talebook PR #1012

1. 原始诉求

“能不能使用 candle-reader 的同款 js 方式” / “read-comic 目录为什么存在，不应该交给后端处理吗”

原 PR 通过 package.json 固定 Git commit，并在 npm 安装时构建 Vue 组件；第一轮静态化仍错误保留了 Nuxt host page。Talebook 的 Candle Reader 实际由后端路由渲染轻量模板，用户要求漫画阅读器与其端到端对齐。

2. 目标与边界

目标

  • 上游提供不依赖宿主 Vue 解析的 standalone ESM/UMD 和 CSS。
  • Talebook 固定、同源托管已构建产物并动态挂载。
  • 删除 Git npm 依赖和安装时构建。
  • 保持 /read-comic、manifest、图片及进度契约不变。

非目标

  • 不发布 npm、不合并上游 PR、不创建 GitHub release。
  • 不改漫画归档安全、权限或数据库。
  • 本轮不启用依赖 latest release 的自动更新，待上游首次 release 后沿用 Candle 工作流。

3. 现状与证据

观察证据结论
原库产物不能被浏览器原生直接加载dist/komga-reader.js 含裸 from "vue"需要 bundle Vue 并提供生命周期 facade。
Candle Reader 的 host 由后端拥有BookRead、webserver/resources/book/creader.html静态资源之外，漫画的入口、权限预检和 HTML host 也应归 Tornado，而不是 Nuxt 页面。
Nginx 原规则不会把连字符路径送给 Tornado^/(api|get|read|…)/ 不匹配 /read-comic/dev、SPA、SSR 三套配置都必须显式代理 read-comic。

4. 方案

方案结论：在 komga-reader 增加 new Reader(target, options) 浏览器 facade 和自包含 bundle；Talebook 固定产物，由 ComicReaderHandler 校验访问后渲染 book/comic-reader.html，模板按版本 URL 动态 import 并管理 API 与 Reader 生命周期。
Route后端预检

Tornado 校验登录、可见性、阅读权限、媒体类型和容器后才返回 host HTML。

Pin固定产物

记录上游 commit，提交 ESM、UMD、CSS、LICENSE 和 NOTICE。

Mount模板挂载

后端模板取得 manifest/进度后实例化 Reader，回调保存进度。

Dispose安全销毁

刷新或离页先保存待写进度并 destroy，避免监听器和 Vue app 泄漏。

5. 影响、风险与回滚

影响范围

上游 standalone API、后端漫画 route/template、三套 Nginx 路由、前端入口链接及静态资源；删除 Nuxt app/pages/read-comic。

保持不变

用户 URL、Reader 界面、manifest/图片/进度 API、归档资源预算、进度 JSON 和既有非漫画阅读器。

主要风险：bundle 内自带 Vue 会增加约 41.84 KiB gzip；通过独立页面按需加载、同源长期缓存和版本 URL 限制影响。三套 Nginx 配置用静态测试锁定后端代理，防止路径落回 SPA/SSR。
回滚：移除后端 host route/template 并恢复 Nuxt 页面即可；无数据迁移，API 不回滚。
