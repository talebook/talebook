将漫画阅读器改为版本化静态 JavaScript 分发

沿用 Candle Reader 的浏览器 bundle 集成边界，移除 Talebook 在安装期从 Git 构建 Vue 包的耦合，同时保持漫画 API 和用户体验不变。

状态：ACTIVE创建日期：2026-08-28所属模块：app影响范围：komga-reader、app、依赖分发需求来源：TB-131 用户反馈；Talebook PR #1012

1. 原始诉求

“能不能使用 candle-reader 的同款 js 方式” / “那你直接开始调啊”

当前 PR 通过 package.json 固定 Git commit，并在 npm 安装时构建 Vue 组件。Talebook 已有 Candle Reader 的版本化静态 bundle 模式，用户要求漫画阅读器与其对齐。

2. 目标与边界

目标

  • 上游提供不依赖宿主 Vue 解析的 standalone ESM/UMD 和 CSS。
  • Talebook 固定、同源托管已构建产物并动态挂载。
  • 删除 Git npm 依赖和安装时构建。
  • 保持 /read-comic、manifest、图片及进度契约不变。

非目标

  • 不发布 npm、不合并上游 PR、不创建 GitHub release。
  • 不改漫画归档安全、权限或数据库。
  • 本轮不启用依赖 latest release 的自动更新，待上游首次 release 后沿用 Candle 工作流。

3. 现状与证据

观察证据结论
当前库产物不能被浏览器原生直接加载dist/komga-reader.js 含裸 from "vue"需要 bundle Vue 并提供生命周期 facade。
Candle Reader 使用稳定静态入口webserver/resources/book/creader.html、app/public/static/candle-reader/漫画阅读器可复用同源静态资源和版本缓存策略。
宿主仍需控制 API 和状态app/pages/read-comic/[bookId].vuestandalone 只负责渲染，回调继续交给 Nuxt 页面。

4. 方案

方案结论：在 komga-reader 增加 new Reader(target, options) 浏览器 facade 和自包含 bundle；Talebook 将该 commit 的产物固定到 public 静态目录，由 Nuxt 页面按版本 URL 动态 import，销毁时调用 destroy()。
Build上游构建

Vue、组件和 facade 打入 standalone ESM/UMD，CSS 单独输出。

Pin固定产物

记录上游 commit，提交 JS、CSS、LICENSE 和 NOTICE。

Mount浏览器挂载

Nuxt 取得 manifest/进度后实例化 Reader，回调保存进度。

Dispose安全销毁

刷新或离页先 unmount，避免监听器和 Vue app 泄漏。

5. 影响、风险与回滚

影响范围

上游构建配置、standalone API、Talebook 漫画页面、前端锁文件及静态资源。

保持不变

用户路由、界面、API、权限、归档资源预算、进度 JSON 和既有非漫画阅读器。

主要风险：bundle 内自带 Vue 会增加约 100 KiB 级静态体积；通过独立页面按需加载、同源长期缓存和版本 URL 限制影响。静态文件与版本不匹配会在模块加载阶段进入现有错误态。
回滚：恢复 Git npm 依赖和 Vue 组件导入即可；无数据迁移，后端不回滚。
