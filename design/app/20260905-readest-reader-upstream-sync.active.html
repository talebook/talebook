将 Talebook Readest 静态阅读器迁移到独立上游

以可复现、可追溯的方式，用 hehetoshang/readest-reader 的 Reader-only 静态产物替换 PR #977 中来自旧仓库的完整 Readest 构建，同时保持 Talebook 的权限、Range 资源与回退协议。

状态：ACTIVE创建日期：2026-09-05所属模块：app影响范围：静态阅读器、启动器、测试与部署契约需求来源：TB-204 / PR #977

1. 原始诉求

“更新 Talebook 当前 Readest 相关 PR 中使用的阅读器实现，使其同步到新的上游仓库 https://github.com/hehetoshang/readest-reader/；保留阅读入口、书籍加载、鉴权和资源访问能力，并完成构建、验证与 PR 回传。”

现有 PR #977 把 hehetoshang/readest@5eaf1013f 的完整静态导出放在 app/public/readest。独立上游已收敛为 Reader-only 边界，且最新提交加入了 Talebook 在线 EPUB source adapter。

2. 目标与边界

目标

  • 固定并记录独立上游提交与构建参数。
  • 保留 /readest/talebook-launch.html 到同源授权 EPUB 的启动链。
  • 保留 HEAD、Range、ETag、MIME、权限失败和 Candle 回退契约。
  • 删除旧构建不再需要的 library/account/worker 产物。

非目标

  • 不引入 Readest 账号、云端书库或支付能力。
  • 不改变 Talebook 登录与书籍可见性规则。
  • 不实现 PDF/TXT 经 Readest 打开。
  • 不修改独立上游的 Moke/Tauri 原生契约。

3. 现状与证据

观察证据结论
PR #977 的静态产物来自旧仓库PR 正文固定 hehetoshang/readest@5eaf1013f来源需改为独立上游并落盘记录。
独立上游没有 release/tagmain@a4fc84077ad4f4c490305961235086f25bd4da12本次固定完整 commit SHA，而不是漂移分支名。
新上游已有安全在线 source adaptermokeRemoteSource.ts 校验同源路径、revision、HEAD、Range、ETag 和 MIMETalebook 启动器须补充 mokeSourceServerUrl。

4. 方案

方案结论：在独立上游检出固定 SHA、初始化其 vendor 后，以 NEXT_PUBLIC_APP_PLATFORM=web 构建 Reader-only 静态导出；同步 out/readest 到 Talebook，保留 Talebook 自有 launcher/legacy worker tombstone，新增来源清单与一致性测试。
固定来源

记录仓库、完整 SHA、版本和构建 profile。

构建同步

安装锁定依赖、生成 vendor 并构建静态 Reader。

协议适配

launcher 传入同源 server 与授权 EPUB URL。

验证交付

运行两仓测试、Talebook 构建与浏览器关键流程。

5. 影响、风险与回滚

影响范围

app/public/readest 构建产物、Talebook launcher 参数、Readest 的 CSP/跨源隔离响应头、静态资源契约测试和 PR 说明。后端 bootstrap/resource API 维持现状。

保持不变

/read/:id 入口、登录/游客/激活权限、EPUB revision、Candle 显式回退、Nginx 私有缓存与 byte-range 转发。

主要风险：新静态构建是 Moke-oriented Reader profile；浏览器托管必须强制 web platform。上游仍会发出不影响阅读的 Tauri bridge 诊断，且 Talebook 的严格 CSP 会拒绝外部在线字体并回退到本地字体。回滚单位是本次同步提交，无数据迁移或清理。

7. 决策记录

  1. 2026-09-05：选择独立上游最新主分支完整 SHA，因为仓库尚未发布 tag/release。
  2. 2026-09-05：Talebook 浏览器构建显式覆盖为 web platform，避免依赖 Tauri IPC，同时复用上游浏览器 fetch transport。
  3. 2026-09-05：保留 Talebook 自有 launcher 与 worker tombstone；两者属于宿主协议与历史兼容，不属于上游 Reader 产物。
  4. 2026-09-05：为上游 Reader 增加最小化 wasm-unsafe-eval、data fetch、blob worker 和 COOP/COEP，仅用于 WebAssembly/worker；跨域字体仍由 CSP 阻断。
