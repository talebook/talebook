阅读器产物改用 npm 包引入，不再提交进仓库

内置 EPUB 阅读器 candle-reader 的打包产物原先直接提交在 app/public/static/candle-reader/ ，每次升级或联调同步都会在 git 历史里留下一份。改为 talebook 在 app/package.json 锁定 npm 包 @talebook/candle-reader 的版本，构建时由 Nuxt 本地模块把产物同步到原来的静态目录。

状态：ACTIVE 创建日期：2026-10-10 所属模块：app 影响范围：app 构建、Docker 前端构建阶段、.github 自动化；不涉及 spec/ 需求来源：项目对话（Rex）

1. 原始诉求

“调整一下 candle-reader 和 talebook 的版本集成方案，改成 submodule 会不会更好？节省 git 仓库空间？”

评估后不采用 submodule：candle-reader 仓库不提交 dist，submodule 只能拿到源码，talebook 构建要多一段 vite build；递归克隆还会带上约 27 MB 的 .git 和 23 MB 的演示 epub；不带 --recursive 克隆或下载 ZIP 会得到空的阅读器目录。用户确认改为发布 npm 包，版本号使用日期版本（tag v26.10.09 ，npm 版本 26.10.9 ）。candle-reader 侧的发布流程已在 talebook/candle-reader#21 合并，26.10.9 已发布到 npmjs。

2. 目标与边界

目标

  • 阅读器产物不再进入 talebook 的 git 历史，升级只改 package.json 与 package-lock.json 中的版本号。
  • Nuxt dev、SSR 构建、SPA 构建与 Docker 镜像中，/static/candle-reader/ 下的文件与锁定版本完全一致。
  • 后端 candle_reader_version() 、creader.html 、Nginx 的静态路径都不变。
  • 新版本由 Dependabot 自动提升级 PR。

非目标

  • 不重写历史，已提交的约 5.5 MB 产物保留在历史里。
  • 不改变阅读器功能、界面或回调契约。
  • komga-reader 等其他内置静态产物不在本次范围。
  • 阅读器 style.css 内联图标字体（gzip 后约 3.5 MB）的体积问题另行处理。

3. 现状、根因与证据

观察权威证据结论
产物直接提交在仓库.github/workflows/update-candle-reader.yml 下载 release 的 dist.zip 后 git add -f 提 PR；联调时 make install 直接拷入并提交每次同步都新增一份产物，2026-10-09 一天就有 9 次同步提交
历史占用完整克隆 2493 个提交，pack 236 MB；candle-reader 相关 123 个对象压缩后约 5.5 MB历史体积不大，但会随同步频率持续增长
npm 包内容与仓库现有产物一致npm pack @talebook/candle-reader@26.10.9 后与 HEAD 中 20 个文件逐一 cmp20 个文件逐字节相同，切换不改变线上阅读器
后端版本号与文件内容绑定webserver/handlers/book.py 的 candle_reader_version() 对 candle-reader.es.js 取 sha256静态路径不变即可，后端无需修改

4. 方案

方案结论：版本由 app/package.json 精确锁定，app/modules/candle-reader/ 这个 Nuxt 本地模块在每次 Nuxt 启动（prepare、dev、build、generate）时，把 node_modules/@talebook/candle-reader/dist/ 拷到 app/public/static/candle-reader/ ，并写入 .npm-version 标记；版本相同则跳过。目标目录加入 app/.gitignore 。
Releasecandle-reader 打 tag

v26.10.09 触发 release.yml，经 Trusted Publishing 发布 26.10.9

UpgradeDependabot 提 PR

只跟踪 @talebook/candle-reader ，改 package.json 与 lock

Installnpm ci

按 lock 安装锁定版本到 node_modules

SyncNuxt 模块拷贝

dist/ 写入 public/static/candle-reader/，随构建输出进入镜像

关键决策

决策点选择理由放弃项
引入方式npm 包Dockerfile 已有 npm ci 并支持 npmmirror；版本锁定与升级交给 lock 和 Dependabotgit submodule（需在 talebook 构建源码、克隆体验差）；构建时下载 release dist.zip（国内访问 GitHub 不稳定）
同步时机Nuxt 本地模块 setupdev、build、generate 都会加载模块，覆盖 npx nuxt dev 这类不经过 npm script 的启动方式；Docker 中模块在 COPY app/ 之后的构建步骤运行postinstall（Docker 的 npm ci 阶段还没有复制源码）；prebuild/predev 钩子（npx nuxt dev 不触发）
本地联调CANDLE_READER_SKIP_SYNC=1 时不覆盖candle-reader 的 make install 拷进来的本地产物不会被下次启动冲掉按文件时间判断新旧（不可靠）
缺包时的表现直接报错并提示执行 npm ci避免静默产出缺少阅读器的构建静默跳过
 
# 升级：通常由 Dependabot 提 PR，也可手动
cd app && npm install --save-exact @talebook/candle-reader@26.10.10

# 联调本地阅读器：在 candle-reader 中 make dist install 后
CANDLE_READER_SKIP_SYNC=1 API_URL=http://127.0.0.1:8080 npx nuxt dev --port 3000 --host 127.0.0.1

5. 影响范围、风险与回滚

影响范围

新增 app/modules/candle-reader/ 、app/test/utils/candle-reader-sync.spec.ts 、.github/dependabot.yml ；修改 app/package.json 、app/package-lock.json 、app/.gitignore 、CODE_WIKI.md ；删除 app/public/static/candle-reader/ 的 20 个已提交文件、candle-reader-version.txt 和 .github/workflows/update-candle-reader.yml 。产品行为不变（阅读器文件逐字节一致），因此不涉及 spec/ 。

保持不变

静态访问路径 /static/candle-reader/ 、creader.html 、后端缓存版本号算法、Nginx 配置、阅读器回调契约。

主要风险：26.10.9 是手动发布的，包内多了 demo.html 与 out.png 两个构建残留，会随之出现在 /static/candle-reader/ 下；它们不被阅读器引用，之后由 CI 从干净构建发布的版本不会再带上。构建环境装不到 npm 包（registry 不可达）→ Nuxt 启动时模块报错、构建失败 → 失败信息明确指向 npm ci ；国内构建通过 BUILD_COUNTRY=CN 走 npmmirror，npmmirror 会自动从 npmjs 同步新版本。已有本地 checkout 的开发者在拉取后，原来的已提交文件会变为被忽略的未跟踪文件，下次 Nuxt 启动时自动替换为锁定版本。
回滚：revert 本 PR 即恢复已提交产物与旧的同步 workflow，无数据迁移。
