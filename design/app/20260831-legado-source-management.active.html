完善 Legado 书源管理入口、导出与示例导入

让管理员从网络书库直接进入 Legado 工作台，完整导出当前书源，并从明确的示例列表导入；同时量化 tickmao 书源被后台停用的真实原因。

状态：ACTIVE创建日期：2026-08-31所属模块：app影响范围：app、webserver、tests需求来源：TB-195

1. 原始诉求

“网络书库中，如果是管理员，增加一个按钮【管理书源】跳转到对应页面；Legado 书源管理页面增加【导出】按钮；【导入内置书源】改成【导入示例书源】，并提供下拉框加入 tickmao full.json 与 shidahuilang good.json；测试 tickmao JSON 为什么大量导入失败。”

2. 目标与边界

目标

  • 管理员在网络书库始终可见“管理书源”，直达 /plugins/legado。
  • 工作台导出全部书源为标准 Legado JSON 数组，并同步当前启用状态。
  • 示例导入明确区分内置样例和两个远端订阅。
  • 用真实 tickmao 文件给出可复核的失败分类。

非目标

  • 不改变 Legado 规则引擎的 JavaScript 安全边界。
  • 不放宽后台体检对失效站点的停用策略。
  • 不改数据库结构，不覆盖同 URL 的本地书源。
  • 不把第三方订阅打包进仓库。

关键区分：import_sources() 会先写入 201 项并排队检测；所谓失败发生在异步有效性检测，而不是 JSON 下载、解析或数据库批量导入阶段。第三方文件中的 _validation_status=valid 全为 valid，但它代表上游校验口径，不等于 Talebook 的非 JS 兼容性和当前部署网络可达性。

4. 方案

管理入口

复用书库页工具栏，仅管理员渲染按钮。

导出

管理员 JSON API 按稳定顺序返回全部 raw；前端生成 UTF-8 文件。

示例导入

内置项走 seed API，远端项复用 URL import API。

反馈

沿用现有导入统计、错误提示和后台检测。

关键决策

  • 导出接口返回标准 JSON 信封，由既有 $backend 完成权限错误处理；文件下载在浏览器端生成，避免绕过统一 API 调用层。
  • 导出数据以原始 Legado 对象为基础，但用数据库当前名称、地址、分组、类型、权重和启用状态覆盖对应字段，避免管理后的状态丢失。
  • 下拉框把远端 URL 当作配置值，不代理、不缓存；确认后复用现有服务端下载与导入逻辑。

5. 影响、风险与回滚

影响范围

网络书库工具栏、Legado 工作台、导入对话框、双语文案、mock API、书源管理 API 与对应测试。

保持不变

登录与管理员权限、去重语义、异步体检、数据库 schema、搜索和阅读接口保持不变。

风险：第三方 URL 可能不可用或内容变化；导入失败沿用现有错误信封。大量导出会在浏览器内构造 JSON，但当前可导入规模远低于既有 100MB 请求容量；测试覆盖多项和状态同步。

回滚：回退新增 API、按钮、选项和文案即可，不产生迁移或数据清理。
