插件目录分类与配置入口优化

让插件目录按 canonical plugin ID 的类型段形成单一分类，突出已启用状态，并把个人配置与实例配置送到正确入口。

状态：ACTIVE创建日期：2026-08-29所属模块：app / webserver需求来源：TB-66 产品体验反馈

1. 原始诉求

  • 已启用插件卡片使用绿色背景突出显示，但状态不能只依赖颜色。
  • 新增「推送设备」Tab；「笔记」改为「划线笔记」。
  • 目录分类对齐 plugin ID 的类型段，避免 manifest capability category 与产品分类混为一谈。
  • 总结并落实配置页规范；微信读书不应要求填写实例级“公开配置 JSON”。
  • 完成测试后提交 PR，目标分支仍为 feat/plugins，不合入 master。

2. 目标与边界

目标

  • 一插件只进入一个目录 Tab。
  • 个人连接不再误走管理员实例连接表单。
  • 设备插件主动作进入已有个人设备管理页。
  • 桌面、iPad 竖屏和 320px 窄屏均可用。

非目标

  • 不修改 capability 接口、运行时读写语义或插件 ID。
  • 不重做微信读书工作台和设备保存 API。
  • 不把复杂插件配置重新暴露为一整块 JSON。
  • 不在本轮部署 beta；交付经评审的 PR。

3. 分类规则

plugin ID 类型段Tab示例
combo综合服务微信读书、Open Library
meta元数据豆瓣 V2、Google / Amazon
annotation划线笔记talebook-brs
review评价Hardcover、NeoDB
source书源OPDS、Legado、Gutenberg
tool书籍工具文本替换、繁简转换、TXT 修复
push推送设备多看、BOOX、掌阅等

manifest 的 categories 继续服务 capability 协议校验，不再承担目录主分类。前端从 talebook.<type>.* 的类型段派生唯一 Tab；未知类型不猜测到其他分类。

4. 配置页设计规范

  1. 先分所有权：connection_owners=instance 才在管理员页管理共享连接；user 配置必须进入个人工作台或个人设置。
  2. 专用流程优先：插件声明 ui.manage_route / manage_dialog 时直接进入工作台，不套通用连接表单。
  3. Schema 生成字段：普通字符串、数字、枚举、布尔值和字符串列表按 config_schema 渲染对应控件；凭据来自 auth_schema，使用密码类输入并保持脱敏。
  4. 不向普通用户展示整块 JSON：复杂对象、批量映射或导入内容应由插件专用页面、导入器或分步表单承载。
  5. 无配置就测试：无凭据、无必填参数的连接器主动作应是「测试」，不先制造空配置步骤。
  6. 状态可解释：安装启用、连接健康和用户是否已配置是不同状态；卡片绿色只强化“已启用”，仍保留图标与文字状态。
微信读书决策：它只允许 user connection，API Key 已在微信读书工作台维护；管理员插件详情只说明这是个人配置并提供「打开工作台」，不再出现实例连接或“公开配置 JSON”。

5. 实现与验收

  • 目录页新增 ID 类型映射、书籍工具/推送设备 Tab、启用卡片语义样式。
  • push provider 声明式管理路由指向个人设备页；个人页支持 ?tab=devices 深链。
  • 管理员详情按 connection owner 分流，阻止 user-only 插件创建 instance connection。
  • 中英文文案和 Playwright mock / E2E 同步更新。
