Legado 跨页选择书源

保留本页选择，并允许管理员一次选中当前筛选的全部结果。

ACTIVE2026-11-26app / webserverIssue #1109

原始诉求

批量启停或删除失效书源时，每次只能选择当前页的 50 项。

目标与边界

保持工具栏和表头只操作本页；本页全选后显示跨页选择与数量。范围是当前标签和搜索词，不是未经筛选的全部书源。切筛选和重新搜索清空选择。继续支持逐行勾选。

方案

选择跨页时按现有列表相同筛选条件只取 ID。启停和删除使用明确 ID；跨页操作额外带原筛选和选择时间，服务端跳过已移出筛选或选择后新建的记录。删除仍显示确认数量，批量删除走既有 JSON 请求体以避免长 URL。数据库按批次提交在同一个事务内。

影响与风险

更新 spec/插件/Legado.md、书源工作台、现有管理员接口和中英俄文案。切页保留跨页选择；重新筛选、体检完成或批量成功则清空。过期的列表响应不替换新筛选结果。兼容旧的查询参数和分页响应。

测试结果

npm run build 与 npm run lint 通过（无 ESLint 错误）；make lint-py、make check-spec（25 篇）、make check-design 与 git diff --check 通过。

Chromium + Nuxt 生产构建 + 短生命周期模拟 API：legado-selection.spec.ts 1 项通过。验证本页 50 项、跨页 53 项、翻页保留勾选、排除个别书源、取消/确认删除、搜索输入清空选择，以及 390px 布局不产生页面级横向溢出；截图为测试数据。

以真实 Tornado 与 SQLite 隔离挂载变更处理函数，1 项 HTTP 验证通过（507 条、分页/搜索/有效性约束、新加入记录、JSON 批量与旧查询参数删除）。仓库完整用例在本环境缺少后端依赖（采集阶段提示缺 BeautifulSoup，Calibre 也未安装），不称为完整后端通过，由 PR CI 检验；未运行 Docker 真实全栈。
