Talebook Audio CLI 仓库拆分

把 CLI 的源码和发布边界迁移到独立公开仓库，Talebook 主仓库仅通过固定提交的 Git 子模块引用。

状态：ACTIVE创建日期：2026-08-29所属模块：packages需求来源：HOU-20

1. 原始诉求

在 hehetoshang 账号下创建专用仓库存放 Talebook Audio CLI，并将 Talebook 仓库中的现有源码目录替换为该仓库的子模块。

2. 目标与边界

目标非目标
保留已有 CLI 提交历史；独立仓库可直接安装和测试；Talebook 固定引用已验证提交；现有目录路径保持不变。本次不改变 CLI 命令、API、登录、播放或 MCP 行为；不自动跟随独立仓库主分支。

3. 方案

历史导出
以 git subtree split 将包目录三次功能提交导出到独立仓库根目录。
固定引用
在 packages/talebook-audio-cli 添加 HTTPS 子模块，锁定独立仓库提交。
兼容验证
递归克隆后运行原有测试、ruff、构建和 Talebook 方案检查。

独立仓库使用公开可读的 https://github.com/hehetoshang/talebook-audio-cli.git，避免公开 Talebook 仓库的克隆和 CI 依赖个人凭据。子模块更新必须通过 Talebook PR 显式审查指针变化。

4. 兼容性与风险

  • 未使用 --recurse-submodules 的克隆不会得到 CLI 工作树；README 和 PR 中需明确初始化命令。
  • 子模块提交被删除或独立仓库改为私有会破坏构建，因此仓库保持公开，并由 Talebook 固定不可漂移的提交。
  • 现有部署路径不变；本次只改变源码所有权和 Git 获取方式，无运行时配置迁移。

5. 测试计划与结果

  • 通过：创建公开仓库 hehetoshang/talebook-audio-cli，默认分支为 main；subtree 导出保留三次 CLI 功能提交，仓库管理权限和匿名可读性已确认。
  • 通过：git submodule status packages/talebook-audio-cli 显示 Talebook 通过 HTTPS URL 固定到独立仓库提交 ba210e809d081c1201d1c0e475370dc87738fe92。
  • 通过：PYTHONPATH=src python3 -m pytest -q，30 个测试通过；ruff check . 与 ruff format --check . 均通过。
  • 通过：python3 -m pip wheel --no-build-isolation --no-deps . 构建 talebook_audio_cli-0.1.0-py3-none-any.whl 成功。
  • 通过：make lint-py，105 个 Talebook 服务端 Python 文件检查通过；make check-design，116 份方案文档通过。
  • 界面审查豁免：本次仅改变 Git 仓库所有权、子模块元数据和开发文档，不修改 Web、终端输出、命令参数或运行时行为，因此没有界面影响。
  • 通过：从 Talebook 远端分支使用 git clone --recurse-submodules --shallow-submodules 完成干净克隆；子模块匿名检出固定提交，且克隆后的 30 个测试再次通过。

6. 决策记录

  • 保留 packages/talebook-audio-cli 路径，避免现有开发命令和部署说明发生无关变化。
  • 选择 HTTPS 子模块 URL，确保匿名克隆可用。
  • 通过 subtree 拆分保留与 CLI 有关的原始提交，不以单次快照重建历史。
