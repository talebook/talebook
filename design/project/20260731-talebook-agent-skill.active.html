原始诉求

在仓库根目录的 skills/talebook/ 创建一个 Agent Skill，让用户通过自然语言操作和使用 Talebook，而非指导开发 Talebook。Skill 需要支持公开实例的 guest 访问、可选账号认证、普通用户与管理员操作，以及基于 Docker Compose 启动新实例的参考说明。

用户逐项确认：CLI 使用单体 scripts/talebook-cli.py；命令采用按领域组织的多层树；顶层为 me、books、remote 和 admin；管理接口全部位于 admin；不提供 raw 与 deploy 命令。

目标与边界

自然触发用户提到操作、管理或部署 Talebook 时自动加载，也支持显式调用 $talebook。
Guest first仅站点地址必填；用户名和密码成对可选，公开实例无需登录。
明确命令CLI 只封装已核实接口，不提供任意 HTTP 请求逃生口。
风险可见破坏性、外发、权限和系统配置操作先预览，再凭 --confirmed 执行。

非目标：不修改 Talebook 业务 API；不实现容器生命周期管理；不保存账号密码；不绕过验证码、访问码或服务端权限；不把部署逻辑塞进 CLI。

执行主轴

成功不以“请求已发出”为准，而以 Talebook 返回成功状态、目标资源可重新查询，或浏览器页面显示预期状态为准。

CLI 与配置设计

CLI 使用 Python 标准库与递归 argparse 子命令，保持单文件可执行。公共参数位于命令树之前：

talebook-cli.py [--site URL] [--user USER] [--password PASSWORD] <service> <command> [options]
参数环境变量规则
--siteTALEBOOK_URL必填；无 scheme 时补 https://，显式 HTTP(S) 保持不变，移除末尾斜杠。
--userTALEBOOK_USERNAME可选；必须与密码同时出现。
--passwordTALEBOOK_PASSWORD可选；环境变量更安全，命令行参数可能暴露于历史或进程列表。

命令行参数覆盖环境变量。未提供用户名和密码时不发送 Authorization 头，以 guest 身份请求。服务端要求访问码、验证码或第三方登录时，Skill 转入浏览器流程。

Skill 信息层级

文件职责加载条件
SKILL.md意图路由、身份探测、风险分级、执行与核验步骤。每次 Skill 触发。
scripts/talebook-cli.py单体多层 CLI、HTTP Basic Auth、上传下载、响应与错误处理。需要 API 操作时直接执行；仅在修复脚本时读取源码。
references/api.md命令树、接口映射、参数、权限、风险和响应说明。选择命令或处理异常响应时。
references/docker-compose.md生成 Compose 配置、启动容器和验证地址。用户要求部署 Talebook 时。
agents/openai.yaml展示名称、短描述和默认提示。由宿主读取。

权限与风险门禁

等级示例行为
只读搜索、详情、列表、状态、日志查看直接执行并核验。
常规写入明确要求的上传、收藏、书架、阅读状态直接执行；失败时展示服务端原因。
外部副作用发送到设备或邮箱展示书籍、目标与格式，确认后添加 --confirmed。
管理写入用户权限、系统设置、书源、主题先验证管理员身份，展示变更摘要，再确认。
破坏性删除、批量操作、清空回收站、迁移数据库展示精确目标、数量与不可逆影响，确认后执行。

风险与回滚

风险控制
接口随业务代码变化接口细节单一来源放在 CLI 与 API 参考，测试覆盖关键请求契约。
命令树过大导致维护困难保持单体文件但按领域分段；公共传输、认证、输出和门禁只实现一次。
密码出现在命令历史支持用户要求的参数，同时在帮助与 Skill 中优先推荐环境变量。
误执行高风险操作CLI 强制 --confirmed，Skill 先向用户展示预览；服务端权限仍为最终边界。

方案已生效；如需改变核心命令或安全模型，应创建新的 WIP 方案替代。本 Skill 可独立移除，不影响 Talebook 业务 API 与前端。
