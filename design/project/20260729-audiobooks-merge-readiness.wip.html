3. 实现方案

工作流设计决策新增验证
合并 master合并而非改写已发布历史；阅读入口抽出统一渲染函数，先 EPUB、再 PDF/TXT/转换格式，同时注入当前发布 Edition。EPUB、TXT、MOBI/AZW3 和有/无已发布音频组合测试；Shelf E2E 使用最新 mock URL 约定。
Candle Reader以已合并的 Candle Reader main 构建新 tag/release，通过仓库既有 release + dispatch 流程同步不可变 dist；Talebook 不手抄 bundle。校验 version 文件、bundle 包含 audiobook 入口；阅读器 E2E 覆盖高亮、换章和“从这里听”。
Podcast/Nginx增加专用 /podcast/v1/ 代理 location，关闭普通 access log，保留应用层脱敏审计；补稳定站点 UUID、Feed GUID、Channel image、gzip/缓存语义。Nginx 配置静态测试与容器请求；RSS/XML、HEAD/304、Range/416、权限变化和普通日志无 Token。
调度器运行进程由 watchdog 周期续租并观察 cancel deadline；优雅取消超时 TERM，再超时 KILL。持久化 last seq，重复/倒序事件直接忽略。静默子进程不被重领、重复事件不重复计数、TERM/KILL 顺序、重启恢复、1–3 workers CAS。
容量与清理领取任务前检查可用空间；周期清理成功缓存和失败临时文件；配置默认沿用现有方案。Feed/Range 采用轻量令牌桶，管理员可冻结订阅。低磁盘拒绝、过期文件清理、受保护/发布资源保留、限速和冻结返回明确状态。
生成与版本Voicebook CLI 仅直接接收 engine、chapters；Talebook 在 inspect 后把 speed 与主角音写入角色表再生成。当前上游没有质量参数，因此只接受真实存在的 standard，界面不展示伪质量档位。Edition action 明确 publish、rollback、delete，partial 默认不可发布。CLI 与角色表落盘测试；非 standard 质量被拒绝；候选发布/回滚保持 GUID、旧版本变 historical；错误状态 UI。
权限与健康公开读取端点保留原书可见性校验，并在规范中记录公共 API 例外；写端点使用认证。详情响应返回可生成能力与 Voicebook health，前端不自行猜管理员/所有者规则。游客/私有书/所有者/管理员矩阵，CLI 不可用和功能关闭状态。
前端结构保持 Composition API；把播放状态改为聚焦的 Pinia 模块并同步架构说明，复杂请求与版本动作集中到 store/composable，避免页面继续膨胀。组件测试、页面 E2E、明暗主题、桌面/移动、空状态、失败态和候选版本操作。

5. 兼容、发布与回滚

兼容策略

  • 数据库只新增字段/索引，启动迁移可重复执行；旧 Edition 和 Job 有安全默认值。
  • 公开音频继续跟随原书可见性；现有客户端路径保持不变。
  • 旧 Candle bundle 在新版本发布前不覆盖；版本文件和 cache-busting 同步提交。

回滚策略

  • 总开关关闭新任务但保留已发布播放；停止 worker 后释放/过期租约。
  • Candle Reader 可回退上一 release，Talebook 静态资源与版本号一起回退。
  • Podcast GUID 与 enclosure 版本稳定；回滚 Edition 不删除历史媒体。
