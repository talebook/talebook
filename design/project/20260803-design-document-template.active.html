统一内部方案模板与单文档生命周期

提供可离线复制、支持 PC 与手机的方案基础格式，并将同一工作的澄清、设计迭代、实现与验证持续收敛在一份文档中。

状态：ACTIVE创建日期：2026-08-03所属模块：project影响范围：design / scripts / tests需求来源：用户直接要求

1. 原始诉求

“你根据 design 里面的历史方案文档，总结一套模版+样式（支持PC+手机），以后design方案时直接套用模版基础格式。”

后续反馈确定：视觉参考 ~/20260803-signals-in-ai-repo.wip.html；顶部元信息使用小型 tags；目录不能挤压正文，宽屏展示完整右侧目录，窄屏使用浮动目录；模板提供可选产品功能矩阵。

新增治理要求：“一个工作只写一份文档，不要保留中间的过程废弃文档。”

2. 目标与边界

目标

  • 复制一份 HTML 即可开始合规 WIP。
  • PC 正文足够宽，手机不产生整页横向滚动。
  • 同一工作从 WIP 到 ACTIVE 只维护一份方案。
  • 保留可访问性、离线阅读和打印基线。

非目标

  • 不强制所有方案使用完全相同的视觉主题。
  • 不要求每份方案保留全部可选章节。
  • 不由脚本猜测两个文件是否属于同一工作。
  • 不删除已合并生效、由独立后续工作替代的历史方案。

3. 模板基线

最终形态：design/TEMPLATE.html 采用 Signals 风格白色卡片、橙色焦点色和轻量阴影；meta 信息用小型 tags 呈现，正文最大宽度为 1160px。
  • 宽屏完整目录漂浮在正文外侧，展示编号和章节名；空间不足时自动切换到不占正文宽度的浮动目录。
  • 必备内容包括原始诉求、目标、方案和测试结果；功能矩阵、证据、图表和决策记录按需保留。
  • 所有 CSS、脚本和图形内联，不依赖 CDN、远程字体或仓库资源。

矩阵是备选章节，以用户任务为行，按实际角色、入口和协议增删列；手机端只允许表格容器局部横向滚动。

5. 单工作单文档生命周期

Create创建唯一 WIP

使用首次创建日期和稳定 feature 命名。

Iterate原文件持续更新

grill、反馈、候选比较和实现偏离均写回同一份 WIP。

Verify回写真正结果

记录命令、页面、失败项和未执行原因。

Activate只留下 ACTIVE

验证完成后改状态和文件名，不保留中间废弃文档。

SUPERSEDED 边界：只用于某份已经合并并独立生效的 ACTIVE，后来被另一个工作替代。它不能用于保存同一工作中的过程稿、方案 A/B/C 或反馈轮次。

6. 影响范围、风险与回滚

改动

更新 AGENTS.md、design/TEMPLATE.html 及对应测试；本次模板工作最终只保留本方案。

保持不变

方案路径、状态值、单文件 HTML 约束和 WIP 合并门禁不变；语义归组仍由开发者与评审判断。

风险：若过早转为 ACTIVE，后续同工作反馈容易再次产生文档。缓解方式是仅在实现与验证真正完成时转 ACTIVE。
