候选方案判断原因
Codex 回到 hosted runner采用历史真实 runs 已证明该边界可以完成 sandbox 与完整发布链；不降低内层权限。
job container 增加 privileged / SYS_ADMIN拒绝扩大容器攻击面，且 EINVAL 不是单纯缺少 capability 的证据。
跳过 sandbox 或 fail-open拒绝会让模型进程失去 workspace-only、网络和凭据隔离，不满足现有安全契约。
固定旧 :dev digest拒绝宿主 Actions 上没有证据表明旧 digest 能解决嵌套架构问题，并会冻结开发工具链。
强制 legacy Landlock拒绝已复现同样的 seccomp 安装失败，且当前细粒度文件规则不能用语义更弱的回退替代。

04实现方案

位置计划改动约束
.github/workflows/codex.yml 移除 Codex job 的 container 与容器专用 shell 默认值；增加固定 Node 24、Python 3.13、Codex 0.144.6 和测试依赖准备；恢复 bubblewrap/AppArmor 安装、profile 加载与 fail-closed 自检。 Codex 版本不因迁移改变；不使用 privileged；不写入宽泛 safe.directory "*"。
受信任测试依赖 由上下文步骤按不可变 github.workflow_sha 读取 requirements-test.txt 到 runner 临时目录，再供安装步骤使用。 不得从可能被请求目标修改的 checkout 读取 bootstrap 依赖。
项目依赖 保留 make init 与 npm --prefix app ci，确保 agent 面对目标分支的 Python 与前端 lockfile，而不是浮动镜像快照。 在恢复模型凭据前完成工具链与 sandbox 验证。
PR hosted smoke 为真实 codex.yml 增加仅在该 workflow 变更的 Pull Request 上运行的 sandbox smoke job；无模型 secret，仅验证 hosted runner bootstrap 与 codex sandbox -- /bin/true。 主 Codex job 在 pull_request 事件保持跳过；smoke job 不评论、不调用模型、不发布代码。
tests/test_codex_workflow.py 把 dev-container 契约改为 hosted-runner 契约，覆盖固定版本、步骤顺序、受信任依赖、smoke 触发范围和 sandbox fail-closed。 测试验证行为契约，不复制整个 YAML。
方案生命周期 验证完成后将本方案转为 ACTIVE，并把 20260722-agent-workflows-dev-container.active.html 转为 SUPERSEDED，注明 Claude 仍在容器、Codex 由本方案替代。 待合并内容不得保留任何 .wip.html。

05安全、兼容与回滚

SECURITY

安全强度不降级

外层从 Docker job container 改为 GitHub 临时 VM，但真正约束模型命令的 Codex permission profile、bubblewrap、seccomp、AppArmor、网络代理和环境变量过滤均保留。sandbox 自检仍在恢复模型凭据之前 fail-closed。

COMPATIBILITY

Claude 与生产镜像不受影响

不修改 claude.yml、Dockerfile、build workflow、生产镜像或应用 API。Codex 仍使用 Node 24、Python 3.13 与 Codex 0.144.6。

PERFORMANCE

接受一次性 bootstrap 时间

每次请求需安装固定 Codex 与测试依赖，启动时间高于复用 dev image；换取 hosted runner 原生 sandbox 能力。25 分钟 job 与 20 分钟模型时限保持不变，测试记录实际耗时。

ROLLBACK

以提交回退为单位

若 hosted smoke 或真实运行出现新问题，回退本 PR 可恢复当前配置；但当前容器方案已被真实失败证伪，回退后 Codex workflow 应视为不可用，不能宣称恢复服务。
