01 / Original request

原始诉求与边界

用户要求参考 lark-cli Skill 的做法，为 Talebook Agent Skill 增加更新提醒。这里的“更新”解释为 Talebook 服务实例版本更新，而非自动更新本地 CLI 文件。

01

结构化提醒

成功结果存在新版本时，追加 _notice.update，便于 Agent 识别而不破坏原接口字段。

02

安静失败

检查权限不足、网络错误或旧版服务不支持接口时，原命令结果照常返回。

03

不自动升级

提醒只报告版本和发布页。升级依赖部署方式，Agent 必须先完成当前任务，再按用户意图处理。

03 / Output contract

输出契约

仅在目标命令成功且服务报告 has_update: true 时附加 notice。版本字段来自现有管理接口；发布地址保持服务返回值。

设置 TALEBOOK_NO_UPDATE_NOTIFIER=1 可禁用额外请求并获得稳定 JSON，适合脚本或严格机器读取。

{
  "err": "ok",
  "books": [],
  "_notice": {
    "update": {
      "message": "Talebook 有新版本 v26.08.1（当前 v26.07.13）",
      "current_version": "v26.07.13",
      "latest_version": "v26.08.1",
      "release_url": "https://github.com/talebook/talebook/releases/tag/v26.08.1"
    }
  }
}
04 / Decisions

关键决策

问题决策理由
检查来源读取 GET /api/admin/update复用服务端周期检查的缓存，不让每条 CLI 命令触发 GitHub 联网。
检查对象仅提供凭据的管理员接口本身是管理接口；guest 和普通用户不应因提醒产生权限噪声。
错误语义best-effort，全部静默跳过更新提醒是旁路能力，不得把一次成功操作改判为失败。
Agent 行为先完成任务，再简短提示与 lark-cli 的 notice 使用习惯一致，避免提醒喧宾夺主。
自动升级不执行Talebook 可通过 Docker Compose 或其他方式部署，CLI 无法安全推断部署目录和更新动作。
