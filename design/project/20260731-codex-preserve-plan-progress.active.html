CODEX COMMENT LEDGER / DESIGN DECISION

总结可以收口，进展不能消失

最终回帖继续使用同一条 GitHub 评论，但只替换临时阶段说明；Codex 已经展示过的执行计划及其最后勾选状态必须成为最终结果的一部分。

原始诉求

维护者：“codex 输出总结时，不要把原来已经执行的 plan 进展覆盖掉。”

当前 workflow 在运行期持续更新一条进度评论，展示 Codex 的计划清单；运行结束时，最终回帖步骤却用结构化 summary 重新构造整段评论正文，再对同一评论执行覆盖更新。结果是总结出现了，但用户刚刚看到的执行轨迹消失了。

目标与不变量

ONE COMMENT

始终单评论

存在实时进度评论时，最终结果只更新该评论；禁止因读取、解析或更新失败而追加第二条回帖。

PLAN SURVIVES

保留最后进展

最终正文保留最新执行计划清单，完成项继续勾选，失败或未完成项继续保持未勾选。

FAIL CLOSED

不能保真就不覆盖

已有评论但无法可靠取得计划边界时，保留原评论并使 workflow 失败，不用总结冒险覆盖进展。

根因

01 · ACKNOWLEDGE

Resolve request context 创建带固定 ID 的初始进度评论。

02 · REPORT

codex_progress_reporter.py 消费 JSONL 事件，把 todo 清单与勾选状态 PATCH 到该 ID。

03 · REBUILD

Post Codex response 从空字符串重新构造 body，其中只有总结、验证和发布结果。

04 · OVERWRITE

最终 updateComment 将运行期正文整段替换，todo 清单没有任何传递通道，因此必然丢失。

目标评论形态

同一 comment_id FINAL / 不再显示“正在处理”

Codex 处理结果

这里保留结构化总结、实际验证结果和发布状态。

执行计划

  • ☑ 定位评论覆盖路径
  • ☑ 实现计划边界保留
  • ☐ 完成尚未通过的验证

最终正文不保留“Codex 正在处理”“正在验证并准备发布”等瞬时文案，也不保留活动计数。计划清单作为结果后的审计轨迹保留。

方案

环节 改动 约束
初始评论 在评论内写入唯一的 plan 起止标记；尚未生成计划时，标记之间为空。 标记不依赖可见中文标题，避免文案调整破坏解析。
实时 reporter 每次渲染都保留同一对标记，并把已转义的“执行计划”区块放在标记之间。 计划文本继续限制数量和长度，并转义 Markdown、HTML 与提及。
最终回帖 先用 getComment 读取当前评论，校验且提取标记区块，再拼入总结正文并更新同一 ID。 只允许恰好一对有序标记；不从 Codex 最终文本重新推断 plan。
长度控制 先为 plan 区块和截断提示预留空间，再截断过长的结果正文，最后追加 plan。 GitHub 评论长度受控时，优先保证计划区块完整，不允许从中间截断。
无初始评论 若最初创建评论已失败且没有合法 comment ID，则按既有逻辑创建一条最终评论。 此时系统从未留下进度评论，所以仍然只有一条评论。

失败策略

如果 comment ID 合法但读取失败、标记缺失/重复/逆序，或者同一评论更新失败，最终回帖步骤直接失败。 不修改原评论，不调用创建评论作为兜底。后续 fail-closed 状态步骤继续把本次交付判为失败。

关键决策

采用：从 GitHub 当前评论读取

最终步骤拿到的是维护者实际看见的最后状态，避免本地快照与最后一次 PATCH 成败不一致。

采用：隐藏边界标记

解析稳定边界而不是匹配标题或列表文本；计划内容仍由受信任 reporter 统一转义。

拒绝：整段旧评论直接追加

会把“正在处理”和“稍后替换”等过时文案冻结在最终结果里，状态语义错误。

拒绝：失败时另发总结

会产生双评论，违背维护者明确确认的单评论约束，也让哪条评论是最终结果变得含糊。

安全、兼容与回滚

  • 不扩大权限：继续使用现有 interaction token；只增加对已知 comment ID 的读取，不新增仓库写权限。
  • 内容安全：plan 仍由 reporter 进行 HTML、Markdown 和提及转义；最终步骤只搬运标记内的受控区块。
  • 兼容无计划运行：标记之间为空时正常发布总结，不伪造执行计划。
  • 兼容初始 ACK 失败：没有 comment ID 时允许创建唯一的最终评论；不属于双评论。
  • 回滚：回退 workflow、reporter 和测试提交即可恢复旧行为，不涉及数据、API 或持久化迁移。

验收标准

  • 实时运行期间仍可看到持续更新的阶段和执行计划。
  • 最终总结出现后，评论数量不增加，原 comment ID 不变。
  • 最终正文不再显示临时阶段文案，但显示最新 plan 清单及原勾选状态。
  • 读取或解析已有 plan 失败时，原评论正文不变，workflow 明确失败。
  • 无 plan 的纯问答或早期失败不会出现空的“执行计划”标题。
  • 超长最终结果的截断不会截断或删除 plan 区块。
