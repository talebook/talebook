1. 方案结论

有声书是现有文字书的衍生媒体版本，复用 Talebook 的书目、封面、作者、系列与访问权限；转换、播放、同步、统计与 Podcast 分发使用独立领域模型，不污染 Calibre 格式字段。

生成

默认 EdgeTTS，支持 Qwen3TTS。快速模式自动完成；高级模式先识别，再通过角色 UI 和单章 TXT 编辑器审查。

播放与同步

章节 MP3 + 句段时间轴。Talebook 提供详情播放器和全站迷你播放器；Candle Reader 自动定位、高亮与“从这里听”。

开放收听

每用户一个私人 RSS；每书一个 Season、每章一个 Episode。第一方精确统计与外部 HTTP 传输估算严格分开。

当前结论：有声书功能以 Beta 对用户开放，导航、书架、详情和制作任务页均须显示 Beta 标识。三仓实现、自动化测试、EdgeTTS 真实长音频和 GitHub Pages 播放已完成；本文仍保持 WIP，因为 Qwen3TTS 云服务返回 Arrearage，49 个 Qwen 音色的十场景资产无法真实生成，Apple Podcasts 真机订阅也仍需外部验收。不得把这两项伪报为通过。

2. 原始诉求、已确认范围与非目标

2.1 原始诉求

Talebook 左侧增加“有声书”，参考 Audiobookshelf 提供浏览、详情、播放和管理；存量文字书可通过 Voicebook 后台排队生成；Candle Reader 支持音文同步高亮；提供丰富默认与自定义选项；补充收听统计，并兼容 Apple Podcasts 的“通过 URL 关注播客”。

2.2 Grill 后确定的不变量

主题已确认决策
输入首版只从 Talebook 现有 EPUB/TXT 生成；不导入已有 MP3/M4B。TXT 为实现音文同步，先转换为 Talebook 的规范 EPUB 后再生成。
同步粒度按句子/对白逻辑片段高亮，不承诺逐字卡拉 OK。
权限播放跟随原书查看权限；管理员默认可生成；站点开关可允许书籍所有者生成。普通用户仅看自己的任务，管理员看全站。
模式快速模式直接生成；高级模式先识别、等待审查。高级模式不暴露完整 book.script，只提供角色结构化 UI 与单章 TXT 对白编辑。
版本一本书可有多个有声版本；首次完整版本自动发布，后续成功结果是候选版本，试听后手动发布，可回滚。
部分章节允许选章与续补；配置一致才可补入同一版本。部分版本默认不可发布，管理员可例外发布。
队列数据库持久化；默认全站并发 1，可配 1–3；支持优先级、取消、失败重试、重启恢复与片段缓存续跑。
音色试听57 个现有音色 × 10 种固定场景全部预生成；角色实际对白可动态试听并缓存。
播放器详情完整播放器 + 全站迷你播放器；刷新恢复但不自动播放；Candle Reader 使用阅读器内播放器。
进度文字阅读与收听进度独立；边听边读不覆盖文字位置，用户可显式“从此处继续阅读”。
Podcast每用户一个站点级私人 RSS；一本书一个 Season、一章一个 Episode；不生成整书合并 MP3。
统计与审计第一方真实收听统计和外部 RSS 传输估算分开；保存原始 IP，默认 90 天，可配置并支持安全保全。

首版包含

  • 有声书首页、详情、章节播放、搜索筛选、继续收听。
  • 快速/高级生成、版本、持久队列、管理操作。
  • 角色 UI、单章脚本编辑、57 × 10 场景试听。
  • 句段同步、书签、临时播放队列、睡眠定时。
  • 用户/管理员/书籍所有者统计视图。
  • 站点级私人 Podcast RSS 与请求审计。

首版不包含

  • 独立音频导入、播客抓取、公开 Podcast 目录提交。
  • HLS/实时转码、Chromecast、M4B、整书合并 MP3。
  • 逐字时间轴、自动字幕、Apple 播放进度回传。
  • 持久播放列表、公开分享、DRM 或防复制承诺。
  • 把 Audiobookshelf 作为外部服务部署或复制其媒体扫描器。

3. 跨仓总体架构

Talebook 是产品与状态权威，Voicebook 是可取消、可恢复的媒体生成器，Candle Reader 是音文同步渲染器。三者只通过稳定协议连接，避免 Talebook 依赖 Voicebook 内部 Python 对象。

调用向下、事件向上；业务状态只写 Talebook 数据库，媒体与时间轴使用版本化文件。

4. 领域模型与存储

不把 MP3 塞入 Calibre 的电子书格式字段。所有路径均保存为相对 AUDIOBOOK_PATH 的安全路径，服务端解析后再次执行目录包含校验。

模型关键字段约束与用途
AudiobookEditionid, book_id, status, engine, config_json, source_fingerprint, script_path, manifest_path, chapter_count, completed_count, duration_ms, size_bytes, created_by, published_atBook 1:N Edition；同一 book 同时仅一个 published；候选和历史版本可回滚。
AudiobookChapteredition_id, source_key, number, title, audio_path, timeline_path, duration_ms, size_bytes, content_hash, episode_guid, first_published_at(edition_id, number) 唯一；发布资产 URL 版本化且不可变。
AudiobookJobbook_id, edition_id, creator_id, mode, status, phase, priority, config_json, chapter_selection, config_hash, progress, lease_owner, lease_until, cancel_requested, attempts, error_code/message, log_path, timestamps持久队列真相；活跃任务按 book + config_hash 去重；租约支持崩溃恢复。
AudiobookProgressuser_id, edition_id, chapter_id, position_ms, segment_id, listened_ms, is_finished, version, updated_at用户与版本唯一；乐观版本避免多设备旧进度覆盖新进度。
AudiobookBookmarkuser_id, edition_id, chapter_id, position_ms, segment_id, note, created_at跨设备书签；跟随有声版本，不写入原文字书进度。
PlaybackSessionuuid, user_id, edition_id, source, device_id, ip, user_agent, started_at, ended_at, current_ms, listened_ms, completed第一方真实统计；播放中增量同步，暂停/后台/关闭时收口。
PodcastSubscriptionuser_id, token_hash, token_hint, active, hidden_books_json, created_at, last_access_at, revoked_at每用户一个活跃站点 Feed Token；数据库不存明文 Token。
PodcastAccessLogsubscription_id, book/edition/chapter, kind, method, status, range_start/end, bytes_sent, ip, user_agent, protected, created_at外部传输估算与安全审计；原始 IP 默认 90 天，保全记录不清理。
AudiobookDailyStatdate, scope, user/book/chapter, source, listened_ms, sessions, starts, completes, requests, bytes长期聚合；第一方与 podcast_estimated 来源绝不混算。
句段不入库：每章可能有数千句，直接写数据库会放大迁移、查询与备份成本。句段放在逐章 timeline JSON 中，章节表只保存路径、哈希与数量；客户端按需加载当前章。

5. 生成流程与持久队列

快速模式

  1. 选择引擎、章节、整体语速、主角音与音质预设。
  2. 创建任务和候选 Edition。
  3. 自动 inspect、选角、逐章生成和打包。
  4. 首次完整版本自动发布；否则进入候选试听。

高级模式

  1. 后台 inspect 后进入“等待确认”。
  2. 角色表用结构化 UI 编辑和试听。
  3. 正文按单章 TXT 编辑，逐章保存与校验。
  4. 确认后锁定脚本修订并进入生成队列。

运行进程失联后租约过期，任务回到 QUEUED；不会把“进程已死”误当成仍在生成。

5.1 队列执行规则

  • 调度器按优先级、创建时间获取任务，以数据库 compare-and-set 取得短租约并定期心跳续租。
  • 默认只运行一本书；配置范围 1–3。本数并发与 Voicebook 内部片段并发分别限流。
  • 取消先写 cancel_requested 并创建取消信号文件；Voicebook 在片段与章节边界退出。超时后才发送 TERM，最后才 KILL。
  • 服务重启时，租约过期的 RUNNING 任务重新排队；已完成片段通过内容/引擎/音色/语速指纹命中缓存。
  • 同一 book + config_hash 的活跃任务返回原任务，避免双击重复计费；配置变化创建新 Edition。

6. Voicebook 稳定协议

6.1 依赖与进程边界

  • Voicebook 默认核心依赖保持轻量；Torch、Transformers、Hugging Face 与 CSI 模型移到 csi 可选依赖。
  • Talebook 固定 Voicebook 版本并以子进程调用，不直接导入内部模块。
  • CLI 新增机器模式、JSONL 事件输出、取消信号、恢复目录与明确退出码；普通人类日志写 stderr。
voicebook-tool generate book.script \
  -o /data/books/audiobooks/editions/42 \
  --engine edgetts \
  --chapters 1-20 \
  --progress-format jsonl \
  --cancel-file /data/books/audiobooks/jobs/99/cancel \
  --resume

6.2 JSONL 事件

事件必需字段Talebook 行为
phase_startedschema, seq, job_phase, at更新阶段与心跳。
chapter_startedchapter_number, title, total_segments显示当前章节与进度分母。
segment_completedchapter_number, segment_index, cache_hit限频聚合后写库，避免每句提交事务。
chapter_completedaudio, timeline, duration_ms, size_bytes, sha256校验路径、ffprobe 和哈希后登记章节。
warningcode, message, context任务继续，UI 显示可审查警告。
failedcode, message, retryable收口 FAILED，保留缓存与脱敏错误。
completedmanifest, chapter_count, duration_ms读取并验证 manifest，进入 FINALIZING。

所有事件包含单调递增 seq、协议版本和 UTC 时间；Talebook 按 seq 幂等消费。未知事件可忽略但记录，主版本不兼容则拒绝任务。

6.4 音色预览资产

目标仍是 Voicebook 包内携带 57 个 MP3 预览包和一个目录 JSON。每个文件包含旁白、日常、喜悦、愤怒、悲伤、恐惧、低语、急切、威严、温柔十段场景及目录信息。Talebook 通过 Voicebook 机器命令发现资源并安全提供，不复制二进制到前端源码；角色实际对白预览按引擎、音色、语速、文本指纹动态缓存。

实际资产：当前已生成并校验 8 个 EdgeTTS 音色 × 10 场景，共 80 段对白；49 个 Qwen3TTS 音色因云 API 实际返回 HTTP 500 / Arrearage 暂无资产。实现不会使用 Edge 音色冒充 Qwen，也不会静默回退。

8. Candle Reader 音文同步

Candle Reader 接收 Edition 与清单 URL，不自行猜测音频结构。当前章 timeline 是唯一时间到文本的映射依据；epub.js CFI 只在运行时由 locator 解析生成。

播放跟随和手动阅读互不抢控制权；用户离开朗读位置时音频继续，自动翻页暂停。

8.1 Reader API 与组件

  • Reader 新增 book_id、audiobook_edition_id 和清单入口；Talebook 的 creader.html 注入当前发布版本。
  • 新增独立 AudiobookPlayer.vue 与 timeline/locator 工具，避免继续膨胀现有 EpubReader。
  • 播放时每 100–200 ms 更新句段索引，但只在 segment 变化时操作 DOM；章节切换才请求新 timeline。
  • 优先用 element_id，回退 dom_path + 文本哈希模糊定位；定位失败清除高亮并记录一次警告，不阻断音频。
  • 支持 Media Session、键盘、屏幕阅读器标签和触摸目标；主题中高亮色使用半透明背景与描边，避免覆盖文字颜色。

9. 站点级私人 Podcast RSS

用户只复制一个 URL。Feed 是该用户可访问有声书的动态视图，不是公开 Podcast 目录，也不是永久绕过权限的下载链接。

Channel

站点标题、站点封面、itunes:type=serial、itunes:block=Yes、稳定 Feed GUID、UTF-8 RSS 2.0。

Season = 书

itunes:season=book_id，书籍封面用于 item image；用户可按书隐藏，版本只取当前已发布。

Episode = 章

标题“《书名》·章节名”，itunes:episode 为章节号，enclosure 直接使用章节 MP3。

兼容性取舍：Apple 的 Season 没有一等“书名”字段，界面可能显示 Season 编号。因此 Episode 标题始终包含书名，并提供书封面；真实 Apple Podcasts iPhone/Mac 验收是发布门槛。

9.1 路由与 Token

GET/HEAD /podcast/v1/{token}/feed.xml
GET/HEAD /podcast/v1/{token}/covers/{book_id}.jpg
GET/HEAD /podcast/v1/{token}/audio/{edition_id}/{chapter_id}.mp3
  • Token 至少 128 bit 随机熵，仅以哈希入库。持有 URL 即拥有该用户当前可访问音频的下载能力；UI 必须明确提醒并支持撤销/重置。
  • 每次请求重新校验 Token、用户状态、书籍查看权限、已发布版本和个人隐藏列表；Feed 中不出现候选版本。
  • Feed 支持 HEAD、ETag、Last-Modified、304 与 gzip；音频支持 HEAD、206 Range、Content-Range、416 和不可变缓存。
  • chapter GUID 由稳定站点 UUID + book_id + source chapter key 生成，版本更新不变；enclosure URL 随二进制版本变化。
  • Feed 使用 RFC 2822 日期、ASCII URL、audio/mpeg、真实 length/duration，并通过 XML 与 Podcast 校验器。

Apple 官方资料与取舍记录见 research/apple-podcast-rss-20260718/findings.md。用户确认的“站点 Feed / 书 Season / 章 Episode”优先于调研阶段的整书 Episode 推荐。

11. 权限、安全、性能与运维

权限与隐私

  • 提交、审查、确认、取消、重试、发布、回滚、删除、播放和下载逐端点鉴权。
  • 任务快照只保存服务端凭据引用，不保存 Qwen Token 或 Cookie。
  • Podcast Token 不出现在普通日志；访问日志关联 subscription id。
  • 只信任配置的反向代理提供的 X-Forwarded-For，防止伪造源 IP。
  • 原始 IP 默认保留 90 天，可配置；安全保全记录跳过清理。

容量与清理

  • 发布/候选版本永久保留至显式删除，并在 UI 显示空间。
  • 成功片段缓存默认 30 天，失败临时文件 7 天。
  • 任务前检查可用磁盘，低于阈值拒绝启动；写入使用临时文件 + 原子替换。
  • 删除版本同时删除媒体和专属缓存，但任务审计记录保留。
  • Range 流量和 Feed 访问限速；对单 Token / IP 的异常访问可冻结。

12.2 三仓实施顺序

  1. voicebook：依赖拆分、定位锚点、manifest/timeline、JSONL、取消恢复、预览资产与测试；先发布固定版本。
  2. candle-reader：播放器组件、同步定位、交互与完整 e2e；打 tag 发布 dist。
  3. talebook：模型迁移、调度器、API、页面、统计、Podcast、Docker 固定 Voicebook、更新 Candle Reader dist。
  4. 联合验收：真实两章 EdgeTTS、跨页面播放、Candle 高亮、RSS/Range、统计和重启恢复。

Talebook 更新 Candle Reader 沿用现有 release + repository dispatch 流程；不手工维护来源不明的打包文件。

12.3 发布与回滚

  • 数据库迁移只新增表/列；启动时 create_all/migrate 创建。旧版本忽略新表。
  • 发布顺序为 Voicebook → Candle Reader → Talebook。Talebook 固定依赖版本，避免跨仓漂移。
  • 回滚先停止调度器并关闭 UI 入口；不删除数据库与媒体。运行任务标记 interrupted，可由新版本恢复。
  • 新发布版本出错时切回旧有声版本；Podcast GUID 保持稳定，enclosure 回到旧不可变资产。
