01 / 原始诉求与已确认事实

原始诉求：修复 Codex 处理 Issue 后创建的 PR 没有遵守 AGENTS.md 的问题，使 PR 正文提供详细说明和 ACTIVE 方案的 GitHub、RawGitHack 固定链接。
规则当时已经生效

PR #932 的基线已要求正文包含背景、关键改动、真实验证、风险或兼容性、方案路径或豁免原因；界面改动还需截图或说明无法截图的原因。

实现阶段没有完全失守

同一提交包含 ACTIVE 方案、组件测试和 E2E 测试，证明 Codex 已读取仓库要求；信息是在发布交接阶段丢失。

workflow 硬编码正文

create_issue_pr 无条件写入“Issue 的自动实现 + Closes”，没有消费结构化摘要、测试、风险或方案路径。

完整 SHA 只能后置生成

Codex 被禁止自行 commit、push 或调用 GitHub API；只有受控发布步骤完成提交后，workflow 才知道可用于固定链接的最终 SHA。

当前结果：Codex 产出方案与验证 → workflow 只保留两行固定模板 目标结果：Codex 产出完整 Markdown 模板 → workflow 校验占位符 → commit SHA 封印 → PR 正文

02 / 目标、边界与验收口径

MODEL-SIDE

Codex 直接提交完整正文模板

  • 用 Markdown 自由组织背景、改动、风险和视觉证据。
  • 在实际验证位置放置唯一的 {{TEST_RESULTS}}。
  • 在方案位置放置路径占位符或方案豁免占位符。
  • 不预先猜测 commit SHA，也不重复书写测试事实。
COMMIT SHA 封条
WORKFLOW-SIDE

受控发布器只注入远端事实

  • 校验正文长度、必备章节和受控占位符。
  • 把门禁确认过的 tests 渲染进正文。
  • 用发布后的完整 SHA 生成 GitHub blob 与 RawGitHack 链接。
  • 追加 Closes #N，再创建或更新 PR 受控区。

目标：PR 正文可直接评审

评审者不打开 workflow 日志，也能看到改动动机、范围、验证、风险、方案与视觉证据边界。

目标：首次创建与后续提交一致

首次 Issue 实现创建正文；已有 Codex PR 的后续发布同步更新正文和方案 SHA 链接。

非目标：允许模型直接操作 GitHub

继续禁止 Codex commit、push、调用 gh 或 GitHub API；发布凭据和最终远端状态只由 workflow 掌握。

非目标：新增截图托管服务

本次不引入图片上传或第三方托管。Codex 提供已有安全 URL；没有可发布截图时必须写明原因，正文不得静默省略视觉证据。

已确认：维护者内容保护

使用 HTML 注释标记 Codex 受控区。后续运行只替换这一段；无标记的现有正文在末尾追加受控区，避免覆盖人工编辑。

已确认：严格门禁

publish 模式缺少 pr_body、必备章节或占位符时拒绝发布，而不是退回两行模板；reply 模式使用空字符串。

03 / 正文模板契约

在现有 .codex-result.json 中只增加一个 pr_body 字符串。publish 模式由 Codex 直接写完整 Markdown；reply 模式必须为空字符串。workflow 不重组文案，只替换两个受控占位符并追加关闭语句。

{
  "delivery": "publish",
  "feature": "codex-pr-description",
  "commit_message": "fix(codex): publish compliant PR descriptions",
  "summary": "用于 Issue 进度评论的简短中文摘要。",
  "pr_body": "## 背景或目标\n...\n\n## 关键改动\n...\n\n## 实际验证\n{{TEST_RESULTS}}\n\n## 风险与兼容性\n...\n\n## 方案\n{{DESIGN_LINKS:design/project/20260803-codex-pr-description.active.html}}\n\n## 视觉证据\n...",
  "tests": [
    {"command": "python3 -m pytest tests/test_codex_workflow.py", "result": "passed"}
  ]
}

不需要方案时，把方案段改为 {{DESIGN_EXEMPTION}}，并紧接具体豁免原因。两个方案占位符必须恰好出现一个。正文中的截图 Markdown 或无法截图说明由 Codex 直接写入“视觉证据”章节。

门禁规则失败行为
正文完整性pr_body 为有上限的非空字符串，并包含背景、关键改动、实际验证、风险与兼容性、方案、视觉证据六个固定二级标题。拒绝 publish，不创建不完整 PR。
真实测试注入{{TEST_RESULTS}} 恰好出现一次；workflow 从已经通过 publish gate 的 tests 生成列表。拒绝正文自报或遗漏验证记录。
方案二选一{{DESIGN_LINKS:路径}} 与 {{DESIGN_EXEMPTION}} 恰好出现一个；前者只允许合法且存在的 ACTIVE 文件，后者后面必须有原因。拒绝 publish，提示方案引用不合规。
视觉证据视觉证据由正文直接表达：界面改动使用截图 Markdown，其他情况明确说明不涉及界面或无法截图原因。固定标题使缺失内容在评审和契约测试中可见。
正文标记只接受零组或一组有序的 Codex 标记；重复、缺边界或顺序错误均不覆盖。提交可保留，但 PR 更新失败并在进度评论中报告。

04 / 发布流程与幂等更新

01 · MODEL编写正文写入 pr_body、tests 和提交元数据。
02 · GATE验证模板长度、标题、占位符、方案路径与文件。
03 · PUBLISH提交并推送受控 App 生成最终 commit SHA。
04 · SEAL替换占位符注入真实测试和两条不可变方案链接。
05 · PR创建或更新替换受控区，保留人工区，保持 Draft。
场景正文行为SHA 来源
首次 Issue 发布创建 Draft PR，正文仅包含完整 Codex 受控区与 Closes #N。本轮 publish 输出。
已有 Codex PR 后续发布读取现有正文；替换唯一受控区，无标记则在末尾追加。本轮新提交。
分支已推送但 PR 缺失补建 Draft PR；复用已经校验的结果文件。checkout 的目标提交。
标记被破坏或出现多组拒绝覆盖并报告错误，不猜测维护者意图。不适用。

05 / 安全、兼容性与回滚

不信任模型输出

继续在 shell 门禁中校验严格键集合、类型、长度、固定标题和占位符。workflow 只解释自有的精确占位符，不执行正文内容，也不允许占位符路径逃逸 design/。

不信任 checkout 辅助脚本

Issue/PR 目标代码可能变化，正文渲染逻辑继续内联在受信任 workflow 版本中，不从 checkout 动态加载 JavaScript。

兼容旧 PR

旧正文没有标记时不删除原文，只追加受控区。新契约上线后，旧格式结果 fail closed，要求 Codex 按新 prompt 重新生成。

回滚

回滚 workflow、prompt 与契约测试即可停止新逻辑；已经写入 PR 的 Markdown 保持可读。受控标记只是 HTML 注释，不影响 GitHub 展示。

发布顺序约束：提交发生在 PR 更新前。如果远端提交成功但 PR API 更新失败，不能回滚已推送提交；最终状态必须明确报告“提交已发布、PR 正文更新失败”，下一次运行可重新渲染。
