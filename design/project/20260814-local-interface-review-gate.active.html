大型功能在激活方案前完成本地界面审查

为会改变产品界面的重大功能增加可追溯的本地审查门禁，让界面问题在方案转为 ACTIVE 前被发现、处理并留下记录。

状态：ACTIVE 创建日期：2026-08-14 所属模块：project 影响范围：AGENTS.md、项目规范测试、界面审查与 Web 规范 skills 需求来源：用户直接要求

1. 原始诉求

“更新一下 Talebook 项目的 AGENTS.md，要求在做大型功能时必须使用 interface-review skill 审查本地变更。”

现有流程要求重要改动创建方案、完成测试并回写结果，但没有明确要求大型界面功能在激活方案前审查本地变更的完整影响面。

2. 目标与边界

目标

  • 大型功能涉及界面时，必须显式执行 interface-review。
  • 审查覆盖当前分支相对默认分支的已提交和未提交本地变更。
  • 审查范围、结论和问题处理情况回写同一份 WIP。

非目标

  • 不把所有需要方案的配置、部署、修复工作都定义为大型功能。
  • 不以界面审查替代正确性、测试、安全或性能审查。
  • 不定制上游 interface-review 或 better-* skill 的规则内容。

3. 规则与流程

本规则中的“大型功能”限定为新功能、用户可感知行为变化和跨模块功能。只要影响页面、交互、文案或其他前端消费者，就进入强制审查流程。

Qualify

识别范围

确认是否属于大型功能以及是否存在界面影响。

Test

常规验证

先完成与功能相关的自动化和运行验证。

Review

本地审查

以 full 模式审查分支提交和未提交变更。

Record

处理留痕

修复阻塞项，并把范围、结论和处理情况写回 WIP。

Activate

激活方案

相关门禁通过后，方案才可转为 ACTIVE。

纯后端豁免：若大型功能确认不影响任何用户界面，可以不执行该 skill，但必须在 WIP 中记录“无界面影响”、判断依据和剩余风险。

4. 影响、风险与回滚

影响范围

更新根目录 AGENTS.md 的开发流程；安装 interface-review 与七个 better-* 依赖并更新 skills-lock.json；加入独立的 web-design-guidelines skill；扩展 tests/test_project_instructions.py 保护规则和 skill 完整性。

保持不变

现有五阶段方案流程、WIP/ACTIVE 生命周期、前端浏览器验收以及各代码质量门禁保持不变。

风险：规则过宽会让纯后端工作执行无意义的界面审查；通过明确界面影响条件和可追溯豁免控制。规则过窄会遗漏共享组件的消费者；通过审查完整本地变更而非单文件控制。

回滚：移除新增规范段落及对应测试即可；不涉及产品数据、接口或部署回滚。

6. 决策记录

  1. 2026-08-14：大型功能限定为新功能、用户可感知行为变化和跨模块功能，不等同于所有必须创建方案的改动。
  2. 2026-08-14：审查位于常规测试之后、方案转为 ACTIVE 之前；存在 HIGH 或 MEDIUM 问题时修复后重新审查。
  3. 2026-08-14：审查范围、最终结论和问题处理情况必须回写同一份 WIP。
  4. 2026-08-14：纯后端且无界面影响时允许豁免，但必须记录判断依据。
  5. 2026-08-14：PR 必须同时安装并锁定 interface-review 及七个 better-* 依赖，避免规范引用无法执行。
  6. 2026-08-14：用户进一步要求将独立的 web-design-guidelines 一并提交；该 skill 作为按 Vercel Web Interface Guidelines 审查指定文件的补充能力纳入同一 PR。
