生产公共层 Nuxt 环境文件修复

创建日期：2026-07-22 所属模块：docker 状态：ACTIVE 需求来源：Pull Request #889 维护者评论
修复前端构建分支拆分后，生产公共层执行 server.py --update-config 时因 app/ 尚不存在而失败的问题，同时保持 SPA、SSR 构建分支和最终镜像内容不变。

原始诉求与问题定位

维护者提供的生产镜像日志显示，production-common 阶段调用 python3 server.py --update-config 时，SettingsSaverLogic.update_nuxtjs_env() 无法打开 /var/www/talebook/app/.env，并抛出 FileNotFoundError。

此前前端产物在该命令之前复制到 app/。PR #889 为使 SPA 与 SSR 构建分支可并行，将前端复制移到 production-common 的后继阶段，因而公共层首次失去创建 app/ 目录的隐式前置条件。

目标与边界

  • 确保公共层运行 --update-config 前，Nuxt 环境文件的父目录已存在且可写。
  • 不改变 nuxt_env_path、后端配置写入行为、前端产物结构或生产 target 继承关系。
  • 不修改 workflow，不使用 Docker socket；真实镜像构建由远端 Actions 在提交后验证。

grill 决策

问题决策理由
在哪里恢复前置条件在 production-common 的目录准备步骤中显式创建 /var/www/talebook/app两个生产分支都依赖该公共层，且配置命令就在此层执行。
是否提前复制前端文件否会重新引入 SPA 与 SSR 分支耦合，抵消 PR #889 的构建优化。
是否让 Python 自动创建父目录否缺陷来自 Docker 阶段前置条件变化；修改通用运行时代码会扩大行为范围。
如何防止回归扩展 Docker 构建图测试，校验目录创建发生在 --update-config 之前无需 Docker socket即可覆盖本次失败所需的顺序约束。

实现与测试结果

在公共层已有的 mkdir 链中增加 mkdir -p /var/www/talebook/app。测试从 production-common 阶段提取文本，断言目录创建命令和 python3 server.py --update-config 均存在，并验证前者位于后者之前。
