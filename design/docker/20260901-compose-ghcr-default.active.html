收敛 Compose 默认运行依赖

让生产与开发 Compose 默认从 Talebook 自有 GHCR 拉取镜像，并把可选豆瓣元数据代理从基础拓扑中移出。

状态：ACTIVE 创建日期：2026-09-01 所属模块：docker 影响范围：Compose / Makefile / 双语部署文档 需求来源：用户原话

1. 原始诉求

“把 yml 的修改提个PR”

工作区已有两份 Compose 修改：默认镜像由 Docker Hub 切到 GHCR，并删除内置的 douban-rs-api 服务及依赖关系。边界核查后，用户确认同步更新仍宣称 Compose 内置该服务的部署文档；PR 评审进一步指出本地构建标签与新 Compose 镜像名不匹配，且英文文档仍保留旧地址。

2. 目标与边界

目标

  • docker-compose.yml 默认使用 ghcr.io/talebook/talebook。
  • 开发 Compose 使用对应的 :dev 标签。
  • 本地生产与开发构建同时产生 Compose 可直接消费的 GHCR 标签。
  • Talebook 启动不再隐式拉起第三方豆瓣代理。
  • 中英文使用文档明确豆瓣代理需由用户自行部署。

非目标

  • 不停止 Docker Hub 镜像发布或移除既有本地标签。
  • 不修改 Dockerfile、CI 或 Kubernetes 清单。
  • 不改变 Talebook 内豆瓣插件的配置接口。
  • 不替用户选择外部代理的部署方式或网络拓扑。

3. 现状与证据

观察证据结论
Talebook 已发布 GHCR 镜像design/project/20260813-ghcr-image.active.htmlCompose 可以消费由本仓库发布的同名 GHCR 镜像。
豆瓣代理是可选外部能力document/README.zh_CN.md、document/README.en_US.md 的豆瓣插件配置章节从默认 Compose 移除不会删除插件配置入口，但中英文内置服务地址说明必须同步修正。
两个 Compose 文件均显式依赖第三方服务docker-compose.yml、docker-compose.dev.yml需同时移除服务和 depends_on，避免保留失效依赖。
本地构建标签与新 Compose 镜像名不匹配Makefile 的 build-spa、build-dev若只切换 Compose 镜像名，make build && make up 会忽略刚构建的本地镜像并尝试使用远程 GHCR 镜像。

4. 方案

方案结论：调整两份 Compose 的镜像地址和服务拓扑；为本地生产与开发构建补充相同的 GHCR 标签，同时保留既有标签；中英文文档改为说明用户需独立部署豆瓣代理并填写其可达 URL；测试覆盖 YAML 结构、双语文档和 Makefile 展开的构建命令。
决策点选择理由不采用
默认镜像源生产与开发均使用 GHCR镜像由同一仓库 workflow 发布，归属和代码托管一致。不删除 Docker Hub 发布能力，也不全局替换其他构建用途引用。
本地构建标签build-spa 和 build-dev 额外写入 Compose 对应的 GHCR 标签保证 make build && make up 与 make dev 能复用刚构建的镜像。不移除原有 Docker Hub 风格标签，避免破坏其他本地与自动化消费者。
豆瓣代理从默认 Compose 完全移除可选第三方能力不应成为 Talebook 基础服务的启动依赖。不保留注释服务或 profile，以免继续暗示项目负责其生命周期。
文档中英文均说明独立部署和可达 URL避免任一语言继续提供已失效的 Compose 服务名。不提供唯一容器编排示例，保留用户网络选择。

5. 影响范围、风险与回滚

影响范围

新下载或重新应用 Compose 配置的用户将从 GHCR 拉取 Talebook；本地构建会额外产生 GHCR 标签；豆瓣插件用户必须让 Talebook 容器能够访问其独立代理。

保持不变

数据卷、端口、环境变量、Talebook 应用行为、既有运行中容器、原有本地镜像标签和 Docker Hub 发布契约均不变。

主要风险：GHCR 拉取可用性与用户网络环境相关；依赖 Compose 内置豆瓣代理的部署在重建后会失去该容器。文档提示迁移边界，解析测试防止服务或依赖残留。
回滚：恢复两份 Compose 的 Docker Hub 镜像地址、douban-rs-api 服务及 depends_on 即可；不涉及数据迁移。
界面审查豁免：本次只修改 Compose 配置、Makefile、部署文档和配置回归测试，不改变 Talebook 页面、交互、文案资源或其他前端消费者，因此无界面影响，不执行 interface-review。剩余风险集中在不同网络环境中的 GHCR 拉取与外部豆瓣代理连通性。
