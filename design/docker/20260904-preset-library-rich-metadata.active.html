预置书库收敛为富元数据格式

移除会丢失作者与语言信息的 PDF、TXT 种子格式，以原始 EPUB 替换；同时让四大名著在 Calibre 与 EPUB 3 中组成可识别、可排序的“中国四大名著”丛书。

状态：ACTIVE 创建日期：2026-09-04 所属模块：docker 影响范围：Docker 预置书库、来源清单、测试 需求来源：用户对话 2026-09-03 至 2026-09-04
原始诉求目标与边界现状证据方案风险测试决策

1. 原始诉求

“data 是 docker 运行目录吧？要加入到 .gitignore里面。docker book里的种子书籍调整一下，只保留epub+mobi+azw3，因为这些导入时能识别出丰富的信息，体现出talebook的优势，去掉 txt + pdf。然后，四部名著要在epub文件里添加‘丛书：中国四大名著’的信息。”

代码核对表明，默认 Compose 已将仓库 data/ 挂载到容器 /data，且根 .gitignore 已存在 data/ 规则。因此该项是现状确认，不新增重复规则。

2. 目标与边界

目标

  • 默认书库保持 10 本、中英文各 5 本。
  • 种子书仅包含 EPUB、MOBI、AZW3，Alice 与 Frankenstein 使用同名 EPUB 替换。
  • 四大名著导入 Calibre 后共享丛书“中国四大名著”，并具有稳定序号。
  • 来源、许可证、转换和最终制品哈希可审计。

非目标

  • 不改写或清理当前 data/ 持久化书库。
  • 不在升级时删除用户已有 PDF、TXT 图书。
  • 不改变上传接口、扫描逻辑或其他格式支持能力。
  • 不调整封面、正文、章节导航和阅读器界面。

3. 现状、根因与证据

观察证据结论
Docker 默认运行目录docker-compose.yml 使用 ${TALEBOOK_DATA_DIR:-./data}:/data；.gitignore 已含 data/无需重复修改忽略规则。
PDF、TXT 元数据贫化sources.json 记录 Alice 与 Frankenstein 经 Calibre 导入后作者为 Unknown、语言为空。换回来源 EPUB 可展示作者、语言、封面、标识符等丰富字段。
来源 EPUB 可复用Git 历史保存两份来源 EPUB；其文件路径和来源哈希可与清单交叉验证。优先复用已经审计的固定制品，不依赖变化中的远端下载。
现有四部 EPUB 为 EPUB 3四个 OEBPS/content.opf 的 package version 均为 3.0。可同时写入 EPUB 3 collection 和 Calibre 兼容元数据。

4. 方案

方案结论：以历史中固定的 Standard Ebooks EPUB 替换两种贫元数据格式；四大名著在 OPF 中同时写入标准 collection 语义和 Calibre 系列字段；清单与测试共同定义可审计契约。
Source复用固定 EPUB

从 Git 历史读取 Alice 与 Frankenstein，并验证来源 SHA-256。

Metadata写入双轨丛书字段

四大名著同时包含 EPUB 3 collection 与 Calibre series/index。

Contract更新来源清单

格式、文件名、哈希、转换记录和元数据策略保持一致。

使用隔离临时书库导入，检查作者、语言、封面、丛书与序号。

5. 影响范围、风险与回滚

影响范围

docker/book/ 的二进制种子、sources.json、预置书契约测试，以及 Dockerfile 构建生成的全新预置书库。

保持不变

现有持久化 data/、运行时导入与格式支持、书籍正文、公开 API 和前端交互均不改变。

主要风险：直接重打包 EPUB 可能破坏 mimetype 首项与不压缩约束，或让清单哈希失配。测试必须逐包校验 ZIP、XML、封面、导航、哈希及实际 Calibre 导入结果。
回滚：以本次提交为单位恢复两个旧格式文件、四个原 EPUB、来源清单与测试；本次不迁移持久化数据，因此没有数据回滚步骤。
