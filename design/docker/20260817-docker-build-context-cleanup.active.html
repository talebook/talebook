收紧 Docker 构建上下文并清理过期截图

让生产 SPA/SSR 镜像只包含运行输入；测试源码保留在 test 并由 dev 继承，同时删除没有任何文档引用的历史截图。

创建日期：2026-08-17所属模块：docker状态：ACTIVE 影响范围：Dockerfile、Makefile、.dockerignore、tests、document/screenshots需求来源：TB-63

1. 原始诉求

“清理 talebook 项目中一些历史过期的截图。优化 dockerfile 构建流程，不要把 test、design 等测试代码和方案文档打包进去，以节省空间。”

现状中生产镜像虽未执行 COPY tests/ 或 COPY design/，但根构建上下文没有按 Dockerfile 输入收敛。用户进一步确认 dev 可以继承 test 并包含测试源码，精简边界只针对 production/SSR。

2. 目标与边界

  • 根 Docker 上下文只允许各 target 实际使用的输入，排除 design/、document/ 等不被任何镜像消费的内容；保留 test/dev 需要的 tests/。
  • make test 继续能构建并运行完整后端测试；开发镜像继续继承 test 的测试源码与工具。
  • 生产 SPA/SSR 不继承 test/dev stage，也不执行 COPY tests/，镜像内容和运行契约保持不变。
  • 截图只删除没有任何 tracked 文件或所属目录引用的项目；保留 README 展示图和仍被方案引用的验证证据。

3. 方案

决策点方案理由
根构建上下文.dockerignore 改为 target 输入 allowlist，允许 app、webserver、conf、docker 与 tests，排除设计、文档、截图和本地产物。默认拒绝未来新增的非镜像资料，同时不破坏 test/dev 的既有能力。
后端测试源码test stage 继续执行 COPY tests/；dev 继续 FROM test。dev 可以比 test 更大，测试源码只存在于 test/dev 分支。
生产边界production/SSR 直接继承 server，不继承 test/dev。多阶段构建只把目标 stage 及其祖先装入最终镜像，因此生产镜像不包含测试源码或工具。
截图判定精确文件路径与父目录路径均没有 tracked 文本引用才删除。使用可复验的保守规则，不破坏已记录证据。

4. 风险与回滚

  • allowlist 漏掉新 COPY 输入会导致构建失败；用静态回归测试固定允许路径，并通过 Docker build check 验证实际解析。
  • tests/ 对构建上下文可见，但只有 test/dev 的可达 COPY 会消费它；回归测试固定 production stage 不复制测试源码。
  • 截图删除只影响仓库历史附件，不影响运行时；Git 历史可恢复。整体回滚只需恢复本次提交。
