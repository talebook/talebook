收紧 Docker 构建上下文并清理过期截图

让生产与开发镜像只接收实际构建输入；测试源码仅在测试 target 中通过独立上下文提供，同时删除没有任何文档引用的历史截图。

创建日期：2026-08-17所属模块：docker状态：ACTIVE 影响范围：Dockerfile、Makefile、.dockerignore、tests、document/screenshots需求来源：TB-63

1. 原始诉求

“清理 talebook 项目中一些历史过期的截图。优化 dockerfile 构建流程，不要把 test、design 等测试代码和方案文档打包进去，以节省空间。”

现状中生产镜像虽未执行 COPY tests/ 或 COPY design/，但根构建上下文没有排除这些目录；同时 dev 继承 test，会把后端测试源码带入开发镜像。

2. 目标与边界

  • 根 Docker 上下文只保留 Dockerfile 实际使用的运行与构建输入，排除 tests/、design/、document/ 等非运行内容。
  • make test 继续能构建并运行完整后端测试；开发镜像继续提供 pytest 等测试工具。
  • 开发镜像不再继承带测试源码的 test stage，生产 SPA/SSR 镜像内容和运行契约不变。
  • 截图只删除没有任何 tracked 文件或所属目录引用的项目；保留 README 展示图和仍被方案引用的验证证据。

3. 方案

决策点方案理由
根构建上下文.dockerignore 改为运行输入 allowlist，再排除前端测试和本地产物。默认拒绝未来新增的文档、截图与方案目录，避免逐项黑名单遗漏。
后端测试源码test target 使用 --build-context test-source=./tests；Makefile 统一传参。生产/dev 构建不发送测试源码，测试 target 仍保持自包含。
stage 继承新增只安装测试依赖的 test-dependencies stage；test 与 dev 并列继承。复用工具层且防止 dev 继承 test stage 中的源码。
截图判定精确文件路径与父目录路径均没有 tracked 文本引用才删除。使用可复验的保守规则，不破坏已记录证据。

4. 风险与回滚

  • allowlist 漏掉新 COPY 输入会导致构建失败；用静态回归测试固定允许路径，并通过 Docker build check 验证实际解析。
  • 直接执行 docker build --target test 的调用方必须同步传入 named context；仓库入口统一由 Makefile 覆盖，并在 Dockerfile 注释中记录命令。
  • 截图删除只影响仓库历史附件，不影响运行时；Git 历史可恢复。整体回滚只需恢复本次提交。

验证项预期结果
