让 Docker 默认数据目录跨容器重建保留

修正生产部署示例把数据放在临时目录的默认值，同时保持容器内数据契约和已有部署的显式覆盖能力。

状态：ACTIVE 创建日期：2026-08-11 所属模块：docker 影响范围：Compose 与部署文档 需求来源：GitHub Issue #959

1. 原始诉求

“talebook不能保留持久化配置吗，重新构建容器导致初始化了”

报告没有提供部署命令、卷检查结果或主机清理记录。仓库证据足以确认：应用配置本应持久化，但生产示例选择了不适合作为长期数据位置的宿主机临时目录。

2. 目标与边界

目标

  • 新部署默认将整个 /data 保存到 Compose 文件旁的 ./data。
  • 允许通过 TALEBOOK_DATA_DIR 使用已有目录或绝对路径。
  • 文档明确配置、数据库和书库均依赖同一个数据挂载。

非目标

  • 不改变容器内 /data 路径或配置格式。
  • 不自动搬迁、删除或覆盖现有 /tmp/demo。
  • 不修改开发 Compose 的隔离测试数据目录。

3. 现状、根因与证据

观察证据结论
管理员配置会写入持久目录webserver/settings.py 与 webserver/loader.pyauto.py 位于 /data/books/settings。
启动不会主动覆盖已有配置docker/start.sh预置文件只在目标缺失时复制，已有非空数据库也会保留。
生产示例使用临时宿主目录docker-compose.yml 与根 README/tmp/demo:/data 可能因主机清理或重启消失，随后容器会按首次启动初始化。
事实与推断：无法仅凭 Issue 确认报告者主机上的具体清理事件；本次修复针对仓库可证实的危险默认值，不声称恢复已丢失数据。

4. 方案

方案结论：生产 Compose 使用 ${TALEBOOK_DATA_DIR:-./data}:/data。默认目录可见、可备份，并在镜像或容器重建后复用；已有用户可以将变量指向原目录，避免强制迁移。
Configure解析数据目录

环境变量优先，否则使用 Compose 同级的 ./data。

Mount挂载整个 /data

配置、用户库、Calibre 书库与资源共同持久化。

Rebuild替换容器

镜像层变化不改变宿主机目录。

Reuse加载已有状态

启动脚本检测已有数据库和配置，不重新灌入。

volumes:
  - "${TALEBOOK_DATA_DIR:-./data}:/data"

5. Grill 决策与兼容性

决策点选择理由未选方案
持久化粒度整个 /data配置、用户库和书库存在一致性关系，符合现有镜像契约。仅挂载 settings 会丢失用户数据库与图书。
默认存储Compose 相对绑定目录用户可直接查看和备份，且不受 down -v 删除命名卷影响。命名卷不利于新用户定位文件。
旧路径兼容环境变量显式覆盖不在自动化流程中猜测或移动用户数据。自动迁移有覆盖、权限和跨文件系统风险。

6. 影响范围、风险与回滚

影响范围

修改生产 docker-compose.yml、中英文部署说明与代码知识库示例，并增加静态配置回归测试。

保持不变

镜像启动逻辑、应用配置、API、数据库、端口、PUID/PGID 和开发环境均不改变。

主要风险：直接覆盖 Compose 的既有用户会看到默认源目录从 /tmp/demo 变为 ./data。文档要求升级前通过 TALEBOOK_DATA_DIR=/tmp/demo 保持原路径，或在停服与备份后自行迁移。
回滚：恢复原 Compose 映射或设置 TALEBOOK_DATA_DIR 即可；本次不改变数据格式，无需数据库回滚。
