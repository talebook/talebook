原始诉求与目标

管理后台检查、下载校验并安装 Python 与预编译 SPA，不更换容器；发布同字节签名资源至 GitHub 与可配置国内源。首次安装加载器仍需更新一次镜像，升级短暂中断服务。目标分支 feat/upgrade，中文 PR，不合并、不正式发布。

设计决策与边界（grill 自审）

开发者已授权实施细节自行决定。仓库没有 grill 技能，逐项自审而不重复询问。仅支持生产 SPA、非 root 应用账号、默认本地 SQLite 与默认书库；SSR、开发、外部数据库、目录自定义及数据库结构变化拒绝安装并要求更新镜像。独立 root 执行器属于可信镜像，不从升级包加载；通过权限受限 Unix socket 接收管理员 API 的固定操作，普通请求不能传 URL、命令或路径。无需 Docker socket。

运行时指纹记录实际 Python、Calibre、系统包、Python distributions 和基础启动协议文件；数据库指纹包含 models.py、migrate_db.py。发布包绑定架构、SPA、提交、序号、大小、哈希、签名。私钥仅发布端持有；可信公钥和源由只读服务器配置注入，默认没有密钥则禁用安装。

方案与状态转换

最终一致性审查补充：预编译 index.html 标记应用版本；统一 backend() 携带该版本，后端在任何业务处理前拒绝旧版本请求（409），客户端刷新。维护闸门覆盖切换窗口，版本校验覆盖恢复服务后的旧标签页，避免旧前端继续向新后端提交操作。

真实容器暴露 Calibre notes/FTS 的专用 tokenizer，需要可信镜像中的 Calibre 扩展校验备份。同步收紧启动边界：bootstrap 自检脚本复制到镜像只读加载器目录，生产启动不再把 Calibre 运行时目录 chown 给应用账号；服务器信任配置拒绝非 root 或组/其他可写的文件。

检查所有配置源的已签名 stable 清单 → 选择最高序号并持久化防回放水位 → 固定提交下载（源间回退同一 SHA）→ 限额/哈希校验 → 拒绝链接与特殊文件的安全解包 → 维护闸门阻止所有外部流量 → 等待后台任务排空 → 停止应用进程及子进程 → 一致性 SQLite backup → 原子切换统一前后端目录 → 启动与健康检查 → 成功持久化并开放流量；失败切回旧代码。日志和事务状态持久化；中断恢复使用已记录的上个应用，不自动恢复数据库。恢复阶段失败保持维护状态供运维修复。

/data/updates 与 /data/books 分离，root 独占写权限；/run/talebook-release/current 为整套前后端链接。镜像带序号与指纹；仅加载比内置版本更新且兼容的已验证持久化版本。镜像升级可越过旧持久化版本。首次部署与变更 runtime 后走镜像升级。升级不运行 pip、apt、git pull；不会修改插件和书库文件。
