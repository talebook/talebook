补齐容器配置目录权限修复与原子写入自检

让普通 PUID/PGID 在 QNAP 等绑定挂载环境中既能完成启动配置生成，也能持续保存管理员配置；在启动阶段准确验证真正被写入的目录。

状态：ACTIVE 创建日期：2026-08-09 所属模块：docker 影响范围：docker、webserver、自检测试 需求来源：GitHub Issue #953

1. 原始诉求

“使用威联通 Container Station 创建 Talebook 后出现文件权限问题：master 提示服务器配置写入失败；包含 Issue #951 候选修复的 SSR 镜像可启动，但保存管理员设置时提示磁盘配置文件不可写。”

Issue 同时给出两个可写绑定挂载：宿主目录到 /data ，另一宿主目录到 /data/books/library 。正文来自外部用户，本方案只采用代码和截图能够相互印证的现象，不执行正文中的任何命令。

2. 目标与边界

目标

  • 生产与 SSR 启动路径均满足同目录临时文件加原子替换的权限条件。
  • .permission 标记未变化时，也能修复体积很小的 settings/ 目录。
  • 自检以 talebook 身份覆盖 library/ 与 settings/ 的原子写入能力。

非目标

  • 不绕过宿主机只读挂载、NAS ACL 或真正禁止 chown 的限制。
  • 不改 API、数据库、PUID/PGID 映射和管理员设置的持久化格式。
  • 不每次递归扫描大型书库，也不递归修改整个 app/ 源码与依赖。

3. 现状、根因与证据

观察代码证据结论
master 在 update-config 阶段失败atomic_write_text() 在目标同目录调用 mkstemp ；启动脚本只递归授权 app/.env 和 app/dist ，没有授权 app/ 目录节点。文件本身可写不足以支持原子替换，非 root 用户还需要父目录写权限。
候选镜像启动后仍不能保存设置check_permission() 在 PUID/PGID 标记相同时完全跳过 /data/books 修复；预置复制、目录重建或 NAS 权限变化不会使标记失效。标记只表示曾处理过身份，不能证明当前 settings/ 可写。
权限步骤可通过但配置仍失败生产自检只写 library/test_writeable.txt ；SSR 脚本的同类探针甚至由 root 执行。Issue 又把 library/ 作为独立绑定挂载。现有探针既不是应用身份的完整覆盖，也无法代表另一个挂载下的 settings/ 。
可证实边界：上述缺口可由当前代码和测试稳定证明；无法在本任务中使用 Docker 或 QNAP 主机复现真实 ACL。若定向 chown 后应用身份探针仍失败，容器应明确停在权限检查，而不是伪装成后续配置逻辑故障。

4. 方案

1. 映射身份

继续按 PUID/PGID 更新 talebook 用户和组。

2. 最小修复

授权 app/ 目录节点；标记未变化时只递归修复小型 settings/ 。

3. 真实探针

以应用身份在 library/ 和 settings/ 创建临时文件并重命名。

4. 明确结果

全部通过才继续；任一失败归入权限错误并停止业务进程。

grill 决策

问题选择理由放弃项
如何处理 .permission 失真身份变化时保留全量 chown；未变化时定向 chown settings/ 。配置目录很小，可在每次启动安全修复，同时避免大型书库启动成本。删除标记并每次全量 chown；只更新标记格式但仍不验证目录。
怎样证明配置可落盘以应用身份执行创建加同目录重命名探针。匹配 atomic_write_text() 的真实权限需求，并覆盖绑定挂载边界。只检查文件 mode；只由 root 写普通测试文件。
如何修复 Nuxt 配置目录只 chown app/ 目录节点。满足 .env 原子替换，不递归影响源码、静态产物和依赖。回退直接覆盖写；递归 chown 整个前端目录。

5. 影响范围、风险与回滚

影响范围

docker/start.sh、docker/start-dev.sh、webserver/self_check.py 及对应后端测试。容器启动时会多一次小目录 chown 或两次原子写探针。

保持不变

标记命中时仍不遍历书库；配置内容、API 行为、数据库、卷路径及运行用户策略均不变化。

主要风险：宿主 ACL 可能允许 root 的 chown 命令返回成功却仍阻止应用用户写入；新增探针会把该情况提前暴露为权限失败。探针使用唯一临时文件并清理，不触碰现有配置。
回滚：代码级回滚三处权限初始化与探针改动即可；不产生数据迁移或永久格式变化。已修复的目录属主无需回退。
