文件目录查询索引与增量更新

2026-10-18 · booksvr · ACTIVE

原始诉求与目标

用户指出十几万行数据库目录浏览不应耗时十几秒，确认已有路径索引但实现全表读取、Go 分组、每请求全量可见性扫描及30秒重建没有利用索引。修正上一版性能验收不足：正常首开、展开、跳页必须通过真实大库计时，不以缓存遮盖全量重复工作。默认仅当前目录、可选递归与私藏/丢失保护保持。

方案

新增持久化目录位置表（book_id、format_key、directory），覆盖索引(directory,book_id)，目录节点表(path,parent)及父目录索引。来源路径仍是唯一事实源，ZIP 引用由已有 Go 解码，目录索引仅保存少量元数据、不缓存书籍正文。新增 dirty book 队列；格式插入/删除/路径或书ID变化、书籍删除/受管路径变化、受管 data 变更、源格式 missing 变化，通过事务内轻量触发器登记受影响书ID，按书去重。读取目录前以128本的小事务增量核对并更新索引，首次仅回填一次；不周期重建全库；独立维护任务每2秒处理队列，避免依赖文件扫描或用户访问。中断后队列仍在，下一次续接。根路径改变触发路径投影重算，不移动源文件。目录计数和精确/递归列表通过目录索引范围执行SQL，分页在SQL中进行，只加载当前页书目。隐私ID用一个JSON参数传入，避免SQLite变量上限；每次权限即时生效，空/丢失目录不显示。

边界与备选

不扩大30秒缓存TTL、不省略权限检查，不每次扫描磁盘。保留原挂载、账号、数据和导入续跑状态。新增表可重建，保留旧镜像回退；旧版本继续写源表时触发器仍记录队列。索引初建耗时在部署预热阶段完成并记录，稳定请求不再全库传到Go。读取失败返回错误，不展示未同步成功的半成品。为确保所有既有SQL写法可捕获，选数据库触发器而不是逐个改动导入/移动/删除调用点。

影响范围

booksvr/internal/library 迁移、目录索引/查询及测试，httpapi目录分页渲染复用。更新 spec/书库.md。无界面影响：页面、控件、文案、导航及响应JSON保持一致，仅替换只读查询的数据执行路径；本次纯后端性能修复可豁免 interface-review，仍真实浏览器回归目录/默认非递归/跳页。

初始验证计划

计划项：精确与递归范围、特殊字符/ZIP、权限和丢失/恢复、删除/移动/改名、多格式、旧data、root变化、迁移重入、增量队列捕获、无变化时不扫描全库、SQL分页与取消恢复。隔离真实DB副本执行首建与稳定查询计时/EXPLAIN QUERY PLAN，Go回归/vet、规格设计校验；真实生产浏览器与API计时通过后部署提交推送，导入在单本边界优雅交接。

隔离性能反馈与方案迭代

首轮增量位置索引：182917 本、190979 格式，首建110.81秒；精确PDF目录查询约10毫秒，但根目录及大父目录COUNT DISTINCT仍需0.92–1.62秒（编译/导入并行）。EXPLAIN确认已经走覆盖路径索引，瓶颈变为每次对子树重复聚合。继续增加节点-书籍去重成员表，采用整数node_id与book_id，分别记录直接/后代归属；节点维护总数、直接数、后代数，按单本增量写成员时事务内更新计数。根目录仅取直接子节点计数，权限排除从成员主键扣减，递归列表也按node_id索引直接分页，不再每次扫描全子树。索引元数据可重建，不保存正文。先隔离重建验证，再在原服务继续运行时低优先级预热生产索引，完成后交接容器，避免用户承担首次回填延迟。手动刷新仅排空增量队列，不再全库重建。

权限与可用性执行位置

目录位置与成员投影在增量同步时已经排除不存在书目与确认缺失格式，目录接口只额外读取当前私藏权限集合，不再重复调用全书库来源不可用书籍聚合；避免对已排除的缺失书重复生成大集合和扣减。用接口级缺失/恢复测试证明不弱化可用性，列表渲染复用已经分页且过滤的页面装配。

与运行中导入协作

历史回填使用128本的小事务，相邻批次之间释放数据库写锁并等待20毫秒，给原导入事务执行机会；等待可被请求取消。正常无变化请求不等待，单批完成也不额外等待。生产预热使用较低CPU和IO优先级，完成前不替换原容器。

完整回归发现与修复

源同步worker回归发现 SQLite 外层 UPSERT 的冲突策略会覆盖触发器内 INSERT OR IGNORE，导致 dirty 主键冲突。正式库未应用。改为 INSERT SELECT WHERE NOT EXISTS，从根本上不尝试重复插入；触发器升级在同一写事务内完成，避免运行中导入遇到触发器缺口。新增重复 UPSERT 队列回归并重跑完整源同步/导入相关测试。

隔离真实大库验证结果

一致性副本：182917 本书、190979 条格式记录。新增成员/计数方案完整历史回填623.60秒（与完整测试并行、较低CPU/IO优先级）；部署将提前完成回填，不把此一次性成本转交用户页面。回填后根目录1.13/1.67毫秒，/books1约0.94毫秒，含29子目录的父目录3.93毫秒，allitebooks约2.15毫秒；7519本PDF返回60个页内书ID为1.57/1.77毫秒。这是library层查询时间，未冒充完整HTTP或页面时间。EXPLAIN显示子节点走book_directory_node_parent、权限扣减走book_directory_member_book，无全库路径扫描。独立SQL核对全部节点计数与去重成员聚合，bad_node_counters=0，dirty队列为0。

首轮完整测试还因临时构建目录缺少未改动的webserver源码，导致4项Python对照契约检查失败；已补齐只读对照源码。另一次在测试生成期间改名测试函数导致旧testmain引用失配，已停止并以固定源码顺序重跑。以上均保留初轮日志，不记录成通过。最终结果见后文。

持续导入期间的索引维护

只在GET时排空队列，会使夜间大量新导入积压到下一次打开目录。复用现有源同步worker的事件/30秒维护轮次主动同步目录索引，即使自动导入关闭也维护；不新增goroutine或计时器。GET仍同步残余变化保证新鲜度。索引维护错误单独记录directory_index_error，不掩盖源同步结果，下一轮重试；停机复用现有context与等待机制。新增源worker回归，在没有目录GET的情况下直接断言初始索引及源删除后的计数更新。

生产观察后的维护调度修正

生产首轮文件核对长时间处于scanning，复用该轮次会让新增格式队列等待文件遍历；观察到304本待同步。此前“复用worker”的实现不够独立，替换为受服务context控制的轻量目录维护协程，每2秒检查并增量处理，取消后等待退出，错误保留队列并记录日志后重试。它只读写索引元数据，不访问源文件；小事务与批间让出写锁继续保留。目录查询仍同步残余变更，不依赖后台定时精度。调整serve生命周期及回归，用独立索引维护证明不受源同步自动导入开关/长扫描影响。该变化明确取代前面不新增协程的初始选择。
