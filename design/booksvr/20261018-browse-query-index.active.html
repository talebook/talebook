浏览查询与分类索引优化

创建日期：2026-10-18 · 模块：booksvr · 状态：ACTIVE

需求来源：书库、分类浏览重复全库读取；测试后部署、提交推送，保持导入任务。

原始诉求与目标

审计书库、分类、筛选和卡片读取；保留响应字段、排序、分页、私藏权限、缺失源保护，不修改书源、导入队列或挂载。

设计决策与边界

沿用用户已确认的可见性和界面规则，内部查询选择按实测决定，无需新增用户决策。元数据和用户库分离，通过有界批量参数传递当前用户不可见 ID。书库和分类书目在 SQL 中过滤、计数和分页，只加载当前页。分类聚合使用覆盖索引，避免分类逐项全库查询；作者别名、Unicode 与空白规范化保留去重语义，作者列表仅顺序读取名称确定规范化/别名分组，由 SQL 合并少量替换项并分页；多名称组以一次批量 SQL 去重计数，不逐组查询。卡片附加字段批量读取。审计扩展到管理列表和搜索相关性排序：管理页沿用既有排序语义，在 SQL 分页；搜索标题只批量读取一次，禁止排序比较器反复访问数据库。

先使用只读 WAL 快照在隔离副本验证 EXPLAIN、权限、排序和大库性能；增量建立必要索引，不重建书库。部署在单本导入完成边界优雅退出并自动续跑，保留回滚镜像。

影响范围与风险

主要涉及 internal/library、httpapi、userdb。无界面影响：接口 JSON、URL、页面结构、文案和交互保持不变，豁免 interface-review；仍通过生产浏览器验证真实数据。spec/书库.md 的实现对照按实际落点更新。隔离核对发现缺失源聚合仍耗时 2.8–7.6 秒，当前页格式读取还误从全库 missing 索引开始。新增缺失书籍投影，由格式、源状态和旧式 data 变化的事务内触发器即时维护，仅初始化一次；缺失保护不依赖目录后台延迟。作者/标签实测仍有每次聚合全部关联记录的成本，因此增加分类计数投影，关联关系变化只对首次/末次书籍关联增减计数（重复关联不重复计数），不在导入时重算整个分类。旧式外部格式写回使用显式 DELETE/INSERT 替代 REPLACE，使默认关闭递归触发器的 SQLite 也正确维护投影。为分类计数增加 (kind,n DESC) 排名索引，先按计数定位，再对相同计数的名称稳定排序，避免每页排序全部分类；无关联的新分类登记零计数。Unicode 名称排序保持一致，无搜索词时不重复调用名称折叠。当前页缺失格式强制从 book_id 索引定位后读取状态。索引建立需要短暂写锁，先测耗时再安排部署；不对正在运行的服务重建索引。分类计数仍保持现有语义，不借性能改动改变分类可见性规则。
