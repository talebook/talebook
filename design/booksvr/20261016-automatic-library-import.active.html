一次启动自动扫描并导入全部书籍

创建日期：2026-10-16 · 模块：booksvr · 状态：ACTIVE · 需求来源：用户反馈扫描中勾选后导入灰色，并要求取消选择、全部自动导入。

原始诉求与目标

保留导入列表及可选勾选；根据用户最新补充，固定显示“全部导入”，不因勾选与否隐藏。一次“全部导入”处理全部配置来源，已发现待导入项先入库，新扫描普通书和 ZIP 按批次自动入库。任务运行期间明确显示阶段、数量及重复启动禁用原因；独立扫描时“全部导入”保持可用，可提交接续任务，关闭或刷新页面不影响任务。

设计决策

用户已明确要全部自动导入；grill skill 不在项目中，按该决定实现，无需另问。沿用现有来源目录、导入模式和内置书库位置；定时监控仍是可选设置。单次任务复用管理员身份与串行写入锁；同一任务重复启动合并，不排队重复全量工作。显式 hashlist 保留旧单独导入语义，hashlist=all 扩展为扫描并自动导入的完整任务，页面允许按需逐本选择，但全量任务不依赖选择。移动模式保留明确确认。

扫描器添加批次完成回调，在普通书批次以及 ZIP 成员批次完成后执行有界 ready 游标导入。后台统一任务从已有待处理开始，然后扫描各根目录并逐批导入，按路径范围过滤；同一文件单项错误记录后继续。目录错误汇报并继续其他有效目录，严重数据库写入错误终止。支持任务取消；重启后已完成记录仍保留，重新启动按现有查重继续。

方案与影响范围

增加后台完整任务回调与状态（running / phase / error）；import/run 的 hashlist=all 一次提交完整工作，scan/run 保留兼容扫描，状态接口跟随两个阶段直到全部结束。前端保留选择并固定显示全部导入，勾选与否都不改变该按钮；展示阶段及已入库/待处理计数；共享任务识别优先完整任务阶段。涉及 spec/书库.md、spec/系统设置.md 和 app 导入页面，保留已有设置与 OPDS 独立导入能力。

测试结果

验证范围：单请求两目录超过 500 本与 ZIP 自动入库；已存在 ready 恢复、重复启动去重、关闭页面/刷新阶段恢复、错误及取消；不选书和已选书时均可见且可用的全部导入按钮；真实 Docker 隔离实例完整流程，正式任务接续；interface-review full 当前分支相对默认分支全部变更；Go、前端单测、构建、规格和方案检查。
