全目录后台扫描与 ZIP 解压导入

创建日期：2026-10-16 · 模块：booksvr · 状态：SUPERSEDED · 来源：用户要求一次扫完全部目录，ZIP 自动解压导入。

替代关系

2026-10-16：ZIP 仅索引时永久保存解压正文的设计已由 ZIP 仅索引与临时文件回收 替代。原全量扫描、分批入库和 ZIP 识别能力继续沿用；当前 ZIP 仅索引只保留来源引用，按需解压后立即清理。

原始诉求与目标

扫描按钮只需点击一次，后台持续遍历全部配置目录；500 仅为内部处理批次，不能截断整次任务。ZIP 合集按包内每本电子书识别、查重和导入，不要求用户手动解压。内置书库仍在 /data/books/library，多个来源挂载保持现状。

设计决策与边界

用户已明确决定全量扫描和自动解压；grill skill 在项目中不存在，本轮直接以已有授权确定实现边界。扫描与入库保留已有两个操作：扫描展开包内条目，导入全部时逐本入库；自动监控启用时自动入库。原 ZIP 保留，move 模式仅处理解出的书，避免删除包含其他内容的源包。

目录采用流式遍历和有界批次，不一次收集所有待处理任务或解压内容。每个 ZIP 一次只物化一本书用于分析，扫描后删除临时文件；导入时再次按保存的包路径、成员链和文件身份读取，校验内容哈希。index 将解出内容保存到 /data/books/import-cache 供长期阅读；copy/move 写入原有内置书库并清理临时文件。纯图片 ZIP 沿用漫画行为；支持嵌套 ZIP、中文旧编码名称。损坏、加密、路径穿越、符号链接及资源预算错误逐条记录，其他文件继续。

ZIP 容器记录使用 expanded 内部状态、源文件大小/修改时间身份和成员数量；成功展开的容器不计作书籍，重扫仅在身份及成员数量都一致且无未完成成员时跳过；旧版失败的 ZIP 自动重新处理。中断后保留已完成条目，后续扫描续处理。源包变化后的旧待导入条目拒绝使用失效来源。

方案与影响范围

扫描服务新增可取消的全量流式入口；HTTP 后台任务持续运行直到全部目录结束，任务状态提供已处理数及压缩包数。导入增加归档来源解析，单本出错不阻断其余待处理书籍。前端显示运行进度、重进页面后恢复任务观察。扫描前幂等建立路径索引及状态/ID 索引，避免全量扫描的逐路径查找退化；自动导入使用每页 500 条的 ID 游标读取，避免全量 ZIP 展开后超出 SQLite 参数数量。

影响 booksvr/scan、httpapi、命令接线、app 导入页面和规格 spec/书库.md、spec/系统设置.md。以 interface-review full 复查当前分支相对默认分支的全部界面差异。

追加：批量删除

用户补充图书管理多选删除无效。已确认管理后台删除回调未装配，接口却把空操作计为成功；单本删除走另一条已接线的路径。批量删除将复用单本删除回调，逐本汇报成功与失败，不再虚报成功，失败项保留选择。仅在隔离实例生成的书籍上实际执行删除验证；不删除用户现有书籍。
