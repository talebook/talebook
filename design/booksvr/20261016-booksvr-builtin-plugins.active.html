booksvr 内置插件装配与全量移植

Go 后端此前只造了空插件注册表，插件中心看不到任何插件、OPDS 开关不可用。本方案新建唯一注册入口 pluginbuiltin，把 Python 侧 39 个内置插件全量移植为 Go 实现并接入启动装配。

状态：ACTIVE 创建日期：2026-10-16 所属模块：booksvr 影响范围：booksvr/internal/pluginbuiltin（新增）、cmd/booksvr、internal/httpapi；spec/插件/ 已覆盖全部 39 个 ID，无行为新增 需求来源：用户原话「原来的Python插件在booksvr下能用吗？是要重写为go的吧？开个分支，把这些全部都补齐了吧」

1. 原始诉求

“原来的Python插件在booksvr下能用吗？是要重写为go的吧？开个分支，把这些全部都补齐了吧”

用户在插件中心看不到任何插件。排查结论：Go 生产代码没有任何 .Register(...) 调用，NewPluginRegistry() 造出空表，/api/admin/plugins 返回 err:"ok" + 空数组（前端走「空列表」分支而非「加载失败」）。Python 侧在 plugin_runtime.py 模块导入时遍历 register.py 的 39 个 provider 注册；Go 侧缺的正是这半句装配。用户澄清后确认：范围 = 全量 39 个；分支 = feat/booksvr-builtin-plugins（从 feat/booksvr-calibre-rewrite 切出，在 fork 仓库开发）。

2. 目标与边界

目标

  • GET /api/admin/plugins 返回 39 条 definitions 与 39 条 installations
  • 39 个 plugin_id 与 Python register.py 完全一致（测试硬编码对齐）
  • POST /api/admin/plugins/opds-service 真正写回 conf/auto.py，不再返回 plugin.not_wired
  • builtin_state["talebook.source.opds"] 含 configured / enabled / service_enabled 三键
  • 每个 provider 的动作语义逐字复刻 plugin_runtime.py:1516-1585

非目标

  • 不改前端 Nuxt 任何代码（app/** 零改动是硬验收口径）
  • 不改 Python 后端（webserver/** 仅作参照）
  • 不新增插件、不改插件协议与 manifest 字段集
  • 不实现 webserver/plugins/captcha/**（不在 39 个之内，Go 已有 internal/captcha）

3. 现状与证据

  • Python 39 个 provider：SOURCE 12 / META 7 / REVIEW 6 / ANNOTATION 1 / TOOL 4 / PUSH 7 / COMBO 2（实测 register.py）。
  • Go 侧构造点 cmd/booksvr/wiring.go 与 httpapi/wiring.go 均 NewPluginRegistry() 后未注册。
  • 已有可复用零件：sourcebase（Base/OPDSProvider）、metabase.MetaSourceMixin、metasource 7 个源逻辑、booksource（Legado 引擎 + VeneraProvider）、booktools/booktransform/normalize/epubmeta。
  • PluginConfig.SaveExtraSettings 未接线 → OPDS 开关恒返回 plugin.not_wired。

4. 方案

4.1 唯一注册入口

新增 booksvr/internal/pluginbuiltin 包，暴露 Register(reg *pluginruntime.PluginRegistry) error；按 Python PROVIDER_GROUPS 顺序（combo → source → meta → review → annotation → tool → push）注册 39 个 provider。注册失败（manifest 非法或契约违反）直接返回错误，启动即失败——与 Python 导入期抛错一致，不静默跳过。

4.2 分派 helper

DispatchInvoke(p, method, args, context) 逐字复刻 Python _call_provider 的动作语义：test 走 self_check（不健康抛 UpstreamError）、无 execute 报 plugin.legacy_action_unsupported、其余走 execute；能力方法名（search_books / get_reviews / browse / push / apply 等）按接口断言分派，未实现返回 plugin.provider_contract。每个 provider 的 Invoke 都是一行委托。

4.3 启动接线

  • newServiceWiring 在构造注册表后调用 pluginbuiltin.Register（不返回 error 的签名下，失败 panic，注册失败属编程错误）。
  • newBookWiring 增加 registry 参数（nil 时自建并注册），serve.go 传入 opts.PluginRegistry，两处共享同一注册表。
  • PluginConfig.SaveExtraSettings 接到 SaveSettings(opts.SettingsPath, args)，OPDS 开关与插件偏好真正写回 auto.py。

4.5 OPDS 开关与状态

GenericOPDSProvider 覆写 manifest（含 ui.service_toggle=="opds"、manage_dialog、healthy_message），实现 PluginStatus（查 opds_sources 表得 configured/enabled，service_enabled 读 OPDS_ENABLED 设置）与无 endpoint 时的健康兜底。

5. 影响与风险

  • 纯增量：新增包 + 3 处接线；plugin_definitions/plugin_installations 新增行对既有库是纯增量（EnsureBuiltinDefinitions 幂等）。回滚即 revert 分支提交。
  • 行为变化：kindle 推送从「device.unsupported」变为可路由到 provider（邮件服务未接线时明确报错）；既有测试已按新事实更新。
  • 已知偏离（按方案风险 3 的缓解策略）：EPUB 美化先落 describe/参数校验/预设 CSS 插值与注入核心，章节标题三层识别与目录页生成留待补全；微信读书元数据构建为简化版（完整 WereadMetadataApi 留待补全）。
  • 环境阻塞：本机 Docker 不可用（dockerDesktopLinuxEngine 连接失败），无法按规范起真实后端做前端体验验证与 interface-review；以 handler 级端到端测试替代，不静默降级到 mock。

7. 决策记录

  • 单一注册入口 pluginbuiltin.Register（方案 B），与 Python register.py 一一对应，让「39 个都注册」成为一条可断言的测试。
  • 注册失败即启动失败（panic），与 Python 导入期抛错一致。
  • SaveExtraSettings 接 SaveSettings(opts.SettingsPath, args)；失败返回 file.permission（沿用 Python 文案）。
  • OpenCC 字典与美化预设以内嵌资源随 Go 二进制分发，避免运行期读 Python 包目录。
