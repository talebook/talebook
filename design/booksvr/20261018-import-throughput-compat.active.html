EPUB 兼容、导入提速与安全续跑

创建日期：2026-10-18 · 模块：booksvr · 状态：ACTIVE

原始诉求

修复 EPUB 兼容性误判与导入速度，重新处理误判记录，核实并修复目录同步保护；检查加密 EPUB 支持；保留正在执行的导入任务进度，测试后部署、提交推送。

目标

容错只用于明确可恢复的格式偏差，保留 ZIP 路径与资源预算保护。解析、存储与封面解耦，控制并发和临时空间，提升真实入库速度。任务有持久化意图，部署在书籍处理边界交接，继续剩余任务；不复制或改写源书，不重置书库。

方案与边界

  • EPUB 允许合法压缩的 mimetype；容器与 OPF 路径先精确匹配，再仅在唯一候选时做大小写兼容，贯穿媒体分析、元数据、封面与阅读器。歧义、安全路径、损坏 ZIP 和资源上限仍明确失败。
  • 检测加密目录/包资源，区分字体混淆与正文加密。研究真实掌阅样本；没有可用密钥的实际 DRM 不冒充可读或可解密，用专门原因保留并报告。可恢复兼容问题重检后回到待导入，密文仍保留明确原因。
  • 导入采用有界的解析预取、串行有序落库与批量标记，避免去重竞争；复用文件身份未变化的扫描分析。支持格式的封面通过持久队列异步补齐，失败重试及重启恢复，不阻塞入库；临时正文预算不变。
  • 全量导入任务持久化管理员与模式，退出/重启自动续跑。第一次从旧版本交接时在用户库写锁下确认没有 importing 行并冻结旧进程，防止观察后又开始下一本；保存续跑意图并干净停止旧程序，再备份和替换容器；新进程继续 pending 记录与目录扫描。若不能安全交接则保留旧任务继续执行，不能强杀中途一本。
  • 目录保护先核对当前 Docker 挂载和旧身份，保留自动保护的严格判定。仅在完整隔离核对当前挂载与来源清单后，执行此次用户授权的显式重新建立基线；空占位、掉线及不可读目录仍禁止自动判删除。身份变化原因与恢复证据记入本方案。

影响 library / media / epubmeta / scan / httpapi / cmd，必要时 EPUB 阅读器消费端；同步更新 spec/书库.md、书籍.md、外部访问.md；不修改已有 ACTIVE 方案。

挂载核对反馈

用户确认 /books 从“小说合集”改挂“books”属于误操作。取消对误挂载建立正式基线；保留当前暂停保护。推荐恢复原“小说合集 → /books”，用户要求移除 Z_lab（均为 ISO），恢复“小说合集 → /books”，将新“books → /books1”，并依据实际文件身份区分旧路径与误挂载期间新导入路径；先在副本验证，已获用户反馈后按该映射随安全交接调整。Z_lab 仅有一条详细目录 TXT，保留书目、来源缺失；不复制源文件。路径修复只改绝对来源前缀，源文件大小全部核对，保留各表行数与书目 ID，普通文件没有 ZIP 引用；保护基线按新映射单独核对。数据库不清空，历史书目与任务保留。

界面审查迭代

审查发现导入失败行只显示“失败”，未消费已有 analysis_error / import_error，新的加密分类因此无法在界面解释。先补状态旁可换行的具体原因（沿用后端恢复建议），增加 E2E 覆盖并重新构建静态前端；在深色、浅色与窄屏真实后端检查，修复后重新审查。真实深色截图发现具体原因放在状态列会挤压扫描信息列（MEDIUM，Introduced）；移到来源路径下方，使用普通正文字体和换行，避免增加状态列最小宽度；重新测试、构建及真实后端渲染复核。复核仍发现长来源路径使状态表头和扫描信息窄至逐字换行，补充两列最小宽度（88px / 128px），路径列继续自适应换行，手机保留 Vuetify 响应布局后再验收。

目录对账性能迭代

完整树核对为 444344 个文件。首次隔离对账长时间停留在等大小候选的 ZIP 查找，读取到 PDG 等非 ZIP 文件；代码核对确认每个缺失的 ZIP 成员会重新打开相同无效候选，且成员名不匹配时也重复读取 ZIP 中央目录。加入仅限单次快照的有界目录缓存：缓存明确无效的 ZIP 及成员名集合（最多 16384 个候选、200000 个成员名），不缓存内容验证结论，不按扩展名过滤，保留 SFX 与改扩展名来源兼容。候选存在目标成员后仍完整 Acquire 校验和全成员归属核对；瞬时 IO 错误不作为无效 ZIP 缓存。增加计数测试证明同一候选只开一次，随后重跑全部 Go 与完整真实对账。正式任务不受重置或停止。

分析复用校核

性能路径的复用指纹补充设备/文件 inode，并核对分析前后文件身份、大小与修改时间。相同大小和时间的原子替换不能复用旧分析，分析期间变化不保存缓存。兼容重检的去重指纹也包含文件身份；非 Linux 无可靠持久文件身份时保守重新分析，仍支持本次调用内的 os.SameFile 预取复核。增加原子替换回归测试，防止优化引入新的兼容性误判。

书名查重性能迭代

真实约 9.5 万本书库的查询计划显示每本导入前按精确书名查重都执行 SCAN books，缺少 title 索引。增加幂等的精确书名索引，保留现有去重语义和串行写入；以 EXPLAIN QUERY PLAN 回归测试验证索引被采用，并使用相同 100 本真实样本重新测量。额外核查 8 个 format.mismatch 的 EPUB，完整读取后全部为零字节填充，是真实损坏文件，不作为兼容性误判回收。

窄屏可读性复核

真实 320px 深色截图显示：无横向溢出并不代表内容可读，数据表仍为桌面列布局，路径和原因被挤到约 40px。明确设置 Vuetify 的 600px mobile breakpoint，窄屏使用原生移动行，将字段名与字段值上下排布，给长路径和失败原因完整宽度。增加移动行和原因宽度至少 200px 的断言，重新构建和复核两种主题；记录为 Layout MEDIUM Introduced，修复后重新审查。

旧基线升级边界收紧

最终代码复核发现 v1 自动升级只校验根目录设备/inode 与根健康标记，不能证明嵌套挂载未同时掉线。删除这条自动放行路径：旧身份摘要发生变化时保持保护，必须经过已授权的管理员完整目录核对和显式重建。v2 的容器重建稳定性与子挂载变化检测不变。正式旧 /books 经前述完整隔离审计后显式重建基线，沿用已有健康标记；当前任务不中断，随后用正常优雅停机交接新补丁。新增回归要求旧摘要不匹配且来源文件消失时仍不得判缺失，显式重建后才允许同步。重新执行来源测试、全包回归、真实镜像与正式阅读验证。

生产并发列表与阅读验收复核

真实运行的导入任务下，切换失败列表后较慢的旧列表请求可能晚于新请求返回，覆盖当前 tab 的结果；隔离副本未运行持续导入，没有暴露这一时间顺序。列表请求增加递增序号，只有最新请求且页面尚未销毁时应用结果、错误和 loading；增加“先请求待处理、后切失败、最后旧响应到达”的回归，重新构建和生产验收，不改后台任务状态。阅读验收同时收紧：仅等待真实 about:srcdoc / blob EPUB 子文档出现正文或已加载图片，并等待遮罩消失；此前通用 iframe 文本检查会把外壳当作成功。实际默认 Candle 已显示封面和章节，显式 Readest 也显示真实封面和正文；Readest 在 HTTP LAN 下另有既有 SharedArrayBuffer worker 异常，未阻止本次正文加载，不声称该可选引擎控制台零错误。
