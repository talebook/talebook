兼容阅读设备上传接口

创建日期：2026-10-18 · 所属模块：booksvr · 状态：ACTIVE

原始诉求

“兼容新老接口好了。再把其它设备的接口也都搜一下资料，看看是否需要增加兼容。”

目标与边界

BOOX 旧推送库和新存储接口兼容；准确保留 HTTP 状态和业务错误；核查多看、汉王、掌阅、当当、PureLibro、Kindle。保留端口和现有设备设置。来源文件和正在运行的导入任务不作数据变更。

方案与决策

沿用旧 library 接口；仅明确 HTTP 403/404/405/410/501 时尝试 storage 接口，写入 /Download。连接中断、超时、限流、5xx（除明确未实现501）、业务错误不重传。两次尝试共享一个超时预算。新接口必须返回 JSON code=0 且未明确 successful=false；旧接口要求 successful 或 isSuccessful 至少一个明确成功标记，且任一出现的失败标记都拒绝。存储接口保留设备同名冲突结果，不能强制覆盖。

SafeHTTP 保留认证响应的原始状态。共用上传器按照结构化错误区分 HTTP、策略、超时和连接失败。Python 兼容后端保持同样的 BOOX 回退规则。

实机迭代证据：2026-10-18 BOOX 重新开启后，Go实机上传通过，返回 code=0、isSuccessful=true、isTokenInvalid=false，message为 /storage/emulated/0/Download/Talebook-传书验证-20261018.txt。追加兼容 successful/isSuccessful 两种字段；任一显式失败或token无效都拒绝成功判定。旧library要求至少一个成功标记，新storage允许仅code=0的已知变体；不把任意设备message直接呈现在HTML错误中。设计边界核对：同一设备、同一目标地址、固定两个端点；不扫描网络、不猜端口、不添加未经证实的上传路径；仅 BOOX 端点拒绝时回退。没有其他设备可实测时记录限制。

现状证据与资料核查

leonFN 宿主机和容器访问设备根路径200，/api/ping 返回ok；旧 library POST403。设备自身 JS 明确使用 storage upload，multipart字段 file 和 path=/Download。GET旧上传接口404不能代表POST不支持，判定采用POST的明确状态。

上游作者的上传器源码：多看 /files + newfile；汉王 /files + newfile/fileName；掌阅 /?action=addBook + Filename/Filedata/Upload，旧版头 application/octet-stream；当当根路径 + files[]；PureLibro /upload + files[]/path。BOOX 旧接口相同。掌阅补充仅HTTP415后使用旧头重试，共享预算，其他接口保持原协议。BOOX官方说明确认设备开启局域网互传后使用其显示地址；具体新接口以用户设备本身JS为第一手证据。当当官方操作指南和PureLibro开发者发布页有网络/WiFi传书能力说明，没有可确认的新版HTTP契约。EinkSync作者README仍给出汉王9310，但未公开足以确认新multipart字段的源码。Kindle核对Amazon邮件传书说明，已有EPUB/PDF/TXT及MOBI/AZW3转换链，无需新增HTTP接口。没有公开新协议和真实设备证据时，不猜测备用路径；其余设备硬件上传尚未实测。

影响范围

booksvr/internal/pluginbuiltin/push.go、safehttp/safehttp.go、webserver/plugins/push/boox.py、spec/插件/发送到设备.md。后端兼容修复，现有错误展示承载准确服务端错误，不新增页面或前端代码。考虑错误文案消费者，执行 interface-review full，结果见后节。剩余风险为无真实设备的厂商接口兼容范围。
