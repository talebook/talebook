大书库分类查询参数上限修复

2026-10-16 · booksvr · ACTIVE · 来源：点击 MOBI 分类报 too many SQL variables

原始诉求

书库浏览点击 MOBI 应正确显示书籍列表。书库浏览格式筛选在过滤 MOBI 之前把全部书库（72,400 本）的 ID 拼进同一 IN 查询，MOBI 只有 7,188 本；独立 /format/MOBI 旧页可用，不能当作用户入口复现。分类通用路径同样会把全部匹配 ID 拼进同一 IN 查询，超出 SQLite 参数上限；在分页前加载全部详情，还会引起大量无用查询。

目标与方案

书库浏览改为直接从格式表查询匹配 ID，与已有可见 ID 求交，再沿用原分页。通用 GetBooksData 每批最多 500 个参数，保留全局去重、输入顺序、缺失 ID 跳过和关联元数据完整性。分类先分批读取 ID 与评分，过滤私有资源，再按原评分降序、ID 降序排序与分页，仅加载当前页完整详情。分页参数、总数、封面、阅读状态、权限和响应协议保持一致。

grill 不可用；用户要求明确，不需新增产品选择。影响 spec/书库.md 的实现对照；这是恢复现有分类能力的后端缺陷修复，没有新增页面、控件、文案或布局。发布使用已验证二进制构建镜像，短暂重启并接续已保存的导入，不清理数据库。

验证结果

全部通过：Go 全部 41 个包，命令 go test ./... -skip "TestFileThemeStoreWriteFileError|TestBackupCreateFailsOnReadOnlyDir" -timeout=300s；两个权限负例分别以 UID 911 执行均 PASS。定向用例 TestGetBooksData*、TestMetaBooks*、TestBookLibrary* 均通过。新增 40,000 个唯一 ID 用例验证跨批去重、原输入顺序、缺失 ID 跳过以及全部关联元数据；40,000 本 HTTP 分类用例覆盖评分、ID 排序、重复格式、孤立 data 行、私藏权限、首尾和越界页、完整封面链接；40,000 本书库流式用例验证格式直接过滤、混合大小写、分页、权限及 NDJSON 首行与逐书协议。页外及其他格式故意放置不可解析元数据，证明没有全库加载详情。

初次测试误把夹具的一项标签写成两项，修正断言后复测通过；初次全包运行少跳过一项 root 权限负例，修正 skip 并以 UID 911 验证，最终全包通过。Windows 写出的 sh 脚本 CRLF 导致 set 失败，转换为 LF 后运行成功。未修改前端源，未重复运行无关前端构建；真实已部署前端通过下列交互验证。提交前校验：25 份规格文档、183 份设计文档和 git diff --check 均通过。
