# Talebook 操作工作流

在用户请求涉及多个命令、写操作、异步任务或管理员能力时读取本参考。具体命令参数和接口以 [api.md](api.md) 与 CLI `--help` 为准。

## 本地书籍

1. 运行 `me status` 确认身份与公开权限。
2. 使用 `books search --name` 找候选书籍；结果不唯一时列出书名、作者和 ID，请用户选择。
3. 使用 `books show --id` 读取完整元数据、格式、权限与当前阅读状态。
4. 只对已经解析出的唯一 ID 执行下载、编辑、收藏、书架、阅读或外发操作。
5. 同时修改元数据和封面时，先确认所有本地文件可读；CLI 返回 `partial: true` 表示前序写入已经生效，不要整组重试。
6. 写入后重新执行 `books show` 或相应只读命令核验。

不要根据列表顺序、模糊书名或上一次会话中的 ID 猜测目标。

## 有声书下载

1. 使用 `audios list [--keyword]` 查看当前身份可见的已发布有声书；结果不唯一时展示书名、作者、book ID 和 edition ID 让用户选择。
2. 使用 `audios show --book-id` 核对书籍、当前已发布版本、章节数量和总大小。
3. 确认用户指定的输出目录不存在，再执行 `audios download --book-id --output`。
4. 成功后核对返回的章节数量、总字节数和逐章路径；目录按章节号使用至少三位数字前缀排序。

下载命令不创建或管理有声版本，也不记录播放进度。任一章节失败时报告服务端错误，确认目标目录没有被发布为完整结果；不要自动改用候选版本、生成任务或 Podcast URL。

## 元数据与阅读状态

- 修改作者、标签等可能代表完整列表的字段前，先读取当前书籍；保留用户没有要求删除的值，不假设接口会自动合并。
- 用户只要求增加或删除一个列表值时，在本地合并当前值与目标变化，再提交完整预期值。
- 保存阅读进度时使用 JSON 对象，并保留服务端不认识的客户端字段；不要把百分比、页码或位置字符串臆造为另一种格式。
- 自动补全、批量转换和写回文件属于可能耗时或覆盖现有数据的操作，先确认目标书籍与影响。

## 网络书库

1. 使用 `remote sources list` 取得真实书源 ID。
2. 使用 `remote search start` 创建搜索任务并保留 task ID。
3. 仅在用户要求等待结果时调用 `remote search status`；运行中且结果未变化属于正常状态。
4. 从搜索结果取得 source ID 与 book URL，再调用详情、目录或章节命令。
5. 保存网络书籍后保留任务标识，并按需调用 `remote books save-status`；完成后用本地搜索确认入库结果。

不要自动无限轮询。用户没有要求等待时，报告任务已启动、任务标识和后续查询命令即可。

## 管理员操作

1. 先运行 `me status`，再让 CLI 执行管理员身份预检。
2. 用管理员列表命令解析唯一用户、书籍、扫描记录、书源或 OPDS 目标。
3. 首次调用高风险命令时不加 `--confirmed`，保留 CLI 输出的脱敏预览。
4. 向用户复述目标、数量和影响；得到本次会话的明确确认后才使用同一组参数加 `--confirmed`。
5. 使用对应列表或状态命令核验结果。

预览与执行之间目标发生变化时，原确认失效，必须重新预览。

## 结果与失败

- 摘要展示书名、作者、状态和有用路径，保留后续操作需要的 book、source、task 等 ID。
- 不把完整 JSON、二进制书籍、封面或日志倾倒到对话中。
- 只读请求可在瞬时网络错误后重试；写操作失败时不要自动重试，先报告 `err`、`msg` 和可能已产生的副作用。
- `partial: true` 必须连同 `completed` 与 `failed` 一起报告，先查询现状，再只处理尚未完成的部分。
- 异步任务已接受不等于已完成；明确区分 started、running、finished 与 failed。
